# Static DAG 公平性诊断与失败分析(2026-09-24,零新调用)

回答两个问题:(1) Static 在故障下的低表现是基线不公平还是真实退化?(2) Static 是否
还有任何维度优势,还是应接受为被支配候选?

## 检查 1:公平性确认(实现层)

Static 故障臂与 Dynamic 使用**完全相同**的初始配置(冻结 POLICY):同一四节点图
(e1/e2→r→v)、同一模型池、同一初始分配(e1/e2=large、r=medium、v=coder)、同一提示、
同一生成参数、同一故障注入集合与种子。唯一区别是恢复策略:Static 的策略为
"检测到失败后整图重执行(同模型)";Dynamic 为"失败节点换模型 + 后继闭包局部重执行"。
修正后的实现保证能力型故障在同模型重执行下持续(此前去重治愈缺陷已修复,
CORRECTION_NOTE_2)。**结论:不存在基线削弱;Static 的低值是无反馈结构在能力故障
下的真实行为。**

## 检查 2:"Static + Retry" 的解析结论(无需新增运行)

在能力型故障定义下,"节点失败后同模型重试"与 Static 的"整图同模型重执行"行为等价:
二者对故障三元组 (任务, 节点, 规划模型) 的再次调用都返回同一失败输出(贪心解码、
故障持续),任务的最终结果分布相同——经验上 Static 存活任务即证据(见检查 3)。
瞬态故障情形下任何重试策略按构造恢复至 clean 水平,该情形在附录中以成本口径
单独报告。**因此 Static+Retry 不构成新基线,添加它不会改变任何故障场景数字。**

## 检查 3:Static 失败位置与传播机制

按注入故障节点位置(种子 20260923;多种子归因表见 RECOVERY_ATTRIBUTION):

| 故障率 | 故障位置 | n | Static 存活 | Dynamic 恢复 |
|---:|---|---:|---:|---:|
| 30% | 证据节点(e) | 15 | 7% | 40% |
| 30% | 推理节点(r) | 11 | 45% | 55% |
| 30% | 验证节点(v) | 10 | **0%** | 40% |

种子 1 的 30% 故障中,Static 28 个失败任务分布:e1×12、v×10、r×6、e2×2;仅有的
6 个存活全部来自 r/e2 故障。机制清楚:**证据与验证节点故障对 Static 几乎必然致命**
(无替代模型、无反馈通路,r 故障时约半数靠 v 独立重算偶然存活);Dynamic 在三类
位置上都有 40–55% 恢复。Static 的问题不是模型能力,而是**缺少故障后的替代动作**。

## Static 的维度地位(修正后)

| 维度 | Static | 是否有优势 |
|---|---|---|
| 质量 | 各场景最低(clean 0.35,f30 0.2861) | 否 |
| tokens | 1482–1503(低于 Dynamic 2174–2249) | 相对 Dynamic 是,但 Single(660–782)更低 |
| 时延 | 4.63–4.66s(低于 Dynamic 6.6–6.8s) | 相对 Dynamic 是,但 Single(0.53–0.66s)更低 |

**Static 在全部场景被 Single 三轴支配**(质量、成本、时延同时更差),相对 Dynamic
仅在成本/时延占优但质量更低——在 (Q,C,L) 空间为被支配候选,超体积独占贡献恒为 0。

## 定位结论

1. 不修改 Static:其低值是真实退化且支持论文动机(无反馈协同结构在故障下引入
   额外风险,类似"无容错的分布式系统")。
2. Static 被支配恰恰验证了 Pareto selector 的前沿过滤:调度器自动把无效 workflow
   (Static)排除出候选,这是机制有效性的一部分而非缺陷。
3. 候选空间的诚实描述:证据前沿目前为 {Single, Dynamic@高故障}(薄前沿);
   丰富前沿的唯一零假设途径是把 Dynamic+Verifier 与 Full-Replay 扩展到故障场景
   (需新执行,约 600–1200 次调用)——若 DV 在故障下因更强的 r 级检测而超过
   Dynamic,前沿将出现第三个成员;若仍被支配,则进一步确认前沿结构。
   该实验为唯一遗留的可选真实运行,是否执行不影响现有结论。
