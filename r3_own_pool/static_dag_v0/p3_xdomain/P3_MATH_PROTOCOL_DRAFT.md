## 建议 DAG（自然三节点，不为对齐财务域而生造节点）
```
question ──► analyze ──► solve ──► verify ──► 最终答案
               │            │          │
            JSON 计划      推导答案     独立复核
```
- **analyze**（模型可分配）：复述问题、列出未知量与条件、给出解题计划。输出 JSON。
- **solve**（模型可分配）：基于题目（+ 分析结果）推导最终答案，格式 `\boxed{...}`。
- **verify**（模型可分配）：对 solve 的答案做独立复核（重推或数值交叉验证），输出 verdict 与修正值。
- **确定性执行层**：sympy 解析 + 有限性校验（可部署的"有效性"信号，不是"正确性"信号）。
- **明确边界（诚实声明）**：数学域没有天然的正确性 oracle；运行时信号 = 格式/解析/有限性 + verify 一致性（模型信号）。正确性只由离线评分器对 gold 判定。这比 code 域（单元测试）和财务域（算术 exec）弱，是数学域的固有属性，不隐瞒。

## 可部署 failure signals（动态触发只能用这些）
1. boxed 答案提取失败；
2. 表达式无法 sympy 解析；
3. 求值为非有限数；
4. verify 与 solve 输出不一致（模型一致性信号）；
5. 禁止：运行时读取 gold（`ground_truth` 仅在离线评分出现）。
