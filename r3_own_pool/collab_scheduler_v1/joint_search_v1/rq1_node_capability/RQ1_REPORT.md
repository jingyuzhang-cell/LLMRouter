## 结论边界（先行声明）

- 分阶段模型表现不同 **≠ 节点级分配优于查询级路由**（需同任务、同契约
  直接对照与路由基线）；
- 历史轨迹不能分离 DAG 分解与恢复的收益（配置/Prompt/任务/故障条件
  不同时只描述不归因）；
- **最终结论（按评审给定句式）**：在 8 个配对任务的冻结轨迹中，不同
  模型的文本抽取输出可用性呈任务依赖差异，未观察到一致排序；这些差异
  尚不能等同于事实正确性或节点分配收益。

## 口径修正记录（v1 → v2）

1. **独立性与分母**：v1 的 17/17、16/16 是同一任务跨配置/状态的观测
   计数，其中 13–14 次为**缓存别名**（复用已执行答案，非独立模型执行）。
   独立任务规模仍为 **8**；每（任务, 节点, 模型）格的真执行仅 **1–4 次**。
2. **注入剔除**：fault30 面板恰好注入 e2 于 08fbbc3f（'{"facts": []}'）、
   v 于 2f745dd1——v1 中 08fbbc3f 的"双方 ~50%"全部为注入伪影；剔除后
   该任务执行层双方完全可用（large 2/2、medium 1/1）。v1"温度 0 下真
   随机"的表述撤回：差异先归因于注入与输入差异，相同任务不等于相同输入
   （已按 prompt 身份/注入/恢复/缓存/模型版本逐项分离）。
3. **术语**：无事实 gold 时，"非空/可解析"仅为**输出可用性代理**，不称
   抽取成功或能力互补。

## 判定依据（代理，执行层口径）

- e1/e2：usable（≥1 可数值化事实）+ operand_recall（gold 派生式非平凡
  字面量覆盖率）——可用性代理，非事实正确性；
- r：expr_ok/eval_ok/gold_match（v2.1 契约统一施加）；gold_match 与上游
  混杂，条件化样本 n=1，登记为缺口；
- v：consistency（与 r 链值一致）+ gold_match；同样混杂上游；coder 与
  large 的差异保留代理与混杂声明。
