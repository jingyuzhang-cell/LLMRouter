## Method

The production `CacheIdentityPredictor` (review/track_b.py) is imported
UNMODIFIED and replayed chronologically per cell exactly as the searcher would
use it (predict → register under its clean/fault30 scope semantics). Actuals
come from the copies' ledgers: per-node hit/new from TRAJECTORY alias records;
cell physical spend from EVALUATIONS/SCENARIOS search_spend; deployment C from
evaluator objectives (kept SEPARATE from search physical spend throughout).
An oracle-scope variant (same identity rules, one shared scope per run — the
fullval runs physically share one scope) is replayed alongside to attribute
error between identity rules and scope-split conservatism.

## Findings (real-model executions; PREDICTOR_ERROR_AUDIT.json has every row)

1. **Node-level cache classification — the precision-1.0 stub claim does NOT
   transfer to real executions.** Cross-source accuracy 0.877, but
   false-hit rate (predicted hit, ledger shows NEW request — the unsafe
   direction for budget) = 1.3% overall, concentrated in the fullval faulted
   cells: 22.7% on run01, and 66.7% inside the `model_changed` bucket there
   (FULL replay swaps models; recovery-path prompts diverge). All 14 false-hit
   rows are itemized in the JSON (`predictor_mismatches`).
2. **Request-level**: campaign v1 proposed session: exact on all 8 cells
   (err 0). Campaign v2 scalarized: MAE 4.5 requests, upper cover 83%. The
   fullval S2/S3 cells undercount by construction (the node-derived request
   prediction excludes recovery/replay calls; −2 to −3 per cell).
3. **Token-level estimates are NOT a bound**: campaign MAE ≈ 3,061 tokens/cell
   with only 8% upper cover (NODE_EST constants overestimate real usage);
   fullval LOCAL both directions (−1,010 run01 / +1,404 cont1); cache-reuse S4
   cells err +100 from the est floor vs actual 0. Token constants need
   recalibration from real usage before any budget-bound interpretation.
4. **Deployment vs search physical** are reported side by side per cell and
   never merged; the static deployment estimate and evaluator C are both
   recorded.
