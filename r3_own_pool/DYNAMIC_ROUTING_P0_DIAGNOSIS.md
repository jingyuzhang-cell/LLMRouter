# 反馈驱动异构DAG：P0降级诊断与最小配对实验

日期：2026-10-14（北京时间）。范围是现有60题真实确认面板、其决策账本、对应代码，以及最多五个场景候选。本轮0模型请求、0GPU加载、无生产算法修改、无历史结果修复。新增文件仅为诊断脚本、结果和报告。

## 1. 一句话结论与最终优先判定

**60题DD失败最直接的原因不是奖励公式，而是“批次墙钟已消耗任务期限＋未校准争用估计＋硬按时门”把全部可行候选挡在选优之前；DS另有固定r模型质量先验0.6低于Qmin0.8的独立阻塞。**反馈/任务失败代理也有问题；自然复杂场景的优化价值仍需资格审查，但不能用场景浅解释这46次硬拒绝的直接成因。

证据强弱排序：

1. **时间语义与可行性过滤（最强）**：DD46/46候选池非空、质量/成本可通过，却所有候选p_on=0；31/46决策时已过deadline。候选表证明硬门为空，不是奖励argmax选了NONE。
2. **质量先验与模型菜单匹配（强）**：DS46/46所有候选q<.8，计划r=medium的合成q=.6决定弱链上界；不是校准质量。
3. **反馈解释/任务质量传播（中强）**：35/46有e2空facts；旧FAILED→整任务质量0是假设。相同shared base下NONE在被DD停止的46题中仍正确18题，其中17题e2空facts；不能将任务状态代理等同最终质量。
4. **合法动作空间（局部已修，当前46次并非空池）**：旧20题曾有闭包枚举缺陷；本60题DD44–92候选、LOCAL可达，不得混用旧故障归因。
5. **奖励数值及权重（没有支持其为本轮主因）**：权重不影响硬过滤，任何权重无法让空可行集产生动作；仍须核查预测准确性及公平收益，不应先换奖励函数。
6. **场景本身（影响研究外部有效性，不是上述硬停直接原因）**：找到一个自然三分支汇合候选，但真实异构边际收益与压力未确认；不能把其算法形状当成已验证优化机会。

总体结论：**DIAGNOSIS COMPLETE；完整异构优化实效试验目前NO-GO；有明确、有限的机制/数据资格准备路线，不再同题无限重跑。**

### 3.3 时间为什么全部归零

[supplementary_runner.py:run_cell](deadline_reward_v1/supplementary_runner.py)先批量执行60题A/R1，再逐任务决策。每题`remaining_work_est`初始化为计划v的stub服务7秒＋停止.5＋启动2.5=10秒，其他59题首个决策的contention=590秒；停止一个任务后移除其估计，随后下降到140秒。

[policy.py:_score_and_pick](deadline_reward_v1/policy.py)将μ_service＋own switch＋contention移入p_on。31题实际剩余期限已负；其余15题虽有剩余时间，估计争用仍压垮按时门。跨臂同shared base、相近批式排队、同prior使结果趋同。

具体定位：DD第一条UID `018e57e9-fe1c-4c75-a6ad-f223e9d90cb0`，ledger第365行，D约113.394842秒、d_remain −19.703085、contention590；q=.85/.95的LOCAL也p_on=0。下一UID `0839b4dd-914c-4b8a-9f31-5256a93e29a9`第366行，D约226.789844、余额93.68717仍被590附近争用拒绝。完整UID及行号见逐任务JSONL。

真正协议冲突是：**决策过滤使用含批式耗时、争用和切换的任务剩余墙钟，而主结算R_conditional后来采用新增物理service时间、排除cache/switch/queue。**同一实验可分别报告这些量，但不能用一个estimand的过滤去声称优化另一个estimand的按时奖励。来源：[joint_verification_runner.py:_per_task_incremental_service/execute](deadline_reward_v1/joint_verification_runner.py)。

## 4. 奖励、预测、反馈及实现问题拆分

### 4.1 不应立即重写奖励

真实公式由[reward.py:expected_rtask](deadline_reward_v1/reward.py)计算：

\[
\widehat R=\hat p\hat q-.5\Delta C/4000-\mathbb E[(T-D)_+]/D-2(1-\hat p).
\]

代码进入候选score，但选优前必须满足质量、按时、成本门。**这46次没有进入可行候选的奖励竞争。**把λf改0、λc改0甚至全部权重改0也不会移除hard deficits。

原日志score用结算文件的D复算最大差4.36e−5；日志保存到十位而结算D/任务release经过不同精度与计时阶段，未保存决策精确d_total，不能宣称逐bit公式对账。没有发现能解释46次硬停的奖励算式错误；精确归因这点小差仍UNKNOWN，需新增日志字段，非改公式。

### 4.2 质量预测不可靠

OutcomePredictor对DONE=1、FAILED未恢复=0，新执行质量用stub q_success，任务取min。r|medium=.6、r|large=.95、v|coder=.85，故DS保持r|medium必然过不了.8，哪怕迟到信念修正。固定计划与门槛本身矛盾，不是恢复实测能力不足证明。

min和DONE代理没有独立校准为任务最终正确率；NONE正确18次正好暴露了“某节点不合旧schema≠最终任务必错”。应该区分必要输入缺失与未必有用的抽取空结果，不能简单把所有空e2当强根因；任务来源需求审定是前置，不是根据Gold事后替输入免责。

### 4.3 按时概率缺乏对应估计目标的校准

p_on正常族由(mu,p90)反推σ，再加确定性shift；真实launcher用了synthetic priors而非reliability FIT分布，FIT只进入deadline尺度。60题批次排队使E2E与服务期限混杂。旧可靠性6/10覆盖<.9本身也不能认证新的云池。

不是“概率估计偏低”一句话可解决：31题原期限真已过；剩余15题则被删除contention的反事实明确翻转。移除争用只是换估计，不保证真实按时；改为服务clock会换研究目标，必须新协议，不能回写旧截止达成。

### 4.4 增量成本没有解释本轮硬停，但不是已校准

逐候选按实际FULL规则重新求和，ΔC=Σnew-call node tokens_p90一致、无执行节点重复。199个朴素差异来自FULL将judge显示cache flags覆写为全新调用；policy用于预测的execute与最终日志的judge.execute并非同一flag快照，属于可审计字段不够清晰的建议，不是本轮多扣成本。

预测成本400–1400、余额300000，无候选预算违规。因此预算拒绝不是46次原因。tokens_p90仍synthetic，不可把求和正确说成实际费用预测准确。该余额只反映臂状态，不直接等同跨臂全局API余额；真正服务器Budget另守全局800/300K，不能省略。

LOCAL缓存身份、FULL全新重放及PENDING首执行已有明确代码；该批没有真正选中动态恢复，不能通过它验证预测与新恢复实际费用的一致性。

### 4.5 在线更新与不可部署银标

当前确认旧policy不运行任务后PriorStore学习；新云事件`full_dag_executor._update_store`读取FULL_DAG_SILVER_V1做recall计数，任务后才更新避免同题未来泄漏，但若部署时银标不可得，仍不是可部署在线信号。只有合同pass/usage/时间/合法引用能无评测标注更新。Thompson可用不等于可靠反馈；不建议新增RL算法。

## 7. (Z,R,π)到底工作到了哪层

候选合法性与枚举：`reassign.enumerate_candidates → SchedulerState.judge → dag_closure`，LOCAL R包含failed及已DONE失效后代，pending单独首次执行；FULL/FULL_DYNAMIC分别原模型/自由全图分配。真实本轮：DD2510行中NONE92、LOCAL552、FULL210、FULL_DYNAMIC1656；三项确实进入表，不是换标签。

真实选择层：所有动态决策chosen=null，故这个面板**没有证明动态联合动作被实际执行并有效**。SS固定LOCAL有真实恢复，已有微试与旧恢复例证明物理接线能执行不同R，但不等于本60题DD学会联合选择。

最小补丁建议（本轮未修改）：

1. `confirmatory_launch.py`：禁止synthetic priors静默用于声称校准的运行；允许明确exploratory uncalibrated标签，不能凭空换成“真实Q”。
