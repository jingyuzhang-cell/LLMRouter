# 5 Experiments

本章围绕三个贡献组织实验：节点级多模型协同选择（5.1–5.2）、反馈驱动执行适应（5.3）、真实失败触发的预算感知恢复与系统诊断（5.4）。5.5 与 5.6 分别给出多轮复用与部署分析两项支撑能力，5.7 以真实执行的三臂综合评价收束。证据层级在全文中显式区分：真实模型调用（live）、基于已采集回答的顺序回放（replay）、由组件统计量驱动的模拟（simulation）；三者不混用。

**评分口径声明**。初版节点表使用常数白名单 \(\{0,1,100\}\) 的表达式执行器评分，该语言无法表达平均类问题（需除以 2–5 等常数），系统性低估 reasoning 节点质量。本章全部表格采用扩展执行器（允许任意有理常数；运算符集合不变）统一重评后的口径（`SCORED_MATRIX_EXEC`），36/300 个 reasoning 单元因此改判（medium 0.19→0.31、large 0.15→0.25、coder 0.17→0.31）。所有方法在同一口径下重评，相对结论不受影响；主结果 Node Router 相对 Query Router 的增益在两种口径下均为 +6.9 pp。

本章实验设置见第 4 章。

## 5.1 GAP Analysis

**拆分质量的执行效用**（300 任务，两域；其中 210 个具有单体对照可配对比较）：同一任务上比较无拆分单体（large 单提示直答）与类型先验 DAG 链（抽取→推理→确定性执行）。结果呈现**域依赖的双向效应**：

| 域 | 单体 n | 单体 | DAG 链 n | DAG 链 | 配对差 [CI] |
| --- | --- | --- | --- | --- | --- |
| MultiHiertt | 50 | 8.0% | 100 | 23.0% | **+14.0 pp [+2.0, +26.0]** |
| TAT-QA | 160 | 52.5% | 200 | 38.5% | **−9.4 pp [−17.5, −1.3]** |
| 合并 | 210 | 41.9% | 300 | 33.3% | −3.8 pp [−10.5, +3.3] |

（协议异质性如实披露：TAT-QA 旧 40 链使用 gold facts、新 160 使用自身抽取；MultiHiertt 前 50 为 live 链、后 50 为节点表重放；单体对照仅在新采集任务上可用。）

**分解效应的方向由任务结构决定**。MultiHiertt 任务（层级表格、多实体定位、平均/百分比运算）单体几乎不可解（8%），分解带来 +14 pp 显著改善；TAT-QA 任务（扁平表、中位 2 步运算）单体已可直答（52.5%），而 DAG 链的表达式接口反而引入两类约束损失——19 个任务的链计算出原始比值后缺少百分比/千位缩放，另有若干表达式解析失败。逐题交叉表（160 题）：两法皆对 56、仅单体 28、仅链 32、皆错 44——**两种执行形态覆盖的任务集合部分不重叠**。

**核心洞见：任务分解本身应被视为一种需要决策的执行策略，而非固定预处理步骤。** 复杂度分层（按推导运算步数）显示分解收益随结构复杂度单调上升：1–2 步任务中 DAG 比单体低 6.6 pp，3 步 +10.0 pp，4+ 步 +20.8 pp；收益方向在约 2–3 步附近发生变化——由于中高复杂度样本仍有限（3 步 n=40，4+ 步 n=24），该位置应视为经验边界而非固定阈值。域内一致：MultiHiertt 全档正收益（层级任务始终值得分解）；TAT-QA 低档显著负、高档显著正（扁平任务仅在高复杂度时值得分解）。

**轻量结构选择器 g(x)（诚实报告）**：以运算步数、上下文长度、表行数为特征的 Logistic 5 折交叉验证选择器达到 36.9%，与 Always Monolithic 持平，Oracle Structure 为 49.2%——**群体层面的复杂度规律成立，但仅靠执行前表层特征的个体级结构选择仍然困难**。运算步数本身来自 gold 推导（部署时不可见），且单次执行的随机成败噪声进一步削弱了任务级标签的可预测性。该结果与全文"输入表象不含决策信息、执行过程信号才携带信息"的结构一致；可部署的结构选择需要更丰富的任务结构特征（表格层级、跨表标志、实体数、廉价规划器预测的子任务数），留作后续工作。

**DAG 执行结构质量的四维分析**（100 个 MultiHiertt 任务，规则评分）：本文从证据覆盖（Coverage，必需操作数是否出现在抽取事实中）、依赖有效性（Dependency，推理 v-引用是否落在实际抽取事实索引内）、节点可执行性（Executability，节点输出能否被解析并执行）与节点原子性（Atomicity，单节点最大运算步数）四个方面分析 DAG 执行结构质量。结果表明，**证据覆盖与最终执行正确性关联最明显**（Pearson 0.377；最终正确任务均值 0.935 对错误任务 0.351），说明上游信息缺失是影响后续 DAG 执行的重要因素；依赖有效性（0.290）与可执行性（0.281）次之，而单纯控制节点粒度（Atomicity 0.078）并不能保证执行效果。需要明确：Coverage 主要反映上游证据抽取质量，而非 DAG 划分方式本身，本文不将"证据覆盖"等同于"拆分质量"，也不主张"拆得越细效果越好"。

## 5.2 Node-level Routing

本节比较同一协议下的三种选择器：查询级路由（仅问题编码）、类型先验路由（按开发数据选取各类型最佳固定模型，无表示学习）与完整节点路由。表 5-3 汇总独立确认结果。

表 5-3　选择粒度消融（独立确认集，493 主节点）

| 方法 | Quality | Tokens / task | Service time / task（s） |
| --- | --- | --- | --- |
| Always Large | 0.4686 | 4991 | 11.71 |
| Query Router | 0.4665 | 4985 | 10.19 |
| Type Prior | 0.5355 | — | — |
| Frozen Node Router | 0.5355 | 4856 | 7.79 |
| Node Oracle | 0.6045 | 5218 | 6.43 |

从查询级到类型先验的跃升贡献了主要增益（开发折内 +5.9 pp CI[+0.6,+8.0]；独立确认 +6.9 pp CI[+3.3,+10.1]，任务级配对区间均不含零）。在此之上，问题编码的额外增量在开发折内为 +1.6 pp，未迁移到确认集（修正口径下 0.00 pp）。因此本文不将贡献定位在学习节点表示，而定位在选择粒度的改变：将路由对象从完整问题下降到类型化节点，使模型间能力差异成为可利用的结构。问题编码作为实例化保留，其跨数据迁移局限如实报告。

**预算对等性**。查询级路由、类型先验与节点路由每节点恰好执行一次调用，决策粒度不同但调用预算相同；节点路由的增益（+6.90 pp）在等调用预算下取得，且每节点 token 更低（1765 vs 1801）。额外调用只在反馈回退（5.4）中出现，与选择粒度无关。

**路由分布**解释了增益的来源。静态节点路由在三种类型上分别集中选择该类型最优模型（extraction→large 191/193、reasoning→medium 73/100、verification→coder 176/200），即粒度改变使类型异构性直接转化为差异化分配；反馈阶段发生 230 次换模，主要将 extraction 从 large 移向 medium（191→115）并分散 reasoning 与 verification 的选择，对应执行记忆对类型内条件的修正。

资源口径上，Node Router 相对 Always Large 以更少 token（4856 vs 4991 / task）与更短服务时间（7.79s vs 11.71s / task）取得更高质量；类型先验不含每节点预测，无独立资源列。整体质量提升需结合类型内解释：优于全局固定模型不等于在每个类型上均优于该类型最佳固定模型。

**级联基线**。经典级联（cheap-first，失败升级：medium→large→coder）在理想失败检测下达到 0.6065（1.63× 调用、2930 tokens/node），高于完整反馈的 0.5842。两点界定其与本文方法的关系：其一，该数字依赖理想检测，实测检测质量下触发式升级同样受 5.4.5 所述检测瓶颈约束；其二，级联按全局成本排序换模，不考虑节点类型条件，其 token 开销（2930）高于反馈（2629），且不具备结构分解维度——5.4.3 中由分解独占恢复的失败不在级联的假设空间内。级联与节点路由回答不同问题（何时升级 vs 谁来执行），二者在此作为互补基线报告。

## 5.4 Failure Recovery and Budget-aware Escalation（真实失败恢复与预算感知升级）

静态分配无法处理执行失败。本节先定位失败来源（5.4.1），再给出 Static 与 Dynamic 两种执行模式的对照（5.4.2），分解各恢复组件的边际贡献（5.4.3），以理想组件替换量化系统瓶颈与潜力（5.4.4），最后给出检测门控、结构分解与预算升级的直接证据（5.4.5）。

本章核心实验链围绕以下递进式问题展开：

1. **阶段级互补是否存在？** → 节点基准：oracle +13.59pp，类型最佳互不相同
2. **同模型传播为何压缩互补？** → Cross-model 3×3 矩阵：extraction 质量主导（+10pp），reasoner 选择仅 +0.5–2pp
3. **跨模型节点组合能恢复多少？** → E_large→R_medium (20.0%) / E_large→R_coder (20.5%)，恢复部分互补性
4. **距离 Exact Oracle 还有多远？** → Exact Oracle 30.5% vs 最优固定组合 20.5%，剩余 10.0pp 为实例级空间
5. **Residual GAP 是否能稳定路由？** → 200 题正向 +22.2%，500 题未复现（−11.1%）
6. **为什么只能在低 coverage 安全利用？** → 5–10% coverage 安全区（GAP +7.4–8.6%，harm 0–1）；扩大后 false override 主导
7. **Dynamic 反馈能否进一步利用互补性？** → live ΔQ +2.1pp 不显著；受控故障 T3 净 +2——机制可执行但受覆盖率约束

### 5.4.2 Static vs Dynamic DAG（后继重调度机制对照）

**两种执行模式的对照实验**（100 任务确认集，条件化节点结果表回放：Q/C/L 取自实测节点×模型矩阵，失败触发读离线评分、后继节点处于标准输入条件；与 5.4 同一证据层级）。两臂共享 FrozenNodeRouter 初始分配与逐任务 token 预算（Static 实现成本 ×1.2）。Static：节点失败仅对当前节点做一次局部 fallback，后继维持初始计划；Dynamic：失败后更新（类型、模型）失败状态记忆，对失败节点做融合回退，并对其后继重调度——模型分配按失败记忆与冻结效用融合重选，上游失败时验证节点可在剩余预算内升级为更强验证模型，每次选择后重算剩余预算；**拓扑不变**。

表 5-4b　Static vs Dynamic（100 任务，task-cluster bootstrap）

| 指标 | Static | Dynamic | 差异 |
| --- | --- | --- | --- |
| 任务成功率 Q | 41.0% [31, 51] | 40.0% [31, 50] | −1 pp（CI 含 0） |
| 平均 tokens | 7020.5 | 7034.6 | +14.1（+0.2%） |
| 平均服务时延 s | 12.81 | 13.26 | +0.45 |
| 失败任务恢复率 | 43.2%（95 失败） | 42.1% | −1.1 pp |
| 后继重调度率 | 0（定义） | **26.3%**（25 任务，平均 0.43 节点） | — |
| 预算违规率（1.2× 头寸） | 0 | 0 | — |
| 超出初始计划率 | 95% | 95% | — |

**结论**：在共享初始路由与固定拓扑条件下，反馈驱动后继重调度能够稳定触发（26.3%，平均 0.43 个后继节点），并在 20% 预算余量下保持零预算违规；但任务质量与 Static DAG 无显著差异（41.0% 对 40.0%，ΔQ 95% CI 覆盖 0），不应表述为 Dynamic 更差。进一步分析表明，主要限制来自多模型共同失败以及可重路由空间有限。

**诊断**（同一 replay，零新调用）：(i) 任务级 Help/Harm 分解为 0/1/40/59（Static错→Dynamic对 / Static对→Dynamic错 / 皆对 / 皆错）——机制几乎不产生任务级翻转；(ii) 真正发生后继重调度的 25 个任务上 Static 与 Dynamic 质量均为 48%（未被稀释的 75 个任务为 37%）；(iii) 41 个被重调度后继中 65.9% 存在可重路由空间（模型池存在正确答案），在这些"原计划模型失败且存在替代"的 8 个节点上，**Dynamic 选中正确模型 8/8，Static 冻结回退仅 5/8**——调度器本身能把反馈转化为正确的后继调整，节点级选择并不差；(iv) 任务级收益为零的原因：决定任务成功的 reasoning 节点在两种模式下都已获得节点级回退，且后继节点处于标准输入条件（上游输出变化未真实传播，见下方证据层级声明）；(v) 唯一的 harm 任务来自失败状态记忆覆盖了冻结回退的正确选择（reasoning Q 向量 [0,0,1]，Static 回退选中 coder 成功，Dynamic 记忆回退选中 large 失败）——这直接指向 **Selective Dynamic Update**：只重调度真正受影响的 descendants，且不覆盖有正向证据的既定回退。

**Live Static vs Dynamic 对照**（48 个 TAT-QA 任务，策略冻结后真实执行，160 次调用；与回放不同，恢复后的真实输出真实传播给后继。诚实标注：该集合此前的诊断分析启发了后续 Dynamic v2 规则设计，故对 v2 而言它是 previously analyzed live confirmation set，不称 held-out）：两臂共享初始分配、prompt、模型池与逐任务预算（Static 实现成本 ×1.2）。结果：Q = 52.1% 对 54.2%（配对 ΔQ = +2.1pp，95% CI [−4.2, +10.4]，覆盖 0，不显著）；成本持平（+1.6 tokens）、时延持平（−0.06 s）；Help/Harm = 2/1；Dynamic 重调度在 52.1% 的任务上触发（24 次 reasoning 升级 large 全部在预算内执行），预算违规 0。失败归因：22 个双失败任务的链路合并后已尝试全部 3 个模型且在相同传播事实下全部错误——**模型池共同失败在真实传播下依然是主导约束**。按预注册三情形判定，本结果属于情形二/三边界：动态控制逻辑可执行（触发 52%、零违规、成本持平），端到端收益受模型池共同失败限制；Live Dynamic 到此为止，不再追加。

**Dynamic v2（选择性更新规则，dev 迭代 + confirmation 一次性执行）**：针对 Live v1 的唯一 harm（失败记忆覆盖有正向证据的冻结回退），在 33 个独立 dev 任务（与全部先前集合互斥）上迭代出四条调度规则——R1 正向证据锁（冻结回退无失败记录时不被覆盖）、R2 切换边际（δ=0.1）、R3 受影响后继门控（恢复输出未实质变化则保持 Static 分配）、R4 能力画像评分（rank − γ·失败数，γ=1）。策略以单一共享函数实现（policy hash 8ee21689…），dev 与 confirmation 共同 import，9 项构造状态单元测试 + dev 记录重放逐决策一致后才执行。

表 5-4c　Static / Dynamic v1 / Dynamic v2（48 任务 confirmation set，真实执行）

| 方法 | Task Success Q | 平均 Tokens | Help / Harm | 预算违规 |
| --- | --- | --- | --- | --- |
| Static DAG | 52.1% | 1402.2 | — | 0 |

**结论**：Dynamic v2 通过正向证据保护、受影响后继门控、关键节点优先和能力画像重路由，降低了反馈驱动重调度带来的负迁移风险。在 confirmation set 上，Dynamic v2 相比 Static DAG 获得 +2.1pp 的正向但不显著质量变化（ΔQ 95% CI 覆盖 0），同时将 harm 降为 0，且成本和预算约束基本保持不变。v2 在保持相同任务级质量的同时消除了观察到的 harm，并略微降低执行成本，说明选择性动态更新主要提升了反馈调度的稳定性，而非显著扩大模型池的能力上限——本文不声称 v2 相对 v1 有更高的准确率。

**两条边界如实保留**：(1) 该 48 任务集合为 previously analyzed live confirmation set（其诊断分析启发了 v2 规则设计），不是 untouched held-out test set；(2) v2 策略整体经等价性验证（policy hash 8ee21689…），但其中 coder→large 的 hysteresis 切换分支在 dev 数据中从未被触发，该分支只有定义与一致性验证、没有独立实证支持，论文不对其单独作效果声明。

**证据层级小结**：回放对照证明调度器节点级选择正确（headroom 节点 8/8 对 5/8）；Live 对照以真实传播验证端到端（触发 52%、零违规、ΔQ 不显著）。两个层级一致地指向同一结论：调度机制可执行且预算纪律良好，端到端收益的上限由模型池共同失败（动作/能力覆盖率）决定，而非调度策略本身。

### 5.4.5 检测门控与结构分解

**验证器敏感性**（节点级回放）：以实测混淆矩阵驱动回退触发，扫描错误召回率——0.27（实测）→ 0%，0.60 → 6.3%，0.80 → 15.6%，0.95 → 18.7%（与类型门控实测锚点吻合）；误报率 0.40 时恢复率为 −40.6%。检测质量为自适应执行定价，且该定价在任务级受限于失败的可恢复性本身。

**类型门控**（节点级回放，扩展口径）：无验证器 0.5355 / 全局验证器 0.5355（231 次重路由、50 次误触发，净增益为零）/ 类型门控 0.5477（186 次重路由、误触发 35、漏检 6）。门控将干预限制在检测可靠的 verification 类型上，把净恢复率从 0% 提升至 28.6%。

**结构分解**（困难 reasoning 节点，真实调用，两域）：扩展表达式语言后直接重问 0/20；failure-aware 分解（报告对齐 → 关系规划 → 表达式 → 检查）在节点隔离基准的 gold-facts 条件口径下，两批共 60 个全模型失败节点中 19 个生成表达式可由 gold facts 计算到标准答案（19/60=31.7%；本规模批 13/40，MultiHiertt 7/24、TAT-QA 6/16；初步证据 6/20）。固定三段模板历史参考 0/10。**端到端判据复核（本次审计）**：该口径衡量"给定黄金证据时能否写出正确表达式"，并非端到端恢复——把 13/40 规模批的分解表达式在真实抽取事实上重算，仅 1/13 仍正确（4 个算错、2 个 v-引用索引错、6 个无抽取记录）。因此 31.7% **作为端到端恢复率结论撤回**，降级为表达式级能力观察；分解适用域的证据组织类定性结论（裸事实丢失实体/期间分组语义，关系推理类失败 0/10）不变。附带发现是表达式语言本身：常数白名单使平均类问题结构性不可表达，本节全部机制比较在扩展执行器下进行以避免把语言修复误归因为分解效果。
### 5.4.6 Budget-aware Escalation and Termination

**预算感知升级实验**（116 个判据纯净真失败，冻结 counterfactual，零新调用）：以剩余预算 \(B^{\rm rem},T^{\rm rem}\) 过滤可行动作后按序执行。时间预算网格显示：\(T^{\rm rem}\le0.5\) s 时仅 retry/switch 可行（Q=1.7%）；\(\le1\) s 时 retrieval/decompose（实测 2.7–4.8 s）不可行，上限为 retry→switch（3.5%）。token 预算从 1200 放开到无限，Q 仅从 3.4% 升至 6.9%（=oracle），成本从约 500 涨至 6332 tokens；恢复效率从 0.063 降至 0.011 恢复/千 token（约 6 倍差距），oracle 以 1/47 的成本达到同一上限。λ/μ 敏感性（\(U=Q-\lambda C-\mu L\)）中，昂贵动作在任何非零成本/延迟权重下均不占优，多数权重下 retry-only 最优。结论：**并不是恢复越复杂越好**——在动作收益很低时，应根据剩余预算控制升级深度，必要时提前终止。

### 5.4.8 Local Subgraph Replan（开发 pilot，NO-GO，未来工作）

**局部子图重规划**（40 节点 dev 真失败集，与冻结 116/pool/pilot/decompose 集全部互斥，判据纯净；336 次真实调用）：模型把剩余计算规划为多步原子子图（s1..sk 确定性逐步执行 + 最终表达式），步骤失败时允许一次证据修复并重规划，改写失败节点及其受影响后继。结果：replan 恢复率 2.5%（1/40），且该节点本可被 retrieval 救回——**动作集 oracle 覆盖率 10.0%→10.0%，净增 0 节点**；replan 平均成本 5931 tokens（约为 decompose 的 2.3 倍），33/40 需要二次规划、29/40 执行器错误。按预注册判据（净增 >2 节点才继续）判定 **NO-GO**：局部子图重规划未扩大恢复动作覆盖率，作为未来工作保留，不再对冻结 116 测试。该负结果与 5.4.4 的 oracle 瓶颈一致：当前恢复上限由证据获取与计算能力决定，而非图的拓扑形状。

## 5.5 Dependency-aware DAG Reuse

多轮任务中，追问通常只改变历史任务的一部分。本节检验依赖感知的局部复用（非输出缓存）：历史图保存节点、边、依赖与版本，修改发生时定位受影响子图，仅重算其后继。实验为 20 个追问任务（原始材料不变、首个事实假设 +10%），历史抽取子图零调用保留，仅重执行推理与验证。

表 5-8　追问场景复用经济学

| 指标 | 结果 |
| --- | --- |
| Reuse Rate | 50%（每任务 2 个抽取逻辑节点） |
| Call Reduction | 50% |
| Token Reduction | 91.4% |
| 新链可执行 / 响应修改 | 19/20 / 19/20 |

与输出缓存的区别是结构性的：任何输入修改都使输出缓存失效并触发全链重算（等价于不复用），而依赖感知复用将重算范围收缩为 \(\Delta V \cup \mathrm{Desc}(\Delta V)\)。token 降幅（91.4%）大于调用降幅（50%）的原因是工作负载结构：被跳过的抽取节点承担长报告上下文的处理，重算节点只消费短事实表示。两项口径限制保留：调用基线按逻辑链记录（非严格物理去重）；token 对照为历史记录对新调用（非同轮对称实验）。结果响应修改（19/20）是执行行为指标，不构成独立答案正确率证据。

**记忆保留策略（剪枝）**：图森林不是无限增长的存储，而是带依赖、带版本、带质量记录的执行经验库，配三条保留策略——(i) 时间剪枝：超出保留窗口未被检索引用的整图淘汰；(ii) 质量剪枝：使用次数 ≥3 且记录成功率 <0.5 的节点移出复用候选集（保留版本历史，仅取消复用资格）；(iii) 相似合并：同构子图合并并保留最高质量版本。当前存储规模（2 图 / 6 节点 + 版本）下三条策略均不触发，作为设计规范声明而非实验声明。

## 5.6 Budget-aware Multi-objective Execution Optimization

本节将资源决策组织为系统决策层。执行策略定义为配置组合

\[
\pi = (\text{模型分配},\ \text{反馈开关},\ \text{恢复机制},\ \text{复用开关}),
\]

五个固定策略（Always Medium/Large、Static、Feedback、Full）由 live 执行实测；在逐任务实测结果表之上，进一步构造**两类自适应策略**——预算自适应（每任务按其预算 \(B_i\) 选择可行集中质量最高者）与难度自适应（按到达时可观测的上下文规模分档选择 static/feedback/full）。所有混合策略的每个组成单元均为真实执行结果，无任何估计。给定预算约束的部署规则为

\[
\max_{\pi} Q(\pi)\quad \mathrm{s.t.}\quad \mathrm{Cost}(\pi)\le B.
\]

表 5-9　live 实测成本与质量（50 任务，固定策略）

| 策略 | Task Success | Tokens / task | 调用 / task | 服务时长（s） |
| --- | --- | --- | --- | --- |
| Always Medium | 16% | 4610 | 2.0 | 318 |
| Always Large | 24% | 4477 | 2.0 | 319 |
| Static | 24% | 4484 | 2.0 | 332 |
| + Feedback | 28% | 4959 | 3.7 | 368 |
| Full Adaptive | 34% | 5637 | 4.1 | 414 |

**预算自适应策略**（逐任务选择，全部为实测组合）：

| 每任务预算 B | Task Success | Tokens / task | 相对固定 Full |
| --- | --- | --- | --- |
| 4,500 | 30% | 4,533 | −19% tokens / −4 pp |
| 4,800–5,000 | 32% | 4,545–4,565 | −19% tokens / −2 pp |
| **5,100–5,200** | **34%** | **4,566–4,578** | **−19% tokens / 0 pp** |
| ≥5,600 | 34% | 4,590 | −19% tokens / 0 pp |

关键结果：**预算自适应在 B≈5,100 时即达到固定 Full 的 34% 成功率，同时节省 19% tokens**。其机制是逐任务成本结构的重尾性——Full 的每任务成本中位数为 4,924、p75 为 6,565、最大 10,702：预算自适应将 20 个超预算任务的昂贵执行替换为该预算内质量最优的廉价执行（多为 Static/Feedback），其中仅 1 个任务因此损失成功率（该任务 Feedback 亦失败，属于多模型共同失败类）。**这一"近零损失的成本削减"只有逐任务决策层才能实现**，是任何固定策略（包括 Full 自身）在平均成本上无法做到的。

**难度自适应策略**（按到达时可观测的上下文规模分档）：以 log 上下文长度的分位数为阈值切换 static→feedback→full，最优混合达到 28% / 5,138 tokens——与固定 Feedback 相当而不及预算自适应。仅用到达时特征预测任务难度不足以指导分级，印证 5.4.4 的结论：失败可恢复性由执行过程而非输入表象决定。

**非支配前沿**（固定策略 + 全部自适应策略，共 21 个实测组合点）：{Always Large (4,477, 24%), B=4500 (4,533, 30%), B=4800 (4,545, 32%), B≥5100 (4,566–4,591, 34%)}——**预算自适应策略全面替代了固定 Feedback 与固定 Full 的前沿位置**。以同一最劣参考点 (5,644, 16%) 计的二维 Hypervolume 由固定策略的 174 提升至 204 token·success 单位。策略空间为离散实测组合，穷举筛选在该规模上即为完备精确方法；扩展到组合级空间时才需要显式搜索程序（本文不引入）。

**预算模块消融**（无预算选择 vs 预算选择，同一实测组成）：

| 策略 | Success | Tokens / task | Service s / task |
| --- | --- | --- | --- |
| Always Full（无预算） | 34% | 5,644 | 8.3 |
| Fixed Feedback（无预算） | 28% | 4,966 | 7.4 |
| **Budget Adaptive（B=5,200）** | **34%** | **4,494** | **6.5** |

预算选择模块本身贡献：**0 pp 成功率损失下 −20% tokens、−22% 服务时长**（相对 Always Full）。组成（50 任务）：26 个任务预算内直接选 Always Large 或 Static 即可保住成功率，12 个高成本任务被降级到 cheaper 策略（其中 11 个在所有策略下均失败——多模型共同失败类，降级无损），1 个保留 Feedback。该消融证明收益来自**决策层**而非任何单一执行臂：固定地选最贵臂（Full）或中间臂（Feedback）都无法同时达到该成本-质量组合。

**可部署控制器（诚实协议）**：为界定预算自适应中逐任务可行集选择的 oracle 成分，比较三层控制器。(i) **到达时特征控制器**（严格 held-out 25/25，Logistic 与深度-3 树）：B=5,200 下 24% / 4,704 与 20%——均低于无预测器的均匀规则（28% / 4,966），到达时特征不含策略选择信息。(ii) **执行感知控制器**（零估计重放）：先执行 Static，以真实 coder 验证器对 Static 输出的判定与解析结果为升级信号（无值或验证拒绝 → 升级 Full）。结果：**34% / 5,354**（仅升级 15–18 个任务）——达到 Full 与 oracle 上界的成功率，成本介于均匀 Feedback 与 Full 之间，**优于所有固定策略与到达时控制器**，且每个信号均为真实执行产出。(iii) **oracle 上界**：34% / 4,494。

| 控制器 | Success | Tokens / task | 信号来源 |
| --- | --- | --- | --- |
| 均匀规则（B=5,200） | 28% | 4,966 | 无 |
| 到达时特征（held-out） | 24% | 4,704 | 输入表象 |
| **执行感知（Static→验证→升级）** | **34%** | **5,354** | 执行过程 |
| 逐任务 oracle 上界 | 34% | 4,494 | 不可得 |
| 固定 Full | 34% | 5,644 | — |

三层结果与全文主线一致：**输入表象不含决策信息，执行过程信号才携带**——执行感知控制器捕获了 oracle 上界与均匀规则之间差距的大部分（成功率 +6 pp），剩余 token 差距（5,354 vs 4,494）来自验证器误拒引发的 10 次多余升级，即 5.5 所量化的验证可靠性瓶颈在决策层的直接代价。

**升级策略消融**（同一重放协议，隔离"信号"与"预算"两个成分）：

| 策略 | Success | Tokens / task | 升级数 | 效率（pp / 千 token） |
| --- | --- | --- | --- | --- |
| A：全 Static（无反馈） | 24% | 4,484 | 0 | 5.35 |
| B：随机 20% 升级（3 seeds） | 24–26% | 4,680–4,803 | 9–12 | 5.00–5.56 |
| Full（全升级，无信号） | 34% | 5,644 | 50 | 6.02 |
| **C：执行感知升级** | **34%** | **5,449** | **18** | **6.24** |

随机升级（同预算量级）只能回收信号价值的 0–2 pp，而执行感知升级回收全部 10 pp——**收益来自信号而非额外预算**。执行感知升级同时具有全表最高效率（6.24 pp / 千 token）：相对全 Static 用 +21% tokens 换 +10 pp 成功率，每一千 token 的边际产出高于任何固定策略（Static 5.35、Feedback 5.64、Full 6.02、Always Large 5.36）。

**失败感知升级（负结果与上界）**：将预算决策升级为"先执行 Static，按失败信号升级到 Full"的两级策略。升级信号全部失效——路由预测质量 Q̂ 对 Static 失败的判别 AUC 仅 0.29（反向），解析失败标志 AUC 0.54（随机）；任何有效阈值实际升级全部 50 个任务。**升级空间的 oracle 上界**：Static 失败的 38 个任务中 Full 仅能救回 5 个（86.8% 为多模型共同失败），精确升级的上界为 34% / 4,778 tokens——不支配预算上界（34% / 4,494）。不存在可被**到达时**信号识别的"需要 Full"子群；执行感知控制器之所以有效，正在于它把判别信号从输入表象换成了验证器对实际输出的判定。

**单位成本收益**（固定策略阶梯）：反馈 +4 pp / 475 tokens = 8.4 pp 每千 token；结构恢复 +6 pp / 678 tokens = 8.8 pp 每千 token；边际平坦（8.4–8.8），说明更高预算买入的是不同机制的接入而非同一机制的递减加量。预算自适应在此基础上提供了**机制选择之外的逐任务粒度节约**（−20%），两者正交（预算–成功率曲线见附图 `budget_success_curve.html`）。

## 5.7 Live End-to-End Evaluation

最后，全部模块在同一 50 个确认任务上真实执行：DAG 构造 → 节点路由 → 执行 → 反馈记忆 → 验证器 → 失败诊断 → 重路由/分解 → 最终答案。三臂策略共享执行缓存（相同节点-模型组合只计费一次）；失败检测为真实 coder 验证器判定，记忆仅由可部署信号（判定结果）更新，评分离线对 gold 进行。

表 5-11　live 三臂综合（与 5.7 同一实验，含 bootstrap 95% CI）

| 方法 | Task Success [CI] | 严格恢复率 | 破坏数 |
| --- | --- | --- | --- |
| Static（Node Router） | 24% [12, 36] | — | — |
| + Feedback | 28% [16, 40] | — | — |
| Full Adaptive DAG | 34% [22, 48] | 5/38 = 13.2% | 0 |

配对差异：Full−Static = +10 pp CI [+2, +18]（区间不含零）；Full−Feedback = +6 pp CI [0, +14]；Feedback−Static = +4 pp CI [0, +10]。后两个差异在 50 任务下为边缘显著，方向一致但需要更大样本确认——这一不确定性如实报告，不因点估计递增而声称各层增益均已统计确立。

综合叙事：**实际能力 34%，理论潜力 50%（表 5-7），16 pp 差距的 12 pp 来自上游抽取、其余来自多模型共同推理失败**。组件边际（+4/+0/+6）与失败归因（抽取 18 / 公式 15）共同解释了这一数字的构成；每个百分点均有实测成本标注（表 5-9）。零破坏（Full 未使任何 Static 成功任务失败）与 13.2% 严格恢复率共同刻画了恢复的收益边界。4 个任务因抽取解析失败使用了 gold 事实接口回退，已披露；验证器 61% 的判定不一致率是当前反馈回路的主要噪声源，也是后续工作的第一优先级。

本章最强独立证据仍是冻结节点路由：相对查询级路由 +6.9 pp（两种评分口径下一致），并以更低 token 与服务时间取得。反馈、恢复与复用各自补充了静态选择无法覆盖的执行维度；系统整体的实际能力由错误传播链而非单一模块决定——这正是把复杂任务多模型执行建模为显式 DAG 并逐组件诊断的价值所在。
