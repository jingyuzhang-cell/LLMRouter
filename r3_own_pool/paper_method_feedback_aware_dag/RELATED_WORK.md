# 2 Related Work

本章按开题技术路线的四个环节组织相关工作：模型路由与能力画像（2.1）、任务分解与 DAG 执行（2.2）、反馈驱动的自适应执行（2.3）、多目标服务与执行记忆（2.4）。每节末尾指出与本文相关的空白。文中引用均为领域内代表性工作，书目信息见参考文献待核对清单。

## 2.1 LLM Routing and Model Capability Profiling

查询级模型选择（Task/Query → Model）已有较系统的探索。FrugalGPT（Chen et al., 2023）提出级联式降本，以低成本模型先行、失败后升级；Hybrid LLM（Ding et al., 2024）训练路由器在强弱模型间按查询难度分配以逼近质量—成本前沿；RouteLLM（Ong et al., 2024）以偏好数据学习查询级路由，在标准基准上取得对最强单模型的成本节省；RouterBench（Hu et al., 2024）则系统化了路由系统的评测基准。与"学习式路由"并行的是能力画像路线：通过基准测试刻画各模型在不同任务上的能力分布（如 MMLU 类评测与各模型卡报告），作为路由先验。这些工作共同确认了一个前提：商业与开源模型在质量、成本与时延上存在显著异构性，且异构性与任务内容相关。

然而，上述方法的选择粒度是整道查询：同一次执行内的所有步骤共享同一个模型决策。本文的节点基准实验显示，抽取、推理与验证三类子任务的最佳模型互不相同，节点 oracle 相对最佳单模型存在 13.59pp 的类型内互补空间——这类互补性只在子任务粒度上可见。现有 query-level 路由难以利用复杂任务内部不同子任务的差异化能力需求；仅进行整题级路由，无法实现本文所称的能力画像（Capability Profile）驱动的节点级路由（Node-level Routing）。

## 2.2 Task Decomposition and DAG-based LLM Execution

任务分解方面的经典证据是思维链提示（Chain-of-Thought, Wei et al., 2022）与最小到最大分解（Least-to-Most, Zhou et al., 2023）：将问题拆为子问题可提升多步推理。结构化方向上，Tree of Thoughts（Yao et al., 2023）把中间状态组织为可回溯的树；Decomposed Prompting（Khot et al., 2023）将任务递归分派给子求解器。系统层面，Planner–Executor 架构（如 HuggingGPT, Shen et al., 2023）以规划器产出任务序列、执行器调用模型或工具；ReAct（Yao et al., 2022）将推理与动作交替；多智能体工作流（AutoGen, Wu et al., 2023；MetaGPT, Hong et al., 2023）以角色化智能体协作；LLMCompiler（Lu et al., 2024）显式地把任务计划表示为 DAG 以支持并行函数调用。工具增强方向上，PAL（Gao et al., 2022）与 Toolformer（Schick et al., 2023）将算术与 API 调用外置给确定性解释器，直接对应本文"确定性工具执行"的设计。

需要强调的是，分解并非普遍有益。分解显式组织了依赖关系、使中间结果可检查，但额外的接口约束、中间格式转换与状态传播也会引入新的误差来源。本文的对照实验正体现了这种双向效应：MultiHiertt 上分解较单体 +14.0pp，而 TAT-QA 的扁平任务上单体直答反超 DAG 链 9.4pp，分解收益随推导步数单调上升。因此，是否采用 DAG 执行应结合任务结构与执行接口的表达范围决定，而非默认"拆分一定提高性能"——这也是本文将结构选择与结构质量分析纳入框架的原因。

## 2.3 Feedback-driven Adaptive Execution

按反馈介入的时机与方式，可大致分为 Static Planning 与 Runtime Adaptive Planning 两类。静态规划在执行前固定结构与分配（多数 prompt 流水线与静态工作流）；运行时自适应方法则包括：重试（retry）、自我反思与自我精修（Reflexion, Shinn et al., 2023；Self-Refine, Madaan et al., 2023）、外部验证器（CRITIC, Gou et al., 2024）、重规划（ReAct 式反思后重新规划）、模型级联与回退（FrugalGPT；Hybrid LLM），以及失败感知的结构调整。值得注意的是，Huang et al.（2024）指出语言模型在无外部信息时难以可靠地进行自我纠错——这与本文的 retry 语义审计结论一致：温度 0 下同配置重执行近乎逐字节复现，重试的价值必须来自信息或能力的变化，而非"再试一次"本身。

本文的 Dynamic DAG 与上述工作的区别在反馈的作用范围：**它不要求每次反馈都修改 DAG 拓扑，而是将运行反馈用于受影响后继节点的选择性模型重调度、剩余预算重分配与恢复决策**；结构重规划只是更高成本的可选动作。两个实验支撑这一设计：Local Subgraph Replan 的开发实验显示改写拓扑未扩大恢复覆盖（净增 0 节点），而后继选择性重调度在真实传播下以零预算违规稳定触发。此外，本文的选择性更新规则（正向证据保护、受影响后继门控、能力画像评分）与"仅靠自我反思不可靠"的文献结论相互印证：反馈的价值在于携带新信息或新能力，而非重复生成。

## 2.4 Multi-objective LLM Serving and Execution Memory

质量—成本—时延的联合优化方面，FrugalGPT 与 Hybrid LLM 建立了质量—成本权衡与级联降本的基本形态；RouteLLM/RouterBench 将该权衡标准化为可比较的基准；预算约束推理与延迟感知服务是部署侧的常见约束形式。这些工作通常以 Pareto 前沿或效用函数（Q − λC − μL）报告策略取舍，但选择粒度多为查询级，且少有把"剩余预算"作为运行时硬约束施加到执行过程内部。

执行记忆与经验复用方面，Reflexion 将失败反思存入情景记忆，Voyager（Wang et al., 2023）维护可增长的技能库，ExpeL（Zhao et al., 2024）从历史经验蒸馏决策知识，Agent Workflow Memory（Wang et al., 2024）将成功的子工作流沉淀为可复用例程。这些工作证明了执行经验的可存储与可复用，但记忆对象多为提示、技能或例程，而非"带依赖结构、模型分配与 Q/C/L 记录的执行图"。

综上，现有研究通常分别研究模型路由、任务规划、运行反馈或历史经验复用，较少在统一 DAG 执行框架下同时考虑节点级能力匹配、Static/Dynamic 双模式执行、历史图复用以及质量—成本—时延约束。本文正是在这一空白处给出统一框架，并以 Static/Dynamic 对照、真实失败触发的恢复矩阵与预算感知升级实验为其提供端到端证据。
