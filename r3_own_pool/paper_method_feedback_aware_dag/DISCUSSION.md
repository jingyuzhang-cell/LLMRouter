# 6 Discussion

## 6.1 主线发现：调度可以更安全，但不能创造能力

全部实验收敛到同一个结论：**动态调度能够更安全地利用已有模型互补性，但不能突破模型池本身的能力覆盖上限。**

这条结论由三个相互独立的证据层支撑。第一层是 Live 端到端对照（48 任务，真实执行、真实传播）：Static 52.1%、Dynamic v2 54.2%，配对 ΔQ = +2.1pp 且 95% CI 覆盖 0；Dynamic v2 将 harm 降为 0、预算违规为 0、成本与 Static 持平（1400.6 对 1402.2 tokens）。第二层是机制诊断（回放层级）：后继重调度在存在可重路由空间（原计划模型失败且模型池存在正确替代）的节点上，选中正确模型 8/8，优于 Static 冻结回退的 5/8——调度策略本身能把反馈转化为正确的模型选择。第三层是覆盖率核算：116 个判据纯净真失败上，四种恢复动作全部执行的 oracle 上界仅 6.9%，且 22 个双失败任务在真实传播后由两臂链路合并尝试了模型池全部 3 个模型、全部错误。三层合起来解释了为什么 ΔQ 不显著：不是调度器不会选，而是选择空间本身不存在。

## 6.2 为什么"更强的动态"没有带来"更高的质量"

Local Replan 开发实验（40 节点，改写失败节点及其受影响后继）净增覆盖 0 节点；预算网格显示从低成本恢复升级到全动作执行，质量 3.5%→6.9%（恰为 oracle），成本约 500→6300 tokens（效率约 6 倍差距）；λ/μ 敏感性中昂贵动作在任何非零成本/延迟权重下均不占优。失败归因显示双失败任务的主导原因是模型池共同失败（同一事实上初始与回退模型皆错）与上游证据缺失（oracle extraction +12pp 是系统最大的单一瓶颈）。这些结果共同说明：**在模型池能力覆盖不变的前提下，恢复侧的策略改进只能重新分配已有互补性，不能创造新的互补性**。因此本文将 Dynamic 的定位从"提高准确率的手段"修正为"在预算约束下安全利用互补性、避免负迁移的控制机制"——Dynamic v2 的价值正是把 harm 降为 0 而不损失质量、不增加成本。

## 6.3 判据纯度：一个被低估的方法学问题

本研究在审计中发现并修正了一个系统性偏误来源：以中间缺陷指标（如抽取操作数不完整）作为失败判据时，大量"潜伏缺陷但最终答案本就正确"的节点会进入失败池，使恢复率被虚假抬高（表观恢复 34 例中 32 例原始终答本就正确；早期文献中 31.7% 的分解恢复率在真实抽取事实上复核后仅 1/13 成立，已撤回）。本文因此将恢复实验的触发条件固定为**最终执行结果真实错误**，并以 retry 等价性审计（同配置重执行 66/69 逐字节复现、非确定性仅 4.3% 且零恢复）排除了"重跑即救"的替代解释。我们建议动态恢复类研究将"真实失败触发 + 判据纯度复核"作为标准报告项。

## 6.4 与老师七个问题的对应

RQ1（拆分）：分解收益呈域依赖与复杂度依赖（MultiHiertt +14pp、TAT-QA 低档 −9.4pp、4+ 步 +20.8pp）；结构质量四维分析表明证据覆盖与最终正确性关联最强（Pearson 0.377），但 Coverage 反映上游抽取质量，不等同于拆分粒度。RQ2（多目标）：Q/C/L 统一度量 + 预算网格 + Pareto + λ/μ 敏感性，阈值由预算/SLA 约束外生决定。RQ3（剩余预算）：B_rem/T_rem 过滤可行动作，T_rem ≤ 1s 时昂贵恢复不可行，预算内升级与终止由数据支撑。RQ4（故障分析）：其价值在于判定真实失败、量化恢复覆盖上限、指导是否继续投入。RQ5（Dynamic DAG）：定义为反馈条件化的后继重调度（拓扑不变），机制健全性由 replay + live 双层验证；修改拓扑的 Local Replan 判定 NO-GO。RQ6（创新）：结构感知执行 + 真实失败触发 + 预算感知选择性重调度，而非"失效类型决定专属动作"。RQ7（Graph Forest）：复用与版本化已实现，剪枝为设计而非本文核心实验结论。

## 6.5 局限

(1) 任务域以财务表格问答为主，跨域泛化未验证；(2) Live Dynamic 对照为 2 节点链（抽取→推理），更深的后继链尚未在 live 层级验证；(3) 48 任务为 previously analyzed live confirmation set，其诊断启发了 v2 规则设计，不构成未接触留出集；(4) v2 的 coder→large hysteresis 切换分支未被 dev 数据触发，仅有定义与一致性验证；(5) 回放层级实验使用条件化节点结果表，后继节点处于标准输入条件，已与 live 层级显式区分；(6) 成本为 token 计量与本地服务时延，未建模货币价格；(7) 恢复动作覆盖上限的结论限定于当前 3 模型池与冻结 prompt，扩池（更强模型、工具增强）是突破上限的自然途径，留作未来工作。
