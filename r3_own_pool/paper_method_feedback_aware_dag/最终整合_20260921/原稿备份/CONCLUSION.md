# 7 Conclusion

本文面向复杂任务的多模型执行问题，提出并系统评估了反馈驱动、预算感知的自适应 DAG 执行框架。框架以模型能力画像支撑节点级控制路由，以显式 DAG 组织任务分解，以 Static / Dynamic 双模式处理执行失败，以图森林支持历史复用，并在质量、成本、时延的多目标约束下选择执行策略。

主要结论有四。第一，模型能力在节点类型间存在稳定的异质性（抽取/推理/验证的最佳模型互不相同，条件口径节点 oracle 相对最佳单模型 +13.59pp），使节点级协同路由相对查询级路由取得 +6.9pp 的可复现增益；同时任务分解的收益依赖域与复杂度，分解应被视为一种需要决策的执行策略而非固定预处理。第二，**条件能力不等于传播能力**：条件口径下清晰的类型级互补性，在真实传播后被共同失败压缩（900 题开发语料中 77.0% 任务全模型皆错，可利用 GAP 收窄至 5pp）；跨模型 3×3 矩阵证明上游抽取质量是主导因素（E_large→R_medium 20.0% 对 E_medium→R_medium 10.0%）——阶段互补性真实存在，只是被同模型绑定掩盖。第三，在真实失败触发与判据纯度审计的前提下，Static 与 Dynamic 两种执行模式的端到端质量无显著差异（52.1% 对 54.2%，+2.1pp，CI 覆盖 0），但 Dynamic v2 通过正向证据保护、受影响后继门控与能力画像重调度，将错误动态调整（harm）降为 0 并保持零预算违规与持平成本——反馈驱动重调度的主要价值在于执行的安全性与稳定性；同时选择性适应优于激进切换（Two-stage 4 次切换零 harm，对 Capability Router 135 次切换 harm 4.5%），残余 GAP 仅能在低覆盖率选择性区域（5–10%）安全转化且在第二确认集未复现。第四，恢复实验量化了框架的边界：在 116 个判据纯净的真失败上，四种恢复动作的 oracle 覆盖上界仅 6.9%；失败的主导形态是模型池共同失败与上游证据缺失（oracle extraction +12pp）。**动态调度能够更安全地利用已有模型互补性，但不能突破模型池本身的能力覆盖上限**——当前瓶颈已从路由错误转移为模型池在困难任务上的共同失败。

上述结论对系统设计与实践的含义是：失败后的恢复决策应当以"是否存在可重路由空间"和"剩余预算是否允许"为第一判据，采用低成本恢复先行、条件升级、及时终止的分级策略；盲目堆叠更复杂的恢复结构（如局部子图重规划，本文开发实验净增覆盖为 0）既不能突破覆盖上限，还会放大成本与负迁移风险。

未来工作按优先级排列：(1) **扩展模型池的能力覆盖**——在共同失败主导的瓶颈下，引入更强推理模型、符号执行器或工具增强（确定性计算、表格结构化检索）是扩大恢复覆盖的根本途径，并应在新的 dev/test 失败集上按本文的判据纯度协议重新评估；(2) 将 Live Dynamic 对照扩展到更深的后继链与多域任务，检验选择性重调度在真实传播下的规模效应；(3) 在具备真实追问负载的场景中验证 Graph Forest 复用与剪枝策略的质量—成本收益；(4) 将恢复决策从实测查表升级为覆盖可恢复性特征的学习型策略，前提是可恢复正样本规模先经动作覆盖扩展而增大；(5) 建立货币化成本模型与端到端时延的在线测量，使多目标权衡可在真实部署约束下复现。

本文的全部实验遵循冻结口径与判据纯度审计：恢复实验以最终执行结果真实错误为触发条件，方法代码经哈希核验，策略以单一共享实现并通过等价性测试，正负结果均如实报告。我们希望这种"先审计判据、再度量收益"的评估方式，对动态恢复与多模型协同方向的后续研究有方法学参考价值。
