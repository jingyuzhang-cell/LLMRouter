# 面向复杂任务的反馈驱动多模型自适应 DAG 执行方法

**Feedback-driven Budget-aware Adaptive DAG Execution for Multi-model LLM Collaboration**

---


# 摘要

面向采购分析、财务报表问答等复杂任务，单一大型语言模型在质量、成本与时延上难以同时满足要求，且"把完整问题交给一个模型"的查询级路由无法利用模型在不同子任务上的能力差异。本文提出面向复杂任务的反馈驱动多模型自适应 DAG 执行框架（Feedback-driven Budget-aware Adaptive DAG Execution for Multi-model LLM Collaboration）：以模型能力画像（质量 Q、成本 C、时延 L）支撑节点级控制路由，将复杂任务分解为显式 DAG 并完成初始模型分配；执行层提供 Static 与 Dynamic 两种模式——Static 在节点失败时仅做局部处理、后继计划不变，Dynamic 在真实失败触发下对受影响后继节点执行选择性重调度与预算重分配；失败恢复采用预算感知的分级决策（恢复、升级或终止）；历史执行图以图森林形式版本化保存以支持跨任务复用，最终在单目标、双目标与多目标约束下进行执行策略选择。

在 MultiHiertt 与 TAT-QA 两域数据上的实验表明：（1）节点级协同路由相对查询级路由取得 +6.9pp 的可复现增益（独立确认、两种评分口径一致），类型级互补空间明确（条件口径节点 oracle 相对最佳单模型 +13.59pp），模型能力异质性是节点级调度的经验前提；（2）任务分解的收益呈域依赖与复杂度依赖：MultiHiertt 上分解较单体 +14.0pp，TAT-QA 低复杂度任务单体更优，分解收益随推导步数单调上升；（3）Live 端到端对照中 Static 52.1%、Dynamic v2 54.2%（配对 ΔQ +2.1pp，95% CI 覆盖 0），Dynamic v2 将错误动态调整（harm）降为 0 且预算违规为 0、成本持平；（4）机制诊断揭示**条件能力 ≠ 传播能力**：条件口径下清晰的互补性在真实传播后被共同失败压缩（900 题开发语料中 77.0% 任务全模型皆错，可利用 GAP 收窄至 5pp），跨模型 3×3 组合矩阵进一步证明上游抽取质量是主导因素（E_large→R_medium 20.0% 对 E_medium→R_medium 10.0%）——阶段互补性真实存在，只是被同模型绑定掩盖；（5）残余 GAP 的实例级路由仅在低覆盖率选择性区域安全（5–10% 覆盖率下 GAP 恢复 +7.4–8.6%、harm 接近零），Two-stage 偏好路由在 200 题确认集呈方向性正信号（+22.2%、零 harm）但在 500 题第二确认集未复现，仅作方向性证据；（6）判据纯度审计表明"节点存在缺陷 ≠ 任务已经失败"，116 个判据纯净真失败上四种恢复动作的恢复率均不显著（0–8.7%），动作集 oracle 上界仅 6.9%——**动态调度能够更安全地利用已有模型互补性，但不能突破模型池本身的能力覆盖上限**，当前瓶颈已从路由错误转移为模型池在困难任务上的共同失败。

本文的边界如实声明：节点级路由的独立确认来自审计后的训练留出集而非官方测试集；部分机制证据为基于已采集回答的回放层级；48 个任务的 Live Dynamic 对照为 previously analyzed confirmation set 而非未接触过的留出集；残余 GAP 路由的收益未能在第二个确认集复现，全部按方向性证据报告；恢复覆盖上限的结论限定于当前 3 模型池与冻结 prompt；局部子图重规划经开发实验判定为无额外覆盖收益，仅作为未来工作。

**关键词**：多模型协同；DAG 任务分解；节点级路由；反馈驱动执行；预算感知恢复；图复用；多目标优化

# 1 引言（研究问题与贡献）

## 1.1 研究背景与问题

复杂任务（如跨表财务问答、多约束采购分析）通常需要先从材料中定位事实，再识别事实间关系并完成计算，最后检查结果是否满足约束。这些步骤存在信息依赖，且对不同能力的要求不同：以 MultiHiertt/TAT-QA 节点基准的实测为例，抽取、推理与验证三类节点的最佳固定模型互不相同（large、medium、coder 分别最优），理想节点级分配相对最佳单模型存在 +13.59pp 的质量空间。仅按完整问题选择单一模型无法同时匹配这些需求，这是把路由对象从查询下降到任务节点的经验前提。

围绕这一前提，本文回答七个研究问题：

- **RQ1（任务拆分）**：复杂任务如何分解为 DAG？分解的收益与任务复杂度是什么关系，拆分/执行结构质量如何评价？
- **RQ2（多目标）**：质量 Q、成本 C、时延 L 如何在同一框架下度量与权衡？阈值由什么决定？
- **RQ3（剩余预算补偿）**：任务执行中已经消耗时间与 token 之后发生失败，后续应如何补偿？
- **RQ4（故障分析的意义）**：失效分析除了分类，还能回答什么？
- **RQ5（Dynamic DAG）**：动态调整应当如何定义、如何验证其有效性？
- **RQ6（方法创新）**：相对于查询级路由与固定流水线，创新点在哪里？
- **RQ7（历史复用）**：历史执行图如何保存、复用与演进？

## 1.2 方法概览

本文框架的执行主线为：模型能力画像 → 控制路由 → 任务分解与 Initial DAG → **Static / Dynamic DAG** 双模式执行 → Graph Forest 历史复用 → 单/双/多目标决策。其中 Static 模式在节点失败时仅对当前节点做局部处理、后继计划与预算不变；Dynamic 模式在**真实失败**触发下，对受影响后继节点执行选择性重调度（模型分配、预算重分配、验证策略调整），并在剩余预算约束下决定继续、升级或终止。局部子图重规划经开发实验判定为不扩大恢复覆盖（净增 0 节点），作为未来工作保留。

## 1.3 贡献

本文的贡献组织为四点：

**贡献一：模型能力画像与节点级协同路由。** 基于不同模型在质量、成本和时延上的异构表现建立能力画像（条件口径节点基准 + 900 题×3 模型的传播口径协议），将复杂任务分解为 DAG 节点并进行节点级模型分配。在审计后的 100 题留出集上，节点级路由相对查询级路由提升 +6.9pp，条件口径节点 oracle 相对最佳单模型存在 +13.59pp 的类型内互补空间。重点不是声称 learned router 跨域一直最优，而是证明模型能力具有明显异质性、节点级调度存在必要性。

**贡献二：Static/Dynamic 双模式反馈执行。** Static 在节点失败时局部处理而保持后继计划；Dynamic 根据真实执行反馈对受影响后继节点进行选择性重新调度。最终 Live 对照（48 任务 confirmation set）结果为 Static 52.1%、Dynamic v2 54.2%，提升方向为正但不显著；Dynamic 的主要价值体现为 harm=0、预算违规=0、成本基本不增加以及反馈调度更加稳定。配套的判据纯度审计（"节点存在缺陷 ≠ 任务已经失败"；表观恢复 34 例中 32 例原始终答本就正确）是使上述结论成立的方法学前提。

**贡献三：能力互补性的机制诊断。** 通过传播口径能力画像、跨模型 3×3 组合矩阵与 Exact Oracle 分析，本文揭示**条件能力 ≠ 传播能力**：条件口径下清晰的类型级互补性，在真实传播后被共同失败压缩（77.0% 任务全模型皆错，可利用 GAP 5pp）；抽取质量是主导因素（E_large→R_medium 20.0% 对 E_medium→R_medium 10.0%），阶段互补性真实存在但被同模型绑定掩盖；枚举 3×3 组合空间的 Exact Oracle 为 30.5%（最优固定组合 20.5%）。残余 GAP 的实例级可预测性（AUC 0.75–0.84）只能在低覆盖率选择性区域（5–10%）安全转化为收益，且在第二确认集未能复现——可预测性不等于可路由性。

**贡献四：历史图复用、多目标资源控制与恢复覆盖率瓶颈的量化。** Graph Forest 保存历史 DAG、模型分配、反馈与 Q/C/L 信息，实现执行经验复用；在预算约束、Pareto 与单/双/多目标策略下处理质量—成本—时延权衡。失败恢复实验进一步量化：在 116 个判据纯净真失败上，四种恢复动作的 oracle 覆盖上界仅 6.9%——**动态调度能够更安全地利用已有模型互补性，但不能突破模型池本身的能力覆盖上限**，当前瓶颈已从路由错误转移为模型池在困难任务上的共同失败。

## 1.4 论文边界

为避免过度声明，全文维持以下边界：节点级评估中 reasoning/verification 使用 gold 输入的条件化口径，与端到端执行分开陈述；独立确认采用审计后的 train holdout，不是官方测试集；部分机制证据为回放层级（基于已采集回答），与 live 层级显式区分；48 个任务的 Live Dynamic 对照为 previously analyzed live confirmation set（其诊断启发了 v2 规则设计），不称 untouched held-out；残余 GAP 路由的收益在 200 题确认集呈方向性正信号、在 500 题第二确认集未复现，全文仅按方向性证据引用；v2 策略整体经等价性验证，但 coder→large hysteresis 切换分支未被 dev 数据触发，不对其单独作效果声明；早期文献中"分解恢复 31.7%"为 gold-facts 条件下的表达式级结果，作为端到端恢复率结论已在本文撤回（真实抽取事实上仅 1/13 成立）。

# 2 Related Work

本章按开题技术路线的四个环节组织相关工作：模型路由与能力画像（2.1）、任务分解与 DAG 执行（2.2）、反馈驱动的自适应执行（2.3）、多目标服务与执行记忆（2.4）。每节末尾指出与本文相关的空白。文中引用均为领域内代表性工作，书目信息见参考文献待核对清单。

## 2.1 LLM Routing and Model Capability Profiling

查询级模型选择（Task/Query → Model）已有较系统的探索。FrugalGPT（Chen et al., 2023）提出级联式降本，以低成本模型先行、失败后升级；Hybrid LLM（Ding et al., 2024）训练路由器在强弱模型间按查询难度分配以逼近质量—成本前沿；RouteLLM（Ong et al., 2024）以偏好数据学习查询级路由，在标准基准上取得对最强单模型的成本节省；RouterBench（Hu et al., 2024）则系统化了路由系统的评测基准。与"学习式路由"并行的是能力画像路线：通过基准测试刻画各模型在不同任务上的能力分布（如 MMLU 类评测与各模型卡报告），作为路由先验。这些工作共同确认了一个前提：商业与开源模型在质量、成本与时延上存在显著异构性，且异构性与任务内容相关。

然而，上述方法的选择粒度是整道查询：同一次执行内的所有步骤共享同一个模型决策。本文的节点基准实验显示，抽取、推理与验证三类子任务的最佳模型互不相同，节点 oracle 相对最佳单模型存在 13.59pp 的类型内互补空间——这类互补性只在子任务粒度上可见。此外，既有能力画像多以单次问答或条件化子任务评测刻画模型能力，少有工作区分"条件能力"（给定正确输入）与"传播能力"（消费自身上游真实输出）：本文将证明二者测量的是不同的能力维度，且互补性的可利用空间主要由传播口径决定。现有 query-level 路由难以利用复杂任务内部不同子任务的差异化能力需求；仅进行整题级路由，无法实现本文所称的能力画像（Capability Profile）驱动的节点级路由（Node-level Routing）。

## 2.2 Task Decomposition and DAG-based LLM Execution

任务分解方面的经典证据是思维链提示（Chain-of-Thought, Wei et al., 2022）与最小到最大分解（Least-to-Most, Zhou et al., 2023）：将问题拆为子问题可提升多步推理。结构化方向上，Tree of Thoughts（Yao et al., 2023）把中间状态组织为可回溯的树；Decomposed Prompting（Khot et al., 2023）将任务递归分派给子求解器。系统层面，Planner–Executor 架构（如 HuggingGPT, Shen et al., 2023）以规划器产出任务序列、执行器调用模型或工具；ReAct（Yao et al., 2022）将推理与动作交替；多智能体工作流（AutoGen, Wu et al., 2023；MetaGPT, Hong et al., 2023）以角色化智能体协作；LLMCompiler（Lu et al., 2024）显式地把任务计划表示为 DAG 以支持并行函数调用。工具增强方向上，PAL（Gao et al., 2022）与 Toolformer（Schick et al., 2023）将算术与 API 调用外置给确定性解释器，直接对应本文"确定性工具执行"的设计。

需要强调的是，分解并非普遍有益。分解显式组织了依赖关系、使中间结果可检查，但额外的接口约束、中间格式转换与状态传播也会引入新的误差来源。本文的对照实验正体现了这种双向效应：MultiHiertt 上分解较单体 +14.0pp，而 TAT-QA 的扁平任务上单体直答反超 DAG 链 9.4pp，分解收益随推导步数单调上升。因此，是否采用 DAG 执行应结合任务结构与执行接口的表达范围决定，而非默认"拆分一定提高性能"——这也是本文将结构选择与结构质量分析纳入框架的原因。

## 2.3 Feedback-driven Adaptive Execution

按反馈介入的时机与方式，可大致分为 Static Planning 与 Runtime Adaptive Planning 两类。静态规划在执行前固定结构与分配（多数 prompt 流水线与静态工作流）；运行时自适应方法则包括：重试（retry）、自我反思与自我精修（Reflexion, Shinn et al., 2023；Self-Refine, Madaan et al., 2023）、外部验证器（CRITIC, Gou et al., 2024）、重规划（ReAct 式反思后重新规划）、模型级联与回退（FrugalGPT；Hybrid LLM），以及失败感知的结构调整。值得注意的是，Huang et al.（2024）指出语言模型在无外部信息时难以可靠地进行自我纠错——这与本文的 retry 语义审计结论一致：温度 0 下同配置重执行近乎逐字节复现，重试的价值必须来自信息或能力的变化，而非"再试一次"本身。

本文的 Dynamic DAG 与上述工作的区别在反馈的作用范围：**它不要求每次反馈都修改 DAG 拓扑，而是将运行反馈用于受影响后继节点的选择性模型重调度、剩余预算重分配与恢复决策**；结构重规划只是更高成本的可选动作。两个实验支撑这一设计：Local Subgraph Replan 的开发实验显示改写拓扑未扩大恢复覆盖（净增 0 节点），而后继选择性重调度在真实传播下以零预算违规稳定触发。此外，本文的选择性更新规则（正向证据保护、受影响后继门控、能力画像评分）与"仅靠自我反思不可靠"的文献结论相互印证：反馈的价值在于携带新信息或新能力，而非重复生成。

## 2.4 Multi-objective LLM Serving and Execution Memory

质量—成本—时延的联合优化方面，FrugalGPT 与 Hybrid LLM 建立了质量—成本权衡与级联降本的基本形态；RouteLLM/RouterBench 将该权衡标准化为可比较的基准；预算约束推理与延迟感知服务是部署侧的常见约束形式。这些工作通常以 Pareto 前沿或效用函数（Q − λC − μL）报告策略取舍，但选择粒度多为查询级，且少有把"剩余预算"作为运行时硬约束施加到执行过程内部。

执行记忆与经验复用方面，Reflexion 将失败反思存入情景记忆，Voyager（Wang et al., 2023）维护可增长的技能库，ExpeL（Zhao et al., 2024）从历史经验蒸馏决策知识，Agent Workflow Memory（Wang et al., 2024）将成功的子工作流沉淀为可复用例程。这些工作证明了执行经验的可存储与可复用，但记忆对象多为提示、技能或例程，而非"带依赖结构、模型分配与 Q/C/L 记录的执行图"。

综上，现有研究通常分别研究模型路由、任务规划、运行反馈或历史经验复用，较少在统一 DAG 执行框架下同时考虑节点级能力匹配、Static/Dynamic 双模式执行、历史图复用以及质量—成本—时延约束；也少有工作系统量化"互补性在何种口径下存在、在何种条件下可被安全利用"这一前提问题。本文正是在这一空白处给出统一框架，并以 Static/Dynamic 对照、条件—传播双口径能力诊断、真实失败触发的恢复矩阵与预算感知升级实验为其提供端到端证据——包括一个如实的负结果：当模型池在困难任务上共同失败时，调度策略的改进空间受能力覆盖上限约束。

# 3 Method

本文提出 **Feedback-driven Budget-aware Adaptive DAG Execution for Multi-model LLM Collaboration**（面向复杂任务的反馈驱动多模型自适应 DAG 执行框架），将复杂任务的模型选择与执行组织统一到任务有向无环图中。方法以节点级能力估计形成初始模型分配，以执行反馈修正后续选择，并以 Static 与 Dynamic 两种执行模式处理真实失败：Static 仅对失败节点做局部恢复，后继计划与预算保持不变；Dynamic 对失败节点及其后继执行反馈条件化的重调度与预算重分配，必要时升级或终止。局部子图重规划经开发实验未获支持，仅作为未来工作保留；历史执行图则通过版本化保存支持相关追问中的结果复用。框架由六个组件构成：模型能力画像（Q/C/L 异构性度量）→ 阶段感知节点路由 → Static/Dynamic DAG 双模式执行 → 选择性适应（仅在真实失败且有正向证据时覆盖默认分配）→ 预算感知控制（C/L 约束下的可行域过滤）→ Graph Forest（历史图复用）。以下分别介绍图构造、节点路由、反馈记忆、动态 DAG 调整、图复用及多目标决策，并区分静态预测、执行时可观测信息与仅用于离线评价的真实标签。

## 3.1 Overview

复杂任务通常要求先从材料中定位事实，再识别事实之间的关系，完成计算或推理，最后检查结果是否满足用户约束。这些步骤既存在信息依赖，也具有不同的能力需求。若仅根据完整问题选择一个模型，所有步骤便共享同一模型的能力与资源开销，难以利用模型在抽取、推理和验证上的差异。同时，将全部步骤置于一次生成中，会使中间结果及其来源难以单独检查，局部错误也难以定位。因此，本文将复杂任务表示为显式 DAG，使子任务、依赖及中间输出成为可调度的对象。

DAG 提供两层决策空间。第一层是在给定结构下为每个节点选择模型，依据该节点的任务类型估计模型质量、成本与延迟。第二层是在执行过程中判断原有分配及结构是否仍然适用。初始路由依赖历史样本，不能保证当前节点在实际输入状态下成功；上游输出不完整、关系理解错误或节点包含过多推理步骤，都可能使原先合理的执行计划失效。本文因此将静态分配作为执行起点，并利用反馈对后续选择进行修正。

反馈记忆与动态调整承担不同职责。前者记录特定模型在特定节点状态下的执行结果，改变后续模型选择所依据的能力估计；后者在检测到真实失败后对失败节点及其后继执行换模型、重新分解及依赖失效处理。二者通过共享执行状态连接，但不等同：一次记忆更新不必引发图修改，一次结构调整也不能代替对模型表现的持续记录。进一步地，用户追问可能沿用已有事实、只修改某个假设，或要求比较多个历史结果。此时，历史 DAG 中仍然有效的节点可以直接复用，而无需重新执行完整任务。

设用户任务为 \(x\)，模型池为 \(\mathcal M\)，初始图为 \(G_0\)，初始分配为 \(\pi_0\)。整体过程可表示为

\[
x\longrightarrow G_0\longrightarrow\pi_0
\longrightarrow \mathrm{Execute}
\longrightarrow \mathcal H_t
\longrightarrow (G_{t+1},\pi_{t+1})
\longrightarrow\mathcal F_{t+1},
\]

其中，\(\mathcal H_t\) 为反馈记忆，\(\mathcal F_t\) 为历史图集合。质量、成本和延迟贯穿上述过程：节点路由使用统一效用，执行记录提供实际资源消耗，候选执行策略最终在相同评价口径下进行多目标比较。框架的核心在于节点级选择、反馈条件化的适应，以及真实失败触发的预算感知动态调整与历史图复用之间的闭环关系。

## 3.2 DAG Construction

给定任务 \(x\) 及其材料 \(D\)，构造

\[
G=(V,E),\qquad E\subseteq V\times V,
\]

其中 \(V=\{v_1,\ldots,v_n\}\) 为任务节点集合，边 \((v_j,v_i)\in E\) 表示 \(v_i\) 的执行需要 \(v_j\) 的输出。每个节点定义为

\[
v_i=(\tau_i,I_i,O_i,\operatorname{Pa}(i),\mathcal K_i),
\]

其中 \(\tau_i\) 为节点类型，\(I_i\) 与 \(O_i\) 为输入和输出约定，\(\operatorname{Pa}(i)\) 为直接依赖节点，\(\mathcal K_i\) 为格式、运算或任务约束。节点输入由原始材料与依赖输出共同确定；只有依赖已经提供有效结果，节点才具备执行条件。图的无环性保证执行可以沿拓扑顺序推进，同时使失败影响范围能够沿依赖关系追踪。

节点类型反映任务中可区分的能力需求。Extraction 从材料中提取实体、数值及相关事实；reasoning 确定事实间关系并产生推理结果或可执行表达式；verification 检查表达式、结论与输入之间的一致性；aggregation 汇总已有结果以回答比较或整合类请求。自然出现的单位转换可作为 transformation 节点保留，但不将其与主要节点类型混合解释。节点类型描述执行职责，而不预设固定模型：不同模型在同一类型上可能仍随问题内容产生差异。

当前实现使用可检查的领域模板组织初始图。以财务问题为例，事实抽取提供后续推理所需数值，推理节点生成表达式，确定性执行器完成数值运算，验证节点检查所得到的关系与结果。该构造方式明确区分语义工作与确定性操作：模型承担事实理解和关系选择，工具执行已有表达式中的算术。图构造本身不被表述为已经实现的通用自由文本规划器，也不将确定性工具的计算正确性归因于模型路由。

输入输出约定使节点错误具有可定位性。例如，抽取节点必须返回结构化事实，推理节点必须引用已给定事实变量，验证节点返回明确判定。若输出无法解析或表达式无法执行，系统可以确定失败发生在哪个接口；若表达式可执行但语义关系错误，则需要进一步检查推理内容。这样的边界为后续模型级与结构级恢复提供依据。

节点级实验与完整图执行采用不同的信息条件。为测量单一节点的模型能力，条件化节点基准可向推理与验证节点提供标准事实，以减少上游错误的干扰；完整执行则使用实际前驱输出。标准事实和评分标签只用于相应实验的输入控制或评价，不作为路由器特征。因而，节点基准回答的是给定输入条件下的模型选择问题，其质量不能直接解释为整个 DAG 的最终成功率。

图的显式性还使“完成一个节点”和“完成整个任务”具有不同含义。一个抽取输出即使符合格式，也可能遗漏后续推理所需事实；一个计算结果即使数值合法，也可能对应错误的比较关系。因此，节点约定同时包含可执行接口与任务含义，前者支持程序检查，后者需要结合具体节点评分或验证结果判断。执行记录保留二者的区别，避免将解析成功直接视为任务成功，也为失败诊断提供可追溯的依据。这种表示不要求所有任务具有相同节点数量，而是要求已有模板中的依赖能够解释输出如何形成。

## 3.3 Node-level Routing

传统查询级路由为完整任务选择单一模型，即 \(r_{\mathrm q}:x\mapsto m\)。本文将选择对象下降到任务节点，定义 \(r_{\mathrm n}:(x,\tau_i)\mapsto m_i\)。同一任务的抽取、推理和验证节点因此可以使用不同模型。路由的目标并非人为分散模型使用比例，而是在固定模型池内，根据不同节点的预期收益与开销选择执行者；若某模型在所有候选上均具有更高效用，集中选择该模型也是允许的结果。

对节点 \(i\) 与模型 \(m\)，定义条件期望质量、成本和延迟为

\[
Q(i,m)=\mathbb E[q_i\mid x,\tau_i,m],\quad
C(i,m)=\mathbb E[c_i\mid x,\tau_i,m],\quad
L(i,m)=\mathbb E[\ell_i\mid x,\tau_i,m].
\]

其中，\(q_i\) 由节点类型对应的评分规则确定，\(c_i\) 与 \(\ell_i\) 分别表示调用消耗及服务时长。执行前不可获得当前调用的真实质量，因此决策使用预测值 \(\widehat Q,\widehat C,\widehat L\)，并与执行后的观测值明确区分。

当前质量预测器保持低容量。令 \(e(x)\) 为冻结 GTE 编码器产生的问题表示，节点特征为

\[
\phi_i=\left[e(x);\operatorname{onehot}(\tau_i);
\log(1+|x|)\right],
\]

其中 \(|x|\) 为问题字符长度。实现中的类型编码覆盖 extraction、transformation、reasoning 和 verification；追问中的 aggregation 使用既有执行流程，不据此宣称已有专门训练的聚合能力预测器。节点表示沿用原问题编码，并通过类型和长度区分节点需求，不加入节点答案、评分结果或未实现的状态编码。

对每个候选模型分别训练 Ridge 质量预测头：

\[
(\widehat w_m,\widehat b_m)=
\arg\min_{w,b}\sum_{i\in\mathcal D_{\mathrm{dev}}}
\left(q_{i,m}-w^\top\phi_i-b\right)^2
+\lambda_{\mathrm R}\|w\|_2^2,
\qquad
\widehat Q(i,m)=\widehat w_m^\top\phi_i+\widehat b_m.
\]

正则强度固定为 \(\lambda_{\mathrm R}=1\)。模型池为 medium、large 和 coder，R1 不进入该节点路由器。开发阶段确定特征、编码器和训练设置后，在完整开发数据上拟合并封存参数；独立确认阶段仅执行推断，不以确认集质量选择参数或改变特征。

成本与延迟采用开发数据中各模型的平均观测值，即当前实现中的 \(\widehat C(i,m)=\bar C_m\)、\(\widehat L(i,m)=\bar L_m\)。这两项构成模型级资源先验，而非已经训练完成的节点条件化开销预测器。综合效用及选择规则为

\[
U(i,m)=\alpha\widehat Q(i,m)
-\beta\widehat C(i,m)-\gamma\widehat L(i,m),
\qquad m_i^*=\arg\max_{m\in\mathcal M}U(i,m).
\]

静态节点实验固定使用

\[
U(i,m)=\widehat Q(i,m)
-0.05\frac{\bar C_m}{1000}
-0.05\frac{\bar L_m}{10},
\]

其中成本单位为 tokens，延迟单位为秒。固定缩放使三项具有明确权重，避免根据测试结果重新选择偏好。系统保留每个候选模型的质量预测、资源先验和效用，而不仅记录最终选择，从而能够区分模型集中选择究竟来自质量预测还是资源惩罚。

节点异构性的经验动机来自节点级 GAP。对某一类型 \(\tau\)，定义

\[
\operatorname{GAP}_{\tau}
=\frac{1}{N_\tau}\sum_{i:\tau_i=\tau}\max_m q_{i,m}
-\max_m\frac{1}{N_\tau}\sum_{i:\tau_i=\tau}q_{i,m}.
\]

该量比较逐节点 hindsight 选择与该类型最佳固定模型。已有独立确认在抽取和推理节点上观察到正 GAP，支持模型能力并非完全同序这一动机。但 Oracle 使用事后标签，不能参与实际选择；正 GAP 也不保证当前表示可以预测全部机会。因此，路由效果仍需通过冻结模型相对查询级路由及固定模型的配对比较判断，而不能仅由 Oracle 上界推导。

消融实验进一步明确了增益来源。本文在相同协议下比较三种选择器：查询级路由（仅问题编码）、类型先验路由（按开发数据选择各类型最佳固定模型，无表示学习）与完整节点路由。结果显示，从查询级到类型先验的跃升贡献了主要增益（开发集 +5.9pp，独立确认 +6.7pp，任务级配对区间均不含零）；在此之上，问题编码带来的额外增量在开发折内为正但幅度有限（+1.6pp），且未迁移到独立确认集（+0.2pp，区间含零）。因此，本文不将贡献定位在学习到强节点表示，而定位在选择粒度的改变：将路由对象从完整问题下降到类型化节点，使模型间能力差异成为可利用的结构。问题编码作为其中一种实例化保留，其在跨数据迁移中的局限被如实报告，更强的节点条件表示与资源预测留作后续工作。

查询级与节点级路由的对照保持相同编码器和模型池，主要区别在于是否引入节点类型及既有长度特征。由此，比较所检验的是改变选择粒度能否帮助利用模型异构性，而不是更大编码器或更深预测器的收益。评价时，同一任务内多个节点共享材料与问题，不能将它们视为完全独立样本；配对重采样应以任务为单位，保留同一任务内各节点及方法之间的关联。整体质量提升还需结合类型内结果解释：优于全局固定模型不意味着在每种类型上均优于该类型最佳固定模型。

## 3.4 Feedback Memory

初始质量预测由开发数据确定，无法完全表达实际执行状态。同一类型节点可能因问题复杂程度、输入条件或先前失败经历而呈现不同成功概率。本文维护执行反馈记忆

\[
\mathcal H_t=\{(v_j,m_j,s_j,r_j)\}_{j<t},
\]

其中 \(s_j\) 表示执行状态，\(r_j\) 包括输出、可获得的执行判定及资源消耗。决策时只使用已经发生的反馈，未执行候选的结果与未来节点标签不进入记忆。反馈因此是有选择的观测：记忆反映已调用模型的历史表现，而非当前状态下所有模型的完整反事实能力。

当前原型以节点类型、问题长度分桶和模型构成初始选择记忆键。长度小于 150 个字符归入短问题，其余归入长问题；另维护类型与模型对应的失败恢复记忆。该状态表示是有限离散条件，不被解释为对完整中间执行状态的学习。设键 \(k\) 下记录成功数为 \(S_k\)，观测数为 \(N_k\)，采用平滑成功率

\[
p_k=\frac{S_k+1}{N_k+2}.
\]

新结果到达后，按对应记录路径更新计数。该统计量描述成功事件的经验频率，不是连续质量标签的精确后验；对于非二元评分，必须保留二者的语义差别。

初始选择将冻结质量预测与记忆统计融合：

\[
\widetilde Q_t(i,m)
=(1-\eta)\widehat Q(i,m)+\eta p_{k(i,s_i,m)},
\]

再沿用成本和延迟惩罚计算模型效用。原型取 \(\eta=0.3\)；失败恢复使用单独记忆，融合权重为 \(0.5\)，并在排除已失败模型的候选中选择替代者。该恢复实现依据融合质量排序，不能写成已经对每次回退重新求解完整的 Q/C/L 优化。

Feedback Memory 的作用是改变未来选择依据，更新的是 \(Q(\text{node},\text{state},\text{model})\) 的经验估计，而不是直接修改边集合或产生新的子任务。图是否需要改变由下一节的失败处理决定。当前反馈实验包含顺序回放，并以可评分节点结果构造成功事件；这验证了反馈对选择的影响，但不意味着在线系统可以无误获得真实质量。实际反馈的可靠性，特别是语义验证误判，会直接影响记忆与后续决策，必须与路由预测误差分开评价。

反馈的时间顺序构成方法的信息边界。在第一个任务执行前，记忆只有平滑先验，静态预测承担初始能力估计；随着任务按固定顺序推进，后续选择才可以受已记录结果影响。离线回放即使持有完整模型结果表，也只能在相应调用发生后揭示该模型的结果。若直接使用全部候选的当前标签更新记忆，就会把反馈路由转化为事后选择。与此同时，记忆融合与回退应分别记录，因为二者同时改变时，最终质量差异不能全部归因于记忆估计更加准确，还可能来自增加执行机会。

## 3.5 Dynamic DAG Adaptation

框架提供两种执行模式。**Static DAG**：DAG 结构与后继节点的模型分配在执行前确定；节点失败时仅对当前节点执行 retry、switch 或 fallback，后继节点维持初始计划与预算。**Dynamic DAG**：执行状态发生变化后，对失败节点及其后继节点的执行策略进行反馈条件化更新——模型分配、成本与时间预算、验证策略均可调整，必要时才做局部结构调整。拓扑变化不是动态性的必要条件；这与"失效类型决定专属恢复动作"无关，动态性的核心是后继执行策略随反馈更新。

### 3.5.1 Feedback State Update

每个节点执行后收集状态

\[
s_t=(\text{result},\ \text{error},\ Q,\ C,\ L,\ B^{\rm rem},\ T^{\rm rem}),
\]

其中 result 为节点输出，error 为执行错误，Q/C/L 为该次执行的质量、token 成本与服务时延记录，\(B^{\rm rem}\) 与 \(T^{\rm rem}\) 为剩余 token 与时间预算。状态按依赖顺序写入执行记忆，作为恢复决策与后继重调度的输入；离线评价用的真实标签不在执行状态中。

### 3.5.2 True Failure Detection

**恢复入口必须是真实失败**：以最终执行结果错误（而非中间缺陷指标异常）作为触发条件。148 节点审计显示，按中间判据入池的失败节点中，表观恢复的 34 例里 32 例的原始终答本就正确（节点有缺陷 ≠ 任务已失败）；判定标准错位会系统性高估恢复率（见 5.4.3）。因此系统先判定真实失败，再决定是否进入恢复，避免对"潜伏缺陷但答案正确"的节点消耗恢复预算。

### 3.5.3 Node-level Recovery

对真实失败节点，恢复动作集为

\[
\mathcal A=\{\text{retry},\ \text{switch},\ \text{re-extract+re-reason},\ \text{decompose},\ \text{terminate}\},
\]

决策形式为

\[
a^*=\arg\max_{a\in\mathcal A}\left[\widehat{\Delta Q}(a,s_i)-\lambda C(a)-\mu L(a)\right]
\quad\text{s.t.}\quad C(a)\le B^{\rm rem},\ L(a)\le T^{\rm rem}.
\]

当前实现中 \(\widehat{\Delta Q}\) 并非学习模型，而是冻结协议实测的恢复率/成本表。116 个判据纯净真失败 × 4 动作的冻结 counterfactual（task_uid cluster bootstrap）表明：**失效类型对恢复动作无显著区分力（各格子 0–8.7%，95% CI 全部覆盖 0），动作集 oracle 上界仅 6.9%——瓶颈是动作覆盖率而非选择策略**；低成本动作（retry/switch，单次约 240–300 tokens、0.3–0.4 s）与昂贵动作（retrieval/decompose，约 2–4 千 tokens、2.7–4.8 s）的恢复率统计无差，温度 0 下同 prompt 重执行近乎逐字节复现（69 个严格重执行样本中 66 个完全一致、0 个恢复），"retry 很强"的表观恢复主要来自判据错位样本。

模型级失败指节点输入输出约定仍然成立，但当前模型未能完成该职责。此时保持节点及依赖不变，重新选择执行模型：

\[
G_{t+1}=G_t,\qquad m_i'\in\mathcal M\setminus\{m_i\}.
\]

冻结重路由原型使用原效用排序中的第二候选，反馈版本则结合恢复状态记忆选取替代模型。有限回退用于约束新增调用开销。若在三个候选模型上全部尝试，并利用真实标签保留正确输出，其结果已接近穷举模型池，不能作为可部署动态策略优于静态路由的证据。

结构级恢复以局部子图替换原节点：

\[
G_{t+1}=G_t\ominus v_i\oplus H_i,
\qquad H_i=(V_i',E_i').
\]

该记号表示移除原节点的执行职责，将前驱输入连接到新子图入口，并使原后继依赖新子图的等价输出。**只对被诊断为结构性失效的节点做局部重构**：当前分解原型针对财务推理，将事实语义对齐（D1：从报告中解释实体、期间和单位）、关系与表达式生成（D2）、确定性计算及语义检查（D4）显式分离，每次触发增加两个节点、每任务至多一次、无递归展开。分解质量从三个维度评价：恢复效果（失败是否被救回）、结构代价（新增节点/调用/资源）与结构必要性（相对换模型与重试的额外恢复量）。需要强调的是，冻结协议全量实验中分解相对低成本恢复动作无显著额外收益（见 5.4），本节的结构替换机制描述其可实现的控制流，端到端有效性证据不足，不作主要贡献宣称。结构调整必须与执行器能力区分：如果任务需要除以年份数，而表达式语言不允许相应常数，则失败首先来自接口表达范围，仅更换模型或增加分解步骤不能消除这一限制；已有分解比较因此在允许相同常数和运算符的执行器条件下进行。

### 3.5.4 Downstream Dynamic Rescheduling

Static 与 Dynamic 的分界在于失败节点的后继 \(\operatorname{Desc}(v_i)\) 是否随反馈更新。Dynamic 模式下，上游失败触发对后继节点的执行策略重调度：模型分配按（类型、模型）失败状态记忆与冻结效用融合重新选择；验证节点在上游失败时可在剩余预算内升级为更强验证模型；每次选择后重新计算 \(B^{\rm rem}\) 与 \(T^{\rm rem}\)。拓扑保持不变。Static vs Dynamic 的对照实验（5.4.2，条件化节点结果表回放，失败触发可读取离线评分、后继节点处于标准输入条件）显示：重调度在 26.3% 的失败任务上触发（平均 0.43 个后继节点），预算违规为零，成本增量约 +0.2%；任务质量与 Static 无显著差异（ΔQ 95% CI 覆盖 0）。诊断表明：41 个被重调度后继中 65.9% 存在可重路由空间，且在这些"原计划模型失败但存在正确替代"的节点上 Dynamic 选中正确模型 8/8、Static 冻结回退仅 5/8——调度策略本身能把反馈转化为正确的后继调整；任务级无增益的主因是决定任务成功的节点在两种模式下均已获得节点级回退，以及回放中后继节点处于标准输入条件、上游变化未真实传播。唯一的 harm 案例来自失败记忆覆盖有正向证据的冻结回退，由此引出 **Selective Dynamic Update** 设计原则并形式化为四条调度规则（R1 正向证据锁、R2 切换边际、R3 受影响后继门控、R4 能力画像评分）；规则以单一共享策略函数实现并经等价性验证后在独立 confirmation 集一次性执行：harm 清零、质量与 Static 持平（见 5.4.2）。在状态真实传播的 live confirmation 对照（48 任务，恢复后的真实输出传入后继）中，上述结论得到端到端验证：重调度触发 52.1%、预算违规为零、成本持平，任务质量与 Static 无显著差异（+2.1pp，CI 覆盖 0），唯一 harm 已被选择性更新规则消除。该结果与 5.4.4 的 oracle 分析一致：动态性的价值在于把恢复决策与预算约束组织成可部署闭环，而非修改图拓扑本身。最终结论固定为：**动态调度能够更安全地利用已有模型互补性，但不能突破模型池本身的能力覆盖上限**（此句应同时进入论文 Discussion 与 Conclusion）。**局部子图重规划（Local Replan）在 40 节点 dev pilot 上未扩大 oracle 覆盖（净增 0 节点，见 5.4.7），作为未来工作保留；全局 DAG 重规划仅作为概念级 fallback，暂无实验支撑。**

节点重算或重调度之后，下游结果可能不再有效。令受影响节点集合为 \(A_t\)，其依赖后继组成的失效范围为

\[
\mathcal I_t=A_t\cup\operatorname{Desc}_{G_t}(A_t).
\]

这些节点被标记为待重新评估，随后按依赖顺序恢复执行。当前小型链式 DAG 原型保守地使后续节点失效；其控制流覆盖异常触发、候选切换及后继重新评估。该机制与普通 retry 的区别不仅在于模型是否改变，还在于执行状态和受影响依赖是否同步更新。动态更新并不要求每次异常都重建整个任务：对于职责清晰、输入完整的局部失败，保留原图有助于限制恢复开销；已经产生且不受变化影响的前驱结果继续保留，受影响输出则不能以旧状态传递给后继。

### 3.5.5 Budget-aware Escalation and Termination

预算约束贯穿恢复与重调度：

\[
B^{\rm rem}=B-B^{\rm used},\qquad T^{\rm rem}=T-T^{\rm used}.
\]

预算网格实验（5.4.6）显示：\(T^{\rm rem}\le 1\) s 时 retrieval/decompose 不可行；从低成本动作升级到全动作执行，质量仅从约 3.5% 升至 6.9%（即 oracle），成本从约 500 涨至 6300 tokens（恢复效率约 6 倍差距）；λ/μ 敏感性中昂贵动作在任何非零成本/延迟权重下均不占优。因此系统按 **Recover → Escalate → Terminate** 三级决策：低成本恢复先行；仍失败且剩余预算允许并存在可观察改进信号时升级；否则终止以避免无效开销。若有限恢复仍然失败，执行记录保留未解决状态，而不能通过忽略失败或读取评价答案生成成功结论。这样的状态约束使动态适应保持明确的异常恢复语义，也使恢复次数与资源消耗能够独立核算。

### 3.5.6 Exact Oracle within the Model-Composition Space

在有限模型池 \(\mathcal M\)（\(|\mathcal M|=3\)）、2 节点传播链与确定性执行下，全部可行模型组合为 \(3 \times 3 = 9\) 种。精确枚举全部组合并逐任务取 Q 最大者，得到定义策略空间内的 Exact Static Oracle：

\[
Q^{\text{oracle}} = \frac{1}{n}\sum_i \max_{(e,r)} Q_i(e,r).
\]

在 200 任务 cross-model 子集上的实测结果：Exact Oracle Q = 30.5%；Always Large（E_large→R_large）Q = 18.0%；Oracle GAP = 12.5pp。最优固定组合 E_large→R_coder Q = 20.5%（Optimality Gap = 10.0pp）。Exact Pareto 非支配集包含 E_large→R_medium、E_large→R_large 和 E_large→R_coder 三个组合（互不支配）。

**边界声明**：此 Exact Oracle 为 3×3 模型组合空间内的精确最优上界，不涵盖 retry/switch/retrieval 等恢复动作、downstream rescheduling 或 Graph Forest；后者属于更复杂的序列决策问题，留作未来工作。

## 3.6 Graph Forest Reuse

在多轮任务中，新的请求通常只改变历史任务的一部分。用户可能要求比较已有结果，或在报告事实保持不变时修改某项计算假设。本文将历史任务图保存为图森林

\[
\mathcal F_t=\{G_1^{(\nu_1)},\ldots,G_K^{(\nu_K)}\},
\]

其中 \(\nu_k\) 表示版本。图森林是可检索、复用和修改的执行历史集合，不要求历史 DAG 退化为树结构。动态调整产生的局部分支可以成为新的图版本，但图森林的范围还包括完整历史任务及其可复用子图。

节点历史记录包括任务输入或事实引用、输出、执行模型、可用质量记录、依赖和版本信息。系统通过这些记录判断历史结果属于哪个输入状态，并在修改后保留旧值，避免新结果覆盖原始执行依据。当前原型按任务标识检索历史图，通过显式事实索引和依赖定位受影响节点；不将其描述为已经实现的语义向量图检索系统。

对于相关追问，处理顺序为 Retrieve、Reuse、Modify 和 Recompute。首先定位相关历史图；随后识别当前仍然有效的输出；若用户修改了输入假设，则产生新版本并标记直接受影响节点及其依赖；最后只执行必要的新节点与失效节点。设追问造成的直接变化为 \(\Delta V\)，形式上可写为

\[
V_{\mathrm{recompute}}=\Delta V\cup\operatorname{Desc}_G(\Delta V),
\qquad V_{\mathrm{reuse}}=V\setminus V_{\mathrm{recompute}},
\]

其中复用集合仍需满足输入含义与原约束不变。原型中的依赖跟踪覆盖所实现的小型图，不据此声称已验证任意规模图上的通用增量计算。

例如，两个历史任务已有结果时，比较型追问可直接读取这些输出，只执行新的汇总节点。若用户假设某个已报告数值提高一定比例，原报告及其抽取结果可以保留，假设变化进入推理输入，仅重算相关推理与验证。若用户实际修改的是源报告内容，则对应抽取结果也应失效。复用边界取决于变化作用于哪个输入，而不只取决于问题文本是否相似。

图复用追求的是避免无必要执行，而非无条件接受历史答案。缓存命中不等于语义正确，验证模型接受也不等于最终答案已经独立核实。现有多轮原型展示了保存、检索、版本保留和局部重算；对质量与资源收益的比较应限制在同一追问工作负载内，并计入实际发生的调用。反馈记忆积累的是状态条件下的模型表现，图森林保存的是任务计算及其依赖，两者分别支持选择经验复用与执行结果复用。

版本信息将追问前后的执行状态联系起来。对一个被修改的节点，历史版本保存原输出及其所属图版本，新版本记录重算结果；依赖节点据此区分自身使用的是旧输入还是修改后的输入。多轮结果因此能够沿版本回溯到具体计算条件。现有实现以显式修改事件驱动这一过程，复用并非由模型自由决定是否跳过节点，而由追问作用的事实与已保存依赖确定。该约束尤其适用于只改变部分假设的任务，可以将变化带来的新计算与对原始材料的重复处理分离。

## 3.7 Multi-objective Planning

节点选择、异常恢复与历史复用会形成不同的执行策略：额外验证可能提高可检查性，但增加成本；结构分解可能恢复复杂节点，也引入更多顺序步骤；复用能够减少调用，但受历史结果有效性约束。因此，最终决策需要同时考虑质量、成本和延迟，而不能仅按恢复节点数选择策略。

令 \(p\in\mathcal P\) 为一个候选执行方案，包含图、模型分配及所采用的恢复或复用策略，其目标向量为

\[
\mathbf z(p)=(Q_p,C_p,L_p),
\]

其中质量最大化，成本与延迟最小化。方案必须在相同任务集、质量定义及资源口径下比较。节点平均质量、最终任务正确率和追问链可执行率属于不同指标，不直接放入同一个 Pareto 集合。当前实现针对有限的已评估策略筛选候选，不宣称穷举全部可能 DAG 或获得全局最优计划。

定义方案 \(p_a\) 支配 \(p_b\) 当且仅当

\[
Q_{p_a}\ge Q_{p_b},\qquad
C_{p_a}\le C_{p_b},\qquad
L_{p_a}\le L_{p_b},
\]

且至少一项严格优于。由此得到非支配集合

\[
\mathcal P^*=\{p\in\mathcal P:
\nexists p'\in\mathcal P,\ p'\succ p\}.
\]

在质量要求明确的场景，可以求解

\[
\min_{p\in\mathcal P}C_p
\quad\mathrm{s.t.}\quad Q_p\ge Q_{\min}.
\]

若仅关注质量与成本，则保留二维非支配集合；若延迟同样重要，则使用三维集合，再依据用户约束或预先给定偏好确定最终方案。节点效用中的加权选择提供固定偏好下的初始分配，Pareto 比较则呈现候选策略之间不同的整体权衡，二者服务于同一 Q/C/L 目标的不同层次。

资源核算必须包含恢复中的额外执行。tokens 是当前推理成本代理，不等同于实际货币支出；延迟记录以调用服务时长为主，也不等同于包含启动、排队和调度的端到端耗时。部分策略比较以平均调用消耗乘调用倍率估算有效成本，并另计验证开销；这类值应标识为估计，不能写成完整逐请求实测。缺少可比延迟的方案不进入三目标集合，Oracle 与依赖完美失败检测的结果仅作为诊断上界。

由此，静态阶段依据节点能力建立初始执行计划，反馈阶段修正后续选择的经验依据，异常阶段更新模型分配或局部结构，历史图复用减少重复计算，多目标规划在可比候选之间明确取舍。该方法将复杂任务内部的能力差异与执行过程中的不确定性共同纳入路由决策，同时保留每项决策所依赖的信息、资源成本和验证边界。

| 合并 | 210 | 41.9% | 300 | 33.3% | −3.8 pp [−10.5, +3.3] |

（协议异质性如实披露：TAT-QA 旧 40 链使用 gold facts、新 160 使用自身抽取；MultiHiertt 前 50 为 live 链、后 50 为节点表重放；单体对照仅在新采集任务上可用。）

**分解效应的方向由任务结构决定**。MultiHiertt 任务（层级表格、多实体定位、平均/百分比运算）单体几乎不可解（8%），分解带来 +14 pp 显著改善；TAT-QA 任务（扁平表、中位 2 步运算）单体已可直答（52.5%），而 DAG 链的表达式接口反而引入两类约束损失——19 个任务的链计算出原始比值后缺少百分比/千位缩放，另有若干表达式解析失败。逐题交叉表（160 题）：两法皆对 56、仅单体 28、仅链 32、皆错 44——**两种执行形态覆盖的任务集合部分不重叠**。

**核心洞见：任务分解本身应被视为一种需要决策的执行策略，而非固定预处理步骤。** 复杂度分层（按推导运算步数）显示分解收益随结构复杂度单调上升：1–2 步任务中 DAG 比单体低 6.6 pp，3 步 +10.0 pp，4+ 步 +20.8 pp；收益方向在约 2–3 步附近发生变化——由于中高复杂度样本仍有限（3 步 n=40，4+ 步 n=24），该位置应视为经验边界而非固定阈值。域内一致：MultiHiertt 全档正收益（层级任务始终值得分解）；TAT-QA 低档显著负、高档显著正（扁平任务仅在高复杂度时值得分解）。

**轻量结构选择器 g(x)（诚实报告）**：以运算步数、上下文长度、表行数为特征的 Logistic 5 折交叉验证选择器达到 36.9%，与 Always Monolithic 持平，Oracle Structure 为 49.2%——**群体层面的复杂度规律成立，但仅靠执行前表层特征的个体级结构选择仍然困难**。运算步数本身来自 gold 推导（部署时不可见），且单次执行的随机成败噪声进一步削弱了任务级标签的可预测性。该结果与全文"输入表象不含决策信息、执行过程信号才携带信息"的结构一致；可部署的结构选择需要更丰富的任务结构特征（表格层级、跨表标志、实体数、廉价规划器预测的子任务数），留作后续工作。

**DAG 执行结构质量的四维分析**（100 个 MultiHiertt 任务，规则评分）：本文从证据覆盖（Coverage，必需操作数是否出现在抽取事实中）、依赖有效性（Dependency，推理 v-引用是否落在实际抽取事实索引内）、节点可执行性（Executability，节点输出能否被解析并执行）与节点原子性（Atomicity，单节点最大运算步数）四个方面分析 DAG 执行结构质量。结果表明，**证据覆盖与最终执行正确性关联最明显**（Pearson 0.377；最终正确任务均值 0.935 对错误任务 0.351），说明上游信息缺失是影响后续 DAG 执行的重要因素；依赖有效性（0.290）与可执行性（0.281）次之，而单纯控制节点粒度（Atomicity 0.078）并不能保证执行效果。需要明确：Coverage 主要反映上游证据抽取质量，而非 DAG 划分方式本身，本文不将"证据覆盖"等同于"拆分质量"，也不主张"拆得越细效果越好"。

从查询级到类型先验的跃升贡献了主要增益（开发折内 +5.9 pp CI[+0.6,+8.0]；独立确认 +6.9 pp CI[+3.3,+10.1]，任务级配对区间均不含零）。在此之上，问题编码的额外增量在开发折内为 +1.6 pp，未迁移到确认集（修正口径下 0.00 pp）。因此本文不将贡献定位在学习节点表示，而定位在选择粒度的改变：将路由对象从完整问题下降到类型化节点，使模型间能力差异成为可利用的结构。问题编码作为实例化保留，其跨数据迁移局限如实报告。

**预算对等性**。查询级路由、类型先验与节点路由每节点恰好执行一次调用，决策粒度不同但调用预算相同；节点路由的增益（+6.90 pp）在等调用预算下取得，且每节点 token 更低（1765 vs 1801）。额外调用只在反馈回退（5.4）中出现，与选择粒度无关。

**路由分布**解释了增益的来源。静态节点路由在三种类型上分别集中选择该类型最优模型（extraction→large 191/193、reasoning→medium 73/100、verification→coder 176/200），即粒度改变使类型异构性直接转化为差异化分配；反馈阶段发生 230 次换模，主要将 extraction 从 large 移向 medium（191→115）并分散 reasoning 与 verification 的选择，对应执行记忆对类型内条件的修正。

资源口径上，Node Router 相对 Always Large 以更少 token（4856 vs 4991 / task）与更短服务时间（7.79s vs 11.71s / task）取得更高质量；类型先验不含每节点预测，无独立资源列。整体质量提升需结合类型内解释：优于全局固定模型不等于在每个类型上均优于该类型最佳固定模型。

**级联基线**。经典级联（cheap-first，失败升级：medium→large→coder）在理想失败检测下达到 0.6065（1.63× 调用、2930 tokens/node），高于完整反馈的 0.5842。两点界定其与本文方法的关系：其一，该数字依赖理想检测，实测检测质量下触发式升级同样受 5.4.5 所述检测瓶颈约束；其二，级联按全局成本排序换模，不考虑节点类型条件，其 token 开销（2930）高于反馈（2629），且不具备结构分解维度——5.4.3 中由分解独占恢复的失败不在级联的假设空间内。级联与节点路由回答不同问题（何时升级 vs 谁来执行），二者在此作为互补基线报告。

## 5.4 Failure Recovery and Budget-aware Escalation（真实失败恢复与预算感知升级）

静态分配无法处理执行失败。本节先定位失败来源（5.4.1），再给出 Static 与 Dynamic 两种执行模式的对照（5.4.2），分解各恢复组件的边际贡献（5.4.3），以理想组件替换量化系统瓶颈与潜力（5.4.4），最后给出检测门控、结构分解与预算升级的直接证据（5.4.5）。

本章核心实验链围绕以下递进式问题展开：

1. **阶段级互补是否存在？** → 节点基准：oracle +13.59pp，类型最佳互不相同
2. **同模型传播为何压缩互补？** → Cross-model 3×3 矩阵：extraction 质量主导（+10pp），reasoner 选择仅 +0.5–2pp
3. **跨模型节点组合能恢复多少？** → E_large→R_medium (20.0%) / E_large→R_coder (20.5%)，恢复部分互补性
4. **距离 Exact Oracle 还有多远？** → Exact Oracle 30.5% vs 最优固定组合 20.5%，剩余 10.0pp 为实例级空间
5. **Residual GAP 是否能稳定路由？** → 200 题正向 +22.2%，500 题未复现（−11.1%）
6. **为什么只能在低 coverage 安全利用？** → 5–10% coverage 安全区（GAP +7.4–8.6%，harm 0–1）；扩大后 false override 主导
7. **Dynamic 反馈能否进一步利用互补性？** → live ΔQ +2.1pp 不显著；受控故障 T3 净 +2——机制可执行但受覆盖率约束

### 5.4.2 Static vs Dynamic DAG（后继重调度机制对照）

**两种执行模式的对照实验**（100 任务确认集，条件化节点结果表回放：Q/C/L 取自实测节点×模型矩阵，失败触发读离线评分、后继节点处于标准输入条件；与 5.4 同一证据层级）。两臂共享 FrozenNodeRouter 初始分配与逐任务 token 预算（Static 实现成本 ×1.2）。Static：节点失败仅对当前节点做一次局部 fallback，后继维持初始计划；Dynamic：失败后更新（类型、模型）失败状态记忆，对失败节点做融合回退，并对其后继重调度——模型分配按失败记忆与冻结效用融合重选，上游失败时验证节点可在剩余预算内升级为更强验证模型，每次选择后重算剩余预算；**拓扑不变**。

**结论**：在共享初始路由与固定拓扑条件下，反馈驱动后继重调度能够稳定触发（26.3%，平均 0.43 个后继节点），并在 20% 预算余量下保持零预算违规；但任务质量与 Static DAG 无显著差异（41.0% 对 40.0%，ΔQ 95% CI 覆盖 0），不应表述为 Dynamic 更差。进一步分析表明，主要限制来自多模型共同失败以及可重路由空间有限。

**诊断**（同一 replay，零新调用）：(i) 任务级 Help/Harm 分解为 0/1/40/59（Static错→Dynamic对 / Static对→Dynamic错 / 皆对 / 皆错）——机制几乎不产生任务级翻转；(ii) 真正发生后继重调度的 25 个任务上 Static 与 Dynamic 质量均为 48%（未被稀释的 75 个任务为 37%）；(iii) 41 个被重调度后继中 65.9% 存在可重路由空间（模型池存在正确答案），在这些"原计划模型失败且存在替代"的 8 个节点上，**Dynamic 选中正确模型 8/8，Static 冻结回退仅 5/8**——调度器本身能把反馈转化为正确的后继调整，节点级选择并不差；(iv) 任务级收益为零的原因：决定任务成功的 reasoning 节点在两种模式下都已获得节点级回退，且后继节点处于标准输入条件（上游输出变化未真实传播，见下方证据层级声明）；(v) 唯一的 harm 任务来自失败状态记忆覆盖了冻结回退的正确选择（reasoning Q 向量 [0,0,1]，Static 回退选中 coder 成功，Dynamic 记忆回退选中 large 失败）——这直接指向 **Selective Dynamic Update**：只重调度真正受影响的 descendants，且不覆盖有正向证据的既定回退。

**Live Static vs Dynamic 对照**（48 个 TAT-QA 任务，策略冻结后真实执行，160 次调用；与回放不同，恢复后的真实输出真实传播给后继。诚实标注：该集合此前的诊断分析启发了后续 Dynamic v2 规则设计，故对 v2 而言它是 previously analyzed live confirmation set，不称 held-out）：两臂共享初始分配、prompt、模型池与逐任务预算（Static 实现成本 ×1.2）。结果：Q = 52.1% 对 54.2%（配对 ΔQ = +2.1pp，95% CI [−4.2, +10.4]，覆盖 0，不显著）；成本持平（+1.6 tokens）、时延持平（−0.06 s）；Help/Harm = 2/1；Dynamic 重调度在 52.1% 的任务上触发（24 次 reasoning 升级 large 全部在预算内执行），预算违规 0。失败归因：22 个双失败任务的链路合并后已尝试全部 3 个模型且在相同传播事实下全部错误——**模型池共同失败在真实传播下依然是主导约束**。按预注册三情形判定，本结果属于情形二/三边界：动态控制逻辑可执行（触发 52%、零违规、成本持平），端到端收益受模型池共同失败限制；Live Dynamic 到此为止，不再追加。

**Dynamic v2（选择性更新规则，dev 迭代 + confirmation 一次性执行）**：针对 Live v1 的唯一 harm（失败记忆覆盖有正向证据的冻结回退），在 33 个独立 dev 任务（与全部先前集合互斥）上迭代出四条调度规则——R1 正向证据锁（冻结回退无失败记录时不被覆盖）、R2 切换边际（δ=0.1）、R3 受影响后继门控（恢复输出未实质变化则保持 Static 分配）、R4 能力画像评分（rank − γ·失败数，γ=1）。策略以单一共享函数实现（policy hash 8ee21689…），dev 与 confirmation 共同 import，9 项构造状态单元测试 + dev 记录重放逐决策一致后才执行。

| Dynamic v2 | 54.2% | 1400.6 | 1 / 0 | 0 |

**结论**：Dynamic v2 通过正向证据保护、受影响后继门控、关键节点优先和能力画像重路由，降低了反馈驱动重调度带来的负迁移风险。在较小的 confirmation set（48 任务）上出现正向信号（+2.1pp，CI 覆盖 0），同时将 harm 降为 0；但在更大的确认集上（500 题）该收益未能复现（GAP Recovery = −11.1%）。因此实例级 residual routing 的泛化收益不稳定，本文将其作为方向性正信号报告，不作为已验证的主结论。

**两条边界如实保留**：(1) 该 48 任务集合为 previously analyzed live confirmation set（其诊断分析启发了 v2 规则设计），不是 untouched held-out test set；(2) v2 策略整体经等价性验证（policy hash 8ee21689…），但其中 coder→large 的 hysteresis 切换分支在 dev 数据中从未被触发，该分支只有定义与一致性验证、没有独立实证支持，论文不对其单独作效果声明。

**证据层级小结**：回放对照证明调度器节点级选择正确（headroom 节点 8/8 对 5/8）；Live 对照以真实传播验证端到端（触发 52%、零违规、ΔQ 不显著）。两个层级一致地指向同一结论：调度机制可执行且预算纪律良好，端到端收益的上限由模型池共同失败（动作/能力覆盖率）决定，而非调度策略本身。

### 5.4.5 检测门控与结构分解

**验证器敏感性**（节点级回放）：以实测混淆矩阵驱动回退触发，扫描错误召回率——0.27（实测）→ 0%，0.60 → 6.3%，0.80 → 15.6%，0.95 → 18.7%（与类型门控实测锚点吻合）；误报率 0.40 时恢复率为 −40.6%。检测质量为自适应执行定价，且该定价在任务级受限于失败的可恢复性本身。

**类型门控**（节点级回放，扩展口径）：无验证器 0.5355 / 全局验证器 0.5355（231 次重路由、50 次误触发，净增益为零）/ 类型门控 0.5477（186 次重路由、误触发 35、漏检 6）。门控将干预限制在检测可靠的 verification 类型上，把净恢复率从 0% 提升至 28.6%。

**结构分解**（困难 reasoning 节点，真实调用，两域）：扩展表达式语言后直接重问 0/20；failure-aware 分解（报告对齐 → 关系规划 → 表达式 → 检查）在节点隔离基准的 gold-facts 条件口径下，两批共 60 个全模型失败节点中 19 个生成表达式可由 gold facts 计算到标准答案（19/60=31.7%；本规模批 13/40，MultiHiertt 7/24、TAT-QA 6/16；初步证据 6/20）。固定三段模板历史参考 0/10。**端到端判据复核（本次审计）**：该口径衡量"给定黄金证据时能否写出正确表达式"，并非端到端恢复——把 13/40 规模批的分解表达式在真实抽取事实上重算，仅 1/13 仍正确（4 个算错、2 个 v-引用索引错、6 个无抽取记录）。因此 31.7% **作为端到端恢复率结论撤回**，降级为表达式级能力观察；分解适用域的证据组织类定性结论（裸事实丢失实体/期间分组语义，关系推理类失败 0/10）不变。附带发现是表达式语言本身：常数白名单使平均类问题结构性不可表达，本节全部机制比较在扩展执行器下进行以避免把语言修复误归因为分解效果。
### 5.4.6 Budget-aware Escalation and Termination

**预算感知升级实验**（116 个判据纯净真失败，冻结 counterfactual，零新调用）：以剩余预算 \(B^{\rm rem},T^{\rm rem}\) 过滤可行动作后按序执行。时间预算网格显示：\(T^{\rm rem}\le0.5\) s 时仅 retry/switch 可行（Q=1.7%）；\(\le1\) s 时 retrieval/decompose（实测 2.7–4.8 s）不可行，上限为 retry→switch（3.5%）。token 预算从 1200 放开到无限，Q 仅从 3.4% 升至 6.9%（=oracle），成本从约 500 涨至 6332 tokens；恢复效率从 0.063 降至 0.011 恢复/千 token（约 6 倍差距），oracle 以 1/47 的成本达到同一上限。λ/μ 敏感性（\(U=Q-\lambda C-\mu L\)）中，昂贵动作在任何非零成本/延迟权重下均不占优，多数权重下 retry-only 最优。结论：**并不是恢复越复杂越好**——在动作收益很低时，应根据剩余预算控制升级深度，必要时提前终止。

### 5.4.8 Local Subgraph Replan（开发 pilot，NO-GO，未来工作）

**局部子图重规划**（40 节点 dev 真失败集，与冻结 116/pool/pilot/decompose 集全部互斥，判据纯净；336 次真实调用）：模型把剩余计算规划为多步原子子图（s1..sk 确定性逐步执行 + 最终表达式），步骤失败时允许一次证据修复并重规划，改写失败节点及其受影响后继。结果：replan 恢复率 2.5%（1/40），且该节点本可被 retrieval 救回——**动作集 oracle 覆盖率 10.0%→10.0%，净增 0 节点**；replan 平均成本 5931 tokens（约为 decompose 的 2.3 倍），33/40 需要二次规划、29/40 执行器错误。按预注册判据（净增 >2 节点才继续）判定 **NO-GO**：局部子图重规划未扩大恢复动作覆盖率，作为未来工作保留，不再对冻结 116 测试。该负结果与 5.4.4 的 oracle 瓶颈一致：当前恢复上限由证据获取与计算能力决定，而非图的拓扑形状。

## 5.5 Dependency-aware DAG Reuse

多轮任务中，追问通常只改变历史任务的一部分。本节检验依赖感知的局部复用（非输出缓存）：历史图保存节点、边、依赖与版本，修改发生时定位受影响子图，仅重算其后继。实验为 20 个追问任务（原始材料不变、首个事实假设 +10%），历史抽取子图零调用保留，仅重执行推理与验证。

表 5-8　追问场景复用经济学

| 指标 | 结果 |
| --- | --- |
| Reuse Rate | 50%（每任务 2 个抽取逻辑节点） |
| Call Reduction | 50% |
| Token Reduction | 91.4% |
| 新链可执行 / 响应修改 | 19/20 / 19/20 |

与输出缓存的区别是结构性的：任何输入修改都使输出缓存失效并触发全链重算（等价于不复用），而依赖感知复用将重算范围收缩为 \(\Delta V \cup \mathrm{Desc}(\Delta V)\)。token 降幅（91.4%）大于调用降幅（50%）的原因是工作负载结构：被跳过的抽取节点承担长报告上下文的处理，重算节点只消费短事实表示。两项口径限制保留：调用基线按逻辑链记录（非严格物理去重）；token 对照为历史记录对新调用（非同轮对称实验）。结果响应修改（19/20）是执行行为指标，不构成独立答案正确率证据。

**记忆保留策略（剪枝）**：图森林不是无限增长的存储，而是带依赖、带版本、带质量记录的执行经验库，配三条保留策略——(i) 时间剪枝：超出保留窗口未被检索引用的整图淘汰；(ii) 质量剪枝：使用次数 ≥3 且记录成功率 <0.5 的节点移出复用候选集（保留版本历史，仅取消复用资格）；(iii) 相似合并：同构子图合并并保留最高质量版本。当前存储规模（2 图 / 6 节点 + 版本）下三条策略均不触发，作为设计规范声明而非实验声明。

## 5.6 Budget-aware Multi-objective Execution Optimization

本节将资源决策组织为系统决策层。执行策略定义为配置组合

\[
\pi = (\text{模型分配},\ \text{反馈开关},\ \text{恢复机制},\ \text{复用开关}),
\]

五个固定策略（Always Medium/Large、Static、Feedback、Full）由 live 执行实测；在逐任务实测结果表之上，进一步构造**两类自适应策略**——预算自适应（每任务按其预算 \(B_i\) 选择可行集中质量最高者）与难度自适应（按到达时可观测的上下文规模分档选择 static/feedback/full）。所有混合策略的每个组成单元均为真实执行结果，无任何估计。给定预算约束的部署规则为

\[
\max_{\pi} Q(\pi)\quad \mathrm{s.t.}\quad \mathrm{Cost}(\pi)\le B.
\]

表 5-9　live 实测成本与质量（50 任务，固定策略）

| 策略 | Task Success | Tokens / task | 调用 / task | 服务时长（s） |
| --- | --- | --- | --- | --- |
| Always Medium | 16% | 4610 | 2.0 | 318 |
| Always Large | 24% | 4477 | 2.0 | 319 |
| Static | 24% | 4484 | 2.0 | 332 |
| + Feedback | 28% | 4959 | 3.7 | 368 |
| Full Adaptive | 34% | 5637 | 4.1 | 414 |

| 每任务预算 B | Task Success | Tokens / task | 相对固定 Full |
| --- | --- | --- | --- |
| 4,500 | 30% | 4,533 | −19% tokens / −4 pp |
| 4,800–5,000 | 32% | 4,545–4,565 | −19% tokens / −2 pp |

| ≥5,600 | 34% | 4,590 | −19% tokens / 0 pp |

关键结果：**预算自适应在 B≈5,100 时即达到固定 Full 的 34% 成功率，同时节省 19% tokens**。其机制是逐任务成本结构的重尾性——Full 的每任务成本中位数为 4,924、p75 为 6,565、最大 10,702：预算自适应将 20 个超预算任务的昂贵执行替换为该预算内质量最优的廉价执行（多为 Static/Feedback），其中仅 1 个任务因此损失成功率（该任务 Feedback 亦失败，属于多模型共同失败类）。**这一"近零损失的成本削减"只有逐任务决策层才能实现**，是任何固定策略（包括 Full 自身）在平均成本上无法做到的。

**难度自适应策略**（按到达时可观测的上下文规模分档）：以 log 上下文长度的分位数为阈值切换 static→feedback→full，最优混合达到 28% / 5,138 tokens——与固定 Feedback 相当而不及预算自适应。仅用到达时特征预测任务难度不足以指导分级，印证 5.4.4 的结论：失败可恢复性由执行过程而非输入表象决定。

**非支配前沿**（固定策略 + 全部自适应策略，共 21 个实测组合点）：{Always Large (4,477, 24%), B=4500 (4,533, 30%), B=4800 (4,545, 32%), B≥5100 (4,566–4,591, 34%)}——**预算自适应策略全面替代了固定 Feedback 与固定 Full 的前沿位置**。以同一最劣参考点 (5,644, 16%) 计的二维 Hypervolume 由固定策略的 174 提升至 204 token·success 单位。策略空间为离散实测组合，穷举筛选在该规模上即为完备精确方法；扩展到组合级空间时才需要显式搜索程序（本文不引入）。

**预算模块消融**（无预算选择 vs 预算选择，同一实测组成）：

| 策略 | Success | Tokens / task | Service s / task |
| --- | --- | --- | --- |

| Fixed Feedback（无预算） | 28% | 4,966 | 7.4 |
| **Budget Adaptive（B=5,200）** | **34%** | **4,494** | **6.5** |

预算选择模块本身贡献：**0 pp 成功率损失下 −20% tokens、−22% 服务时长**（相对 Always Full）。组成（50 任务）：26 个任务预算内直接选 Always Large 或 Static 即可保住成功率，12 个高成本任务被降级到 cheaper 策略（其中 11 个在所有策略下均失败——多模型共同失败类，降级无损），1 个保留 Feedback。该消融证明收益来自**决策层**而非任何单一执行臂：固定地选最贵臂（Full）或中间臂（Feedback）都无法同时达到该成本-质量组合。

**可部署控制器（诚实协议）**：为界定预算自适应中逐任务可行集选择的 oracle 成分，比较三层控制器。(i) **到达时特征控制器**（严格 held-out 25/25，Logistic 与深度-3 树）：B=5,200 下 24% / 4,704 与 20%——均低于无预测器的均匀规则（28% / 4,966），到达时特征不含策略选择信息。(ii) **执行感知控制器**（零估计重放）：先执行 Static，以真实 coder 验证器对 Static 输出的判定与解析结果为升级信号（无值或验证拒绝 → 升级 Full）。结果：**34% / 5,354**（仅升级 15–18 个任务）——达到 Full 与 oracle 上界的成功率，成本介于均匀 Feedback 与 Full 之间，**优于所有固定策略与到达时控制器**，且每个信号均为真实执行产出。(iii) **oracle 上界**：34% / 4,494。

| 控制器 | Success | Tokens / task | 信号来源 |
| --- | --- | --- | --- |
| 均匀规则（B=5,200） | 28% | 4,966 | 无 |
| 到达时特征（held-out） | 24% | 4,704 | 输入表象 |
| **执行感知（Static→验证→升级）** | **34%** | **5,354** | 执行过程 |
| 逐任务 oracle 上界 | 34% | 4,494 | 不可得 |
| 固定 Full | 34% | 5,644 | — |

三层结果与全文主线一致：**输入表象不含决策信息，执行过程信号才携带**——执行感知控制器捕获了 oracle 上界与均匀规则之间差距的大部分（成功率 +6 pp），剩余 token 差距（5,354 vs 4,494）来自验证器误拒引发的 10 次多余升级，即 5.5 所量化的验证可靠性瓶颈在决策层的直接代价。

**升级策略消融**（同一重放协议，隔离"信号"与"预算"两个成分）：

| 策略 | Success | Tokens / task | 升级数 | 效率（pp / 千 token） |
| --- | --- | --- | --- | --- |
| A：全 Static（无反馈） | 24% | 4,484 | 0 | 5.35 |
| B：随机 20% 升级（3 seeds） | 24–26% | 4,680–4,803 | 9–12 | 5.00–5.56 |
| Full（全升级，无信号） | 34% | 5,644 | 50 | 6.02 |
| **C：执行感知升级** | **34%** | **5,449** | **18** | **6.24** |

随机升级（同预算量级）只能回收信号价值的 0–2 pp，而执行感知升级回收全部 10 pp——**收益来自信号而非额外预算**。执行感知升级同时具有全表最高效率（6.24 pp / 千 token）：相对全 Static 用 +21% tokens 换 +10 pp 成功率，每一千 token 的边际产出高于任何固定策略（Static 5.35、Feedback 5.64、Full 6.02、Always Large 5.36）。

**失败感知升级（负结果与上界）**：将预算决策升级为"先执行 Static，按失败信号升级到 Full"的两级策略。升级信号全部失效——路由预测质量 Q̂ 对 Static 失败的判别 AUC 仅 0.29（反向），解析失败标志 AUC 0.54（随机）；任何有效阈值实际升级全部 50 个任务。**升级空间的 oracle 上界**：Static 失败的 38 个任务中 Full 仅能救回 5 个（86.8% 为多模型共同失败），精确升级的上界为 34% / 4,778 tokens——不支配预算上界（34% / 4,494）。不存在可被**到达时**信号识别的"需要 Full"子群；执行感知控制器之所以有效，正在于它把判别信号从输入表象换成了验证器对实际输出的判定。

**单位成本收益**（固定策略阶梯）：反馈 +4 pp / 475 tokens = 8.4 pp 每千 token；结构恢复 +6 pp / 678 tokens = 8.8 pp 每千 token；边际平坦（8.4–8.8），说明更高预算买入的是不同机制的接入而非同一机制的递减加量。预算自适应在此基础上提供了**机制选择之外的逐任务粒度节约**（−20%），两者正交（预算–成功率曲线见附图 `budget_success_curve.html`）。

## 5.7 Live End-to-End Evaluation

最后，全部模块在同一 50 个确认任务上真实执行：DAG 构造 → 节点路由 → 执行 → 反馈记忆 → 验证器 → 失败诊断 → 重路由/分解 → 最终答案。三臂策略共享执行缓存（相同节点-模型组合只计费一次）；失败检测为真实 coder 验证器判定，记忆仅由可部署信号（判定结果）更新，评分离线对 gold 进行。

表 5-11　live 三臂综合（与 5.7 同一实验，含 bootstrap 95% CI）

| 方法 | Task Success [CI] | 严格恢复率 | 破坏数 |
| --- | --- | --- | --- |
| Static（Node Router） | 24% [12, 36] | — | — |
| + Feedback | 28% [16, 40] | — | — |
| Full Adaptive DAG | 34% [22, 48] | 5/38 = 13.2% | 0 |

配对差异：Full−Static = +10 pp CI [+2, +18]（区间不含零）；Full−Feedback = +6 pp CI [0, +14]；Feedback−Static = +4 pp CI [0, +10]。后两个差异在 50 任务下为边缘显著，方向一致但需要更大样本确认——这一不确定性如实报告，不因点估计递增而声称各层增益均已统计确立。

综合叙事：**实际能力 34%，理论潜力 50%（表 5-7），16 pp 差距的 12 pp 来自上游抽取、其余来自多模型共同推理失败**。组件边际（+4/+0/+6）与失败归因（抽取 18 / 公式 15）共同解释了这一数字的构成；每个百分点均有实测成本标注（表 5-9）。零破坏（Full 未使任何 Static 成功任务失败）与 13.2% 严格恢复率共同刻画了恢复的收益边界。4 个任务因抽取解析失败使用了 gold 事实接口回退，已披露；验证器 61% 的判定不一致率是当前反馈回路的主要噪声源，也是后续工作的第一优先级。

本章最强独立证据仍是冻结节点路由：相对查询级路由 +6.9 pp（两种评分口径下一致），并以更低 token 与服务时间取得。反馈、恢复与复用各自补充了静态选择无法覆盖的执行维度；系统整体的实际能力由错误传播链而非单一模块决定——这正是把复杂任务多模型执行建模为显式 DAG 并逐组件诊断的价值所在。

# 6 Discussion

## 6.1 主线发现：调度可以更安全，但不能创造能力

全部实验收敛到同一个结论：**动态调度能够更安全地利用已有模型互补性，但在当前模型池的能力覆盖范围内，性能提升空间有限。**

这条结论由三个相互独立的证据层支撑。第一层是 Live 端到端对照（48 任务，真实执行、真实传播）：Static 52.1%、Dynamic v2 54.2%，配对 ΔQ = +2.1pp 且 95% CI 覆盖 0；Dynamic v2 将 harm 降为 0、预算违规为 0、成本与 Static 持平（1400.6 对 1402.2 tokens）。第二层是机制诊断（回放层级）：后继重调度在存在可重路由空间（原计划模型失败且模型池存在正确替代）的节点上，选中正确模型 8/8，优于 Static 冻结回退的 5/8——调度策略本身能把反馈转化为正确的模型选择。第三层是覆盖率核算：116 个判据纯净真失败上，四种恢复动作全部执行的 oracle 上界仅 6.9%，且 22 个双失败任务在真实传播后由两臂链路合并尝试了模型池全部 3 个模型、全部错误。三层合起来解释了为什么 ΔQ 不显著：不是调度器不会选，而是选择空间本身不存在。

## 6.2 为什么"更强的动态"没有带来"更高的质量"

Local Replan 开发实验（40 节点，改写失败节点及其受影响后继）净增覆盖 0 节点；预算网格显示从低成本恢复升级到全动作执行，质量 3.5%→6.9%（恰为 oracle），成本约 500→6300 tokens（效率约 6 倍差距）；λ/μ 敏感性中昂贵动作在任何非零成本/延迟权重下均不占优。失败归因显示双失败任务的主导原因是模型池共同失败（同一事实上初始与回退模型皆错）与上游证据缺失（oracle extraction +12pp 是系统最大的单一瓶颈）。这些结果共同说明：**在模型池能力覆盖不变的前提下，恢复侧的策略改进只能重新分配已有互补性，不能创造新的互补性**。因此本文将 Dynamic 的定位从"提高准确率的手段"修正为"在预算约束下安全利用互补性、避免负迁移的控制机制"——Dynamic v2 的价值正是把 harm 降为 0 而不损失质量、不增加成本。

## 6.3 判据纯度：一个被低估的方法学问题

本研究在审计中发现并修正了一个系统性偏误来源：以中间缺陷指标（如抽取操作数不完整）作为失败判据时，大量"潜伏缺陷但最终答案本就正确"的节点会进入失败池，使恢复率被虚假抬高（表观恢复 34 例中 32 例原始终答本就正确；早期文献中 31.7% 的分解恢复率在真实抽取事实上复核后仅 1/13 成立，已撤回）。本文因此将恢复实验的触发条件固定为**最终执行结果真实错误**，并以 retry 等价性审计（同配置重执行 66/69 逐字节复现、非确定性仅 4.3% 且零恢复）排除了"重跑即救"的替代解释。我们建议动态恢复类研究将"真实失败触发 + 判据纯度复核"作为标准报告项。

## 6.4 与老师七个问题的对应

RQ1（拆分）：分解收益呈域依赖与复杂度依赖（MultiHiertt +14pp、TAT-QA 低档 −9.4pp、4+ 步 +20.8pp）；结构质量四维分析表明证据覆盖与最终正确性关联最强（Pearson 0.377），但 Coverage 反映上游抽取质量，不等同于拆分粒度。RQ2（多目标）：Q/C/L 统一度量 + 预算网格 + Pareto + λ/μ 敏感性，阈值由预算/SLA 约束外生决定。RQ3（剩余预算）：B_rem/T_rem 过滤可行动作，T_rem ≤ 1s 时昂贵恢复不可行，预算内升级与终止由数据支撑。RQ4（故障分析）：其价值在于判定真实失败、量化恢复覆盖上限、指导是否继续投入。RQ5（Dynamic DAG）：定义为反馈条件化的后继重调度（拓扑不变），机制健全性由 replay + live 双层验证；修改拓扑的 Local Replan 判定 NO-GO。RQ6（创新）：结构感知执行 + 真实失败触发 + 预算感知选择性重调度，而非"失效类型决定专属动作"。RQ7（Graph Forest）：复用与版本化已实现，剪枝为设计而非本文核心实验结论。

## 6.5 统一机制解释：从条件能力到传播能力

三组独立实验揭示了一个统一的机制：**模型互补性在条件节点层面清晰可测，但在真实传播后被上游抽取质量差异掩盖**。

条件节点评估（gold facts）下，Node Router 可恢复约 50% GAP（类型级模型异质性稳定）；传播口径下，共同失败占主导（900 题开发语料中 77.0% 任务全模型皆错；200 题确认集为 76.5%），oracle gap 缩小至 5pp。Cross-model 3×3 矩阵精确定位了机制：E_large→R_medium (20.0%) > E_medium→R_medium (10.0%)（+10pp），说明 **medium 的推理能力被自身弱抽取掩盖，而非互补性消失**。当抽取质量被 large 固定后，medium 和 coder 的推理互补性重新浮现。

因此，**分解为 DAG 的价值不在于"拆分本身提高性能"，而在于解除模型能力之间的绑定**——让最适合抽取的模型与最适合推理的模型可以独立组合。

## 6.6 Residual GAP 可学习性

在 1600 题（900 dev + 200 conf + 500 conf500）上，residual GAP 的可利用性呈 coverage-dependent 特征：5–10% coverage 下 GAP Recovery 为 7.4–8.6% 且 harm 极低；coverage 扩大后 false override 急剧增加。Oracle 上界仅 6.9%（116 真失败），表明**当前模型池的能力覆盖率是全部恢复策略的硬上界**。

四级机制链：

$$ \text{Stage-wise complementarity exists} \Downarrow \text{Propagation noise masks part of it} \Downarrow \text{Selective routing exploits only limited residual gap} \Downarrow \text{For hard all-fail cases, capability coverage becomes the dominant ceiling} $$

三级结论：
1. 条件节点环境下模型互补性可学习（Node Router ≈ 50% GAP Recovery）
2. 真实传播压缩可利用互补空间（oracle gap 5pp；1600 题合并语料共同失败 76.7%）
3. Residual GAP 的实例级可预测性有限（AUC 0.75–0.84 但不转化为选择收益），保守选择性切换（Two-stage τ=0.5）在 200 题确认集与 dev 交叉验证上呈方向性正信号（+22.2% / +4.4%，零 harm），但 500 题确认集未能复现（−11.1%）——泛化不稳定，仅作方向性证据

**D0–D4 诊断边界**：在所分析的 all-fail 子集上，进一步改善 evidence retrieval、selection 和 routing 并未带来稳定收益；即使在 gold facts 条件下，最终正确率仍仅为 31%，说明当前模型池的推理能力覆盖构成主要剩余瓶颈。此结论限于所分析的 all-fail 子集，不扩展为整个任务分布的绝对结论。

## 6.7 局限

(1) 任务域以财务表格问答为主，跨域泛化未验证；(2) Live Dynamic 对照为 2 节点链（抽取→推理），更深的后继链尚未在 live 层级验证；(3) 48 任务为 previously analyzed live confirmation set，其诊断启发了 v2 规则设计，不构成未接触留出集；(4) v2 的 coder→large hysteresis 切换分支未被 dev 数据触发，仅有定义与一致性验证；(5) 回放层级实验使用条件化节点结果表，后继节点处于标准输入条件，已与 live 层级显式区分；(6) 成本为 token 计量与本地服务时延，未建模货币价格；(7) 恢复动作覆盖上限的结论限定于当前 3 模型池与冻结 prompt，扩池（更强模型、工具增强）是突破上限的自然途径，留作未来工作。


## 6.8 四条核心结论

1. **Conditional capability ≠ propagated capability。** 条件节点评估下模型互补性明显（oracle +13.59pp），传播后互补空间被上游错误压缩至 5pp——两者测量的是不同的能力维度。

2. **Predictability ≠ routability。** 单模型成功倾向可预测（AUC 0.75–0.84），Residual GAP 也存在部分可利用信号，但这种信号只能在低覆盖率的选择性路由区域（5–10%）安全转化为收益；扩大覆盖率后泛化不稳定。

3. **Stage-wise complementarity is real。** Cross-model 3×3 矩阵表明，当抽取质量被固定（E_large）后，medium 和 coder 的推理互补性重新浮现——阶段互补性是真实的，只是被同模型绑定掩盖。

4. **Selective adaptation is safer than aggressive switching。** Two-stage 在较小 confirmation set 上出现正向信号（harm=0），但在更大的 confirmation set 上未复现；相比之下，激进切换（135 次 Capability Router 切换）导致 harm 4.5%。**少而准的切换比多而激进的切换安全，但泛化收益仍不稳定。**

**最终结论**：动态调度能够更安全地利用已有模型互补性，但不能突破模型池本身的能力覆盖上限。当前系统的主要限制不再是单纯的路由错误，而是模型池在困难任务上的共同失败。未来提升应优先扩展执行能力覆盖，例如引入更强推理模型、符号执行器和工具增强，而非仅增加调度复杂度。

# 7 Conclusion

本文面向复杂任务的多模型执行问题，提出并系统评估了反馈驱动、预算感知的自适应 DAG 执行框架。框架以模型能力画像支撑节点级控制路由，以显式 DAG 组织任务分解，以 Static / Dynamic 双模式处理执行失败，以图森林支持历史复用，并在质量、成本、时延的多目标约束下选择执行策略。

主要结论有四。第一，模型能力在节点类型间存在稳定的异质性（抽取/推理/验证的最佳模型互不相同，条件口径节点 oracle 相对最佳单模型 +13.59pp），使节点级协同路由相对查询级路由取得 +6.9pp 的可复现增益；同时任务分解的收益依赖域与复杂度，分解应被视为一种需要决策的执行策略而非固定预处理。第二，**条件能力不等于传播能力**：条件口径下清晰的类型级互补性，在真实传播后被共同失败压缩（900 题开发语料中 77.0% 任务全模型皆错，可利用 GAP 收窄至 5pp）；跨模型 3×3 矩阵证明上游抽取质量是主导因素（E_large→R_medium 20.0% 对 E_medium→R_medium 10.0%）——阶段互补性真实存在，只是被同模型绑定掩盖。第三，在真实失败触发与判据纯度审计的前提下，Static 与 Dynamic 两种执行模式的端到端质量无显著差异（52.1% 对 54.2%，+2.1pp，CI 覆盖 0），但 Dynamic v2 通过正向证据保护、受影响后继门控与能力画像重调度，将错误动态调整（harm）降为 0 并保持零预算违规与持平成本——反馈驱动重调度的主要价值在于执行的安全性与稳定性；同时选择性适应优于激进切换（Two-stage 4 次切换零 harm，对 Capability Router 135 次切换 harm 4.5%），残余 GAP 仅能在低覆盖率选择性区域（5–10%）安全转化且在第二确认集未复现。第四，恢复实验量化了框架的边界：在 116 个判据纯净的真失败上，四种恢复动作的 oracle 覆盖上界仅 6.9%；失败的主导形态是模型池共同失败与上游证据缺失（oracle extraction +12pp）。**动态调度能够更安全地利用已有模型互补性，但不能突破模型池本身的能力覆盖上限**——当前瓶颈已从路由错误转移为模型池在困难任务上的共同失败。

上述结论对系统设计与实践的含义是：失败后的恢复决策应当以"是否存在可重路由空间"和"剩余预算是否允许"为第一判据，采用低成本恢复先行、条件升级、及时终止的分级策略；盲目堆叠更复杂的恢复结构（如局部子图重规划，本文开发实验净增覆盖为 0）既不能突破覆盖上限，还会放大成本与负迁移风险。

未来工作按优先级排列：(1) **扩展模型池的能力覆盖**——在共同失败主导的瓶颈下，引入更强推理模型、符号执行器或工具增强（确定性计算、表格结构化检索）是扩大恢复覆盖的根本途径，并应在新的 dev/test 失败集上按本文的判据纯度协议重新评估；(2) 将 Live Dynamic 对照扩展到更深的后继链与多域任务，检验选择性重调度在真实传播下的规模效应；(3) 在具备真实追问负载的场景中验证 Graph Forest 复用与剪枝策略的质量—成本收益；(4) 将恢复决策从实测查表升级为覆盖可恢复性特征的学习型策略，前提是可恢复正样本规模先经动作覆盖扩展而增大；(5) 建立货币化成本模型与端到端时延的在线测量，使多目标权衡可在真实部署约束下复现。

本文的全部实验遵循冻结口径与判据纯度审计：恢复实验以最终执行结果真实错误为触发条件，方法代码经哈希核验，策略以单一共享实现并通过等价性测试，正负结果均如实报告。我们希望这种"先审计判据、再度量收益"的评估方式，对动态恢复与多模型协同方向的后续研究有方法学参考价值。
