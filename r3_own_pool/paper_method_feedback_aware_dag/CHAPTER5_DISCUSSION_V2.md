# 5 讨论

> V2 草稿,2026-09-25。依据:PAPER_EVIDENCE.md / FROZEN200_RESULTS / FROZEN200_DIAGNOSTIC /
> EXACT_PARETO / POOL_ANALYSIS / 全部修正后数据。术语与主张强度遵守 TERMINOLOGY_FROZEN。

本章围绕四个问题讨论实验证据的边界与含义:(1)本文方法的核心价值是什么;(2)当前的主要
瓶颈在哪里;(3)在什么条件下多智能体协同调度值得采用;(4)后续研究方向。

## 5.1 恢复能力存在,但无差别干预引入损害

本文最重要的机制发现来自独立冻结面板(Frozen 200)的分层诊断:Dynamic DAG 的恢复
能力与干预损害同时存在,二者几乎完全抵消。

在 30% 能力型故障下,Single LLM 的 110 个 clean 正确任务中有 31 个被故障破坏
(存活率 71.8%)。Dynamic 在这 31 个受损任务上修复了 15 个(恢复率 48.4%),显著
优于 Static(存活率 0–25%)。然而,在 79 个 Single 仍然正确的任务上,Dynamic 的
重执行破坏了其中约 25%,导致总体优势仅为 +0.7 个百分点(0.4033 对 0.3967)。

这一发现界定了当前方法的真实瓶颈:**不是恢复能力不足,而是对"何时值得启用恢复"
缺乏准确预测**。事后选择性调度上界(Selective Scheduling Oracle,使用事后标签)
达到 50.5%,比 Always-Single 高 10.8 个百分点、比 Always-Dynamic 高 10.2 个百分点。
该上界证明存在显著的任务级选择空间,但不可直接部署——它依赖"哪些任务在 Single 下
会存活/受损"的事后信息。本文的 Pareto-aware 调度器正是在这一方向上的初步尝试,以
(故障风险, 预算)状态在前沿内选择策略,在 32 个已测状态上逐点不劣于任何固定策略。

因此,后续工作的核心方向不是把 Dynamic 从 40%提升到 42%,而是开发准确的任务级
干预决策——即 Selective Collaborative Scheduling。

## 5.2 大组合空间不等于非平凡有效优化空间

第 4.4 节的精确 Pareto 实验(18 个配置、穷举)揭示了一个结构性事实:在当前模型池、
任务面板和故障模型下,节点模型分配 (m_r, m_v) 对平均质量几乎没有影响——9 个无恢复
配置 Q 完全相同(0.3500),8/9 个有恢复配置 Q 差不超过 1.7 个百分点。有效的决策
维度坍缩为恢复策略 Z 的二元选择(启用/不启用),形式前沿的三个配置中两个高质量点
成本差仅 2 tokens(ε_C=0.1% 时坍缩为 2 点)。

这意味着:Large combinatorial configuration space ⇏ non-trivial effective optimization
space。在受限子空间内,精确枚举已能找到全部非支配配置,复杂搜索算法(如 NSGA-II)
在这个空间中不必要。第二篇工作若要做自动 Pareto 搜索,应扩展真正可变的维度——
执行拓扑 Y(DAG 结构、节点数、分解深度、并行/串行关系、验证位置、恢复边)——
而不是继续在 X(节点模型分配)上搜索。

## 5.3 协同调度的适用条件

综合全部实验证据,多智能体协同调度(特别是带反馈恢复的 Dynamic DAG)在以下条件
同时满足时具有部署价值:

**(1)故障风险非平凡。**Clean 条件下 Single LLM 以最低成本占优(0.5500/603 tokens),
对两种 DAG 策略构成帕累托支配;Dynamic 的质量收益在 clean 下不显著(+5.0pp,p=0.109)。
只有当持续性能力故障存在时,Dynamic 的恢复优势才体现(vs Static 零伤害配对 +8 至 +12pp,
p<0.001)。

**(2)反馈可诊断。**恢复的先决条件是故障能被部署可得信号检测到。执行级失败(表达式
不可执行、输出不可解析)的检测 F1 为 0.78–1.00;推理级错误(可执行但结果错误)对基础
信号召回为 0。跨域证据一致:MBPP(单元测试反馈)上 Dynamic +6.0pp,Math500(parse/
一致性信号覆盖不足)上 Dynamic 仅 +1.0pp。

**(3)恢复动作有效。**即使检测到故障,恢复也受限于模型池中是否存在能解决该子任务的
替代模型。固定动作覆盖实验(116 节点)显示并集仅 6.9%;Frozen 200 诊断中 v 节点故障
的恢复率仅 15.4%(vs e/r 节点 31–33%)。

**(4)干预收益大于干预成本。**这是 Frozen 200 揭示的第四个条件——也是最容易被忽视的。
Dynamic 的重执行不是免费的:在不需要恢复的任务上,干预本身引入 25%的损害。当受损
任务的基率较低(Single 存活率 71.8%)时,恢复收益无法覆盖干预成本。

## 5.4 方法论反思:两次数据修正的教训

本文经历了两次数据完整性修正,均在论文定稿前自行发现并完整留痕(附录):(1)v 节点
评分解析缺陷导致全部 120 个初始验证输出被误判为不可解析;(2)多种子故障注入实现中
的去重缓存使静态臂的整图重执行意外命中 clean 输出,故障被"治愈"。两次修正共同
说明:在依赖真实 LLM 调用的实验中,执行日志的 (model, prompt) 级别审计与逐层
一致性检查不可省略;预注册协议与冻结面板是防止确认偏误的必要手段,但只有配合
执行后的独立验证(如 Frozen 200)才能提供完整的可信度链条。

## 5.5 局限

1. **单领域主面板。**核心故障证据来自 TAT-QA 财务表文推理;Math500 与 MBPP 提供了
   跨域边界参照(100 题各),但未重复完整的三种子故障协议。
2. **模型规模与栈。**全部结果使用本地 Qwen2.5 7B/14B(-GPTQ) 模型与单卡 24GB GPU;
   14B-GPTQ 存在约 10% 的会话级输出非确定性(温度 0),该噪声已量化并纳入解释边界。
3. **故障覆盖。**能力型故障模型覆盖"指定模型对指定子任务持续失败"的情形;瞬态
   故障(按构造可由重试恢复)与对抗性故障不在覆盖范围内。
4. **调度器的选择信号。**Pareto-aware 调度器使用 (故障风险估计 p̂, 预算 B) 作为状态,
   其中 p̂ 在评估中取真实注入率;部署时 p̂ 为监测估计,含估计误差。调度器未使用
   任务级特征(如复杂度)做逐任务干预决策——Frozen 200 诊断表明这是最有价值的
   扩展方向。
5. **候选池规模。**故障场景下可评估臂为 3–5 个;Exact Pareto 实验的 18 配置在
   受限子空间内穷举。更大的候选池需要新的执行预算。

## 5.6 未来方向

**(1)选择性协同调度。**本文证据指向的核心方向:开发任务级的干预决策函数 g(x, s),
仅在故障风险高且可恢复的任务上启用 Dynamic,避免对低风险任务的过度干预。Oracle
上界(+10.8pp)表明该方向的理论空间显著大于进一步提升 Dynamic 本身。

**(2)自动 Pareto 工作流搜索。**第二篇工作的方向:当候选空间从当前的受限子空间
(固定拓扑,仅变 m_r × m_v × Z)扩展到完整 (X, Y, Z) 空间(可变拓扑、节点数、
分解深度)时,精确枚举不再可行,需要代理辅助搜索(surrogate-assisted search)。
关键挑战是第 3.X.3 节识别的评估昂贵性:Q(π) 的每次评估需要真实 LLM 调用,
搜索必须利用能力画像先验 + 温度-0 重放校准的代理模型,并对少量候选做真实验证。
MEoH(AAAI-25)的"支配-不相似度"种群管理准则可适配到 (X,Y,Z) 配置距离上。

**(3)更丰富的反馈信号。**当前部署信号(解析/执行/一致性)对推理级错误召回为零。
可探索的方向包括:选择性跨模型交叉验证(仅对高风险推理节点触发第二意见)、
基于历史恢复成功率的条件恢复策略、以及利用单元测试等确定性反馈源。

**(4)多轮与增量场景。**本文限于单轮独立任务;历史图复用(Graph Forest)在修改型
追问中展示了 50% 的执行节省潜力,但未与故障恢复机制集成。
