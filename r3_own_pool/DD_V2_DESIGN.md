# DD-V2 最小改进方案 + V2 实验设计（阶段二/三，零调用设计文档）

原则：P3-60 已见结果——只作诊断/探索性开发，**永不**同时用于选择改进并证明其有效；V2 确认必须用新独立任务集。不修改 V1 权重/阈值/冻结任务。

## 阶段二：三个最小机制改动（按归因优先级）

### 改进 1（最高优先）：真实时延先验 + 争用解耦

- **决策先知替换**：`PRIORS_STUB_V1` → 由可靠性 FIT 对象（10 格实测、独立于 P3）构建的 `node_profiles`（v|coder 0.33s 等）。硬约束（Q_min、按时、预算）语义不变——这是修正输入，不是放松约束。
- **争用项解耦**：批处理串行执行器下，"59 个共同任务 × 估时"不是本任务候选的属性而是**调度器排队信号**。V2 将争用从候选可行性 mu_e2e 中分离为独立的调度延迟项（候选过滤用本任务服务+切换估计；批次排序用争用估计）。两种设计（分离 vs 保留但用实测先知）在开发集上消融比较，预注册选择规则。
- 依据：归因 §3——p_on=0.000 全灭由 stub 均值 7.0s × 争用 59×10s 造成；FIT 实测早已存在。

### 改进 2：真实质量校准 + 软约束/静态回退（明确区分）

- **校准（改进 A）**：在独立开发数据（可靠性 fit-24 + 分解基准既有执行的节点级观测，皆非 P3-60）上估计 P(终端正确 | 节点类型, 模型, 异常状态, 恢复动作, 反馈)，替代 stub q_success + min 合成。校准误差（校准集上的 Brier/排序）随 V2 报告。
- **软约束 vs 硬约束（明确声明，不偷偷取消安全要求）**：Q_min 与 ε 保持为 V1 的**硬**约束语义用于 DD-V1 复现臂；DD-V2 中研究带风险惩罚的软版本（不可行候选按预测劣势折减分数而非直接剔除）作为**新设计的策略筛选**，其与硬约束的差别在协议中显式标注。
- **静态回退（改进 B）**：DD-Cal+Fallback——当动态池无可行候选且静态 LOCAL 配方通过**物理预算与合法性**检查时，执行静态回退而非 EARLY_STOP。数学上不保证 ≥SS（预测误差仍在），协议中如实声明。

### 改进 3：真正的联合选择

- 候选进入选择阶段后，NONE/LOCAL/FULL 的真实可行性与 Ê[R] 联合比较（V1 机制已有此能力但从未被触达——归因 §3）。依赖闭包、缓存身份、重执行合法性全部保留。

## 阶段三：V2 实验设计（五臂，新独立集，双口径预注册）

| 臂 | 说明 |
|---|---|
| SS | 原始静态基线（不变） |
| DD-V1 | 原始机制，stub 先知原样（复现负结果的条件） |
| DD-Cal | 仅替换真实校准先知（改进 1+2 校准部分） |
| DD-Cal+Fallback | + 静态回退（改进 2 回退部分） |
| DD-V2 | + 争用解耦 + 软约束 + 联合选择（完整改进） |

- **面板**：新独立 60 任务（TAT-QA train 剩余 ~1,370 池，排除 P3-60、微试 3 及一切历史使用；新种子，同资格过滤，冻结哈希）。P3-60 仅用于开发集诊断。
- **双口径预注册**：(a) 服务时延机制收益（V1 同口径，可比）；(b) **端到端口径**——T 含真实切换墙与排队（批次排序固定或轮转），D 锚相应调整；两口径分别预注册解释，不混用。
- **记录**：Q、tokens、真实切换（次数+墙）、等待、截止时间、双口径奖励、全部决策行。
- **分析**：主对照 V2−SS 与 V2−DD-V1（分离"修输入"与"改机制"的贡献）；配对符号翻转 + 任务簇 bootstrap；解释规则沿用预注册文档（负结果同等显著度）。
- **预算**：五臂 × 60 任务，缓存隔离同 V1 设计；按本次实测（469 请求/186K/五段~35 分钟）外推 ≈ 600–700 请求 / ~240K tokens / ~45–60 分钟墙钟；拟议上限 **800/300K/7,200s**（待批准）。
- **开发集流程**：改进 1–3 先在开发任务（P3-60 + fit-24 重叠池之外的开发样本）离线消融；有限预算受控验证后冻结 V2 配置，再申请新集确认。

## 避免事项（绑定）

不降 Q_min 重跑旧 60；不动奖励权重/时间惩罚；不筛 DD 有利子集；不以 SS 金标/输出作为 DD 决策输入（SS 结果仅离线诊断）。
