## 更正与执行缺陷披露（操作员审计后追加；原始数据与结算未改动）

**撤回"E 在线学习有害/死亡螺旋"归因**。台账证据：E 在四个任务中执行了
**0 次 repair/fallback 调用**——学习存储从未获得任何新样本，"学习"没有
发生。ΔU(E−D)=−0.179 是两条真实轨迹的差异，其来源是**模型服务的随机
输出与时延**（T05：D 首次 GLM 完整输出 119.8s vs E 被截断 147.5s→E 终
止），而非学习更新。学习效应**尚未检验**。

**TERMINATE 后仍重执行的缺陷（已修复）**。`_gate_recover_root()` 在
TERMINATE 后未检查终止状态、仍重执行失效闭包：T08 D 组 50.36s 终止后
又跑 TL+XC 至 105.57s（D=90s）；E 组 71.21s 终止后至 125.34s。这违反
动作语义——TERMINATE 必须真正终止。修复+定向回归 PASS（终止后零调用）。

**审计中发现的第三个缺陷（已修复）**：门控动作键 `REPAIR:` 被映射层
静默当作 ACCEPT（映射只认 `RETRY:`）——这解释了 D/E 为何 0 次模型修复
调用：**试点中的 D/E 实际只运行了 {LOCAL_REPAIR, TERMINATE, ACCEPT}
动作子集**。因此 ΔU(D−C)=+1.444 的收益来源限定为零调用修复+终止止损+
不烧调用的接受，**不含模型切换/参数修复**；D 的 q 未超 C 与此一致。
修复后定向回归 PASS（REPAIR 真实执行、TERMINATE 后零调用）。
