# UNIFIED_VERIFICATION_DESIGN — 独立反馈驱动联合调度验证（冻结设计稿，2026-10-30）

> 按 operator 裁决：一次完整验证（不拆实验），覆盖反馈学习效果 +
> 六策略完整对照 + 独立任务泛化。**待完整字段授权。**

## 1. 研究问题

> 在未参与画像更新的独立任务上，利用真实执行反馈更新的调度器，
> 能否在异常条件下获得比原始调度器更好的终端 Q/C/L？

## 2. 设计（一次性完整实验）

### 任务（独立、未参与反馈更新）
从冻结基准池选取 **2 个独立任务**（非 T-P2/T-D1，候选：V01-yuandao
复盘型 + T02-huanrui 当时型——池内 VERIFIED_DOCS、SHA 在案、
Silver 参考可构建）。**需确认映射。**

### 画像条件（2 种）
- **frozen**：原始冻结画像（Flash=低成本低时延假设）
- **feedback**：反馈更新画像（Flash 实测 1.5× token / 1.2× 时延）

### 策略（6 种，同异常态配对）
Static / Simple-Dynamic / R-only / π-only / **Joint(R,π)** /
**Joint(Z,R,π)**（Z 含 IDENTITY + 全部语义守卫候选）

### 异常注入（冻结协议）
- 传输级故障（f3 时间线节点，与 Stage-C v2 同点位——跨任务可比）
- 证据失效（如任务有替代来源：检验 Z=SUBSTITUTE_EV 的触发与收益）

### 规模
2 任务 × 2 画像 × 6 策略 × 2 重复 = **48 run**
（共享前缀 + 同态分叉 → 预计 ~40 + 48×4 ≈ 232 次调用，
~280K Token——需较大包络）

### 简化选项（如需控制预算）
2 任务 × 2 画像 × 4 核心策略（Static/π-only/Joint(R,π)/Joint(Z,R,π)）
× 2 重复 = 32 run，~150 次调用，~180K Token

## 3. 评价

- 独立终端 Q_eff（Silver 候选层，冻结参考）
- 真实 Token / 现金 / 墙钟 / 按期率 / 合同通过率
- **逐 (task,rep,strategy) 配对差异**（frozen vs feedback）
- 逐层归因：静态分配 / 动态恢复 / π 重分配 / Z 结构编辑

## 4. 判定

| 判定 | 条件 |
|---|---|
| 反馈学习有效 | feedback 画像臂在 ≥50% 配对中 Q 不劣且 C/L 不劣于 frozen 画像臂 |
| 联合调度有效 | Joint(R,π) 在 ≥50% 配对中优于 Static（复验 Stage-C 结论于独立任务） |
| Z 有条件价值 | 在证据失效场景中 Joint(Z,R,π) 选择合法替代且 Q 高于硬修臂 |

### 修正后任务方案

**事实**：冻结池中仅 T-P3 一个任务完全未曝光且证据零重叠。

| 选项 | 内容 | 局限 |
|---|---|---|
| **A（推荐）** | T-P3 单任务 × 2 画像 × 2 异常 × 6 策略 × **2 rep = 48 run** | 单任务，结论限定于该事件类型 |
| B | T-P3 + T-D2（证据部分曝光） | T-D2 与 T-P2 共享 3 份康得新文档——需降级结论 |

**选 A**：单任务全量（2 rep）优于多任务降重复——同任务内配对比较的
统计效力更强，且证据完全清洁；单任务局限如实披露。
