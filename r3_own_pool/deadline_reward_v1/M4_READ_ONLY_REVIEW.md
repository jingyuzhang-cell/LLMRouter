## 2. Review items

### R1 — NONE arm semantics
**PASS.** `run_arm(..., 'NONE')` executes planned stages A → R1 → V1
only; no recovery stages are constructed; matching candidates: NONE
candidates in `enumerate_candidates` carry π over pending nodes only.
The M4-era `recovery.run_arm` is used by `test_recovery` for all three
arms; the policy path composes stages identically.

### R2 — LOCAL arm semantics vs production
**PASS.** `_local_er_r2_r3` / `_local_v2_v3` mirror
`fault30_run.eval_config`'s LOCAL_REROUTE stage-for-stage: ER trigger =
empty facts (D1) with the panel-detection-order memory rule
(coder/medium); R2 trigger = facts-actually-changed; R3 = unparseable r
(D3), ungated, escalate to large; V2 = final-state original-vs-last r
comparison; V3 = latest-v fail (D5). Verified line-by-line against
fault30_run.py:292-422; T3a/T3b per-task and single-task-panel parity
(t3a_*_per_task, t3a_single_panel_*) is bitwise against the production
reference.

### R3 — FULL arm semantics: static E-arm vs dynamic FULL are distinct
**PASS.** In `reassign.enumerate_candidates`: arm `FULL` pins every
non-trigger node to its PLANNED model (E-arm matched semantics, per
`netbenefit_runner.recovery_plans` + the grouped replay loop);
arm `FULL_DYNAMIC` allows menu reassignment over the whole legal
re-execution set. `recovery.run_arm` executes the STATIC variant
(no_cache replay, all charged); tests `m5_t2_static_full_pins_planned`
vs `m5_t2_dynamic_full_reassigns_downstream` pin the distinction. The
M4 reference (`production_reference` in test_recovery.py) is built from
the E-arm path only — it is never compared against FULL_DYNAMIC.

### R4 — Are the references truly independent?
**PASS.** The reference for all three arms is generated by PRODUCTION
code (`evaluator._evaluate` over `MeteredExecutor` + `Budget` + a stub
dispatch), not by any `deadline_reward_v1` module. The engine under
test never imports from the reference path (verified by import-graph
checks in test_stub_engine/test_m5). The reference's expectations enter
the test only as ground truth for comparison; no `deadline_reward_v1`
code writes into the reference's artifacts (the reference runs in a
tempdir owned by the test). Reproduction: `python3 -m
deadline_reward_v1.test_recovery`.

### R5 — Single-task T3a & cross-task T3b coverage
**PASS.** T3a literal: `t3a_single_panel_{NONE,LOCAL,FULL}` — one-task
panels, bitwise sequences + physical counts. T3b: global order (model-

### R6 — Detection order, cache identity, call sequence, ledgers
**PASS.** Detection predicates are mirrored in `detection.py` with
parity tests against production (`parse_facts_safe`, `value_of`,
`json_value`, `close` — probe grids in test_m2/test_dag_closure).
Cache identity = (model, input_sha) mirroring the production alias;

parity caught it). Per-call ledger fields complete (call_start, call,
switch, task_summary, session_summary); three-way reconciliation

handling are pinned in the boundary/phase-3 suites.
