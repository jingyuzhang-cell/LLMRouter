# 实验 2：DAG 质量传播建模与联合动态调度决策验证

## 阶段一：决策差异根因（审计完成）

**Q1：D 为什么选 1 节点而 Oracle 选 2-3 节点？**

根因是 D0 的质量公式：`total_q = (q_prior × |R| + 0.1 × (N-|R|)) / N`

| 闭包大小 | D0 的 total_q | 成本 | 效用 |
|---|---|---|---|
| 1 节点 | (0.175 + 0.7) / 8 = 0.109 | 2,500 tok / 12s | −0.162 |
| 2 节点 | (0.350 + 0.6) / 8 = 0.119 | 5,000 tok / 24s | −0.173 |
| 8 节点 | 0.175 | 20,000 tok / 96s | 超截止 |

D0 把未修复节点质量统一为 0.1 并用全节点数做分母——修复更多节点
确实提高质量，但成本线性增长更快，且不知道"修复上游会改善下游"。
因此 D0 选 LOCAL_REPAIR（R=0，免成本）或最小闭包。

**Oracle 用不同的质量函数**（含传播效应+噪声），知道修复源节点会
级联改善下游，因此 2-3 节点的精确闭包+混合模型是最优平衡。

## 阶段二：D0-D3 质量估计模型

| 模型 | 机制 | 关键假设 |
|---|---|---|
| D0 | 均匀 Wilson-LB 均值 | 所有节点等质，无传播 |
| D1 | 节点类型异构 | extraction/reasoning/verification 有差异，无传播 |
| D2 | **DAG 传播** | 修复上游→下游获得传播增益（乘性），未修复节点保持原质 |
| D3 | D2+保守校准 | 传播增益乘 confidence 收缩因子 |

## 阶段三：消融结果（8 节点钻石 + 多路径，零调用模拟）

### 实验 B：Oracle Gap

| 臂 | eU | 闭包 | Oracle Gap |
|---|---|---|---|
| C 简单门控 | −0.367 | 8n 全 DS | +0.279 |
| D0 原始 | −0.150 | 0n (LOCAL) | +0.062 |
| D1 节点异构 | −0.150 | 0n (LOCAL) | +0.062 |
| **D2 传播** | **−0.088** | **1n DS** | **0.000** |
| D3 传播+校准 | −0.115 | 1n DS | +0.027 |
| Oracle | −0.088 | 1n DS | — |

**核心发现：D2 完全消除 Oracle Gap。**

- D0/D1 不知道修复上游会改善下游 → 认为 LOCAL_REPAIR（零成本）
  比修复更好 → Gap = 0.062
- D2 知道修复源节点会传播改善到全部下游 → 愿意花 2,500 tok 修
  一个节点 → 选到与 Oracle 相同的动作 → Gap = 0
- D3 的保守校准牺牲少量效用换取鲁棒性 → Gap = 0.027

### 为什么 C 最差（−0.367 vs D2 的 −0.088）？

C 选 8 节点全闭包+全 DS：
- Token 成本 = 8 × 2,500 = 20,000（λ_c × 20K/60K = 0.167 惩罚）
- 时延 = 8 × 12s = 96s（80+96=176s < 200s 勉强按期）
- D2 只修 1 节点：Token = 2,500（惩罚 0.021），时延 = 12s

**差距主要来自成本惩罚，不是质量。**

## 回答关键问题

**Q1**：D0 选错闭包因为质量公式把未修复节点统一为 0.1 并除以总节点数，
不知道修复上游会传播改善下游——传播效应是缺失的关键信息。

**Q2**：D2 的传播模型提高了终端质量预测（Gap 从 0.062 降至 0.000），
正确识别了"小闭包+好模型 > 大闭包+便宜模型"。

**Q3**：D2 将 Oracle Gap 从 0.062 缩小到 **0.000**（完全消除）。

**Q4**：收益来自**质量传播**而非异构分配——D1（异构无传播）与 D0
（均匀无传播）的 Gap 完全相同（0.062）；D2（加入传播）单独消除全部
Gap。在本实验设定下，闭包选择比模型分配更重要。

**Q5**：改进在包含分支/汇合的 DAG 上有效（钻石与多路径结果一致）。
链式 DAG 待验证（传播效应在链上是否同样显著）。

**Q6**：**尚未验证**。当前证据来自模拟效用（Oracle 也用 D2 的质量
函数），非真实执行。需要：
- 不同质量函数的 Oracle（如使用真实模型输出而非 D2 估计）
- 真实调用验证 D2 的传播预测是否与实际质量一致
- 在更多 DAG 结构和截止条件下测试鲁棒性
