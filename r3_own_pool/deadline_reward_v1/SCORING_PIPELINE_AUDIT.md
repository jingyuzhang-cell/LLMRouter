# 评分链路审计报告

## 确认的 Bug

`eval_scoring_ref` 将 DAG 的**所有节点输出**拼接后搜索参考事实：
```python
combined = ' '.join(str(v.get('answer', '')) for v in outputs.values())
```

这意味着：
- 中间节点（extraction/reasoning）提到参考事实即计为"命中"
- 即使最终交付的终端答案不包含该事实，也可能被判为高质量
- 反之，终端答案语义正确但措辞不同时被判为零分

## 对 CT01 结果的影响

CT01 的唯一参考项是 `p:处罚`（"处罚"关键词）。

- C 臂 q=1.0：可能被污染——8 节点全闭包重执行中，**某个中间节点**
  提到了"处罚"，被拼接后计为命中。终端答案是否包含"处罚"未知。
- D0/D2 q=0.0：整个管线没有任何节点输出包含"处罚"关键词。
  这可能准确（所有节点都未产出该词），也可能因为措辞不同。

**结论：CT01 的 q 值不可信，不能用于策略比较。**

## 修复

新评价函数 `terminal_eval.py`：
1. `terminal_q`：仅评估 **sink 节点**（无下游的最终节点）的输出
2. `pipeline_q`：所有节点拼接（诊断用，标注事实在哪一层丢失）
3. 主分析使用 `terminal_q`
4. 诊断报告显示 `lost_in_synthesis`（在管线中有但终端丢失的事实）
