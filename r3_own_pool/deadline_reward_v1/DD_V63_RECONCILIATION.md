## 一、JNS Regret 差异根因（0.0033 vs 0.0862）

**DD-V6.2 的 JNS 结果无效——使用了错误的效用函数。**

| | DD-V6.2 JNS | DD-V6.3 JNS |
|---|---|---|
| 效用函数 | 简化版（固定 5.0s 时延、无质量传播） | 真实版（模型时延 + K_m 竞争 + 质量传播） |
| regret | 0.0033 | 0.0862 |
| 结论 | **无效**（在简化函数上，坐标搜索也全达 Oracle） | **有效**（正确基线） |

DD-V6.2 的 `algo_jns` 在实现时调用了 DD-V6 的简化 `utility()` 而非
DD-V6.1 的真实 `utility_realistic()`。简化函数下 JNS 看起来好是因为
问题本身可分。DD-V6.3 的 0.0862 是 JNS 在真实耦合下的正确表现。

## 三、π-only 的全局 Oracle Regret

π-only 固定 R={fault}，不搜索恢复范围。其 "regret=0.0032" 是在
**受限动作空间内**的最优。全局 Oracle regret（vs 完整 (R,π) 空间）
可能更高——当更大 R 有更优解时。

**验证**：Alternating 搜索完整 R 但 regret=0.0052 > π-only 0.0032，
说明在当前 9 状态中 **R={fault} 就是最优 R**——更大 R 不产生更好
的解。但这可能是测试 DAG 的特性（单故障+小闭包），不代表一般情况。

## 四、对下一步算法设计的启示

基于 k×prop 交互机制的精确理解，新算法应该：

1. **识别资源-质量耦合块**：两个节点共享模型槽位（K_m 竞争）且
   存在质量传播依赖时，它们的模型选择不可独立优化
2. **块内精确求解**：在耦合块内（通常 2-4 节点），穷举模型组合
   是可行的（2^4=16 组合）
3. **块间保留坐标搜索**：不同块之间的节点可以独立优化
4. **增量更新**：反馈到达时只重新求解受影响的块

这与 operator 建议的"反馈驱动的交互感知联合块优化"一致。
