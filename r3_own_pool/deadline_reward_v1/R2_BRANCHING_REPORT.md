## 预算纪律事故（我的错误）

`pre_check` 的容差为 `cash + 0.01 > cap`，假设单次调用成本
<¥0.01；实际本实验单次调用成本 ~¥0.014（2-3K 输出 token/次），
导致最后一次放行的调用把总额推到 ¥0.1940，超上限 ¥0.004。
**修复**: 容差必须 ≥ 单次调用最大合理成本（本设置下 ≥¥0.02）。

## 机制发现（关键，检查输出验证）

1. **b1 == b2 == b3 逐字节相同**（温度 0 + 相同输入 + 相同提示词
   → 分支输出克隆）。
2. **修复后的 b0 == b1 == b2 == b3**（健康分支节点产出完全一样）。
3. **x1 == sink**（sink 在 4 路上游输入下输出与 x1 相同）。
4. **D2 重执行的 sink == 原 sink**（修复未改变 sink 的信息状态：
   b0 修复后与其余三路无差异）。

**结论**: 我的 R2 实现把所有非根节点设为同质 "reasoning" 角色
（同一提示词），分支间零信息特化 → b0 故障不损失任何独有信息 →
定向恢复无价值。这不是操作者 R2 概念（定向 vs 全量恢复效率）的
证伪，而是**实现层设计缺陷**：分支必须承载互补信息（异质角色），
故障才可造成不可替代的信息损失。

## 对 R2 修正版的设计要求

- 四分支异质角色（如 b0=时间线、b1=金额、b2=处罚、b3=主体关系，
  各自提示词要求仅汇总该类事实）→ sink 综合四路
- 评分项按角色分布（每分支至少 2 个专属评分项）→ b0 故障时
  其专属项在 D0 下必然丢失、D2 修复后恢复
- 预算: shared 8 + D2 3 + C 7 = 18 调用；成本上限需按实测单次
  ~¥0.014 重新核定（≥¥0.28 才安全；或压缩输出 token）
- 预检容差 ≥¥0.02
