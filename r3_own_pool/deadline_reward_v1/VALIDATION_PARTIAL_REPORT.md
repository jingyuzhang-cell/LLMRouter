**mean dU(D−C) = +0.006（2正/3负，5 arm-reps）**

这与试点的 +1.444 形成鲜明对比。解释：
- 试点的 D 优势部分来自**随机性混淆**（不同首次输出→不同故障轨迹）和
  **执行缺陷**（TERMINATE-后-重执行浪费的 token/时间被算到 C 头上，
  REPAIR→ACCEPT 映射使 D 跳过了不必要的调用）；
- 共同初始输出下，D 和 C 在这两个任务的恢复决策**几乎相同**（C 的
  简单门控已选择与 D 的门控相同的动作）；
- 两任务全是截断型故障，围栏型假故障（D 的零调用修复优势所在）在此
  未大量出现。

**这与试点结论不矛盾——试点证明的是"在实际混合故障+随机输出环境"
中 D 的资源/时延节省；本验证证明的是"在控制随机性+同故障实现"下
D 的恢复决策本身与强简单基线几乎不可区分。**
