## 二、n_sup2 故障合同冻结（交付 #2）

| 项 | 冻结内容 |
|---|---|
| 故障注入 | n_sup2 真实执行调用 → 输出替换为 GARBAGE 显式占位（截断型失效） |
| 可观测时点 | n_sup2 调用完成后（契约检查失败：JSON 解析通过但内容=占位） |
| 失败调用开销 | 计入共享前缀（Flash 调用 1 次，token/时延已付） |
| 合法恢复闭包 | closure(n_sup2) = {n_sup2, merge, verify, sink}——模型节点={n_sup2, verify, sink} |
| 有效缓存保留 | n_main、n_sup1 的输出（输入未变→缓存有效，不重执行） |
| merge 成本 | **程序节点，零 LLM 调用**，但计入实际执行时延（~0s：纯 JSON 合并） |
| verify/sink 消费合同 | verify 消费 merge 输出（三线事实+占位标记）→ 逐条标注 doc 来源与 verdict；sink 消费 verify 输出 → 终端 JSON 契约 |

**验证臂数重算（不混淆故障与重复）**：
- 主实验：**2 事件 × 1 故障（F-sup2）× 2 截止档 × 2 重复 × 7 策略 = 56 逻辑臂**
- F-verify、F-none 另列探索（不计入 n=2、不混入主实验臂数）

## 四、56 臂物理调用预算（交付 #4）

**共享前缀（每状态 = 事件×故障×D×重复）**：
- n_main + n_sup1 + n_sup2(失败) = 3 次真实 Flash 调用
- 8 个状态（2 事件 × 2D × 2 重复）× 3 = **24 次**

**策略臂执行（同动作共享）**：
- 每状态 7 策略但物理动作 ≤4 种（accept/targeted/full × Flash/DS3）
- 每动作 3-5 次模型调用（模型节点数）
- 估算每状态 ≈ 15 次执行 × 8 状态 = **120 次**
- **总调用 ≈ 144 次**（上限 160，留 10% 异常余量）

**DS 现金**：
- SINGLE-DS（5 DS 调用/臂）仅在 D_tight 状态：4 状态 × 5 = 20 次
- π 活跃臂（JOINT/π-only）DS≤3/臂：4 状态 × 2 臂 × ≤3 = 24 次
- 合计 ≤44 次 DS × 实测均价 ¥0.004 ≈ **¥0.18**（非高峰）
- 最坏高峰 44 × 0.032 = ¥1.41 → **非高峰强制 + 硬顶 ¥0.60**（含 10% 余量）
