## 三、机制发现：GLM 温度 0 非确定性 → C 的优势是重采样方差

C 臂重执行兄弟分支时，**thinking 块随机出现使 temp=0 重执行不再
复现原输出**（C 臂 b1 think=True len=514 vs shared b1 think=False
len=699，输出实质不同）。因此：

- deepseek 轨道的假设"全量重执行 = 冗余复制"（R2 同质实验中逐字节
  克隆）**在 GLM 上不成立**——重执行是"重掷骰子"；
- C 的额外命中（1 个实体：元道通信股份有限公司）来自重采样后的
  兄弟输出进入 sink，**是抽签方差而非系统性信息恢复**；
- 单次运行无法区分"全量重执行的系统收益"与"多一次抽签的方差收益"
  （C 臂 7 次调用 vs D2 3 次 → 更多抽奖券）。

这是 GLM 轨道上"定向 vs 全量"对照的**根本混杂因素**，如实记录。

## 四、评分工具勘误（波及既往运行，对称影响）

同一日期键格式缺陷影响所有历史运行（R1/R2/CT10）：仅当月/日两位
数字时日期键可评（如 `d:20231017`），其余静默失效。**各臂同键，
差值方向不受影响**；R1 与 CT10 的正向 Δt_q 证据在可评键上依然成立，
但有效键数低于名义值（如 R1 名义 10 键、有效约 7 键）。
评分器修复后新运行不再受影响；历史数据不改写。
