## 摘要

大语言模型（LLM）多智能体系统越来越多地采用有向无环图（DAG）编排复杂任务，
例如基于多份公告的资本市场事件调查。现有研究关注调度算法的优化（模型选择、
故障恢复、资源分配），但忽视了一个更基础的因素：**DAG 节点间的信息传递合同**。

本文基于三个真实 A 股事件（舜天、欢瑞世纪、*ST卓然）的 9 份官方公告、
~250 次真实模型调用，系统研究 LLM DAG 中信息架构与模型选择对终端质量的
相对影响。核心发现：**修正 verify 节点的信息瓶颈（增加 merge→sink 直通边）
使 Flash 模型的终端事实覆盖率从 0.150 提升至 0.750（+400%）——这一影响
远大于模型替换差异（Flash 0.750 vs DeepSeek 0.850，差 0.100）**。

在正确合同下，我们进一步检验了联合动态调度 a=(Z,R,π) 的条件性价值：
模型分配 π 确实可以改变恢复决策 R 的可行性（三事件复现），但联合搜索
与最强独立优化（π-only、反向顺序、交替优化）在两模型池下等价——原因是
质量模型的（弱）单调性。我们给出等价的结构性条件，并提出 Verify-Q
四维核验质量评价体系（事实正确性、跨文档一致性、证据可追溯性、下游有效性），
揭示节点核验质量与终端事实覆盖之间的断裂。

**关键词**：LLM 多智能体系统；DAG 信息架构；异构模型调度；质量传播；资本市场事件调查

## 第一章 绪论

### 1.1 研究背景

LLM 多智能体系统在处理复杂任务（如多文档调查、代码生成、数据分析）时，
通常将任务分解为 DAG 结构：抽取节点处理原始输入、验证节点核验跨源一致性、
综合节点生成最终输出。每个节点可分配不同模型（异构池），系统面临
质量—成本—时延（Q/C/L）联合优化问题。

现有研究聚焦于调度算法：如何选择模型（π）、如何决定恢复范围（R）、
如何选择恢复方式（Z）。但我们在真实实验中发现一个更基础的问题：
**DAG 的信息传递架构（哪个节点的输出能到达哪个下游节点）对终端质量
的影响可能超过所有调度决策的总和**。

### 1.2 核心研究问题

**RQ：在 LLM DAG 多智能体系统中，信息传递架构与模型选择对终端任务质量
的相对影响是什么？在正确架构下，联合动态调度是否具有不可替代的价值？**

分解为三个子问题：
- RQ1：异构模型在 DAG 不同节点上的 Q/C/L 差异有多大？（能力画像）
- RQ2：DAG 信息架构如何影响这些差异的终端表达？（质量传播）
- RQ3：在正确架构下，联合 (R,π) 优化相对于独立/顺序优化是否有独有收益？
  如果没有，等价的结构性条件是什么？

### 1.3 贡献概要

1. **信息架构 > 模型选择**（发现级贡献）：verify 节点信息瓶颈使 Flash 终端
   质量被低估 400%；修正后 Flash-DS 差距从 0.700 缩至 0.100
2. **联合调度条件性价值**（实证级贡献）：π 使能 R 的机制在三事件复现，
   但效用优势仅在截止期窗口内出现；与强基线等价的条件=质量模型单调
3. **Verify-Q 评价体系**（方法论贡献）：四维核验质量独立评价，揭示核验
   正确性与事实传递率的分离
4. **异构能力画像**（数据级贡献）：Flash/DS 逐节点时延差 3.5-18.5×，
   质量差异事件依赖

### 1.4 论文结构

第二章文献综述；第三章方法设计（DAG 合同 v1/v2 + 调度框架 + 评价体系）；
第四章实验（三事件 × 七策略 × 合同对照）；第五章结果分析；第六章讨论与结论。

## 第三章 方法设计

### 3.1 DAG 信息传递合同

#### 3.1.1 合同 v1（基线：verify 瓶颈）

```
n_main/n_sup1/n_sup2 → merge → verify → sink
```

verify 输出 `{item, doc_a, doc_b, verdict, note}`——不包含原始事实数据。
sink **只消费 verify 输出**，因此所有未被 verify 显式引用的事实都被丢弃。

#### 3.1.2 合同 v2（修复：事实直通）

```
n_main/n_sup1/n_sup2 → merge ─────────→ sink（完整事实集）
                              ↓                ↑
                           verify ────────────（核验判定）
```

关键变更：(1) 新增 merge→sink 边（事实直通通道）；(2) verify 只输出判定
`{fact_id, verdict, note}`；(3) sink 同时消费事实集与判定。

#### 3.1.3 恢复语义

合同变更**不影响恢复闭包**：closure(n_sup2) = {merge, verify, sink} 在两种
合同下相同。verify 失效时，v2 合同下 sink 仍获全部事实（标 UNVERIFIED）。

### 3.2 调度框架

#### 3.2.1 联合动作 a=(Z,R,π)

- Z ∈ {KEEP, VERIFY, REEXEC_LOCAL, REEXEC_EXPAND}
- R ∈ {accept, repair_sup1, repair_sup2, repair_both, full}
- π ∈ {Flash, DS}^(PENDING 节点数)

#### 3.2.2 策略对照

| 策略 | R 决策 | π 决策 |
|---|---|---|
| STATIC | 预固定 | 预固定 |
| SD-FC | 故障位置规则 | Flash |
| R-only | 输入衍生信号 | Flash |
| π-only | 固定 targeted | 逐节点 Q/C/L |
| SEQ-R→π | 先 R 后 π | 顺序 |
| SEQ-π→R | 先 π 后 R | 顺序 |
| Alternating | 交替协调 | 交替 |
| JOINT | 联合枚举 argmax | 联合 |
| SINGLE-DS | — | 全 DS 参照 |
| Oracle | 精确枚举最优 | 枚举 |

### 3.3 评价体系

#### 3.3.1 Silver 终端质量

key_facts 关键词覆盖率（金额+日期+处罚词，规范化子串匹配）。

#### 3.3.2 Verify-Q 核验质量（四维）

| 维度 | 内容 |
|---|---|
| D1 事实核验正确性 | 引用事实是否可在原文定位 |
| D2 跨文档一致性判定 | verdict 是否合理（一致/互补/冲突/未定） |
| D3 证据可追溯性 | 是否同时含文档引用+具体事实 |
| D4 下游有效性 | 关键事实传递率（verify→sink） |

#### 3.3.3 效用函数

eU = q×1(按时) − 0.5×token/C0 − 迟到惩罚 − 2.0(若迟到)

## 第五章 结果分析

### 5.1 信息架构的主导效应

Flash 链 Silver 在 v1→v2 合同间的变化（+0.600）是 Flash vs DS 模型差异
（0.100）的 **6 倍**。这证明：

1. 不修正信息架构，任何调度算法的 Q/C/L 测量都被信息瓶颈污染
2. 模型间的"质量差异"可能主要是接口行为差异
3. 合同设计应作为调度系统优化的**前置步骤**

### 5.2 联合调度的条件性价值

π 使能 R 的机制（JOINT 选 targeted+DS，SEQ 因 Flash 检查选 accept）在
三事件上一致出现——但效用优势的条件极窄：
- 舜山+0.12（最优臂边际胜出）
- 欢瑞+2.83（含 SEQ 边际迟到罚）
- 卓然−0.10（前缀漂移致全臂迟到）

**联合搜索与 SEQ-π→R/Alternating 在所有事件上等价**——原因不是算法
缺陷，而是质量模型的（弱）单调性使最优 π 收敛到全 DS。

### 5.3 Verify-Q 与 Silver 的断裂

Flash verify 的核验质量（D1=1.00, D2=1.00）与终端 Silver（v1=0.150）
之间存在巨大断裂——根因是信息瓶颈（D4=0.10）。v2 合同修复后 Flash Silver
跳至 0.750，但 verify 的核验质量**不影响 Silver**（Silver 只衡量事实覆盖）。

**两个口径衡量不同能力**：Silver 衡量"下游有效性"（D4），Verify-Q D1+D2
衡量"核验判断质量"——两者不应混用。

### 5.4 质量传播模型

```
上游抽取 → merge(事实集) → verify(判定) → sink(终端报告)
                 ↘ (v2直通) ↗
```

质量传播的关键路径是 **merge→sink 的事实通过率**（v1=10%, v2=100%），
而非 verify 的核验质量。这解释了为什么"更多核验条目"（Flash 7 vs DS 3）
不等于"更高终端质量"。

## 第六章 讨论与结论

### 6.1 主要结论

1. **信息架构 > 模型选择**（+400% vs +13%）：DAG 合同设计是 LLM 多智能体
   系统质量优化的第一序问题
2. **联合调度的价值是条件性的**：在两模型池+Silver 评价下与强基线等价
  （质量模型单调）；价值出现在"模型速度改变恢复可行性"的截止期窗口内
3. **核验质量 ≠ 终端质量**：Verify-Q 四维评价揭示两者间的断裂由信息
   传递瓶颈造成

### 6.2 对领域的启示

- **LLM DAG 框架设计者**：节点间信息传递合同应作为一等公民设计，不是
  实现细节——信息瓶颈可使模型质量被低估 400%
- **调度算法研究者**：在评估调度策略前，先验证 DAG 合同的完整性——
  在有瓶颈的合同上，调度算法的比较结果可能是信息流差异的伪影
- **模型选择实践者**：模型在特定节点上的"质量"取决于下游能否消费其
  输出——不应仅凭节点级指标做全局选择

### 6.3 局限性

- 两模型池（Flash+DS）：单调性可能是模型池规模的函数
- Silver 评价：关键词覆盖不等于语义正确性；人工 Gold 未完成
- 探索性 n=1-2：多数结论需要更多重复实验确认
- 单故障类型：多故障并发的动作空间未在真实实验中测试

### 6.4 未来工作

1. **第三模型引入**（qwen-plus）：测试是否打破质量单调性 → 混合 π
2. **多故障并发**：R 从 {accept,targeted,full} 扩展到 5+ 选项
3. **反馈驱动在线质量更新**：在正确合同下的执行期间反馈
4. **人工 Gold 评价**：73 条 key_facts 的人工语义核验
5. **跨领域验证**：代码生成、数据分析等非资本市场任务
