# GLM FE 筛选质量分析（零调用，A–E 五层）

依据：`fe_screening_runs/fe_20261013_211741/FE_LEDGER.jsonl`（已标记 INCOMPLETE 的原始运行）
机读结果：`GLM_FE_QUALITY.json`
范围：10 条 delivered GLM 响应（FE1–FE5 × GLM-5.3 / GLM-5.3-Flash）。零新增模型调用。

## A. 格式契约（严格 JSON）

**0/10 通过严格 JSON。** 其中：

| 类别 | 数量 | 明细 |
|---|---|---|
| 空响应（answer 长度 = 0） | 3/10 | FE1/GLM-5.3-Flash, FE2/GLM-5.3, FE4/GLM-5.3-Flash |
| 非空但 JSON 截断 | 7/10 | 全部为 "Unterminated string" / "Expecting value" 类截断错误 |
| 合法 JSON | 0/10 | — |

非空响应的 JSON 解析失败位置全部落在文本末尾（如 FE3/GLM-5.3 在 char 1910/1942 处字符串未闭合），是输出中途被截断的典型特征，而非格式理解错误。

## B. 事实支持（诊断性抽取，仅非空截断文本）

从截断文本中用正则抽取类事实片段（日期/金额/实体），**仅作诊断，不作为质量结论**：

- 7 条非空响应全部含有结构化事实片段（9–33 条/条），含日期、金额（万元/亿元/%）、处罚实体词（罚款/市场禁入/虚增等）。
- 说明模型确实在按契约抽取事实，输出在事实列表中途被截断。

## C. Silver 召回（仅 FE3/FE4/FE5 可评；FE1/FE2 = NA）

按规则：FE1/FE2 无可评 Silver 事实集 → **NA（既不是 0 也不是 100%）**。

|---|---|---|---|

**注意**：这是在"输出被截断"条件下的召回（文本不完整，列表后半部分缺失），是截断机制的下界估计，不是模型能力结论。Flash 在 FE3 上高于 GLM-5.3 与截断位置差异有关，样本量过小不可比较。

## D. 失败机制（核心发现）

**10/10 条响应 completion_tokens 恰好等于 2048 = max_output_tokens 上限。**

三重证据定位机制：

1. **3 条空响应 + 2048 completion_tokens**：可见文本为 0，但 2048 个输出 token 全部被消耗。GLM-5.3 / GLM-5.3-Flash 是推理模型，Anthropic 兼容端点的 `max_tokens` 同时覆盖不可见的思考 token 与可见文本。当模型在思考阶段耗尽 2048 token 时，可见输出为空。这是"思考 token 吃满预算"的直接证据。
2. **7 条非空响应全部在 JSON 中途截断**（Unterminated string）：可见文本 + 思考 token 合计再次撞上 2048 上限。
3. **延迟特征**：20–34s（输入仅 1.1K–6.3K token）与重度推理一致，与"纯文本生成 2048 token"不一致。

**结论：失败根因是输出长度契约与推理模型机制的错配，不是事实抽取能力不足。** 2048 的 max_output_tokens 对"思考 + 完整 JSON 事实列表"双重预算而言过小。 FE1/GLM-5.3-Flash（31.9s）、FE4/GLM-5.3-Flash（24.3s）整段思考后零可见输出，是最极端的表现。

**契约缺口（本次暴露）**：FE 启动器未记录 `stop_reason`/`finish_reason`（历史 screening_full80 台账有此字段，FE 启动器属回归）。恢复执行器已补上该字段。

## E. 真实 Q/C/L

| 维度 | 结果 |
|---|---|
| 质量 Q | 严格 JSON 0/10（机制性截断）；截断文本诊断性召回见 C |
| 成本 C | 现金 ¥0.00（订阅覆盖）；token 消耗 53,642（in 33,162 + out 20,480） |
| 延迟 L | 20.1–34.3s/条（GLM-5.3 均值 ~21.3s，Flash 均值 ~30.8s，本批 Flash 反而更慢，与思考耗尽一致） |

注意：订阅覆盖 ≠ 零成本。20,480 个输出 token 全部撞上限，是"付费买截断"的最差组合——预算被消耗但没有产出可解析结果。

## 对调度研究的含义

这是反馈感知调度研究的直接素材：**节点执行失败可能源于"模型机制 × 输出契约"错配**（推理模型的 token 预算需要覆盖思考+输出两层），而非模型能力。调度器若将此类失败误判为能力不足并切换模型，会用错补救手段（换模型而不是放宽 max_tokens/改契约）。恢复执行（DS/Qwen 非燃烧思考型）将提供同一契约下的对照。

## 修复动作（已进入恢复执行器）

1. `max_output_tokens` 保持 2048 以维持与 GLM 同契约配对（对照实验要求），DS/Qwen 历史调用显示其直接输出（108–? token、stop_reason=stop）远低于该上限；
2. 记录 `stop_reason`/`finish_reason` 与 `truncated` 字段；
3. 计费读 JSON 文件（修复 `import rates` 错误）；
4. fail-stop：首个意外错误立即停止并写 INCOMPLETE，不再续跑；
5. model_id 修正：`deepseek-flash`（历史台账实证，费率反推绑定），弃用 `deepseek-chat`。
