# extract_current：独立参考完整性及实体角色验收

结论：**来源中的表格参考验收通过；完整节点Q的准入未通过。** 已完成四份历史输出的逐事实离线核验，没有新模型请求。四个Q_objective继续为null，不把合同FAIL变为Q=0。

## 1. 参考实际证明了什么

原始材料为欧菲光《关于媒体报道的澄清公告》，证券代码002456，公告编号2026-075，落款2026年8月10日。冻结PDF SHA256：`98c437b56d8b87e2ada7d95d467fc4c0f64a218185bff693dcbf18f1792f2f81`。这里只核验既有文件，不重新抓取；落款日期不等于独立确认的实际发布时间。

两张实际交易表共有7行、3年度，即21个金额单元，另有1个落款日期。新验收逐条检查数值跨度、表头跨度、交易关系跨度、行标签及年份列序；另从两段原文独立枚举金额位置，与参考的21个位置集合完全一致。两个交易对手×三个年度的6项合计均与分项精确相等。不是仅凭旧文件写了complete=true就宣称完整。

新侧文件为每条参考保留：issuer=002456、counterparty、交易行角色、年度列、万元单位、总计/分项身份、来源版本及跨度。三种角色必须区分：

- 披露主体：欧菲光。
- 交易对手：新菲光或新思考。
- 交易内容/方向：销售、采购、出租厂房、租入设备或合计。

因此参考端可以完整解释这些表格金额。例：123.48万元同时是2023年“出租厂房给新菲光”的金额，也是该对手当年的合计；9,222.97万元在第4页是新思考相关“应付账款”2023年末余额，不能改称实际交易额。

## 2. 为什么22条还不是完整节点Gold

原始任务要求“抽取当前公司立场及既往实际交易，保留对象、期间、单位和列角色”。它包括非数值的公司立场、归属的主张；原输出也含claims。旧22条只覆盖两张表及落款，不能证明完整覆盖公司立场、全部必要主张或其他entity_attribute。

原Prompt没有规定必须逐一枚举21个单元，也没有规定合计与所有分项都算等权必要要求。因此不能把模型未逐格列出视为21项中的FN。否则会事后改变F1的必要内容分母，并重复计算合计及其组成内容。

这不是重新定义原Gold，而是区分“来源表格集合完整”和“原任务必要要求集合完整”。旧参考自己也明确complete_task_reference=false，本轮核验支持这个边界。

## 3. 输出角色为什么仍有不可识别部分

原Schema只有entity_id、粗粒度actual_transaction_amount、time等字段，没有独立issuer_role、counterparty、transaction_row_role或total/detail字段。原系统提示也没有规定entity_id只能代表issuer。因此GLM把新菲光/新思考填入entity_id，不能仅因不同于参考中的issuer就判事实错误。

其他模型填issuer也不等于已声明交易对手或行角色。不能从任意local_id的英文名称推测遗漏的语义字段；证据ID定位可单独检查，但不能偷偷把被选片段里的全部含义当成模型已经正确声明的内容。这会把证据选择指标和内容指标重新混在一起。

数值唯一匹配可以定位候选参考，不能独自证明交易方向已正确表达。重复零值、分项与合计同值更不能任意一对一匹配：例如2024年的0可出现在不同对手、不同交易行或合计中。不存在唯一绑定时，不判TP，也不判模型错。
