本轮结论：**NODE_CAPABILITY_FRAMEWORK_OFFLINE_READY**。已形成可运行的条件能力测量入口、24个完整请求模板、来源可核验的固定输入、质量记录接口及空矩阵；本轮0付费模型请求、0GPU、无完整DAG执行。不再以反复修同一抽取节点作为下一轮研究目标。

## 1. 测量对象和实际节点

原图 `opinion_multisource_dag_v1/GRAPH.json` 保持不变：6节点、6依赖边，来源是人工审定任务图，不能称本轮LLM自动规划成功。

|节点|测量职责|共同输入|输出合同|
|---|---|---|---|
|extract_current|当前公告事实抽取|原公告全部冻结窗口、同一目标和截止|quote.v2轻量候选测量合同|
|extract_media|新闻主张及归属抽取|冻结媒体短片段和同一目标|原OPINION_CONTRACT_V2|
|retrieve_history|历史预计/暂估口径检索|冻结历史公告|原OPINION_CONTRACT_V2|
|reconcile|多源金额、时间及范围关系核验|固定的三路合法前置输出|原OPINION_CONTRACT_V2|
|assess|有引用的受限风险与可靠性分析|固定事实、主张及UNKNOWN关系|原OPINION_CONTRACT_V2|

reconcile的既有纯工具实现只合并血统，不能替代这里对关系分类与说明的条件能力测量；本协议选择让LLM执行该图原有语义职责，不添加节点。文件读取、来源版本、跨度/合同/时间校验仍由确定性程序完成，不为它们调用模型。若未来只测纯工具合并，应另列确定性基线，不让四模型虚耗请求。

extract_current的轻量测量输出仍不同于原全图facts+claims完整端口合同。本批**不**声称这些真实输出可以直接传到原图下游。下游使用另行冻结的共同前置输入，正是为了隔离条件能力；真正端到端比较前必须做显式版本化端口消费接线，不能补造time、claims或置信度。

## 2. 合法前置输入与信息隔离

`NODE_SPECS.json`按原图的祖先闭包构造各节点输入，保留字段、ID、来源版本及数据依赖。相同节点四模型的messages和input_hash完全一致。

下游参考输入来自旧 `opinion_contract_v2/STUB_OUTPUTS.json`，身份明确为**既有人工编写的Stub参考前置状态，不是真实模型上游输出，不是Gold或完整正确答案**。本轮只读复核每项原文引用及各前置节点合同、依赖和最低来源覆盖；已通过的来源事实可以作为条件输入，关系/风险的语义真值仍UNKNOWN。它不是证明“语义完美”的Oracle上下文。

请求只包含当前目标的来源、任务、输入和Schema，绝不包含该目标的期待输出对象。旧参考输出作为祖先合法状态使用，不能被当成待测模型质量标签。每个单元重建独立Guard，无共享候选注册表、无客户端结果缓存；当前单元的输出、耗时及质量不会进入后续单元输入或选择。旧失败样本不混入新批的前瞻分母。

四模型全跑属于**离线能力测量**。未来实际调度是每个节点选择一个模型，不能把24次画像调用当成一次在线模型分配的成本。

## 3. 四模型配置和现实差异

|冻结请求模型ID|端点|模式|
|---|---|---|
|qwen-plus|DashScope compatible-mode/v1/chat/completions|enable_thinking=false|
|deepseek-flash|api.deepseek.com/chat/completions|thinking.type=disabled|
|glm-5.3|open.bigmodel.cn/api/paas/v4/chat/completions|thinking.type=enabled，reasoning_effort=low|
|glm-5.3-flash|同上Chat端点|项目既有Flash候选，冻结thinking enabled和low|

三供应商均Bearer认证，分别使用DASHSCOPE_API_KEY、DEEPSEEK_API_KEY、ZHIPU_API_KEY；默认离线启动绝不读凭据。未来独立授权后只在内存读取并用于官方认证，不写入Prompt、响应或账本。

前三模型文档依据延续[已冻结核查](opinion_three_model_extract_v1/OFFICIAL_INTERFACE_EVIDENCE.json)。[智谱官方GLM-5.3页](https://docs.bigmodel.cn/cn/guide/models/text/glm-5.3)明确不可禁用思考，不能暗中设成与Qwen/DeepSeek相同模式。Flash名称在本项目既有PARAM_RECOVERY_RESULTS中有真实记录，但本轮未验证其在新Chat端点的账户可用性及参数接受；官方模型页链接指向 `https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash`，本轮读取超时，未编造其内容。新增请求ID小写是本批明确冻结的候选，不能把旧Anthropic结果当成新Chat接口已验证。返回model不在白名单即停止，不修改大小写/切端点重试。

全部请求同temperature=0、json_object、max_tokens=4096、非流式。GLM思考可能占用输出额度，4096并不意味着同等可见答案空间；参数相同也不代表相同采样分布。提供方内部缓存、分词器、动态别名权重及服务端排队均有差异。保留这些混杂，本批仅比较**冻结部署配置在同一节点输入下的观测**，不是纯权重受控实验。模型顺序按节点轮换以缓解固定顺序偏差，不按观测结果调整。

## 4. 质量不是一个伪造总分

每个格子保存原始输出、raw_schema_pass、adapted_schema_pass、evidence_guard_pass、适配类型、原生违规、实际usage、身份、request_id、费用状态和API/格子墙钟。

- **verified（限定范围）**：真实来源身份/哈希、原文跨度、数值支持、材料截止。extract_current独立L1参考还提供能匹配到原表的发行人、金额、单位、实际发生额角色、落款日期等字段准确性。
- **proxy**：引用覆盖、注册表实体一致性、结构/依赖完整性、声明不确定性。关系类型准确性、句子含义和风险严重程度不因Schema通过升级为verified。
- **UNKNOWN**：全任务事实precision/recall、没有独立参考的主张关系正确性、全部期间/列归属、主观研判和未来影响。不能填0、0.6或1作为模型质量先验。

`L1_REFERENCE.json`由来源规则独立生成，包含22项限定参考；数字不来自被评模型。整个任务参考不完备，`recall=null`。`verified_field_accuracy`仅在独立参考可匹配的字段上计算，同时保存分子、分母及字面无支持数量。合规失败保持在24格分母中，不能丢弃失败后只报高分。其他节点目前多为引用/依赖可验证及语义UNKNOWN，没有假装补齐六节点确认性Q矩阵。

## 5. 执行/失败协议与预算草案

独立实验入口：`opinion_node_capability_matrix_v1/RUN.py`。默认模式只验哈希、共同输入和合法祖先状态；仅 `--execute` 加新批准授权文件才可能访问API。

- 一事件×6个语义LLM节点×4候选模型=**最多24请求**，每格仅一次，禁止重试、修复、模型评审、额外规划或fallback。
- 每请求输出4096 Token；配置输出占额合计98304。输入Token及现金费用上界**未认证**，须对新24请求范围独立接受探索风险，不能沿用已结束三模型授权。
- 单请求120秒，完整客户端3600秒（含准入与保存），提前60秒停止派发以预留结束空间；24×120+60=2940秒，余660秒供准入与本地处理。缺时间不派发，未知usage保留UNKNOWN，不记零。
- **单格**格式、截断或证据合同失败：保存并结束该格，不修复；其他独立格仍用同一参考输入执行。这与上一批“首个合同失败全停”不同，已显式预登记，不能追溯改变旧批次。
- 网络/API账户异常、身份不明、不可恢复接口异常、资源风险：全批停止。永久排他claim防重复启动，派发前fsync记录预留。
- 无客户端缓存；服务端缓存Token单独记录。实际费用待账单以请求ID、UTC和模型核验，不能将估算写作已支付成本。
- API往返含网络和远端排队，不声称纯服务推理时延。客户端超时不证明远端取消或费用为零。

## 6. 从测量走向论文核心的五阶段

|阶段|下一步条件|公平比较与边界|
|---|---|---|
|节点能力|冻结共同参考输入后收集四模型各格结果|单事件一次只有可行性/差异线索，不是稳定能力排序|
|静态多目标分配|多独立事件中出现可核验Q、真实C/L及可利用差异|固定单模型、预登记固定异构、简单历史统计与优化策略比较；UNKNOWN不得转质量常数|
|完整DAG执行|各端口消费者显式兼容，让真实上游输出流向下游|同任务Single、同模DAG、异构DAG；计入规划、画像/路由分摊、接口和恢复成本|
|反馈路由|事件级留出、只用决策前数据及可部署反馈|固定模型、简单历史均值与反馈规则对比；当前标签不能提前进入选择|
|联合恢复|具有两个有意义合法范围，可靠状态/预测及真实动作数据|比较强两阶段与联合策略，不能预设FULL提高Q；Qmin/epsilon不变，D仍UNKNOWN|

节点质量不可相加或默认相乘获得Q_task。本轮没有定义这类聚合器，也没有用空矩阵运行优化器。任务时延的关键路径 `max_path ΣL`只是在无限并发/忽略争用等假设下的估算；真实部署需测排队、并行限制、网络、切换、接口、恢复及总起止，不能把串行画像的总和当DAG关键路径实测。最终任务质量与净收益必须由真实完整分配轨迹独立测量。

四模型全节点画像也不等于在线四模型ensemble；如以后采用并行投票，必须独立计入四份调用及聚合费用。
