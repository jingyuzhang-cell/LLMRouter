# 证据合法性—独立内容质量—执行可靠性：三层测量V1

**已完成零调用实现及既有24格的离线复评。** 原始24格仍为8格合同通过、16格拒绝；原始模型输出、原评分、来源、证据ID目录、Prompt、DAG和ZCODE均不改。本轮真实API0、GPU0、无Git提交。

代码和新结果：[opinion_measurement_three_layer_v1](opinion_measurement_three_layer_v1/)。本版是**事后探索性质量侧评**，不是新真实实验或原实验预登记确认性终点。完整Q尚未可识别，不编造0.xx或临时选权重。

## 2. 三层各回答什么

**L：合法性。** 原始`contract_pass`继续表示输出能否合法进入DAG；原生Schema、适配Schema、evidence_guard分别保存。Schema拒绝时，完整合同明确失败，而尚未运行的证据守卫保持UNKNOWN，不伪造“全部事实均错”。新评分不释放任何事实到线上。

**Q：独立来源内容质量。** 不调用`EvidenceState.accept/fact/metrics`来决定内容分数，也不使用模型confidence、自评或是否被守卫接纳。先从冻结原文独立生成参考并保存hash，然后才读取模型响应。事实内容参考匹配不依赖模型选中的evidence_id、声明的source_id、原合同结果；实际引用是否正确另行评估。匹配仅限该节点合法来源快照，不跨任务替换原始来源。

**R：执行可靠性。** HTTP响应、服务端身份、finish_reason、完整JSON、截断、超时/远端未知分别记录；格式违规不直接等于API可靠性失败。当前24份观测均有HTTP200、正常完成及完整JSON，原生Schema通过21份；不能因此声称事实正确或可靠概率已校准。

同一候选可同时出现多个错误，四类不是互斥分区：证据选择、内容/角色/期间、表示/Schema、执行可靠性。每个新侧评都附原始首错及原正式状态。

## 3. 独立参考及可识别范围

`INDEPENDENT_REFERENCE.json`共26条来源参考：原有21个年度交易表金额单元及1个落款日期，再由通用文本语法读取4个历史年度额度/暂估披露。新增解析规则不包含模型输出或硬编码金额答案，保留原始数值跨度、年度、单位、口径及文档hash。另为完整来源建立数值出现位置和明确余额行索引，识别“应付账款”等余额不属于交易发生额。

这些参考是**公司披露/原文内容**，不是世界真值、完整任务Gold或主观研判答案。历史规则只覆盖明确语句，不能声称完整覆盖所有表格。规则开发及评分发生在真实结果之后，不能把本版当独立未见事件的确认性评测。

每字段输出正确、错误、UNKNOWN、NOT_APPLICABLE、已评分分母、总候选数和可评分比例。UNKNOWN和不适用都不填0/1，空分母不产生1.0。未匹配参考的事实不自动判错；有独立余额行反证时，仍可确认角色错误。字段局部正确不能替代counterparty/row/实体角色或完整任务覆盖。

## 4. 真实复评：同样“拒绝”，信息已经不同

下表为`extract_current`，格式为**正确/错误/UNKNOWN**；单位证据一列另列不适用。所有原始正式合同仍拒绝。

|模型|参考覆盖的数值/日期等值|字段角色|年度精度|所选单位字面证据|
|---|---|---|---|---|
|DeepSeek-Flash|13 / 0 / 0|13 / 0 / 0|10 / 0 / 3|6 / 6 / 0，另1不适用|
|Qwen-Plus|13 / 0 / 0|13 / 0 / 0|9 / 0 / 4|3 / 10 / 0|
|GLM-5.3|13 / 0 / 2|13 / 0 / 2|13 / 0 / 2|13 / 0 / 2|
|Qwen-Flash|12 / 0 / 13|12 / 13 / 0|0 / 12 / 13|6 / 19 / 0|

这些候选集合不同，分母不同，不能把13/13和12/12简单排成完整模型能力排名。DeepSeek和Qwen-Plus存在“内容可匹配来源，但单位或角色证据ID错误”的候选；Qwen-Flash的13项角色反证及12项不受支持的日精度不因数字命中而消失。未评分金额不称错误，也不称正确。零/重复金额在多年度/多行出现而缺少唯一绑定时，年份可识别性也保留UNKNOWN。

历史抽取节点也获得有限的独立字段测量：GLM、Qwen-Plus和DeepSeek各有4条金额/口径可由新增明确语句参考支持，Qwen-Flash有2条；其他候选保留UNKNOWN。无需再付费重跑就能读取已有响应中的可用信息。

### 实体角色歧义不能伪装成模型事实错误

GLM部分候选把交易对手“新菲光/新思考”写入`entity_id`；旧参考按上市公司issuer约定记录，因而旧守卫拒绝。现有Prompt要求保留对象，却未以独立字段完整区分issuer、交易对手及row role。

新质量层只判断该实体是否为该条来源披露的参与者；不能仅因它不同于参考的issuer约定，就给“实体真实正确率0”。`entity_role_binding`对未明确的角色保持UNKNOWN；如果选的是明确不属于该数值参考的另一交易对手，仍会判参与者不匹配。**没有改旧守卫，也没有把GLM历史结果改成成功。** 这是后续完整语义评价需明确的合同含义，不应通过更多调用来猜。

## 5. 日期、单位、Schema与语义分别处理

- 有效的`2025-06-30`与`2025年6月30日`在离线内容比较中等价；无效日期不被修正，年度不能扩写为1月1日。本24格的日期精度问题是语义问题，不能伪称全部是中文/ISO格式问题。
- 用Decimal做元/万元/亿元的严格数学等价比较：123.48万元与0.012348亿元等值；123.48万元与123.48亿元不等值。仅评分内部比较，不改值、不替换单位、不重选证据。未支持的币种/单位保持UNKNOWN。
- Schema不合法的事实仍可独立评内容。例如缺role_evidence_ids不妨碍确认其数值与原文参考一致；但完整合同仍失败、不得下传。
- 原始3格Schema失败照旧；缺字段、额外字段不能被评分器自动补成合法输出。reconcile缺claim_ids不视为模型明确声明空数组。

## 6. 候选召回与合流的处理

`retrieval.py`只使用既有任务问题、节点subtask和节点允许来源，对原目录做确定性词法排名，生成最多12个建议ID。没有Gold、参考事实、正确数值、模型输出或任务答案作为召回输入；来源范围不变，全部原始ID仍保留，没有自动改错ID。

`RETRIEVAL_SHADOW.json`只是离线榜单，**本次没有改变任何实际模型输入**。若以后启用top-k过滤/检索增强，它将是新的输入协议，必须先测召回覆盖并新冻结；不能将旧24格称为检索增强实验，不保证top-k必含必要证据。

reconcile已不复制上游对象。新侧评保留逐关系格式/引用及事实属性比较，但这些只是兼容性proxy。事实ID合法、期间/口径相符或不同，不足以证明自由主张支持/冲突的完整语义真值。`relation_accuracy_independent`仍UNKNOWN，不用原合同的关系守卫给自己打Q。

assess/report同理：8个合同PASS不会变成8个主观高质量标签。未来影响、投资判断、开放风险质量继续UNKNOWN。

## 7. 能否交给调度器

`THREE_LAYER_MATRIX.jsonl` / `.csv`包含24行：原合同/格式、独立内容Q向量、证据选择向量、缺失mask、错误类别、原Token、费用状态和实际时延；`FIELD_LEVEL_REPLAY.json`可逐候选追溯。旧8通过/16拒绝不变。

本版**不冻结事后挑选的加权权重**，`weighted_Q`及`Q_node_full`均为null。局部可观察元组得分另存，有分母和覆盖限制，不能称完整事实正确率。完整召回、实体角色绑定、主张/风险质量未识别时，不能为静态分配填0，也不能让动态策略借其通过Qmin。

可交付给ZCODE的是版本化观测和局部质量向量，供离线分析；本轮未修改或更新调度器、奖励、Qmin、epsilon和deadline，也没有把同一任务的事后评分回写成当时在线先验。未来若需要标量任务Q，先补独立任务接受条件、实体/行角色及评价覆盖，再在新结果产生前冻结权重或适用评分；不以合同通过率作为Q。
