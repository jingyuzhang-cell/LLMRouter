## 3. 角色判定规则已经明确的部分

- **transaction_counterparty**：由交易表所属章节中的交易对手确定，不能因金额相同跨交易对手匹配。
- **transaction_item**：由行名区分销售、采购、出租厂房、租入设备，不仅比较数值。
- **transaction_amount**：单一交易行的年度实际流量。
- **total_transaction_amount**：显式合计行。即使金额等于某一分项，也保持不同来源身份；不能擅自把二者算重复或彼此替代。
- **balance**：某时点的往来余额，不能匹配为年度交易流量。相关余额不是原任务自动新增的必要输出，本版仅定义排除混淆规则。
- **entity_id**：原任务没有规定只能是issuer。合法交易参与者身份不等于已经声明完整issuer/counterparty角色，不能事后惩罚所有非issuer输出。
- **时间**：年度不能变成某个具体日；落款不等于独立发布时间。
- **来源**：匹配包含source_id与source_sha256，不允许跨来源版本。

`roles.match`只有完整、明确的内容身份才给MATCH；不同角色给NO_MATCH，缺少身份给UNKNOWN。内部Decimal单位换算只比较数学等价，不修改模型输出。函数消费的是已明确裁决的规范内容元组，**没有偷偷从旧响应补出新字段**。这些名称是评价侧身份定义，不是对冻结输出Schema的修改。

## 4. 为什么仍未通过完整Gold验收

目前不是缺少能抄进文件的正确数字，而是三项尚未成立：

1. **必要内容的闭合集合**：原任务要求公司立场，但没有穷举必须包含的原子主张。8个相关原文段落可能含多个主张，不能直接声称完整、唯一、等权。
2. **总计与分项的覆盖关系**：原任务没有规定必须输出21个表格单元，也没有指定合计能否代替分项。直接以21为分母会额外添加要求，甚至重复计权。
3. **历史输出角色可识别性**：参考现已明确角色，但原输出没有完整角色字段。数值相等、local_id英文名称、选中一个含有多个事实的片段，都不足以自动证明完整内容角色。

所有原文字符已进入44个段落索引，只证明文本覆盖，不证明必要语义集合穷尽。未审核段落明确标UNADJUDICATED，不静默丢弃；自由转述的蕴含、公司主张真值及未来影响保持UNKNOWN。

因此`scalar_ready`返回明确失败项：`TASK_REQUIREMENT_ATOMIZATION_UNRESOLVED`、`NECESSITY_AND_DOUBLE_COUNT_POLICY_UNRESOLVED`、`OUTPUT_CONTENT_ROLE_NOT_IDENTIFIABLE`及各要求尚未验收的具体编号。没有调用score.py算四个Q。
