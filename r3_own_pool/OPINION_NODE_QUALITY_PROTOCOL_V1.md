# 独立节点质量评分协议 V1

本版冻结评分定义与可执行聚合器；不生成新的模型观测，不改Prompt、Evidence ID合同、既有24格或ZCODE。它是看过探索结果后形成的开发协议，**不能追溯称为旧24格的预登记，也不能声称完全未受模型表现启发**。确认性使用须先对未见事件冻结独立参考及评分规则，再产生模型响应。

## 1. Q究竟表示什么

定义 `Q_objective(node, model, task)` 为：在明确限定的节点任务范围内，输出是否正确完成独立、可核验的内容要求。它不是合同通过率、模型confidence、未来经营判断正确率或模型成功概率。`Q_full`继续保留UNKNOWN，尤其不把开放研判质量压成伪精确数字。

本版采用**原子要求级、等重要性的F1**，不为模型擅长的字段设权重：

`Q_objective = 2TP / (2TP + FP + FN)`。

TP为唯一匹配且所有必要内容属性正确的要求；FP为独立证据确认的错误断言或重复要求断言；FN为完整参考中未完成的要求。合法且独立证实的额外内容单列，不加分、不罚分；无法验证的额外内容为UNKNOWN，不能假装正确。重复表达先按冻结原子化规则去重；真实重复提交相同要求才作为重复项。

选择F1是本版公开的规范性取舍：同时约束错误输出和遗漏，避免只输出一个简单事实取得高分。它**不是无价值判断的自然真理**，也未证明适合任务级效用；原子要求的划分本身影响权重，必须在响应产生前冻结，不能拆分某模型容易做对的要求抬分。本版不做结果驱动调参或新增加权组合。

**标量准入同时要求：**任务范围封闭、范围内参考完整、输出原子化和匹配规则冻结、每个输出原子均有独立裁决、参考及证据版本可追溯。任一不满足，Q为null并记录具体缺口。UNKNOWN不从分母悄悄移除后产生高分，不填0或1。解析失败导致无法辨识输出内容时Q为UNKNOWN；独立确认输出为空且参考完整时才能记遗漏并得0。执行合法性另报，不借内容得分解除守卫。

## 2. 六节点的独立评分单位

|节点|原子要求及正确条件|独立依据|当前尚缺什么|
|---|---|---|---|
|extract_current|一个明确表格单元/披露事实：实体的issuer或counterparty角色、列角色、值与单位、期间及口径同时正确|冻结表头、行标签、跨页单位结构、原文跨度及哈希|现有21金额+1日期仅是局部参考；现输出没有完整角色字段，部分角色仍无法唯一解释|
|extract_media|一个新闻主张：谁、针对谁、何时、声称什么及FACT_ASSERTION/OPINION等性质|合法新闻片段本身；准确复述或可独立判断的等价转述|只有片段，不能评价全文召回；自由转述的语义等价不能靠字符串匹配自动裁决|
|retrieve_history|一个历史披露事项：主体角色、发生/披露时间、预计额度/实际/暂估口径及数值单位|历史公告独立表格/明确句式|已有4条规则参考不代表历史任务完整参考|
|reconcile|一个任务必需的事实—主张比较或未决项：对象、期间、口径及关系判断均成立|上游冻结内容加独立关系证明规则/裁决；有差异不自动等于矛盾|稳定ID只证明引用合法；自由主张关系真值和必需比较集合尚未独立穷尽|
|assess|一个要求分析的风险议题：断言受既有事实支持、保留相应限制及不确定性|独立的证据蕴含与任务要求裁决|未来影响及风险等级没有可靠真值；仅有引用不证明断言受支持|
|report|一个必须传达的事实/差异/未决项/证据限制，内容忠实于来源且无错误新增|冻结任务要求与独立事实/关系裁决|报告覆盖要求及自由文本支持关系尚未封闭；篇章风格不计客观Q|

对一个事实的数值、单位、实体、时间、角色不分别堆权重：完整元组才贡献一个TP。各字段正确率仍独立报告，供归因；无法确认实体角色时，不因值正确给整个事实TP，也不直接判FP。

`assess/report`若只对可验证的有限要求评分，必须使用明确的scope_id，例如“来源忠实与必要信息传达”，不能改名为“风险研判正确率”。无法独立裁决的主观结论保留UNKNOWN。不能要求所有六个节点一定都有0.xx。

## 3. 三组指标继续分开

1. 内容：上述Q_objective及逐字段正确/错误/UNKNOWN、参考覆盖范围、TP/FP/FN、可裁决比例。完整召回只在完整参考范围内成立。
2. 证据：文档/事件/版本/时间合法性、所选片段对值/实体/单位/角色的支持；ID存在和quote命中属于必要检查，不能单独证明语义正确。部分字面支持指标标proxy。
3. 合同与执行：原生Schema、适配Schema、守卫、是否可下传、错误类别；HTTP、截断、Token、时延、费用待核验分别保存。合同失败不自动等于内容全错。

内容Q不使用原守卫是否accept作为标签。来源忠实不等于外部世界真值；未来经营影响、市场情绪走势、投资价值仍UNKNOWN。

## 4. 独立标签与信息隔离

参考文件必须有event_id、node_id、scope_id、required_atom_id、实体角色、字段角色、期间/口径、来源跨度/哈希、正确性依据、完整性声明及审核身份。没有完整性证据不得填reference_complete=true。

裁决文件逐输出原子保存raw_output_hash、output_atom_id、原文位置、CORRECT_REQUIRED/CORRECT_EXTRA/INCORRECT/UNKNOWN、匹配要求ID、独立证据与理由。与模型身份、Token、时延及价格分离。评分员不先看模型名称和排名；先封存参考，再读响应，不能根据响应增加“必要要求”。匿名化只能减少偏差，不能消除开发人员已见结果的事实。

优先采用来源规则自动验证；规则不能可靠证明蕴含时留UNKNOWN。若需要独立人工/专家裁决，须单独声明其成本、分歧与复核规则；本版没有添加人工Gold，没有调用LLM评审。另一模型裁决也只能是单独验证过的proxy，不能自动升级确认性质量。

## 5. 可执行接口与限制

`opinion_node_quality_protocol_v1/score.py`只聚合独立裁决，不读取模型、守卫或confidence。输入为必需要求ID、逐输出原子裁决、范围/规则身份及完整性状态；输出Q、分母、UNKNOWN与不可评分原因。标量门禁是数据声明的消费接口，不是独立标签真实性的证明，正式使用前还需审核参考与裁决证据。

12项合成断言覆盖完美输出、遗漏、重复、错误、UNKNOWN、局部参考、缺独立裁决、正确额外信息、不存在参考、重复输出身份、空回答与不冒称完整质量。合成测试不证明真实语义裁决已完成。

## 6. 既有24格与ZCODE边界

旧24格仍是8通过、16拒绝；原始侧评向量照旧。本版**不复算、不排名、不填满24个标量Q**。旧数据只用于开发和错误分析，不用于对新评分协议的确认性收益宣称。

将来提供给分配器的记录必须带node/model/event、input_hash、contract_hash、rubric_hash、reference_scope、Q_objective或null、可识别mask、C的币种与账单状态、L的起止定义。Q是一次条件化质量观测，不是质量概率先验，更不是足以通过Qmin=0.8的可靠保证。多事件留出与历史截止验证后才可估计预测能力。正式Qmin/epsilon/D及聚合语义由原协议保持；本版不修改ZCODE，也不把不同节点的局部F1直接相乘作任务成功率。

## 7. 唯一下一步与结论

**下一步先完成一个节点的独立参考可识别性验收，不发模型请求。**优先extract_current：在既有来源中冻结明确的表格事实范围与issuer/counterparty角色解释，逐要求证明表头、行、期间、单位及来源；检查旧输出哪些可唯一解释，不能解释的继续UNKNOWN。若现有输出结构无法辨识角色，明确这个字段缺口，不能靠评分器猜。该工作是评分参考验收，不是再改Prompt追求模型通过。

完成后可发布该限定范围的客观Q，其他节点逐一满足同样条件；不为了整张表有数字而伪造关系/主观质量。暂不新增24次调用。

结论：`SCORING_SPEC_FROZEN`；`FULL_Q_MATRIX_NOT_READY`。目前具体阻塞是参考清单的完整性、实体角色可识别性及关系/自由断言的独立裁决，不是模型接口或缺少新的真实请求。本轮完成后停止。
