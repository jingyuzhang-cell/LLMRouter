# 模型级预算上界补充核验

结论：不能认证原CNY3.50/USD0.05为现金硬上限；本轮不改变预算、不启动调用。

精确Tokenizer并非数学上界的唯一途径：可以用模型允许的最大计费长度替代。但这种粗界会很宽，并且必须使用对应长度档位的价格。Qwen不能在模型级长输入情景仍沿用0.8/2低阶价格。

三模型官方上下文标为1M，本核验用2,000,000 Token覆盖十进制/二进制解释及整个输入封装；对Qwen用北京非思考最高阶输入4.8、输出48元/百万，DeepSeek用峰值未命中0.3/1.2美元，GLM用8/28元。均为公开接口假设下的用量费用情景，不是现金扣款认证。

|情景|CNY总额|USD总额|
|---|---:|---:|
|每次输入2M，输出仍按冻结1024/8192|84.215808|1.2024576|
|输入和输出均用2M粗界，不依赖请求输出上限语义|499.2|6.0|

这不意味着18KB提示词会实际花费上述金额，也不证明真实请求必然超过原信封；只是模型级粗界不足以证明小额现金上限。公开上下文约束能帮助限定正常计费用量，但不能替代账户计费规则、异常失败请求扣费与供应商现金控制。

## 明确的下一决策

- 坚持小额现金硬上限：当前维持HOLD，需供应商完整Token计量/封装依据或供应商端可执行的现金控制。已有P50/P95和13项执行测试都不能弥补这个证据。
- 若用户明确选择探索性小额估费信封：可继续完成受限HTTP发送接线；原8请求、36,864输出Token、无重试及失败停止不变。该选择不自动授权付费执行，也不把估费改称硬预算。

当前真正的限制是预算风险政策与外部计费证据，不是再缺一轮FakeMeter测试。为避免继续循环，不新增通用机制测试、不调整实验定义，不自行提高预算。
