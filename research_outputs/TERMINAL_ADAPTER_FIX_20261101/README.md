# 终端评分接口修复（隔离副本）

修复已实现，16条已保存输出完成影子回放；没有部署到ZCode当前运行器，也没有修改旧成绩。所有源码和数据均留在本目录。

## 修复范围

- 以任务事前公开fact_id绑定subject/predicate/unit/date_type；value、quote保持模型原值，不从参考答案补值。
- adapter只接收明确白名单槽位；包含value、description、source_evidence、accepted_values、derivation等额外字段时拒绝，减少参考泄漏。
- 显式输出的主体/单位等与槽位冲突时保留冲突，不自动纠正。未知fact_id保留，不删除以美化分母。
- 用完整引用做空白归一化定位，唯一命中才附加原始文档ID、页码、字符跨度和哈希。不同位置重复出现即报告歧义，不按答案选择，不取第一个短前缀命中。
- 页面文本哈希重新计算；原始PDF哈希沿用已有清单，不宣称本次重新核验原始PDF。引用可定位不代表它支持事实，仍由冻结评分器检查。

## 实际验证

SHADOW_RESULTS.json保存16条结果及每项定位诊断。16条影子事实F1均非零，排除了原始“缺字段导致全0”的接口故障。原在线分数仍保留为0，不改判。344条引用中134条唯一定位、171条歧义、39条未匹配。证据门禁16/16仍FAIL，完整终端Q未据此提升。

引用定位比旧的首24字符命中更严格；不能将较多歧义当作模型内容全部错误，也不能为让门禁通过放宽规则。优先在未来输出合同中携带真实doc_id/page，重复引文保留明确上下文；这种改动不能事后冒充原实验输入。

已有Gold身份及参考答案泄漏问题不由本修复消除。影子回放不是新实验、不是独立终端质量证明。

## 接入与复算

`online_adapter.adapt_sink(sink_text, contracts, tid)`提供与原runner同名同参数的适配函数；只解析一个完整JSON对象，不执行模型。将其导入**未来新版本运行器**即可替换适配调用；不要覆盖已结案runner或旧结果。适配只负责槽位和引用，不补造question_relevance等评分判断，也不将UNKNOWN置零。

- 边界验证：`python -B -m unittest -v test_adapter`
- 历史影子回放：`python -B replay.py`

已验证7项边界：字段补齐且值不变、私有槽位字段拒绝、全文而非前缀匹配、歧义拒绝、显式冲突保留、篡改哈希拒绝、未知事实保留。冻结评分器、ZCode原runner/事后适配器、原pairs及final_report在回放前后SHA-256一致。零模型调用，零费用。

## 新来源ID接口（未来协议候选，不追溯旧实验）

`evidence_registry.py`提供源文档注册、定位与`adapt_registered`评分接入。只依据全文、源哈希和机械分句生成片段（最长512字符）；不根据Gold事实裁剪，不读取参考值。不改节点分配和评分器。

新协议输出使用`answers:[{fact_id,value,evidence_ids:[...]}]`。程序从所选ID还原quote/doc_id/page/start/end及哈希；未知ID、混用旧quote接口、重复ID、页面/注册表篡改均拒绝。位置消歧来自ID本身，不是从答案猜选证据。旧输出没有ID不能自动补成新协议的成功结果。

PUBLIC_REGISTRIES/INDEX.json包含新收集三个任务的92/137/252个片段，共481个，全部通过原文跨度回取验证。HTML的page=1明确标为HTML_LOGICAL_TEXT_UNIT，不冒充PDF页号。资料仍为未独立裁决研究材料；来源注册不能认证任务独立性。

允许选择多个ID，但每个ID必须是给模型看过的登记片段；引用多段不自动证明语义关系成立。机械片段可能截断长句或涵盖无关内容，因此原评分器的支持性检查仍必须保留；不能靠整页拼接覆盖Gold跨度骗过门禁。没有承诺修复全部语义支持错误或提高真实模型通过率。

`test_registry.py`验证重复原句按位置区分、未知ID拒绝、源版本变化拒绝、注册表改写拒绝、错误value不修补、构建稳定性。无模型调用。ZCode源码、原批次、原评分器与旧影子结果均未改动。下一步需要在未来版本明确采用该接口，不能将其当作本轮真实实验已验证。

## 模型可见证据范围与评分接入

新增`evidence_input.prepare`生成仅包含问题、公开槽位和本次可见片段的消息，并生成派发侧可信receipt。`finish`校验消息/槽位哈希、任务身份、实际可见ID、登记片段版本，再通过`adapt_registered`转成冻结评分器所需的terminal对象。

即使证据ID在总注册表中存在，未在该次消息中提供也拒绝。模型不能提供或替换receipt；调用方必须保存由prepare生成的派发侧receipt。此约束依赖可信调用方保管receipt，不声称提供外部签名或OS隔离。

六项集成检查通过：完整路径保留错误value、未见片段拒绝、跨任务未知ID拒绝、输入文本篡改拒绝、槽位变化拒绝、登记片段变化拒绝。测试响应是明确的内存夹具，不计入模型实验。未新增模型调用，未改变原始任务评分或ZCode程序。

到此，字段交接、唯一原文定位、来源ID和本次可见范围这条离线接口路径已收口。它尚未部署到真实运行器，也未验证模型是否稳定遵循新输出协议；证据语义支持和终端质量仍交原评分与审阅流程判断，不能把位置检查当作事实正确性。
