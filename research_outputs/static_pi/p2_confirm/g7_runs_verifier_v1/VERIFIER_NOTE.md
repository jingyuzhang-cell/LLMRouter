# 核验器实例化修正归档（2026-11-11，第3次启动后停止）

现象：修复docs_norm后块1数据健康（G6-M answers 14/引文12），但G7臂核验器将D1告知书引文12/14判"终"
（告知书公告转述的处罚条目多为无"拟"字前缀的裸条目），14/14全部判失败，2次重锚定徒劳耗尽。

根因：核验器提示词实例化偏离预注册§4.2——§4.2规定输入为(fact_id, document_id, verbatim_quote)，
document_id为合法判阶依据；我的实例写成"仅按quote文本自身语义、不使用外部信息"，事实上禁止了文书语境，
与R2"引文语义（决定书记载拟处罚内容对拟阶段事实有效）"的语义模型不符。

修正（v2，依§4.2）：判阶=句内显式阶段标记优先（"拟决定/拟对"→拟；无标记时按文书语境基线
（D1=事先告知书→拟；D2=决定书→终，除非句内含拟标记））。跨度级Gold判阶不受影响（analyzer独立）。

损耗：11次调用（块1），归档记账；正式账本重启。偏差链：implfail_v1(docs_norm)→interrupted_v2(基础设施)
→verifier_v1(本归档)——全部如实记录，均属实现/实例化层，预注册与Gold未改动。
