**依据**：操作员 2026-11-07 P2-B 结题指令第三节。
**问题**：P2-B 中 G1 与 G2 的信息基础不一致，G2−G1 的差混入了确定性基础设施效应。

## 一、P2-B 中的信息不对称

## 二、修订方案

### G1 修订（P2-C 执行版）

G1 获得与 G2 相同的**确定性支持**（不依赖模型调用的基础设施）：

| 新增 | 内容 | 来源 | 是否模型调用 |
|---|---|---|---|
| ✓ | 确定性派生值行 | 代码直接从原文解析处罚行并求合计（与 base_total_v2 同逻辑，但直接读原文而非 E_D2 输出） | **否** |
| ✓ | M3 后处理 | V5 M3 检测 → SELF_EVIDENCE_INCONSISTENT 转未知 | 否 |
| ✗ | 证据表 | **不提供**——这是 E 节点模型调用的产物，提供即等同于执行了部分 DAG | — |
| ✗ | J2 核验 | **不提供**——这是 J2 模型调用的产物 | — |

### G2-G6 不变

保持 P2-B V1.1 的完整 DAG 管线（E→J1→J2→SINK + 证据表 + 派生值 + M3）。

## 二-A、派生值数据源统一（操作员追加要求）

**问题**：P2-B 中 G1 的派生值来自原文、G2 的来自 E_D2 输出——输入来源不同，可能因 E_D2 漏提而产生不同合计。

**修订**：六臂共用同一个派生值，统一从 **D2 原文** 直接解析处罚行并求和（不经过 E_D2 模型输出）：

```python
# 在 runner 中替换：base = BT.total(OLD.extract_json(e_texts['E_D2']), docs['D2'])
# 为：
def source_base(d2_text):
    """从 D2 原文解析处罚行，确定性求和（不经 E_D2 模型输出）。"""
    flat = re.sub(r'\s+', '', d2_text)
    parties = []
    for names, amount in re.findall(
        r'[一二三四五六七八九十]+[、（(](?:对)?(?:责令)?([^。;]{1,300}?)(?:改正[，,])?'
        r'给予警告[，,]并(?:分别)?处以([\d,，.]+)万元的?罚款', flat):
        for n in re.split(r'[、，,和及]', names):
            if 2 <= len(n) <= 15:
                parties.append(dict(name=n, penalty_amount=f'{amount}万元'))
    return BT.total(dict(parties=parties), d2_text)

base = source_base(docs['D2'])  # 所有臂（G1-G6）使用同一个值
```

- G1 的用户消息和 G2-G6 的 SINK 用户消息中的派生值行使用 **同一个 base 结果**。
- E_D2 模型输出不再参与派生值计算（仅供证据表和 J1/J2 使用）。
- **如果程序解析与 Gold 合同不一致：停止该任务的派生值注入，检查解析遗漏/重复/金额归属，人工核对原文，修正后重新通过离线校验。** Gold 经人工核验，作为独立校验基准，不因程序解析结果而推翻。（操作员 2026-11-07 修正：原文"以原文解析为准"有误，ST索菱曾真实发生正则遗漏公司 60 万。）

| 对比 | 测量内容 | 混杂控制 |
|---|---|---|
| G2 − G1 | 多智能体分解 + 证据表 + J2 核验的联合价值 | 派生值与 M3 已统一 |
| G6 − G2 | 动态调度的增量价值 | 不受 G1 混杂影响 |
| G6 − G3 | 有害恢复规避能力 | 不受 G1 混杂影响 |

**G2−G1 仍包含证据表与 J2 的效应**，因为这两者是多智能体分解的产物。要进一步分离"分解本身"与"信息供给"，需要额外的消融臂（如 G2-no-evidence），但这超出 P2-C 范围，留作讨论。
