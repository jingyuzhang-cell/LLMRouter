# RQ2 V1 Phase 1/2 结果与独立审计

**状态：零真实 API；192 次额度继续 HOLD；本轮不宣称 70% 达成，也不启动真实实验 GO。**

**核心结果：F-AR（反馈换模）没有超过静态 MGC；V-CR（验证+局部修复）能显著提高终端 Q，并在 stable .20 的 15%/20s 预算下名义达到 GQ/GF/GR/JOINT≥70/70/95/70（JOINT=.76），但 H0（两模型能力完全相同）仍有 JOINT=.31。A3 假阳性审计失败，因此 J-MO 按预注册审计门停止，不运行。**

---

## 0. 指标口径（再次确认）

- `GQ/GF/GR/JOINT` 是 100 次切分的**验收通过率**，不是模型准确率。
- `Q` 是终端绝对质量；`ΔQ` 是相对 Static 的绝对提升。
- stable .20、20% matched 的 R5 基线：Static Q=45.48%、MGC Q=52.99%、Node-Type Q=55.89%；GQ=46%、GF=79%、GR=99%、JOINT=42%。
- 本轮 Phase 1/2 的 `Q` 和通过率分开报告。

---

## 1. Phase 1：F-AR（反馈驱动动态换模）

### 1.1 策略

- 按 DAG 拓扑执行；每个节点执行后得到父节点事实的 TP 比例 `q`。
- 在成本/时延约束内，用阈值策略决定下游是否消耗 GLM token：
  - 10/15%、20% strict：最多 1 个 GLM，候选 `m,v,p`（均满足 Makespan ≤1.10×Static）。
  - 20% matched：最多 2 个 GLM，候选 `m,r,v,p`（任意两节点组合均 ≤1.20×Static）。
- 阈值在 24 个训练任务上网格搜索；测试集只评估。
- 同 split 对照：Static、静态 MGC 代理（10/15/20s 用 `m`，20m 用 `m+v`）、per-task oracle（测试集选择，不可部署上界）。

## 2. Phase 2：V-CR（独立验证 + 局部修复）

### 2.1 机制与预注册

- 基础执行：固定可行分配（`DS`=all-DS、`m`、`m+v`）。
- 验证器对“坏事实”（非 TP 或定位/支持失败）以 `sens` 概率标记；对“好事实”以 `1−spec` 概率误报。
- 被标记事实尝试一次局部修复：成功概率 `p_rep`，成功则设为 TP∧定位∧支持；每次尝试计 `c_rep`（节点价格单位）和 `l_rep`（节点时延单位），误报也计数。
- report gate 失败优先验证/修复（`sens_gate`）。
- 优先级：gate → 关键事实 → 其他 DEC 事实；`max_rep` 次；每次尝试前检查成本 cap 与 Makespan deadline。
- 所有随机数按任务 CRN；V-CR 与自身 base 在同一任务上比较。

### 2.2 初始参数被 H0 审计否决

初始参数：`sens=.80, spec=.90, p_rep=.75, c_rep=.02, l_rep=.02, max_rep=3`。

- stable .20 训练：Q 65.77%、ΔQ +21.38pp、成本 +10.9%、Makespan +9.0%。
- **H0（两模型能力完全相同）测试：Q 55.06%、ΔQ +16.19pp、GQ/GF/GR/JOINT = 1.0。**

**结论：初始 V-CR 参数不可接受。** 它能在“无模型差异”下独立制造通过结果；2% 节点成本/75% 修复成功率/3 次修复的假设过于乐观。不能作为 RQ2 成功证据。

### 2.4 关键审计结论

1. **初始 V-CR 被否决**：H0 JOINT=1.0；参数不可信。
2. **保守 V-CR 在 stable .20 的 15% 和 20s 名义达标**：GQ .78、GF .95、GR 1.00、JOINT .76；成本 +12.9%、Makespan +8.6%。但 **H0 仍有 JOINT .31**。
3. **10% 预算失败**：stable .20 DS+V-CR ΔQ +.0693/GQ .32，与 H0 +.0704/GQ .31 几乎相同——**10% 下的增益完全来自随机纠错，不是模型差异**；m+V-CR 无修复空间（成本 cap）。
4. **20% matched 的 m+V-CR JOINTm .99，但 strict 10% Makespan 下 GRs=0**（Makespan +12.5%）；strict 目标不成立。
5. **stable .15 15% JOINT .56、20m strict .01、mixed .20**；70% 目标未达成。
6. **终端 Q 仍只有 54.19%（15%/20s）和 56.87%（20m）**；70% 终端 Q 未达到，也不能用 GQ .78 代替。

## 4. 如何解释“70% 名义达标”

- stable .20、15%/20s、m+V-CR：GQ .78、GF .95、GR 1.00、JOINT .76，**名义上满足 70/70/95/70**。
- 但 H0 的 V-CR 单独就有 JOINT .31；10% 下 V-CR 的 ΔQ 与 H0 几乎相同。
- 因此这 70% 不能全部归因于“异构模型调度”；它至少部分来自验证/修复对随机错误的纠正。
- 要把它变成可信的 RQ2 结果，必须做 **2×2 factorial**：模型异质性（stable vs H0）× 验证（off / sham / real），并报告交互效应；目标应写成“**在 H0/sham 对照下不通过，而 stable 下通过**”，而不是只看 stable 的绝对通过率。

---

## 5. 结论与下一步

1. **F-AR 失败**：父节点 q 阈值换模没有超过静态 MGC；per-task oracle 的差距仍在，但需要更强的在线信号/学习策略，不能靠单阈值。
2. **V-CR 有真实效果，但当前验收被混杂**：保守参数在 stable .20 15%/20s 名义达标，但 H0 31%、10% 失效、20m strict 失败、mixed/stable .15 不足。
3. **J-MO 不运行**：A3 失败；先解决验证机制的混杂，再谈联合调度。
4. **下一轮修正设计**：
   - 加入 **sham verifier**（无信息验证：sens=spec 或 repair=no-op）和 **2×2 factorial**；
   - 修复成本/时延按“一次模型调用”量级重新标定，而非当前 2% 节点成本；当前保守参数已改为 10%；
   - 目标改为条件目标：stable JOINT≥70 且 H0/sham JOINT≤5%（或交互显著），否则保留失败；
   - 10% 预算不作为 70% 目标的可达区间，除非验证成本显著降低；
   - terminal Q 单独设目标；当前最高保守 Q 56.87%，不是 70%。
5. **零真实 API；192 HOLD；不申请 GO。**
