| 费用差 | +¥1.56（¥9.534 → ¥11.092） |

逐任务终态差：E05 **−42.42pp**、E06 **−19.44pp**、E07 0、E08 **−23.33pp**。
逐任务 raw 差：E05 **−18.18pp**、E06 **−2.78pp**、E07 0、E08 **+3.33pp**。

**结论（分三层）：**

1. **终态层：C 更差。** 点估计 −21.30pp，cluster CI 全在 0 以下；但 n=4 任务，精确符号置换 p=0.25，不能宣称确证性显著。按预注册的机制验证口径，这是**强方向性负证据**，不是确证性结论。
2. **事实层：差异不显著。** 去掉 report 门后，C−B 只有 −4.41pp，CI 跨 0；E08 的 C raw 甚至 +3.33pp（C 80.0 vs B 76.67）。所以“GLM 抽不出事实”不成立；C 的事实质量与 B 接近，E07/E08 持平或更好。
3. **失败层：GLM 的终态交付。** C 的 report 门通过率 66.67% vs B 91.67%；C 有 **4/12** 次 report 门失败（E05 r2、E05 r3、E06 r1、E08 r2），B 仅 1/12（E05 r1）。C 的 chosen 解析失败 **12/57**（GLM 11、DS 1），B 仅 **2/57**（DS 2）。C 的失败集中在 reason（4）、report（4）、verification（3）——正是分配给 GLM 的节点类型。GLM 在 2000-token 上限下输出更长/更易截断，导致 `stop=max_tokens`、JSON 不完整、report 门失败。**这不是“异构模型更笨”，而是“当前异构分配 + 固定 token 上限”在终态交付层不可用。**

**为什么终态负值大于 raw 负值**：C 的门失败不是随机均匀的，而是偏向事实更多、raw 更高的 rep（E05 r2 raw 81.8、E08 r1/r2 raw 80.0）。这些 rep 的终态被门判 0，拉低了 C 的终态均值；门内条件 Q（57.31%）也因此被负选择偏差压低。raw Q 是更干净的能力度量；终态 Q 是部署度量。两者都重要，但不能混用。

**成本**：C 比 B 多 22 次调用、多 ¥1.56、多 102.4s，却终态低 21.30pp；C 不具成本效益。C 的 cited facts 更少（370 vs B 604），但核验调用更多（230 vs 219）——GLM 的 report/merge 复述更少，去重命中率更低（37.8% vs 63.7%），单位事实的核验成本更高。

## 6. 机制与成本结构

### 6.1 终态门与截断

- C report 门失败 **4/12**，全部伴随 report 调用的 `stop ∈ {length, max_tokens}`；B 1/12，伴随 `length`。DeepSeek 的 stop 叫 `length`，GLM 叫 `max_tokens`，语义相同。
- C 的 chosen parse 失败 **12/57**（GLM 11、DS 1）；B 2/57（DS 2）；A 2/57（DS 2）。
- C 的失败按节点类型：extract 1、reason 4、report 4、verification 3——GLM 承担的三类节点全部中招。
- 典型例子：C|E08|r1 base report 截断（2000），reroll 1716 tokens 成功、18 条事实被采纳，终态门通过；C|E08|r2 base 截断，reroll 仅 544 tokens 且 0 事实，未采纳，门失败。**同一个 GLM report 节点在不同 rep 间可成功/失败，取决于输出长度，不是事实质量。**

### 6.2 去重核验（本批次的成本关键）

| 臂 | cited facts | verify calls | unique | reused | 复用率 | cap hits |
|---|---:|---:|---:|---:|---:|---:|
| B | 604 | 219 | 219 | 385 | 63.7% | 0 |
| C | 370 | 230 | 230 | 140 | 37.8% | 0 |

- 不做去重，B+C 需要 **974** 次核验（604+370），仅核验就超过 800 上限；去重后 **449** 次，节省 **525** 次（54%），是本批次能完成的前提。
- 去重按“每执行唯一 `(fid,value,doc,quote)`，首次判定复用”，安全上限 64，**0 次触发**；没有截断事实。
- C 的复用率低（37.8% vs 63.7%）：GLM 的 merge/report 更少逐字复述上游事实，导致更多唯一核验、单位事实成本更高。这是去重收益的模型依赖性，值得记录。

### 6.3 重掷与异常

- B 重掷 1 次被采纳；C 2 次被采纳（含 C|E08|r1 的 report 恢复）。
- 无 `prod_missing`/`cite_missing`；异常几乎全是解析/截断。
- 逐节点“base vs reroll 槽位变化”无法计算：runner 只存被采纳输出，base 事实在采纳后未落盘。**这是仪器化缺口**；本报告只报告采纳计数与执行级 B−A/C−B，不伪造节点级重掷收益。
- 下游传播成本未单独隔离：B/C 的顺序执行成本包含所有下游调用，但没有“无重掷”的反事实；只能报告执行级成本差。

## 9. 审计、限制与不可外推项

1. **n=4 任务，非确证性**：任务级精确符号置换两侧最小 p=0.125；C−B p=0.25。cluster bootstrap CI 是探索性区间，不是确证性检验。不得写“显著优于/劣于”；写“点估计负向、方向稳健、非确证”。
2. **max_tokens=2000 是共同冻结约束，也是 C 的混杂**：C 的终态负值主要来自 GLM 输出截断/解析失败。本批次不能区分“异构分配本质上不好”与“GLM 需要更大的 report token 预算/结构化输出约束”。**不能在 V2 事后改 max_tokens 或阈值**；应作为 V3 的新预注册机制。
3. **真实任务不是 13 槽**：V1.5 Gold 每任务 10–12 个事实槽（共 44）。本报告 Q 与 R5 合成 Q（13 DEC 槽）不可直接比较；与 V1 中期/收口报告同一评分器。
4. **节点级重掷收益缺失**：base 输出未在采纳后落盘；无法做同节点前后槽位配对。下游传播成本也未隔离。需要 V3 的仪器化修复。
5. **无 H0 世界**：真实模型无法构造纯零世界；B 是模型无关重执行对照，C−B 是异构归因。不要把 C−B 解释为“对 H0 的拒绝”。
6. **A 复用 V1**：A 的 12 条是 V1 已完成记录，未重跑；B/C 为 V2 全新。旧 B4 Pilot 未混入主分析。
7. **评分修正已披露**：report 门从 base 信号改为被采纳输出；C|E08|r1 从 0 恢复到 80.0%。原始输出与 adopted 标记可复核；不是事后提高成功率。
8. **Token 记账**：V2 预算状态 482,758 = ledger 实际；V1 的双计已修复。GLM 缓存命中的 `in` token 计数可能偏低（同一 prompt_sha 的 base/reroll 出现 1623 vs 23），但不影响调用/费用口径；token 上限按执行器账本计。
9. **无阈值/成功率/评分标准修改**：B/C 的成功概率、提示、DAG、Gold、MOSE 未改；只改了核验去重、token 记账、arm 选择和停止守卫。所有失败执行保留。
10. **192 HOLD 未动**；V2 未使用。
