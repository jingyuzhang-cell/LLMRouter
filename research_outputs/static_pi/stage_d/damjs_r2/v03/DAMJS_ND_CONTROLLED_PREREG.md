# DAMJS_ND_CONTROLLED 预注册（正式版 · 2026-11-07 冻结）

**科学问题**：恢复操作失败时，多智能体 DAG 执行系统能否保留此前有效的执行结果（安全提交），使保护效果传递到真实下游执行并改善终端答案质量。
**证据定位**：受控条件下的因果机制验证。它只证明特定异常条件下的机制，**不代表自然服务环境中的平均收益**（后者由后续自然条件四臂实验验证）。注入的失败永不计入任何服务失败率统计。
**真实 API 调用未授权**：执行需单独 GO（`DAMJS_NDC_GO=run` + `STAGE_D_REAL_CALLS_AUTHORIZED=1` + 本文件 SHA 已登记于 `DAMJS_ND_CONTROLLED_MANIFEST.json`）。

## 1. 设计

**公共上游夹具 + 单点注入 + 两臂配对**（按操作员 2026-11-07 修订）：

每个重复 i：
1. **生成运行**（真实）：E1–E4 与 J1 首调真实执行；J1 产出有效 v1 后**立即终止**，其响应（文本/Token/墙钟）构成公共夹具 F_i；
2. **两臂执行**（顺序按预登记种子随机化，背靠背运行以贴近同一服务时段）：
   - 上游 E1–E4 与 J1 首调：回放 F_i（两臂逐字节相同）；
   - J1 修复调用：**受控注入**——2026-11-06 冒烟实录的 8,192 撞限空响应（in 1,690 / out 8,192 / 墙钟 119.83 s），两臂逐字节相同，墙钟在两臂执行时钟中一致体现；
   - J2 / SINK / FMT：真实执行，各自消费实际收到的 J1；
   - 调度策略两臂相同，EV 两臂均关闭（隔离 ND 效应）。
- 臂：R2（nd=off）与 ND-only（nd=on）；重复 ×3；场景 S3（J1 部署缺陷照常）；截止期 240 s。
- 执行器/看门狗/评分/身份校验与方案 A 完全一致。

## 2. 终点（按裁决的层级）

| 层级 | 终点 | 判定 |
|---|---|---|
| **主机制终点** | ND 是否逐字节恢复有效 v1（R2 是否发生破坏性覆盖） | 事件流逐字节比对，3/3 必须 |
| **主质量终点** | **配对 ΔTP（严格·归一）**，ND − R2 | 逐重复报告 + 均值，**不做显著性承诺** |
| 次质量终点 | 配对 ΔTP（宽松） | 同上 |
| 其他终点 | 引用支持率（CORRECT_GOLD / 有答案数）、下游节点有效性（J2/SINK 消费的 J1 是否有效）、ND 本地回滚开销 vs 全链路成本差 | 描述性 |

**统计定位（冻结声明）**：3 组重复为机制验证。即使 3/3 ND 胜出，单侧精确符号翻转检验最小 p = 1/2³ = 0.125，**不可能达到 0.05**；3/3 回滚成功支持执行机制正确，3/3 质量改善为方向性证据。确认性实验（如需符号检验：单侧 5 组全胜 p=0.03125、双侧需 ≥6 组，仅为理论下限非功效样本量）另行设计。宽严两个口径并列报告，不以宽松增长掩盖严格证据质量。

**预测（预登记）**：P1 R2 臂 3/3 破坏性覆盖、ND 臂 3/3 逐字节回滚；P2 配对 ΔTP 严格·归一 ≥ +4/重复（N2 反事实：宽松 +6、归一严格 +9），宽严同向；P3 ND 本地回滚零额外调用、本地零时延，但**全链路成本差按实测报告**（下游 J2/SINK 因消费不同内容，Token/时延可能不同，不得断言为 0）；P4（失败判据）任一 ND 臂出现无效输出提交到有效输出之上（C1 违反）→ 机制失败，停批。

## 3. 记账（真实与模拟分离，冻结）

| 类别 | 记录 | 预算处理 |
|---|---|---|
| 真实 API 调用 | 次数、Token、实际现金 | 计入硬上限（保守） |
| 注入响应 | 历史-Token（1,690+8,192/次）、模拟核算费（¥0.0243/次）、模拟墙钟 119.83 s | Token/调用数计入硬上限（保守），**现金不计**；台账单列 |
| 注入墙钟 | 两臂执行时钟一致睡眠（1:1） | 截止期比较因此成立 |

台账每行区分 `real_calls / injected_calls / real_cash / simulated_accounting`。注入调用的结果类别为 `injected`：不进估计器任何计数、不触发锁存（防御性，两臂 EV 已关）。

## 4. 隔离纪律（硬性）

1. 每次执行记录 `controlled_injection=true` 与注入点清单；
2. 注入失败不计入任何服务失败率统计（先验、在线估计、后续任何汇总）；
3. 本批数据单独分层，永不与自然条件批次合并；
4. 生成运行与臂运行的身份块、组件校验与方案 A 相同。

## 5. 预算与停止规则

- 估算：每重复 9 次真实调用（生成 5 + 两臂各 2）+ 1 次注入；3 重复 ≈ **27 真实 + 3 注入 ≈ 30 次计入 / ~12 万 Token / 实付现金 ~¥0.16 / 模拟核算 ¥0.073**。
- 硬上限：**50 次调用 / 160,000 Token / ¥0.35（核算）**，共用 R2 全局授权账本，任一触顶即停。
- 停止规则：R2 批次五条 + V03_PATH_EXCEPTION + C1_VIOLATION（ND 臂破坏性覆盖）+ 注入点未命中（受控实验失效）。

## 6. 实现与验收（批准后零调用）

- 子进程新增三个开关：`APILOT_GEN_STOP_AFTER=J1`（生成运行在 J1 成功结束后写夹具并退出）、`APILOT_UPSTREAM_FIXTURE=<progress>`（上游回放）、`APILOT_INJECT={node,at,response}`（修复调用注入）。R2/ND 两臂同代码仅开关不同。
- 零调用验收（`test_v03_ndc.py`）：生成运行停在 J1；两臂上游与夹具逐字节一致；注入两臂逐字节一致且记为 `injected`；臂序随机化可复现；双口径台账分离；两臂时钟一致体现注入墙钟；R2 破坏性覆盖 / ND 逐字节回滚；身份与网络零调用检查；真实门禁（缺 GO / 缺冻结登记即拒绝）。

## 7. 成果表述边界

本实验若 P1–P3 成立，成果表述为："在受控异常条件下，非破坏性提交机制在真实 DAG 执行链路中逐字节保留了有效执行结果，保护效果传递到真实下游执行，终端质量（严格·归一与宽松双口径）配对改善，且本地开销为零、全链路成本差为实测值 X"。不得表述为"自然服务条件下的平均收益"或"统计显著提升"。
