# DAMJS_V0_3_PILOT 勘误第 1 号（EV 统计口径 · 零调用 · 2026-11-07）

**对象**：`DAMJS_V0_3_PILOT_PREREG.md`（af9cbf87…）第 3 节（H-EV 估计规则）。**原文件不改**；本勘误经操作员确认后成为该节的替代文本，并须重新冻结登记后方可放行真实模式。相关证据：`ev_prior_audit.py` → `EV_PRIOR_AUDIT.json`（932bb7b1…）、`test_v03_prelaunch.py` → `PRELAUNCH_RESULTS.json`。

## 一、操作员指出的错误，成立

Beta(33, 67) 含 100 个伪观测，来源只有 9 次调用：这是 **11.1 倍的伪观测放大，不是降权**。"由 3/9 降权"的推导陈述错误。3/9 的 Clopper-Pearson 95% CI 为 [7.5%, 70.1%]，比 [24.2%, 42.5%] 宽得多。

## 二、核验中发现的另外三处口径问题（同节）

1. **正常先验与失败事件定义不一致（比先验强度更实质）**。估计器的冻结失败定义是"超时 ∨ 撞限 ∨ 不可解析"；而 Beta(14,250) 只统计了撞限（14/264=5.3%）。按估计器自己的定义，基线失败率为 **37/264 = 14.0%**——已经高于 10.5% 拒绝阈值。若采用该口径，EV 门禁在**正常服务、无任何锁存**时就会拒绝首次结构修复。两种口径必须二选一并冻结。
2. **37 里的 23 次是 120 秒截断超时，不可迁移**。这些全部发生在基线环境（J1 决策时刻 ≈126 s = 基线执行器 120 s socket 超时 + 少量偏移，全部为 J1 首调，J1 决策时刻都紧跟其后），属右删失；试点的 J1 超时是 W_eff ≈ 190–219 s，该事件在试点环境几乎不可能复现。冒烟当晚按冻结定义的失败是 4/9（3 撞限 + 1 次 L2 截断），不是 3/9。
3. **L=11 与 μ=1.29 跨口径混用，且 L 的对照基准非典型**。(a) μ=1.29 是宽松 TP 的均值差；L=11 取的是严格口径——阈值 10.5% 混合了两个口径。(b) 基线 S3 的 Static 严格 TP **8 次全为 0**（其 SINK 引用一律用节点名 E1–E4）；冒烟那次 Static S3 严格 11 分依赖它恰好用了文档号 D1–D4，属非典型抽样。以典型基线计，严格口径的 μ_success=+13.57（修复成功时引用走 relay 携带的文档号）、L_baseline=0——即严格口径下修复几乎纯上行，无损失可防。分口径重估（基线 S3，8 次）：宽松 μ_success=+1.89（n=7 成功）、L_baseline=4.25（n=1 失败）、冒烟实测 L∈{6,10}。
4. 次要：μ=1.29 的推导脚本（GAIN_TABLE bootstrap，种子 20261105）不在仓库中，无法零调用复核；分口径重估覆盖了这一缺口。

聚类敏感性（你要求的）：按执行聚类 DEFF=1.07–1.10、按 8 个时间窗 DEFF 0.62–1.19，时间异质性 χ² 检验 p=0.44–0.73——**相关性不是问题**，14/264 或 37/264 的样本量本身足够；无需按簇折扣（n_eff 240/246）。

## 三、决策矩阵：哪些组合在哪个状态点接受/拒绝（零调用穷举）

四个状态点（正常服务首调后决策；锁存·首调撞限；锁存·首调有效但 >154 s；锁存·修复失败后）× 2 组正常先验 × 3 组慢服务先验 × 5 组 (μ, L)。全部 60 行见 `EV_PRIOR_AUDIT.json`。关键结构：

1. **慢服务先验的选择只影响锁存后的 p̂ 数值（0.25–0.75），几乎不影响决策**：锁存状态下 5 组 (μ,L) 参数里 4 组都会拒绝；唯一例外是严格口径 (μ=13.57, L=0) 恒接受。=> 你的直觉被证实：**参数敏感性的真正来源是 (μ, L) 口径，不是慢先验强度**；方案二（重造慢先验）单独做不解决问题，必须与 (μ, L) 一起冻结。
2. **真正的分叉点是正常先验口径**：cap-only（5.3%）→ 正常服务首修接受；估计器定义（14.0%）→ 正常服务即拒绝首修（EV-only 臂在典型服务下也将全程不修复，该臂退化为 Static 类行为——这本身是一个可检验的机制预言，但必须作为有意设计写入预注册，而不是口径意外）。
3. Jeffreys 极端慢先验（Beta(0.5,0.5)+1 败 = p̂=0.75）下唯一翻转为接受的组合也是严格口径——再次指向 (μ, L) 是主导参数。

## 四、建议的修正参数组（供裁决，二选一，零调用可再核验）

- **E1（宽松口径，推荐）**：
  - 执行内估计器的失败定义维持冻结（超时∨撞限∨不可解析，含试点 W_eff 超时）；
  - **正常先验的来源计数剔除 23 次 120 s 删失超时**（基线环境特有、不可迁移，按缺失处理而非计为成功）：撞限 14/241 + Jeffreys → **Beta(14.5, 227.5)**，均值 6.0%，95% CI 约 [3.4%, 9.4%]；
  - 慢先验 **Beta(2.0, 3.5)**（3/9 幂先验 a0=0.5，n_eff=5.5，95% CI [5.9%, 76.0%]，如实反映 9 次调用的不确定性）；
  - **μ=+1.89（宽松、成功条件、n=7）、L=10（宽松口径下观测到的最大失败损失）**，阈值 μ/(μ+L)=15.9%。取最大值是为了避免刃口：L=4.25 时"锁存·首调有效但 >154 s"恰落在阈值上（0.308 对 0.3078）。
  - 决策表（对三组慢先验稳健）：正常服务首修接受（6.0% < 15.9%）；三种锁存状态全部拒绝（p̂ 0.31–0.46）。
- **E2（严格口径）**：先验同 E1；μ=+13.57、L=0（或 11）→ 阈值 100%（或 55%）：门禁在任何状态都不拒绝结构修复，EV 臂检验退化为"记录器"；不推荐，但如实列出。
- 预注册同时声明：EV 的现场检验目的 = **"锁存后拒绝"是否发生且正确**，不承担"正常服务下区分 5.3% vs 14.0%"的任务（后者需要跨执行服务状态账本，属 V0.3+）。
