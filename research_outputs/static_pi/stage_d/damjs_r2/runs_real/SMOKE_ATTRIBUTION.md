**机制**：A‴ 执行器是"末次尝试覆盖"语义——修复重跑没有产出有效输出时，**先前有效的 1,974 字符 J1 输出被空字符串覆盖**，且无回滚。质量损失全部来自这一步。

**逐 claim 差异**（Static 13 ∩/vs DAMJS 7）：

| 类别 | facts | 数量 |
|---|---|---|
| Static 对、DAMJS 丢 | A3, B1, B2, D_2, D_4, E2, F1, F3 | **−8** |
| Static 错、DAMJS 对 | A1, A2（均为 `CORRECT_BUT_UNSUPPORTED_CITATION`，Z_format 的格式级恢复，非证据级） | **+2** |
| 净差 | | **−6** |

丢掉的 8 个 fact（主体绑定 A3、编号 B1/B2、事件判定 D_2/D_4、数量 E2、日期 F1/F3）全部依赖 J1 中继内容——它们在 Static 中由"无 relay 但内容完整的 J1"支撑，在 DAMJS 中随空 J1 一起丢失。

**CP 的 TP=3 是同一机制**：J1 首调 68.8s（3,538 out，合法）→ 修复调用 126.6s 撞限（169 字符碎片不可解析）→ 覆盖 → 丢 10 个 fact，且无 Z_format 补救。DAMJS 比 CP 多出的 4 分中，+2（A1/A2）可归因 Z_format，+2（D_1/D_3）是 J2/SINK 在不同输入下的模型随机性——诚实口径：**Z_format 对 CP 的净贡献是 +2，不是 +4**。

**结论（P0-1）**：TP 13→7 不是"修复这个动作类别错了"，而是**修复调用撞上服务长尾 + 执行器末次覆盖语义把有效输出摧毁**。在基线服务条件下（撞限率 5.3%），同样的决策是正期望的；在当晚条件下（33%）是负期望。算法按冻结规则运行，规则缺的是"动作执行失败概率"这一项。

## P1　CP vs DAMJS 恢复行为差异；History 是否真的减少了无效恢复

**S3 三臂对比**：

| 臂 | 恢复动作 | 调用 | 核算¥ | makespan | TP |
|---|---|---|---|---|---|
| Static | 0 | 7 | 0.0339 | 97.0s | 13 |
| Current-Proposed | 1× structure_repair（撞限，浪费） | 8 | 0.0534 | 221.8s | 3 |
| DAMJS | 1× structure_repair（撞限，浪费）+ 1× format_repair（FMT 本地，零调用，+2） | 8 | 0.0489 | 185.7s | 7 |

两臂的浪费相同（同一次撞限修复）；¥/时延差异主要来自 J1 首调时长（27.9s vs 68.8s）的服务随机性，不是策略差异。

**History 的实测与反事实**：

- 实测：DAMJS S3 中 History 触发 2 次（J1 Z_structure 增益 0 → 禁止；FMT Z_format 增益 0 → 禁止），候选列表中相应动作确实消失。
- **但在本次真实冒烟中两次拦截都不是决定性的**：第二次 J1 决策时 d_rem=84.8，Z_structure 的时延门槛 137.9 > 84.8——即使没有 History，时延门禁也会拒绝。分层防御（History → 时延门禁 → 执行器重跑上限）在本例中冗余。
- 反事实：CP 的第二次 J1 决策发生在 t_rem=39（<60，原生门禁拦截）。**若 CP 的修复像 DAMJS 一样在 t=155 完成（t_rem=84.8 > 60），原生策略会再烧一次 J1 调用（约 ¥0.0243 + 120s）**——History 恰好覆盖原生策略放行的 (60, 门槛] 窗口。T4 重放测试（300s 截止期）已实证该窗口：History 在时延可行的条件下阻止了第二次修复。
- 诚实结论：**History 机制工作正常、方向正确；本批实际省下 0 次调用（CP 靠时间运气同样只浪费了一次），反事实省 1 次**。其独立价值需要 30 次批次中"早发性持续故障 + 宽松截止期"的案例来检验——S3@240s 正是这类案例，值得在正式批次重点观察。

## 量化：动作执行不确定性如何翻转决策（事后演示，n=6，仅供方向参考）

冻结门禁只看时延 L̂，不看 P(动作失败)。用本批实测代入：

```
E[ΔTP | Z_structure(S3)] = P(修复有效)×(+1)  +  P(撞限)×(−6)
  基线服务（撞限率 5.3%）：0.947×1 + 0.053×(−6) ≈ +0.63  → 修复正确
  当晚服务（撞限率 33%，95%CI [7%, 70%]）：0.67×1 + 0.33×(−6) ≈ −1.31 → NONE 才正确
```

（+1 = 基线中修复后 TP 14 vs Static 13；−6 = 本批实测破坏性重试损失。）

进一步分解：**−6 的损失里最重的杠杆不是概率估计，而是执行器的末次覆盖语义**。若重试失败时保留先前有效输出（损失界 ≈ 0 而非 −6），则当晚条件下 E[ΔTP] ≈ 0.67×1 + 0.33×0 ≈ +0.67 > 0，修复仍然正确。换言之：**"非破坏性重试"一项就能让现有冻结算法在长尾条件下保住正期望**——这是论文层面最有价值的单点设计启示（属冻结执行器语义，本批不改动，仅记录）。
