## 0. V1 结论定位（修正后）

**初步观察**：动态调度终端收益可能受异常机会与可恢复性影响（C +10.77pp 4/5 rep 正向；B −4.00pp）。**此为研究假设，n=2 事件不能证明异常密度-收益统计相关**；V2 受控异常实验即为该假设的定向验证。

## 1. 设计不变项

四场景（S1–S4）× 两组（HomDS+D1D2 vs Joint(Z,R,π)）× C+B 两事件 × 3 rep = 48 执行。注入只在执行接口（不改证据/Gold/提示词）；两组完全相同异常（按 task/rep/node 固定）；原始+注入后响应均保留。

## 2. 四场景修订细节

### 2.1 S1 节点失效（R 共同 / π 增量）
- **瞬态**（DeepSeek 截断 1 次→同模型重掷正常返回）：两组均恢复——共同 R 机制验证，不计动态独有。
- **持续**（**DeepSeek 模型特异性**连续 2 次截断；**Qwen 调用不注入**，保证异构兜底可真实执行）：两组 DS R 均败后，仅 DYN 走 π（qwen）——π 增量检验。
- HomDS 两次失败后不再尝试异构模型，按冻结基线失败处理继续（缺失状态保留）。
- 度量分两层报告：共同层（R 恢复）+ 增量层（π 恢复——DYN 独有）。

### 2.2 S2 证据冲突（Z1）
注入清单冻结三信息：

| 字段 | C 事件注入 | B 事件注入 |
|---|---|---|
| fid | C-01（举报日） | B-02（收到告知书日） |
| 冲突值 A（正确） | 2019年4月11日（suspend 原文） | 2021年8月13日（notice 原文） |
| 冲突值 B（注入错误） | 2019年4月10日 | 2021年8月14日 |

- 注入方式：**在 merge 的上游输入中同时保留两个版本**——分支 A 携带原始正确值（C-01=2019-04-11 / B-02=2021-08-13），分支 B 追加注入错误值（4-10 / 8-14），同 fid 不同日期——确保 Z1 确定性检测（fid 分组内日期集合不一致）可触发。原始文书不修改。
- **核验节点可访问原始证据文档**（prompt 含原文），非仅比较两个冲突值。
- 度量：冲突识别率 / 正确值恢复率 / 错误值是否进入终报 / 引用是否指向支持正确值的原文。

### 2.3 S3 Merge 持续失败（Z2）
**故障传播规则（冻结）**：
1. 三连败（base + R + π）针对**同一逻辑执行实例**（原 merge 节点）；
2. Z2 拆分后，子 merge 节点**不预设成功/失败**，按正常模型执行，真实失败保留；
3. join 节点完成**真实汇聚**（模型调用），不拼接 Gold 答案；
4. 本场景定位：**原聚合执行实例的局部失效实验**——不证明所有持续异常都能被拆分解决。
5. **归因边界**：S3 检验完整动态策略在持续失效下的表现（联合收益），不单独证明 Z2 因果贡献（无消融，与联合归因纪律一致）。
6. **HomDS 两次失败后**：不尝试异构模型，按基线失败处理继续执行（merge 缺失状态传递到 report）。
- 度量：拆分前后事实恢复率、终端 Q 变化、子 merge 真实失败率、增量资源。

### 2.4 S4 上游全灭（Z3）+ UNRECOVERED 状态

**注入响应冻结**：每个 extract 节点的 base 和 reroll 响应替换为**不可解析的截断文本**（如 `{"facts":[{"fid":"ext` 截断于 20 字符处），确保 parse_ok=False——不是空 JSON `{"facts":[]}`（合法解析不触发 Z3）。逐节点核对两次执行均注入。HomDS 按基线继续下游执行；DYN 执行 Z3 部分报告。
**新增状态 `UNRECOVERED_DUE_TO_EXECUTION_FAILURE`**：与真 UNKNOWN（如 C-13）严格区分——证据存在但执行失败导致未获取 ≠ 事实本身不可知。

六指标（原文"Z4"更正为 Z3）：
1. 错误断言数（输出事实中不匹配 Gold 的条数）
2. 无依据事实比例（无原文引用的输出事实占比）
3. 正确 UNKNOWN 识别率（真未知槽被标 unknown 的比例）
4. 未恢复事实覆盖率（UNRECOVERED 槽被如实报告的比例）
5. 无效下游调用节省（vs HomDS 的下游重掷次数差）
6. 部分报告是否准确说明缺失原因（人工检查/规则匹配"因上游失败未获取"类表述）

## 4. 四级成功区分（逐级统计，不混报）

| 级别 | 定义 |
|---|---|
| **triggered** | 判据满足、动作启动 |
| **executed** | 动作完成（拆分 DAG 合法无环 / 核验节点返回有效输出 / 兜底调用完成） |
| **recovered** | 恢复了此前缺失的 Gold 槽（逐槽前后对照） |
| **terminal-benefit** | 恢复事实进入终报且值匹配 Gold |

## 5. 统计口径（探索性）

- 48 执行 ≠ 48 独立任务：每场景 2 事件 × 3 rep = 6 配对观测，聚类单元=事件（n=2）。
- **逐事件逐 rep 必报**；事件级聚类描述性区间；不作确证性显著性宣称。
- 注入条件下的成功率 ≠ 自然场景恢复概率，分开报告。
