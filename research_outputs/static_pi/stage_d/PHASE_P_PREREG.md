# Phase P 预注册：节点级能力异质性测量（探索性，冻结待授权）

**状态**：设计冻结，**未执行**。零调用产出。
**定位（操作员 2026-11-02 裁定）**：Phase P **不是**"模型能否运行"的连通性测试，
而是**新执行条件（thinking=low）下的节点级能力异质性测量**。
**结论边界**：60–70 次调用属**探索性**；不得据此宣称能力差异具有普遍性，

## 1. 研究问题（RQ）

> **异构大模型的节点级能力差异，在什么任务条件和资源约束下，能够转化为 DAG 协同执行的整体收益？**

Phase P 只回答其中第一个子问题：

> **不同模型与不同节点类型之间是否存在稳定的能力交互效应？**

即：模型优势是否**随节点类型改变**，而不是某个模型在所有节点上统一占优。
若不能证明交互效应存在，则"节点级异构分配"这一整类策略在**该条件下**没有可利用空间。

## 2. 被测对象（取自冻结执行器，不新增节点）

`d2_executor.py` 的 DAG：`E1,E2 → J1`；`E3,E4 → J2`（J2 亦读 J1）；`J1,J2 → SINK`。

按功能归并为 **5 类节点**（与操作员设计一致）：

| # | 节点类型 | 代表节点 | 性质 | 上游条件 |
|---|---|---|---|---|
| T1 | 抽取-职位/日期 | E1（E_POSITION_ADDENDUM） | 源文档条件 | 任务原文 |
| T2 | 抽取-其他字段 | E3（E_SYSTEM） | 源文档条件 | 任务原文 |
| T3 | 合并+中继 | J1 | 上游条件 | **固定** {E1,E2} |
| T4 | 口径消歧 | J2 | 上游条件 | **固定** {J1,E3,E4} |
| T5 | 终端组卷 | SINK | 上游条件 | **固定** {J2} |

模型：`glm53flash`（GLM-5.3-Flash，`thinking: low`）与 `deepseek`（现配置），
两模型使用**完全相同**的 system/user/max_tokens（E 2000 / J1 3000 / J2 4000 / SINK 4000）。

## 3. 设计：固定上游 + 配对重复

**关键设计决定**：T3–T5 的上游必须**与所用模型无关**，否则测到的是"整条链"而非"节点能力"。
因此每个任务先跑一次**参考链**（GLM）产生固定上游快照，之后两模型都在**同一份快照**上被测量。

每个任务（D1、D2、D3）执行：

| 步骤 | 内容 | 调用 |
|---|---|---|
| ① 参考链（GLM，rep1） | E1,E2,E3,E4 → J1 → J2 → SINK，产出固定上游快照 | 7 |
| ② GLM rep2 | T1(E1)/T2(E3)/T3(J1)/T4(J2)/T5(SINK)，上游全部用①的快照 | 5 |
| ③ DS rep1 | 同上 5 类，同一快照 | 5 |
| ④ DS rep2 | 同上 5 类，同一快照 | 5 |
| 小计/任务 | | **22** |

- ① 的 7 次调用同时**就是** GLM 的 rep1 测量（E1/E3/J1/J2/SINK 五类已含在内，E2/E4 为构建快照所需）。
- 三个任务：**3 × 22 = 66 次调用**（上限 **75**，含重试）。
- 任务：D1、D2、D3（源文档来自 `stage_a/executor.py` 的 `SRC`，冻结哈希可校验）；
  D4（纳川）**不用**，保留作后续独立验证。

**重复的意义**：同一模型、同一输入、两次独立调用 → 给出**重复间方差**，
作为"模型间差异是否超过噪声"的分母。这是本设计能判定"稳定性"的唯一来源。

## 4. 测量指标（全部代码可判定）

| 维度 | 指标 | 判定方式 |
|---|---|---|
| **合同合规** | JSON 可解析、必需字段齐全、schema 类型正确 | 代码 |
| **领域正确性** | T1/T2：抽取字段与源文档一致率（字符串/日期规范化后精确匹配）<br>T4：计数字段与源文档可核计数一致 | 代码 + 源文档 |
| **上游保真** | T3/T4：上游事实在输出中的保留率（无丢失、无改写、无新增） | 代码（集合比对） |
| **终端质量** | T5：`terminal_quality.evaluate_terminal_quality` 既有口径 | 复用冻结评分 |
| **成本 C** | 输入/输出 token、核算费用 | API usage |
| **时延 L** | 单次调用墙钟 | 计时 |
| **可靠性** | 失败率、超时率、截断率、解析失败率 | 代码 |

## 5. 假设与判定（探索性，非确认性）

设 Δ(type, task, rep) = Q_GLM − Q_DS 于该节点类型。

| 假设 | 判据 | 含义 |
|---|---|---|
| **P-H1 交互效应存在** | 存在节点类型对 (i,j)，使 Δ_i 与 Δ_j **符号相反**，且在 **≥2/3 任务**中成立；**或** max Δ − min Δ ≥ 2 × 重复间合并 SD | 节点级异构分配存在可利用空间 |
| **P-H2 空间可被利用** | 在 DS 占优的节点类型上，DS 的 token 或时延亦更优 | 换模能同时改善 Q 与 C/L |
| **P-H3 稳定性** | 同一 (type, model, task) 的两次重复 Δ 差 ≤ 1 × 重复间 SD 的 2 倍 | 差异不是采样噪声 |
| **P-H4 合同不劣** | DS 的合同合规率不低于 GLM −10pp | 换模不破坏下游契约 |

判定：
- **异质性存在（GO to Phase Pi）**：P-H1 ∧ P-H4，且 P-H2 至少在 1 个类型上成立。
- **无可用异质性（停止异构分配方向）**：P-H1 不成立（某模型在全类型统一占优，
  或类型间差异小于噪声）。→ 阶段报告"该条件下节点级异构无空间"，
  Phase Pi 的主实验改用**统一模型**基线，不再设计异构臂。
- **数据不足**：重复间方差过大以致无法判定 → 如实报告，不追加预算去"测到显著"。

**纪律**：若未发现异质性，**不得**更换任务、修改评分或增加重复来制造差异。

### 10.1 DeepSeek 可达性：已定位阻塞，有解

- `capital_opinion_pilot/transport.py:13` 定义 `OPENAI_MODELS['deepseek'] = ('deepseek-flash', 'https://api.deepseek.com', 'DEEPSEEK_API_KEY')`，
  密钥从**环境变量**读取。
- 实测：`DEEPSEEK_API_KEY` **不在当前环境**（`ABSENT`）；`ZHIPU_API_KEY` 等同样不在。
  → 实验代码路径**当前无法调用 DeepSeek**（会话本身走 ZCode 的 provider 配置，与此无关）。
- 但 ZCode `provider_config.json` 的 `deepseek` provider **有非空密钥**，且模型名 `deepseek-flash` 与
  `transport.py` 中一致。

**解决办法（不新增模块，执行脚本内 6 行）**：启动时从 provider 配置读取密钥并注入
`os.environ['DEEPSEEK_API_KEY']`，**不打印、不落盘**；随后用 **1 次极短调用**确认可用。

若该密钥被服务端拒绝：**不伪造异构结论**，Phase P 降级为单模型测量并如实标注
（此时 P-H1 无法检验，实验作废且仅计已耗调用）。
