## 0. 科学问题

在受控异常条件下，联合动态调度中的 π（异构模型兜底）、Z1（冲突核验插入）、Z2（结构拆分）能否将局部恢复转化为终端质量收益？

已验证不重测：R（三次正向）、Z3（初步正向，绝对量减少）。

## 1. 设计

| 场景 | 验证 | 注入方式 | 执行数 |
|---|---|---|---:|
| S1 持续失效 | **π** | DS base+reroll 截断；**Qwen 不注入** | 12 |
| S2 证据冲突 | **Z1** | Gold fid 双版本进 merge 输入 | 12 |
| S3 持续合并失败 | **Z2** | merge 三连截断→拆分 | 12 |

两臂：HomDS+D1D2 / Joint(Z,R,π)。任务 C+B × 3 rep。共 **36 执行**。

## 2. 注入规则（冻结）

### S1（π 增量验证）
- 注入目标：**merge 节点**（C+B 均为 merge，位于关键路径，交付类节点）。
- 注入方式：**仅对 model=deepseek 的调用截断**（base attempt=1 + reroll attempt=2）；**model=qwen 的调用不注入**。
- HomDS：两次失败后按基线处理（缺失传递）。
- DYN：两次失败后 π 触发 → Qwen 兜底（attempt=3，无注入）→ 真实执行。
- 度量：π 恢复的 Gold 槽数、恢复事实是否进入终报、vs HomDS 缺失状态的配对差。

### S2（Z1 冲突核验）
- 注入目标：merge 节点的**输入事实列表**（非响应文本）。
- 注入方式：在 merge 的上游事实中追加与 Gold 同 fid 的错误值条目：
  - C 事件：fid=C-01, 正确值=2019年4月11日(suspend), 注入错误值=2019年4月10日
  - B 事件：fid=B-02, 正确值=2021年8月13日(notice), 注入错误值=2021年8月14日
- **实现修复**：注入操作在 `node_prompt` 构造 upstream JSON 时追加，非在 cap_transport 响应后追加——确保模型实际看到双版本同 fid 输入。
- Z1 检测：merge 输出中同 fid 分组内日期集合不一致 → 触发核验。
- 核验节点：prompt 含**原始证据文档**（非仅冲突值对），要求核实正确日期并给出证据跨度。
- HomDS：无 Z1，冲突值可能直接进入终报。
- 度量：冲突识别率 / 正确值恢复率 / 错误值是否进入终报 / 引用是否指向正确原文。

### S3（Z2 结构拆分）
- 注入目标：merge 节点三次调用（base + reroll + reroll2）**全部截断**——不分模型，node 级注入。
- **代码修复**：π 失败后必须路由到 Z2 分支（V2 中此路径断裂）。
- Z2 触发：三连败后拆分为按上游分支的子 merge + join。
- **子 merge 与 join 不注入**，真实模型调用，真实失败保留。
- HomDS：两次失败后按基线处理（merge 缺失传递到 report）。
- 度量：拆分前后事实恢复率 / 子 merge 真实成功率 / 终端 Q 变化 / 增量资源。

## 4. 评分与统计纪律

- 评分器：V1 修正版（doc 映射），AI 单人 Gold 限定保留。
- **逐事件逐 rep 必报**；触发/执行/恢复/终端四级分开；每动作记录恢复的具体 Gold 槽。
- 增量 token/费用/时延逐动作记录。
- 注入恢复率 ≠ 自然故障恢复率（分开表述）。
