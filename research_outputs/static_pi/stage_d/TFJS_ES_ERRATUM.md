# 勘误：ES（引用准确性）评分器归一化不对称（2026-11-06，TFJS-V2 第一步零调用审计发现）

## 一、错误

`rq_dajf2_score.evidence_support` 对 quote 使用 `norm()`（剥离空白与 `,，、；;：:`），对文档内容只剥空白——**两侧归一化不对称**。含逗号/冒号的逐字引用（"4,383.65 万元，占…"类金额事实）永远无法匹配。

**证据**（V1 DA-JS-v1 persistent r1 的 29 条 Z2 并集事实）：23 条被判"无效"中 **21 条纯因标点不对称**；修正后有效率 0.207 → **0.931**。

**偏差方向**：ES 被系统性**低估**；且讽刺地有利于改写型引用（改写常去掉逗号 → 通过），不利于逐字引用（保留逗号 → 失败）——即偏差方向恰好压低了保真机制的表现。

## 二、影响范围

- **受影响指标**：所有历史 ES / UAR / ES_merge 数值（RQ_DAJF_V1_TERMINAL_RETRO、RQ_DAJF_V2_SCORED、TFJS_G1/G2_SCORED 及各 freeze 中的 ES 字段）。修正后产物已重新生成，旧值备份为 `*.es_biased.json.bak`。
- **不受影响**：全部 Q（slot_hits 两侧对称归一化，已核验）、Q_merge/Q_report/时延/成本/调用数。
- **臂内排序**：同批两臂用同一偏置指标 → 相对比较基本不受影响；例外见下。

## 三、被撤回/修正的结论

| 原结论（TFJS_V1 收口） | 修正后 |
|---|---|
| B 臂 ES 塌缩（ΔES=−8.4pp），根因 fid 冲突遮蔽 | **撤回**。修正后 G1 ΔES≈0（r1 +0.067 / r2 +0.003 / r3 −0.047 / 其余 0）；B r1 ES=1.000。"ES 塌缩"主体是评分器伪影 |
| 引用准确性受三重约束（上游 quote + 报告改写 + fid 冲突） | 修正为**单一主因：报告是否保留逐字引用**。上游 quote 有效率实测 0.88–0.97；fid 冲突真实存在（冲突率 8.8%–62%）但目前对 ES 近乎无害 |
| ES 是终端瓶颈之一 | **撤回**。修正后所有臂 ES 0.88–1.00、UAR≤0.10。终端唯一明确瓶颈=**报告段事实覆盖损失**（Q_report 0.27–0.31 vs Q_merge 0.36–0.44，损失 25–30%） |

## 五、对 TFJS-V2 的影响（设计前提更新）

操作者三步方案的原始前提修正：
1. fid 命名空间化仍然必要——但理由从"修复 ES"改为"**修复覆盖**"（唯一身份使逐事实回填与逐事实核算成为可能；fid 冲突率 8.8–62% 实测）。
2. "上游 quote 不可靠、需从 extract 恢复"——**不成立**（上游 0.88–0.97 有效；按值锚定恢复率 0，因 split-merge 改写了 value 文本；且几乎无需恢复）。该修复项取消。
3. C 臂（身份+证据完整保真）的价值聚焦于**覆盖传递**：Q_report 上限 0.439 vs B 实际 0.311，可回收空间 +12.8pp；ES 上限 0.938 vs B 0.930——ES 预期无增益（预注册）。

**流程声明**：本勘误是对可证实 bug 的修正（证据存档 `TFJS_V2_STEP1_AUDIT.json`），非口径变更；Gold 与 Q 评分规则未动；历史 freeze 文件保持原样，本勘误取代其 ES 列。
