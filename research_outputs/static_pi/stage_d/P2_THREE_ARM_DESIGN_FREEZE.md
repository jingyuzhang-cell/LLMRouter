## P2-2: 异常条件设计

### 三类预定义异常

| 异常类型 | 可观察表现 | 恢复动作 | 注入方式 |
|---|---|---|---|
| **执行实例异常** | 截断/解析失败/输出不完整 | R（重执行） | 注入空文本或截断 |
| **信息质量异常** | 必需事实缺失/上游输出不满足下游合同 | Z/R（结构修复/重执行） | 部署缺陷（遗漏关键 prompt 附录） |
| **模型能力不匹配** | 当前模型输出质量低于替代模型 | π（换模） | 路由到已证截断的模型 |

### 异常注入纪律

1. **可复现**：注入条件有确定性 seed → 三臂面对完全相同的异常
2. **可观察**：异常由契约守卫检测（B-1 五类判定），非人工判断
3. **可恢复**：至少存在一种已知恢复动作可修复该异常
4. **公平**：三臂看到相同异常信号，但策略不同（Static 不动 / Fixed 固定动作 / Joint 诊断选择）
5. **标注**：注入异常单独标记为"机制验证"，不冒充自然异常发生率

### Fixed-Recovery 设计原则（不能故意弱化）

Fixed-Recovery = 对每种异常类型执行**预定义的固定恢复动作**（不诊断异常类型，一律用同一种策略）：
- 遇到任何异常 → 执行结构修复 + 重试（不用换模）
- 这不是"不恢复"，而是"不诊断就恢复"——与 Joint 的差异在于**是否根据异常类型选择动作**

## P2-3: 三臂冻结

| 臂 | 策略 | 动作权限 | 诊断 |
|---|---|---|---|
| **Static** | 静态异构分配 | 零动作（异常→失败） | 无 |
| **Fixed-Recovery** | 固定恢复 | 任何异常→结构修复+重试（不换模） | 无 |
| **Joint-Dynamic** | 诊断驱动联合 | 按异常类型选择 Z/R/π | 有（契约守卫+信号族） |

### 共同条件（三臂完全一致）

- 相同任务、Gold、DAG 初始结构
- 相同模型池（GLM-5.3-Flash + DeepSeek-Flash + Qwen-Plus）
- 相同预算（调用/Token/现金硬顶）
- 相同截止时间
- 相同异常注入（同 seed 同时刻同类型）
- 相同评分合同（P0 定义的 Q_terminal）

## P2-4: 统计与验收冻结

### 主要终点

$$\Delta Q = Q_{\text{Joint}} - Q_{\text{Fixed-Recovery}}$$

（核心问题：诊断驱动的选择是否比固定动作有额外收益）

### 次要比较

| 比较 | 回答 |
|---|---|
| Joint vs Static | 动态调度整体收益 |
| Fixed vs Static | 恢复动作的基础收益 |
| ΔC, ΔL | 成本/时延代价 |
| 异常恢复成功率 | 可靠性维度 |
| 错误断言率 | 安全性（≤基线+5pp） |
| π 实际换模→终端传导 | 换模价值 |

### 统计设计

- **配对单位**：同 rep 内三臂共享 E 输出 + 同异常 seed → rep 内配对
- **任务间独立**：每任务为独立推广单位（不把 rep 当独立任务）
- **主检验**：配对精确符号翻转（exact permutation）
- **样本量**：待功效分析（基于 MVR2 开发数据的效应量和方差）
- **预注册最小有意义效应**：ΔQ ≥ 0.05（5pp 终端质量差）

### 安全门禁

- 错误断言率 ≤ 基线 +5pp
- 保护槽倒退 ≥2 → 停止
- INCOMPLETE ≥1/3 → 停止
- 预算触顶 → 停止
