# MVR2 逐槽语义错误分析（零调用；2026-11-04）

**方法**：对 Static healthy 4 rep × 27 槽共 108 个槽-run，用三层文本（J1/J2/SINK）回溯"正确值在哪一层首次消失"。
**数据**：`MVR2_SLOT_ERROR_ANALYSIS.json`。

---

## 一、首次信息丢失位置汇总

| 位置 | 槽-run 数 | 占比 | 含义 |
|---|---|---|---|
| **SINK 映射** | **57** | **53%** | 正确值已在 J1 和 J2 中存在，SINK 填错槽/填错值 |
| **J1 前丢失** | **26** | **24%** | 正确值在 J1 文本中不存在（E 未抽出或 J1 未中继） |
| 无丢失（正确） | 23 | 21% | SINK 输出正确 |
| J2 丢失 | 2 | 2% | J1 有但 J2 未保留（极少数） |

**结论：53% 的错误发生在 SINK 层的"值→槽位映射"，24% 在 E→J1 信息传递层，仅 2% 在 J2。**

## 二、错误机制分类

### 类型 A：SINK 值-槽映射错误（57 槽-run，53%）

**现象**：正确值在 J1/J2 文本中明确存在（如"233836800"），但 SINK 把它填入错误的 fact_id。

**典型案例（rep 1）**：
- FA1（欺诈发行罚款=233,836,800）→ SINK 填了"23,883.68 万元（综合罚款）"——把 FA3 的值填进 FA1
- FE1（告知书文号=处罚字【2026】14号）→ 值在 J1/J2 中存在，SINK 引用格式错
- FG1-FG4（各年虚增营收）→ 精确金额在 J2 中，SINK 输出带"万元"或映射错年

**根因**：MVR2 有 **27 个槽位、多个当事人在多个阶段的金额矩阵**——SINK 需要将 J2 的多维输出映射到 27 个具体 fact_id。这是**终端映射的上下文窗口/注意力问题**，不是信息缺失。

### 类型 B：E→J1 信息传递丢失（26 槽-run，24%）

**集中领域**：
- 个人当事人处罚（FB2-FB5：曹亚蕾/吴志锋的欺诈/信披/综合罚款）——E 层可能未按当事人拆分或 J1 阶段矩阵遗漏个人
- 拟罚（FC1）与拟终差（FC2）——需要 Da+Db 跨文档对比计算，J1 未产出差异值

**根因**：E 层按文书抽取，**当事人粒度不够细**（E 输出可能只列了公司总罚款而未逐人拆分），或 J1 在构建阶段矩阵时遗漏了个人行。

### 类型 C：少数 J2 丢失（2 槽-run，2%）

J1 有但 J2 的核验/汇总未保留——极少数，可能是 J2 的输出 JSON 结构限制。

## 三、按 predicate 类型的错误率排序

| 高错误率（≥90%） | 低错误率（≤50%） |
|---|---|
| 虚增营业收入 **100%** | 收到日期（告知/决定）**25%** |
| 欺诈发行罚款 **100%** | IPO 募资 **50%** |
| 行政处罚结果 **100%** | 停牌日期 **50%** |
| 禁入年限（拟）**100%** | |
| 交易所函文号 **100%** | |
| 禁入年限（终）**88%** | |

**规律**：**金额精确值和文号格式是高错误区**（编码/格式+映射复合）；**日期类相对低**（简单值映射）。

## 四、"恢复≠正确"的机制解释

Proposed 的诊断换模恢复了 GLM J1 的执行失败→DS J1 完成阶段衔接→链路 COMPLETE。但 MVR2 的 **53% 错误在 SINK 层映射**——SINK 是 DS 节点，不受换模影响。换模恢复了 J1（24% 的信息传递层错误中的一部分），但无法改善 SINK 自身的映射能力。

**科学含义**：恢复动作（换模）作用于故障节点（J1），但终端质量瓶颈可能在不同节点（SINK）——**恢复的靶向性决定恢复的质量效果**。

## 五、对论文的贡献

1. **终端映射是多主体矩阵任务的瓶颈**（53%）——不是信息不存在，是映射错
2. **E 层粒度不足导致信息源头缺失**（24%）——粒度修复（逐当事人拆分）比恢复动作更根本
3. **恢复靶向性**：换模修复 J1 不能改善 SINK 的映射质量——恢复动作需匹配质量瓶颈节点而非故障节点
