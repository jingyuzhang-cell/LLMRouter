## 一、缺陷根因与修复

**根因**（冻结 `terminal_quality._decimal`）：数字分支要求裸可解析 Decimal——带单位后缀（元/万元/%）或千分位逗号即解析失败返回 None，**双向对称受害**：金标带元（KANGMEI B3–B5）→ 金标自检失败（unTPable）；输出带万元（MVR1 罚金）→ 语义正确判错。ZEDA B2 为 % 味同款。MVR1 F1–F6 金标为有损表示（原文带万元、金标存裸数字，已逐条源文核验）。

**v2 修复（对称、保尺度语义）**：
1. 数字/金额/百分比解析：NFKC → 去空格与千分位 → 前导负号 → 尾部单位（%|亿元|万元|亿|万|元）→ 比较 **(数值, 单位) 二元组**——'150万元' ≠ '150元'（尺度保留），'22，548，513，485.42 元' ≡ '22548513485.42元'。
2. 文本：冻结前缀连接词表（通过/以/采用/使用/利用/借助）两侧对称修剪。
3. 金标补丁 sidecar（源文逐字核验）：MVR1 F1–F6 → '1000万元/150万元/100万元/60万元×3'。原始契约文件未动。

**v2 金标自检：五任务全部 0 unTPable**（含负数金标 E06 G 系——修复过程中发现并修正了 v2 初版的负号回归）。
