# H2 决策信号审计——发现 Gold 泄漏（2026-11-05）

## 发现：异常检测步骤使用了 Gold 依赖信号

H2 控制器的异常分类逻辑为：
```python
if checkpoint_Q < 0.3: anomaly = "E坍缩"  # ← Q 由 scorer_qp1_v2 计算，依赖 Gold
else: anomaly = "none"
```

**KANGMEI**（Q=0.857 → none）和 **ZHANGZIDAO**（Q=0.25 → E坍缩）的异常判定均依赖 Gold 评分。这在真实部署中不可用。

## 泄漏范围分析

| 步骤 | 信号 | Gold 依赖？ | 影响 |
|---|---|---|---|
| 异常检测（Q<0.3 → 异常分类） | v2 Q 分 | **是 ← 泄漏** | 决定了控制器是否被触发 |
| verify_pass 计算（池大小） | 四部件核验 | **否** | 金盲 ✓ |
| 动作选择（anomaly+vp → NONE/R/Z） | 类型+vp | **否** | 金盲 ✓ |
| 恢复执行（E重抽/J/SINK） | 模型调用 | **否** | 真实执行 ✓ |

**泄漏仅在第一步（异常检测）**——一旦异常被检测到，后续的动作选择和执行全部金盲。

## 金盲替代方案（零调用可验证）

ZHANGZIDAO 的 J=0（pool=11 但安全绑定数为零）本身就是一个金盲异常信号——**证据存在但无法安全绑定到任何事实槽位**。

| 任务 | pool | J 绑定数 | 金盲异常判定 | 与 Gold 版判定一致？ |
|---|---|---|---|---|
| KANGMEI | 18 | 5 | J≥1 且 pool≥10 → 正常 | ✓（= none） |
| ZHANGZIDAO | 11 | **0** | **J=0 且 pool≥5 → E/J 异常** | ✓（= E坍缩） |

## 结论

1. **H2 的方向性结论不变**——金盲替代信号（J 绑定数=0）产生与 Gold 版完全相同的异常判定，控制器的 NONE/Z 决策与恢复效果均不受影响。
2. **但当前实现存在 Gold 泄漏**——论文必须如实标注"异常检测使用了 Gold 评分，金盲替代信号（J=0）已验证产生一致判定"。
3. **后续部署应改用金盲信号**：J 绑定数 / verify 放行率 / S2 支持率均可作为异常检测代理。

**建议**：论文中将此作为"控制器信号设计"的讨论内容——从 Gold 依赖的异常检测过渡到金盲信号是系统实用化的必要步骤，H2 已验证两种信号在当前任务上判定一致。
