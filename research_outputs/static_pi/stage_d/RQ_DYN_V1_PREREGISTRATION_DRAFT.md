## 3. 动态策略（冻结规则，先定后看）

**信号**（沿用+扩展）：解析失败 / 截断（stop∈{max_tokens,length}）/ 生产缺失 / 引用缺失 / 下游输入退化（上游有效事实数 < 输入的 50%）。

- **R（恢复）**：信号触发→重掷 1 次同模型；仍失败→进入 π。
- **π（重分配）**（依据 CAP/语义输入分布教训：**画像不直接指导实时分配，π 只按"可靠性/时延"证据动作**）：
  - extract 类失败二次重掷 → qwen（其后 deepseek）；
  - 交付类（merge/report/verification）失败重掷 → qwen（CAP 实测 0% 截断）；
  - **关键路径节点**（到 report 的最长剩余链上的节点）失败 → 优先 deepseek 重掷（时延），二次失败才 qwen；
  - verification 节点初始仍 deepseek（CAP n=1 不构成初始异构依据）。
- **Z（结构调整）**（预定义合法动作，逐动作记录触发依据）：
  - Z1 报告前插入一致性核验节点（当 ≥2 条上游事实间存在时间/主体冲突标记）；
  - Z2 merge 失败两次 → 拆分为按支路 merge + 汇聚 join；
  - Z3 上游全空（extract 全失败）→ 跳过下游 merge/report 的重掷，直接降级为"部分报告 + 显式 UNKNOWN"。
- 全部动作计入成本/时延；无任何动作的执行如实记录为"未触发"。
