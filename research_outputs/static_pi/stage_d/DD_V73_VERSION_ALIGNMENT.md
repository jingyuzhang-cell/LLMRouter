## 四、Check 2：静默截断

| 问题 | 详情 |
|---|---|
| 截断模式 | `[:PER_PARENT_CAP]`（3,800 字符/父级） |
| 守卫 | **无**（无长度检查、无异常、无标记） |
| 影响 | n5/n6 双父合并时，超出 3,800 的部分被静默丢弃 |
| 合并长度 | 7,400 字符（3,700×2），但下游合同可能需要更多 |

**两个问题叠加**：切片不够长（检查 1）+ 合并输出被静默截断（检查 2）→ 下游节点无法看到完整信息。

## 五、解除 HOLD 的最小必要修复

### 修复 1：扩展证据切片（零调用代码修改）

将 6,000 字符切片扩展至**覆盖完整文书**（或至少覆盖偏移 0–10,000）。代价：
- n1/n2 输入 token 增加约 60%（从 ~2,000 → ~3,200）
- 总 token 预算从 ~60K → ~80K
- 需重跑 26 项 dryrun 确认提示词构建仍正确

### 修复 2：添加截断守卫（零调用代码修改）

在多父合并处添加长度守卫：超限时记录 `truncated: true` + 截断字节数，不静默丢弃。

### 修复 3：PROXY 节点参数声明

entity_graph 的 q=0.80/0.58 在实验中标注为 **PROXY（未经校准）**，结果解释时单独报告其不确定性。

### 修复后需重新验证

1. 重跑 26 项 dryrun（零调用）
2. 重跑检查 1（零调用）→ 确认不可达事实 = 0
3. 重跑检查 2（零调用）→ 确认截断守卫生效
