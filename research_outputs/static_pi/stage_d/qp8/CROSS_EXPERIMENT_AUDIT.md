# QP4/QP7/QP8 跨实验提示污染核查（零调用）

---

## 一、核心数据：value 字段存在率

| 实验 | 系统提示 | E 条目总数 | 含 value | **value 率** |
|---|---|---:|---:|---:|
| **QP4-D** | `P1.E_SYS`（无 EVIDENCE_REQ） | 80 | 79 | **98.8%** |
| QP5-C C2 | 同 QP4 + 补抽 | 35 | 35 | 100% |
| **QP7** | `P1.E_SYS + EVIDENCE_REQ`（重复） | 757 | 69 | **9.1%** |
| **QP8** | 同 QP7 | 268 | 36 | **13.4%** |

**结论：QP7 和 QP8 的所有 E 输出（无论 GLM 还是 DS）的 value 率都从 ~99% 暴跌到 ~9-13%。原因是系统提示中重复加入了 EVIDENCE_REQ。**

## 二、QP7 污染范围确认

| 检查项 | 结果 |
|---|---|
| QP7 哪些臂受影响 | **全部四臂**（single_ds, static, dynamic_pi, joint）——所有臂用同一 `E_SYSTEM` |
| Static 臂 m,v=GLM 是否也受影响 | **是**——E 层仍是 DS（受污染），m,v 的 GLM 无法弥补 |
| Dynamic-π 的升级是否修复了此问题 | **否**——升级触发的 GLM E 也用同一重复系统提示 |
| 5 个"不可处理"任务 | **E 输出有条目但无 value**（KDX 5 条, YJT 12 条）——不是"无法处理"而是"格式污染" |

**QP7 的 +0.075 是在全部臂共享同一格式污染条件下的相对比较——内部效度可能成立（所有臂同等受制），但绝对 Q 值被系统性压低。**

## 三、QP5-C 为何不受影响

QP5-C 的 E 调用**复用了 QP4 的缓存**（purpose key 相同、prompt sha 相同），没有重新调用。因此 QP5-C 的 E 输出继承了 QP4 的正确格式（value 率 100%）。

QP5-A 同理——全部缓存回放 QP4 输出。

**只有 QP7 和 QP8 产生了新的 E 调用**，使用了被污染的系统提示。

## 四、因果链

```
QP7/QP8 runner 代码:
  E_SYSTEM = P1.E_SYS + '\n' + P1.EVIDENCE_REQ     ← 重复！
  user = e_user(contract, docs, 'E1')                ← 这里也含 EVIDENCE_REQ

模型收到两次相同的证据要求指令
  → GLM/DS 都将输出从 "平铺 {facts: [{field, value, doc, page, quote}]}"
    切换为 "嵌套 {bucket: {sub: {doc, page, quote}}}"（无 value）
  → verify_evidence 要求值被引文接地 → 无值 → 全部拒绝
  → 证据表空/极小
  → SINK 无证据支撑
  → 终端 Q 从 ~0.38-0.44 降到 ~0.13-0.24
```

## 五、对历史结论的影响与处置

| 实验 | 原结论 | 修正 |
|---|---|---|
| QP4/5-A/5-C | 正向结果 | **保留**——E 输出来自正确提示配置 |
| QP7 Dynamic-π +0.075 | 方向性正收益 | **降级为"污染条件下的策略比较"**——内部相对排名可能有效但不可外推 |
| QP7 5 个不可处理任务 | DS 能力不足 | **推翻**——是提示污染导致，非模型能力 |
| QP8 E 层升级无效 | GLM E 不优于 DS E | **推翻**——GLM E 也被同一 bug 污染，未测试到 GLM 真实能力 |

## 六、修正方案

**单行修复**：从 `E_SYSTEM` 中删除重复的 `EVIDENCE_REQ`：

```python
# 修复前（QP7/QP8）:
E_SYSTEM = P1.E_SYS + '\n' + P1.EVIDENCE_REQ  # 重复！

# 修复后:
E_SYSTEM = P1.E_SYS  # EVIDENCE_REQ 已在用户提示中，不重复
```

修正后需重跑的实验：
- **QP8 三臂**（~200 次）——现在才能公平测试 GLM E vs DS E
- **QP7 四臂**（~500 次）——修正后才能公平测试动态调度
- 但 QP7 可以在 QP8 确认 GLM E 有效后再决定是否必要

## 七、方法论教训

**系统提示中一条指令的重复可以将模型输出从"含值平铺"翻转为"无值嵌套"，使整条下游管线失效。** 此前归因于"模型能力差异""任务不可处理""E 层升级无效"的现象，实际上都是这一个 bug 的下游表现。

**教训**：跨实验的提示变更必须做 sha 级对照，不能只看"逻辑等价"就假设行为不变。
