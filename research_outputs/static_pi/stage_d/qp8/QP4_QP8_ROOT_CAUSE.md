# QP4/QP8 逐事实溯源报告：覆盖率 0.9→0.06 的根因（零调用）

**科学问题**：同样的 GLM 模型，同样的任务和文书，为什么 QP4 证据覆盖率 ~0.88 而 QP8 只有 ~0.06？

---

## 根因：系统提示中 EVIDENCE_REQ 被重复，改变了 GLM 的输出结构

| | QP4 | QP8 |
|---|---|---|
| 系统提示 | `P1.E_SYS`（不含证据要求） | `P1.E_SYS + '\n' + EVIDENCE_REQ`（**重复加入**） |
| 用户提示 | `e_user(contract, docs, 'E1')`（含 EVIDENCE_REQ） | 同左（含 EVIDENCE_REQ） |
| **证据要求出现次数** | **1 次（用户提示）** | **2 次（系统+用户）** |

**结果**：证据要求在系统提示中重复出现后，GLM 将输出从"平铺 facts 列表（含 value）"切换为"嵌套桶结构（仅含 doc/page/quote，不含 value）"——**与 DS 的输出结构完全一致**。

| | QP4 GLM 输出 | QP8 GLM 输出 |
|---|---|---|
| 结构 | `{'facts': [{field, value, doc, page, quote}]}` 平铺 | `{bucket: {sub_key: {doc, page, quote}}}` 嵌套 |
| **value 字段** | **有**（6/6 条目有值） | **无**（0/6 条目有值） |
| doc+quote | 6/6 | 6/6 |

**下游连锁**：无 value → `verify_evidence` 拒绝 → 证据表空 → SINK 无证据 → Q 下降。

## 逐事实追踪（E06 r1, e0 节点）

| 环节 | QP4 | QP8 |
|---|---:|---:|
| E 原始条目数 | 22（e0+e1） | 21 |
| 含 value 的条目 | **22/22** | **0/21** |
| 含 doc+quote 的条目 | 22/22 | 21/21 |
| 通过 verify_evidence | **17/22** | **13/21**（通过接地检查但无值可绑定） |
| gold 事实覆盖 | **15/17 = 0.88** | **14/17 = 0.82**（名义高但值缺失导致终端无法回显） |

注：QP8 的 verify_evidence 通过数（13/21）看似不低，但这些条目的 value=None，导致 `match_evidence` 无法将证据绑定到 m 层事实 → `ev_map` 为空或极少 → SINK 收到的证据表实际上不可用。

## 修正方案（零成本）

**从 QP8 的 E 系统提示中删除重复的 EVIDENCE_REQ**——它已经在用户提示中通过 `e_user('E1')` 存在。修正后 GLM 将恢复 QP4 的平铺+含值输出格式。

这不影响科学设计：
- 证据要求仍然生效（在用户提示中）
- 仅消除系统提示中的冗余指令
- QP4 的结果证明该提示组合能产出高覆盖率

## 对整个研究的影响

1. **QP8 的"E 层升级无效"结论需要重新审视**——GLM E 的覆盖率低不是模型能力问题，是提示工程 bug。
2. **QP7 的 Dynamic-π 结果也可能受此影响**——QP7 也用了同样的重复系统提示。
3. **修正后重跑 QP8 三臂可能得到不同结论**——预期 GLM E 覆盖率恢复到 ~0.88，终端 Q 可能显著提高。
4. **这是一次重要的方法论教训**：系统提示的微小变化（重复一条指令）可以完全改变模型的输出结构，进而使整个下游管线失效。
