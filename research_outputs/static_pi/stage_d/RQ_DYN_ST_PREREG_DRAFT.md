## 1. 任务：江苏舜天（600287）信息披露违法事件分析

**事件跨度**：2009–2024（15 年），从持续虚增收入到 ST 风险警示的完整演变链。

### DAG 结构（基于真实信息需求）

```
[ext_correction] ──差错更正公告──┐
  (涉及年度/科目/金额/财务影响)     │
                                   ├──→ [merge_timeline] ──→ [verify_cross_doc] ──→ [report]
[ext_penalty] ───处罚决定书──────┤     (事件时间线重建)      (跨文档一致性核验)    (综合分析)
  (虚增金额/年度/方式/主体/文号)    │
                                   │
[ext_warning] ───风险警示公告───┘
  (ST实施/停牌/原因)
```

**依赖边必要性**：
- `merge_timeline` 依赖 3 个 extract：需要差错更正(2022)→立案(2022.11)→告知(2023.6)→处罚(2024)→ST(2024.7)的完整时间线
- `verify_cross_doc` 依赖 merge 输出：需要对比差错更正的"会计处理调整"与处罚的"虚假自循环业务"——同一行为的两种描述是否构成事实矛盾
- `report` 依赖 verify：综合结论须基于已核验的跨文档关系

**注意**：ST-12（冲突核验槽）不预设存在矛盾——两者可能是同一事项的不同层次描述（会计处理 vs 交易实质）。核验节点访问原始证据，如实输出结论。

## 5. 预算推导

任务文档 118KB / 5 文档 → 输入 token 较大。V1-V4 实测 C_sjzg（3 文档 ~7KB）约 27K token/执行。ST 文档大 ~17×，但只有 3 个 extract 节点读各自文档。

| 项 | 估算 |
|---|---:|
| 输入（extract 各读 ~30KB → ~8K tok each, merge/report ~5K） | ~30K/执行 |
| 输出 | ~3K/执行 |
| 10 执行 + 动态动作余量 | ~400K |
| **Token 上限** | **600,000** |
| **调用上限** | **120**（~12/执行） |
| **费用上限** | **¥2.5** |
