新任务必须来自**新文档、新事件**；不能从现有文档改问法。每个新事件组至少 2 份文档，支持真实 DAG。

## 3. 新任务六查（缺一不可）

| 检查 | 通过标准 |
|---|---|
| 原文存在性 | 每条 Gold 可在原文定位 |
| 事实正确性 | 数值/主体/日期/关系准确 |
| 证据充分性 | 原文支持，不是外部规则推断 |
| 节点归属 | 事实属于该节点职责 |
| 输入独立性 | Gold 不在该节点输入中 |
| 派生关系 | 结论可由前提严格推出 |

任一不通过 → 不进入面板；删除不算通过。

## 4. 任务结构要求

- 至少 2 个上游分支 + 汇合；节点类型至少 3 类（extract/timeline/merge/verification/report）。
- 每任务 4–8 节点、8–20 条事实、1–2 条 UNKNOWN。
- 下游节点的 Gold 必须是**派生关系/结论**，不能复制上游事实。
- 任务级 deliverable_schema/unknown_boundary 与节点级 Gold 一致。

## 5. 建议

- 先补 A 的 1–2 个事件组，验证面板流程与六查；不直接冲 C。
- B 的 9–10 个新事件组是“局部 0.20、70–80%”的最低真实方案；若真实效应只有 0.15，B 不够，需 C 的 25–26 个新组。
- 在目标 MDE 未定前，不启动大规模建题；否则会用任务数掩盖效应定义问题。
- E04 的重建优先级高于新建：它的 3 份文档可支撑“重大违法强制退市 + 交易类退市 + 先触及先适用”的任务，但必须重写事实集，不能沿用 M8-P2 的 D 类财务事实。
