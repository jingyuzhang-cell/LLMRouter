## 0. 三个先决判断

1. **效应尺度必须先统一**：V1.6 的 Δ=0.10/0.15/0.20 是**局部节点准确率差**，不是终端 Q 差。V1.7 的主效应定义为**独立测试任务上的 task-equal 终端 Q 差**。本模拟给出的映射是：
   - 局部 0.10 → 终端 ΔQ≈0.057
   - 局部 0.15 → 终端 ΔQ≈0.086
   - 局部 0.20 → 终端 ΔQ≈0.114
   终端只有局部的约 57%；不能把 0.20 直接说成“终端提升 20 个百分点”。
2. **+1 TP 是科学意义门槛，不是可调参数**：以 E04 的 35 个唯一槽位计，+1 TP=0.0286（task-equal 中一任务）。V1.7 要求主效应的**最小有意义值**至少相当于一个 +1 TP；不因任务数多就降低。
3. **A/B/C 的定位不同**：
   - A 8/8（16）：局部 0.20、up=1.0 时功效 0.595；只能初步验证，不能声称 70%。
   - B 12/12（24）：局部 0.20 时 0.820；局部 0.15 时 0.530；推荐作为“检测较大互补”的方案。
   - C 20/20（40）：局部 0.15 时 0.840，局部 0.20 时 0.955；检测较小效应。
   这些是 synthetic；B 的 80% 只在局部 0.20 成立，不能套用到 0.15。

## 1. P1：最小可检测效应（MDE）与研究目标

### 1.1 主效应定义

- **主估计量**：`ΔQ_term = mean_t[Q_strategy(t) − Q_BestUnified(t)]`，t 为**独立测试任务**。
- `Q_t = TP_t / slots_t`，task-equal；fact-equal 只作敏感性。
- **局部节点差**（local Δ）仅作为机制/设计参数，必须与 ΔQ_term 分开报告。
- **+1 TP**：保留绝对门槛；主结论必须同时满足 ΔQ_term>0、至少一个任务达到 +1 TP 等价、fact-equal 同向。

### 1.2 效应尺度对应

| 局部 Δ | 终端 ΔQ（synthetic） | 相当于 E04 +1 TP 的倍数 | 说明 |
|---|---|---|---|
| 0.10 | 0.057 | ~2.0 | 需要 C（40）才有 ~47% |
| 0.15 | 0.086 | ~3.0 | C（40）~84%；B（24）~53% |
| 0.20 | 0.114 | ~4.0 | B（24）~82%；A（16）~60% |

### 1.3 MDE 结论

- 若目标是“70% 发现至少一个 +1 TP 的真实收益”，现有证据支持：局部 0.20 需 24 个任务（12/12）；局部 0.15 需 40 个（20/20）；局部 0.10 需 >40。
- **不接受**“为了 80% 把预期效应写成 0.20”的做法；必须先有独立证据表明局部互补至少 0.20，或接受更大任务数/探索性结论。
- 若真实局部互补 <0.10，现有任务规模只能做探索；不得声称确认性收益。

## 2. P2：独立验证设计

### 2.1 三段切分

| 集合 | 用途 | 禁止 |
|---|---|---|
| 训练 | 估计节点能力、学习匹配规则 | 不看测试 |
| 验证 | 选择阈值/规则稳定性（训练内层） | 不进最终检验 |
| 独立测试 | 只做一次最终评估 | 不参与任何选择/调参/Gold 修改 |

- A：8 训练（内层 4 验证）/8 测试；B：12/12；C：20/20。验证集从训练内层切出，测试集完全隔离。
- **主检验**：测试任务上的 task-equal 配对差 + 精确符号翻转（双侧，DP 实现）；H0 目标 0.05。
- **LOTO 仅诊断**：V1.6 已证明其 H0 假阳性 0.11–0.37，不得进入确认性结论。

### 2.2 选择与检验分离

- 策略（含 Node-Type/Task-Conditioned/Complexity-Aware）只在训练+验证上确定；测试集一次评估。
- Best Unified 也只在训练上选；不得用测试集挑“更好的统一模型”。
- Oracle 只在测试集上事后计算，不参与策略训练/选择，不作为可部署策略。

## 4. P4：收益传播机制

### 4.1 局部→终端的分解

`ΔQ_term ≈ Σ_nodes w_node × Δnode × propagation_node − cost/latency penalty`

- `w_node`：节点输出在终端槽位中的权重；
- `propagation_node`：该节点错误被下游放大/吸收的系数；
- 关键节点：extract（上游事实）、merge/verification（冲突与错误放大）、report（终端汇合）。
- 本模拟显示局部 0.20 → 终端 0.114（约 57%），上游 0.85 再降到约 0.10；这与“局部优势被 DAG 传播稀释”一致。

### 4.2 要回答的机制问题

1. 哪些节点的质量提升能传递到终端？（按节点类型/深度/分支）
2. 哪些节点是误差放大的关键位置？（merge/verification 的输入冲突）
3. 哪些节点值得用高能力模型，哪些用了反而浪费成本？
4. 互补是否随 DAG 深度/分支结构变化？
5. 终端增益是否足以覆盖额外调用/时延？

### 4.3 Oracle 对照

- **Oracle Matching**：在独立测试集上，对每个节点事后选择真实表现更好的模型，计算理论上限。
- 用途：判断“模型池是否有足够互补”。若 Oracle 也无明显优势 → 模型池问题；若 Oracle 有明显优势而实际策略达不到 → 预测/调度问题。
- 限制：Oracle 只用测试集事后计算，不参与训练/选择，不作为可部署策略，不进入确认性策略比较。

## 7. 五个研究问题与 RQ1 边界

1. 能力异质性：不同模型是否存在稳定的节点级差异？
2. 能力匹配：能否用任务/节点特征预测差异？
3. 终端收益：节点匹配是否改善完整 DAG 的终端 Q？
4. 动态调度：执行异常下联合 Z/R/π 是否进一步改善 Q/C/L？
5. 收益边界：在何种复杂度/资源/截止时间下动态调度有价值？

**RQ1（V1.7）只回答 1–3**；4–5 属于 RQ2/RQ3。RQ1 的结果不能替代后两者。
