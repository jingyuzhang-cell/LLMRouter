## 一、反馈信号体系（正式定义）

| 类别 | 状态 | 检测方式 | 进入调度器？ |
|---|---|---|---|
| 节点执行状态 | 正常 / 执行异常 / 执行实例失效 | 契约守卫（空文本、传输错误、截断、JSON 或 schema 无效） | 是（已有） |
| **节点输出语义状态**（Node Output Semantic Inconsistency） | M1 跨节点证据不一致 | J2 的判断与已逐字核验的证据表对照 | **是** |
| | M2 派生结果不一致 | 模型给出的合计与确定性基础模块对照 | **否**：基础模块直接提供派生值，M2 只报告 |
| | M3 输出与自身证据不一致 | SINK 答案与其引文、证据表按槽位类型对照 | **是** |

所有检查只读节点输出、证据表和已经发给模型的槽位定义（fact_id、subject、predicate、unit），**不读 Gold**（测试 S6 用语法树检查验证）。

## 二、V2 规则

**槽位类型**只由槽位定义推断：
- 谓词含“合计/总计” → derived
- 以“是否”开头 → negation
- 含“文号” → doc_number
- 以“日期”结尾 → date
- “职务” → title
- 有 unit → amount
- 其余 → text

**M1 两态**（候选行按类型匹配；派生槽不适用）：
- `EXPLICIT_SUPPRESSION`：J2 状态为 unverifiable 一类（中英文同义词表已冻结），而证据表中有候选行。
- `OMISSION`：J2 没有提及该槽，而证据表中有候选行。
- 候选规则：
  - 文号：证据句里有【年】号格式，且含主体片段。
  - 日期：证据句里有日期，且含谓词去掉“日期/收到”后的 3 字片段。
  - 否定：证据句里有否定短语，且含谓词片段。
  - 职务：证据句里有主体名，且有职务词。
  - 金额：证据句里有数字，且含谓词或主体片段。

**M2 基础模块**：
- 纳入规则已冻结：对决定书抽取（E_D2）中带金额的**不同当事人**求和，先统一换算为万元。
- 同一人出现两个不同金额时拒绝计算，不猜。
- 代码中没有任何答案常量（测试 S3 检查“201”不在源码中）。
- 三臂共用同一个模块。

**M3 分类型**：
- 普通事实：引文在证据表中，且答案值能在引文中读出（日期按年月日、文号按年和号、职务按全部职务词）。
- 派生事实：答案值与基础模块的结果一致，不要求单句引文。
- 否定事实：答案是否定，且证据表中的引文含否定短语。

**安全指标**（`safety_metrics.py`）：
- 五个指标按您的口径计算：Q_all、错误断言率、错误断言负担、覆盖率、拒答率；另外拆出“静默遗漏率”（未断言也未声明 unknown）。
- 没有任何断言时，错误断言率记为 **None**，安全门判 **UNDEFINED**，永不判 PASS（测试 T2）。冻结评分器在这种情况下报 0.0，安全模块不采用它（测试 T4）。

## 三、开发数据上的 V1 → V2 对照（同一批输出，不是精度估计）

| | V1（保留，`MECHANISM_DETECTION_OFFLINE.json`） | V2 |
|---|---|---|
| M1 | 17 槽中识别 15，F17 漏报 | 明确压制 11 槽（终端全部 ABSENT）；遗漏 6 槽（终端全部 TP）；F17 已覆盖 |
| M2 | 3/3 识别 | 基础模块得出 201（16 人）；3/3 模型合计不一致；不再作为调度动作 |
| M3 | 6/6 识别，误报 2（F19 派生、F20 否定） | 无据或错误答案全部识别，标记只落在非 TP 答案上 |

V2 规则修改都是**看过这批数据之后**做的，所以上表只说明 V2 修正了 V1 已知的结构性问题，不说明 V2 在新数据上的精度。

V2 开发过程中又修了两处规则，均如实记录：
1. 谓词“利润总额比例”被误判为派生槽，原因是关键词“总额”；派生关键词改为只认“合计/总计”。这个问题是在开发数据上发现的。
2. 日期槽关键词对语序敏感（“告知书收到”匹配不上“收到事先告知书”），改为去掉“日期/收到”后取 3 字片段。这个问题是在合成用例上发现的。改后开发数据结果不变。

**M1 两态的终端后果与您的判断一致**：
- 明确压制会让 SINK 放弃正确回答，是需要恢复的状态。
- 遗漏在本批中 SINK 都自行找到了证据，未必需要恢复。

不过遗漏 6/6 都来自同一臂的同一次 J2 输出，独立观测只有 1 次，不能据此认定“遗漏无害”。
