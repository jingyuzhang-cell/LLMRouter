## 5. 必须修正的策略混淆（阻塞确认性实验）

`Retry-only` 与 `pi-only` 的 TP 恒为 0，**不是因为它们的决策更差，而是因为它们中止了管道**：

```
异常 → R₀ 重执行 → 缺陷依旧 → 再次检测 → R₀ … → 超过重执行上限(2) → 节点 FAILED
     → 下游 J1/J2/SINK 永不执行 → 无 SINK 输出 → TP=0
```

而 `Static` 臂**忽略异常继续执行**，因此仍得到 6 左右的 TP。

**这构成了对 R₀ 与 π 的系统性惩罚**：把"持续性缺陷"变成了"整条管道失败"，
而不是"带着缺陷继续跑"。这使：

- `Δ_Z = Joint − π-only` 虚高（对比对象被策略废掉）；
- `Retry − Static` 变成 −6~−8，而非"重试无效"的真实效应。

**两种可选修法（需操作员裁定，本轮不擅自改）**：

| 方案 | 做法 | 后果 |
|---|---|---|
| **A** | 重执行上限后**接受最新输出并继续**，标记 `degraded` | R₀ 与 Static 可比，Δ_Z 才有意义 |
| B | 维持 hard-fail，但**把 INCOMPLETE 作为独立终点**报告，TP 不参与主比较 | 需改变主要终点定义 |

**建议 A**：符合"节点执行成功但输出有缺陷"的现实语义，也让四臂只差 Z/π。

## 7. 能支持与不能支持的结论

**能支持（Pilot 级）**
1. 在抽取合同缺失必需字段的条件下，**重执行与换模都无法修复**（6/6 与 6/6）；
2. **任务重新分解可以恢复该字段**（6/6），代价 +29% 调用；
3. **字段恢复不自动转化为终端质量提升**（Z 中位 4.5 < Static 6.5）；
4. 六臂执行、计费、评分、账本全链路可运行（0 截断、0 异常退出）。

**不能支持**
1. Z 优于 R₀ 或 π 的**效应量**——受 §5 策略混淆影响；
2. 任何 Z×π 交互结论（n=3，方向不一致）；
3. 确认性推断（单任务 T1，6 个配对单元，N=6 双侧最小 p=0.031 > Holm 0.025）；
4. 对外推到其他任务/其他缺陷类型。
