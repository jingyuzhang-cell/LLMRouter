## 0. 研究问题（RQ4）

**执行交付约束如何影响异构大模型的能力互补及其在 DAG 中的终端质量收益？**

核心假设：不同模型的节点级能力互补**不必然**转化为终端任务收益；输出长度约束、结构化输出可靠性会改变（可能抵消）异构协同的实际收益。

V2 的证据基础（已冻结）：
- 事实层（去门）：C−B = −4.41pp（CI [−13.64, +1.81]，跨 0）——GLM 参与后事实质量无明确劣势；
- 交付层：C 的 report 门通过率 66.67% vs B 91.67%；C 的 chosen 解析失败 12/57（GLM 11）vs B 2/57；截断风险调用（输出 ≥1900 token）C 占 27/32；
- 终态：C−B = −21.30pp（CI [−36.68, −5.83]），差距几乎全部由交付层贡献。

**本实验不是修 GLM 截断的工程项目**，而是检验：交付约束是否是异构能力互补兑现的瓶颈。若交互效应≈0，则应认真怀疑当前 GLM/DS 分配本身的互补性（转向主线第 1 项：真实任务上的节点能力测量）。

## 1. 设计：2×2 因子（复用 V2 作为基线层）

| 单元 | 模型分配 | 交付条件 | 数据来源 | 执行数 |
|---|---|---|---|---:|
| **HomBase** | DS+DS（V2 B 机制） | 基线（max_tokens=2000，V2 原样） | **复用 V2 B（冻结）** | 12 |
| **HetBase** | GLM(reason/verification/report)+DS（V2 C 机制） | 基线 | **复用 V2 C（冻结）** | 12 |
| **HomImp** | DS+DS（同 HomBase） | **改进交付 D1+D2** | 新执行 | 12 |
| **HetImp** | GLM+DS（同 HetBase） | **改进交付 D1+D2** | 新执行 | 12 |

- 任务 E05–E08 × 3 重复，与 V2 完全同任务、同材料、同 Gold、同评分器、同重掷/去重核验规则。
- **纪律**：改进交付条件对两个模型、两个臂**完全相同**；不得只放宽 GLM。所有新增 token、调用、时延全额计账。
- 复用合法性：V2 B/C 即基线交付条件下的同设计执行（同提示、同任务、同重复结构），作为基线层配对使用；V2 记录只读。
- 备选（不推荐，2× 成本）：四单元全部重跑。默认复用方案。

## 2. 改进交付条件（冻结定义，两臂同规则）

**D1（比例 token 预算）**：交付关键节点（kind ∈ {reason, verification, report, merge}）的 `max_tokens = 2000 + 150 × n_upstream_facts`，上限 6000；抽取节点维持 2000。依据：V2 中 GLM report 成功样本在 ≤1716 token 完成、失败样本全部在 2000 截断；上游事实数 10–20 → 预算 3500–5000。
（V1.5 覆盖层把 E05 ext_doc1 归为 timeline，仍按 2000。）

**D2（紧凑结构化输出）**：交付关键节点的系统提示追加（逐字冻结）：

> 输出契约：facts 数组只包含本节点新增或整合后的事实，禁止整句复述上游已给出的事实（如需保留上游事实，value 用不超过 20 字的摘要，quote 填上游事实的 fid，doc 填原 doc）。每条新事实的 quote 不超过 60 字且必须逐字取自文档。无法确认的项列入 unknown。

预期机制：report 不再重抄上游事实 → 输出变短、截断减少、JSON 可解析率上升；副作用（如实测）如实记录。

**不变的量**：抽取节点提示与预算、重掷信号与选优规则、去重核验规则（每执行唯一四元组、cap 64）、成功概率/质量门/评分标准/成本口径、任务与 Gold。

**最小仪器化修复（预注册内）**：base 与 reroll 输出**都**落盘（V2 只存被采纳输出，导致节点级重掷收益不可审计）；记录每节点 base/reroll 的槽位状态，供 H3 分解。

## 3. 假设与终点

| 假设 | 陈述 | 主要证据 |
|---|---|---|
| **H1 交付主效应** | 改进交付提高 report 门通过率与终态 Q（对异构性取平均） | HomImp+HetImp vs HomBase+HetBase 的门通过率与 Q_main |
| **H2 交互效应（核心）** | 改进交付对异构臂的终态收益大于同构臂：Δint = [(HetImp−HetBase) − (HomImp−HomBase)] > 0 | 任务级配对交互对比 |
| **H3 交付归因分解** | V2 终态差距的大部分由交付层解释：改进交付后 C−B 终态向 C−B 事实层（−4.41pp）收敛 | 终态−事实层差距分解 + 门通过率 |

- **主要终点**：任务等权终态 Q_main；report 门通过率（执行级，n=12/单元）。
- **次要终点**：Q_raw（去门诊断）、Q_full（**维持"核验器未验证"标签**——V-1 实测特异度 0.529 未过 0.85 门，Q_full 只作乐观上界）、调用/token/¥/墙钟、去重复用率、按模型×节点类型的解析失败率。
- **资源纪律**：任何 ΔQ 必须与 Δtoken/Δ调用/Δ时延并列报告；禁止把"预算加大带来的改善"单独归因于异构协同——这正是 2×2 交互项存在的意义。
- **预注册子组**：E07（V2 中 C 门通过率 100% 的任务）作为"无交付失败"内部对照：预期 HetBase 与 HetImp 在 E07 上差异小；若 E07 也大幅变化，提示 D2 有副作用。

**解释规则（先定后看）**：
- 交互 > 0 且 CI 不跨 0（任务级 cluster bootstrap）→ 交付约束限制了异构能力互补的发挥，异构协同值得在改进交付下重新评估；
- 交互 ≈ 0 且 HetImp 仍低于 HomImp → 当前 GLM/DS 分配的互补性存疑，回主线做真实任务节点能力测量；
- 交互 ≈ 0 且两臂同升 → 交付是普遍瓶颈而非异构特有，改进交付应进入基线机制，异构问题独立重审；
- H1 成立但 H2 不成立 → "GLM 需要更大预算"是普通工程事实，不构成异构协同证据。

## 4. 统计计划与功效（诚实版）

- **主分析**：任务级（n=4）配对交互对比；精确符号置换（两侧最小 p=0.125）+ 任务聚类 bootstrap 95% CI（执行级 12 对/单元，按任务聚类）。**探索性，不做确证性宣称**。
- **功效（从 V2 实测方差推导）**：任务级单对比 sd（终态）≈ 17.4pp → 交互项每任务 sd ≈ √2×17.4 ≈ 24.6pp；n=4 任务、α=0.05 双侧、80% 功效的 MDE ≈ 2.80×24.6/√4 ≈ **34.5pp**（se ≈ 12.3pp）。**本批次只能检测大交互（≥30pp）**；小交互需扩任务集（需新 Gold，另立申请）。
- **门通过率恢复**（次要终点）：HetBase 8/12 → 目标 ≥10/12；n=12 时 0.667→0.917 的单侧精确二项检验功效约 63%，如实报告功效不足。
- **重复数**：3（与 V2 平衡配对）。重复内方差主要来自门双峰性（B E05 sd .366、C E08 sd .377）；若 D1/D2 稳定门，任务均值精度将随之提高，这是 H1 的内在部分。
- 无 H0 纯零世界：基线单元（V2 B/C）即未处理对照；E07 子组作内部稳健性。

## 6. 与研究主线的关系

本实验是主线第 4–5 项（反馈驱动动态调度、Q/C/L 联合优化）之间的一个机制验证节点：它回答"在什么执行条件下异构能力互补可兑换为全图质量"。无论结果正负，之后都回到主线：
1. 交互为正 → 在改进交付基线上重测动态调度（RQ1 类机制）与静态分配（主线第 3 项）；
2. 交互为零/负 → 先做主线第 1 项（真实任务上 GLM/DS 的节点类型级 Q/C/L/R 能力画像），再决定分配策略。
