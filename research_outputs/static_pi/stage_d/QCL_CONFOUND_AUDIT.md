# 混杂分析报告：动作数规则的证伪与动作类型规则的建立（零调用 · 2026-11-05）

## 一、重要更正：**"动作数 ≤2"是混杂伪影，不可作为规则**

此前报告基于全臂汇总得到"3+ 动作有害（−0.34）"。分层分析证明该结论**混杂**：

### 按场景分层后的动作数-收益

| 场景 | 动作数 | n | TP 均值 | 构成 |
|---|---|---|---|---|
| **S3** | 0 | 8 | 12.25 | 全 Static |
| S3 | 1 | 14 | 13.00 | Proposed 7 + R-only 7 |
| S3 | 2 | 3 | 8.67 | 混合 |
| **S3** | **3** | **17** | **13.24（好！）** | π-only 7 + Simple 6 + Fixed 4 |
| S3 | 6 | 5 | **6.20（坏）** | Fixed 3 + Simple 1 + π-only 1 |
| S3 | 12 | 1 | 7.00 | Fixed |

**S3 中 3 个动作是好的（13.24），坏的是 6+ 个动作。** 汇总时的"3+"把 acts=3（好）与 acts=6-12（坏）混在一起，制造了伪规则。

（注：S4 中 acts=3 确实差（8.05），但那是因为 R/π/Simple 在 S4 选了**错误的动作类型**——见下节。不是数量问题。）

## 二、真正起作用的规则：**动作类型必须匹配故障家族**

### S4（format 故障，8 配对）的决定性证据

| 臂 | 使用 format_repair | TP 均值 |
|---|---|---|
| Static | 0/8 | 7.25 |
| R-only | **0/8** | 8.00 |
| π-only | **0/8** | 8.00 |
| Simple-Dynamic | **0/8** | 8.00 |
| Fixed-Composite | 8/8 | 12.38 |
| **Proposed-Dynamic** | **6/8** | **13.38** |

**S4 全部 8 个执行都有 format 故障。四个不使用 format_repair 的臂（含 R/π）TP 全部卡在 7-8；使用 format_repair 的两臂达到 12.4-13.4。**

**R（重试）和 π（换模型）对格式故障完全无效**——因为重新执行产生同样的格式异常，换模型也不改变格式规则。**只有 format_repair（Z 类）有效。**

### S3（structure 故障，10 配对）的动作类型差异

| 臂 | 动作类型 | TP 增益 vs Static |
|---|---|---|
| R-only | retry/rerun | −0.10 |
| π-only | swap | −0.90 |
| Simple | retry | +0.50 |
| Fixed | structure_repair+format+swap | −0.10 |
| **Proposed** | **structure_repair（sig 分类后）** | **+2.10** |

**同为"1 个动作"，structure_repair 优于 retry 与 swap。**

**重复 swap（≥2）与重复恢复轮次（≥2）是同一现象的两种计数，均与崩溃强关联。**

## 四、修正后的规则集（用于 Deadline-Aware 算法设计）

| 规则 | 内容 | 证据强度 |
|---|---|---|
| **R1 类型匹配** | fault=format → **必须 format_repair**；retry/swap 无效（+0.00 × 21 案例） | **强（决定性）** |
| **R2 类型匹配** | fault=structure → **structure_repair 优于 retry/swap**（+2.10 vs −0.10/−0.90） | 中（n=10） |
| **R3 重复上限** | **恢复轮次 ≤1**（第 2 轮起崩溃率 58.5%；Fixed 内部从 13.28 降至 5.75） | **强（剂量-反应）** |
| **R4 swap 上限** | **≤1 次 swap**（≥2 次 TP 均值 5.00，含 0 分案例） | **强** |
| ~~旧 R~~ | ~~动作数 ≤2~~ | **证伪：S3 中 3 动作 TP=13.24** |
| R5 无故障 | fault=none → NONE | 中 |

## 五、对 Deadline-Aware 算法的设计约束（修正版）

```
输入（金盲）：fault_family(D1/D2/D3), n_rounds, n_swaps, t_rem, budget_left
第一阶段（是否干预）：
  fault=none → NONE
  t_rem < estimated_remaining_path → NONE（外推，待验证）
第二阶段（恢复什么）：
  fault=format      → Z(format_repair)   [R1]
  fault=structure   → Z(structure_repair) [R2]
  fault=model_suspect → 谨慎：先 R 一次试，或直接 NONE（数据 n=2 不足）
第三阶段（恢复到哪里为止）：
  n_rounds ≥ 1 → 强制 NONE（不再恢复）  [R3]
  n_swaps ≥ 1 → 禁止再 swap            [R4]
```

**R3/R4 取代原"动作数≤2"——这是更准确、更有证据的约束。**
