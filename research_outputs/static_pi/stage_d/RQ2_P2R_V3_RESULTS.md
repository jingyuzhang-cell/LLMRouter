# RQ2_P2R_V3 结果：交付改进是通用机制，但未释放当前 GLM/DS 组合的异构互补

**批次完成度：21/24 执行（HomImp 11/12、HetImp 10/12，各缺 E08 尾部），624/700 调用、560,505/800,000 tokens、¥22.50/¥28，无触顶，按执行边界守卫停止。两起传输事故（1 次读超时崩溃、1 次调用挂起后杀进程），沉没 38 次调用，全部保留在账本。**

## 三个科学问题的回答

### RQ1：交付改进是否提高终端质量？——**是，且是通用机制**

| 单元 | Q_main | 较基线 | 门通过率 | Q_raw |
|---|---:|---:|---:|---:|
| HomBase（V2 B） | 62.54% | — | 91.67% | 67.84% |
| **HomImp（D1+D2）** | **69.43%** | **+6.89pp** | **100%**（11/11） | 69.43% |
| HetBase（V2 C） | 41.24% | — | 66.67% | 63.44% |
| **HetImp（D1+D2）** | **54.72%** | **+13.48pp** | **80.0%**（8/10） | 65.64% |

- 改进交付把同构臂的门通过率推到 **100%**、异构臂从 66.67% 恢复到 80.0%；终端 Q 双臂都升（+6.9 / +13.5pp）。
- **E05 是最干净的证据**：HomImp 与 HetImp 同时 +27.27pp（基线 51.5%/9.1% → 改进后 78.8%/36.4%）——交付改进对两臂等效，是**通用执行机制**，不是异构专属。
- D2 合同的机制兑现：改进臂 report 节点只输出新增事实（如 HomImp|E05|r1 report 仅 2 条、成功解析），不再复述上游 10–27 条导致截断。

### RQ2：改进交付是否释放异构互补？——**未释放（交互≈0）**

| 逐任务交互 Δint=(HetImp−HetBase)−(HomImp−HomBase) | 值 |
|---|---:|
| E05 | **0.00pp**（两臂各 +27.27，完全抵消） |
| E06 | **0.00pp** |
| E07 | +3.03pp |
| E08（薄样本：Het 1 rep vs Hom 2） | +23.34pp |
| **均值** | **+6.59pp** |
| 任务聚类 bootstrap 95% CI（探索性） | **[−17.42, +31.16]**（跨 0） |
| 精确符号置换 p | 0.50（n=4 下限 0.125；探索性） |

- 交互点估计为正但**不显著**，且主要由薄样本 E08 贡献；4 个任务中 2 个**恰好为零**。
- **异构臂的交付失败没有完全修复**：HetImp 门 80% vs HomImp 100%；GLM 在 merge/report 上仍于新预算（4250–4850）截断（如 HetImp|E05|r1 base 与 reroll 双双 `stop=max_tokens`），D1 的 150 token/事实公式对 GLM 的输出冗长仍不够。
- **H3 分解**：异构差距从基线"终态 −21.3 / 事实层 −4.4"变为改进后"终态 −14.7 / 事实层 −3.8"——交付改进解释了终态差距的约 1/3；剩余差距仍是 GLM 交付层失败，事实层两臂始终接近（−4～−3.8pp，跨 0）。

### RQ3：是否产生实际部署收益（HetImp vs HomImp）？——**没有**

| 指标 | HomImp | HetImp | 差 |
|---|---:|---:|---:|
| Q_main（任务等权） | **69.43%** | 54.72% | **−14.71pp** |
| 每执行调用 | 26.6 | 32.9 | +24% |
| 每执行 token | 20,101 | 33,939 | **+69%** |
| 每执行费用 | ¥0.925 | ¥1.232 | +33% |

异构臂质量更低、更贵、慢 3 倍。Q_full 按纪律只作未验证次要指标，不进结论。

## 节点级重掷的首个可审计答案（双输出仪器化）

17 次重掷的 base/reroll 配对：**7 次采纳全部是"base 解析失败(score=1)→reroll 成功(28–64)"；10 次未采纳全部是"1→1 双失败"**；没有一例"两边都成功、选优留好"的选择偏差。结论：重掷机制真实地从瞬态解析失败中恢复，但**对系统性截断无效**——GLM 截断的节点同提示重掷仍截断（1→1 ×10 全在 HetImp）。修复必须发生在预算/合同层（D1 已部分做到），重试层无解。

## 研究决策（按预注册解释规则，两条同时命中）

1. **两组都提升但交互≈零** → **D1+D2 交付改进作为通用执行机制进入基线执行栈**（它把同构基线从 62.54% 推到 69.43%、门 100%）。
2. **交互零且 HetImp 仍差** → **停止围绕当前 GLM/DS 分配继续调参**。当前组合的"能力互补"在事实层始终≈0（−4.4 → −3.8pp，跨 0），交付层系统性劣势（截断、慢 3 倍）无法靠重掷修复。按第二件任务推进：**真实节点级 Q/C/L/可靠性能力测量，不预设 GLM 擅长推理/DS 擅长抽取，找真正互补的模型组合**，然后再验证动态联合调度。

**未启动任何下一批付费实验；V2 只读、余量未挪用、192 HOLD 未动。**
