# RQ1 V1.8.2-R5：预算约束下 DAG 异构分配的 128 全枚举、Pareto 前沿与可部署策略

**状态：零真实 API；纯 SYNTHETIC；192 次真实调用额度继续 HOLD；本轮不构成真实实验 GO。**

**一句话结论：在 128 固定分配空间内，10% 与 15% 预算下不存在任何可部署策略（连 Constrained Oracle 都达不到 MVS）；20% 预算下只有在 stable H1 δ=.20 且把 Makespan 上限放宽到 20%（matched）时，MGC / Joint-Pareto 才在约 40% 的独立切分中同时通过三项——总体均值 +0.0751 仍略低于 MVS，严格 10% 时延下为 0。潜在收益真实存在（Node-Type +0.081/+0.104），但当前离散成本 + 关键路径 + MVS 的可行集无法稳定兑现。**

## 0. 指标释义（重要纠正）

R5 的 `GQ/GF/GR/JOINT` 是 **100 次独立切分的验收通过率**，不是模型回答准确率。终端 Q 是另一条轴：

| 指标 | stable H1 .20、20% matched 的 R5 结果 | 含义 |
|---|---:|---|
| Static 终端 Q | 45.48% | 统一 DS 基线的绝对终端质量 |
| MGC 终端 Q | 52.99% | 可部署策略的绝对终端质量（切分均值；人口层 53.29%） |
| Node-Type 终端 Q | 55.89% | 成本/时延超限，不可部署 |
| GQ | 46% | 100 个切分中满足 MVS 终端增益的比例 |
| GF | 79% | 满足关键事实净收益检验的切分比例 |
| GR | 99% | 满足成本/时延/可靠性约束的切分比例 |
| JOINT | 42% | 同一切分同时满足 GQ∧GF∧GR 的比例 |

所以“JOINT 42%”不等于“回答准确率 42%”；它表示在 100 次切分中有 42 次同时通过三项验收。70% 是 RQ2 的**新增研发目标**，不是对 R5 验收标准的追溯修改。

## 2. 实验设计

### 2.1 分配空间与 CRN

- 7 节点：`e0, e1, t, m, r, v, p`；2 模型：GLM（model 0，价格 1.0，时延 1.0）与 DS（model 1，价格 0.6，时延 0.75）。
- 全部 **2^7 = 128** 种分配；同一情景内所有分配共享同一任务、同一 `U` 数组（CRN），策略只改变模型映射。
- 终端 Q：13 个可判定槽（排除 report 的 UNKNOWN 槽）；槽正确要求 `TP ∧ 定位 ∧ 支持 ∧ report 执行`；MVS = 1/13 = **7.6923%**，未降低。
- 关键事实：`(v,0),(v,1),(p,0)` 三个；关键 TP 要求 `TP ∧ 定位 ∧ 支持`；净收益按每任务 `ΔTP − ΔFP`，精确符号翻转检验（预注册 M1）。

### 2.2 情景

| 情景 | δ | sign | up | extra_parse | pure null |
|---|---:|---|---:|---:|---|
| H0 pure null | 0.00 | stable | 1.00 | 0.00 | 是 |
| stable H1 .15 | 0.15 | stable | 1.00 | 0.00 | 否 |
| stable H1 .20 | 0.20 | stable | 1.00 | 0.00 | 否 |
| mixed H1 .15 | 0.15 | mixed | 1.00 | 0.00 | 否 |

### 2.3 预算与截止时间

- 成本上限：相对该次切分中训练集选出的 **Static**（R4 定义：最佳统一模型）的 `(1+cap)`，cap ∈ {10%, 15%, 20%}。
- **matched 时延**：Makespan ≤ `(1+cap) × Static`。
- **strict 时延**（R4 冻结的 10% 规则）：所有 cap 下 Makespan ≤ `1.10 × Static`。
- 非劣：解析率、合同成功率 ≥ Static − 0.02。
- 验收：GQ（μ≥MVS 且 95% CI 下界>0）、GF（关键净收益≥1 且精确 p≤0.05）、GR（成本/时延/非劣）；JOINT 在同一切分上取交集，不做乘法。

### 2.4 训练/测试与规模

- **人口层**：每情景独立训练集 300、评测集 800；评测集用于 128 全枚举、Pareto、Constrained Oracle。
- **重复切分**：每情景 100 次独立切分；每次池 48 个任务，随机 24 训练 / 24 测试，任务/`U` 种子随重复变化；训练集只用于选策略，测试集只用于评估。
- 200 次切分尝试在环境限制下中断；正式结果用 100 次（每情景 N=100，配对 CI 为 100 个切分均值上的 95% 正态区间）。这是规模选择，不是阈值修改。

## 4. 关键路径：为什么 m+v 是唯一的“质量够”点，也是时延冲突点

| 分配 | 成本 | Makespan | ΔQ stable15 / .20 | 关键路径 | 10% | 15% | 20%m | 20%s |
|---|---:|---:|---:|---|---|---|---|---|
| all-DS | 0.600 | 2.850 | 0 / 0 | e0,e1,m,r,p | ✓ | ✓ | ✓ | ✓ |
| m | 0.657 | 3.075 (+7.9%) | +0.0356 / +0.0479 | e0,e1,m,r,p | ✓ | ✓ | ✓ | ✓ |
| m+v | 0.714 | 3.275 (+14.9%) | +0.0599 / **+0.0781** | e0,e1,m,v,p | ✗ | ✗ | ✓ | ✗ |
| m+p | 0.714 | 3.250 (+14.0%) | +0.0484 / +0.0640 | e0,e1,m,r,p | ✗ | ✗ | ✓ | ✗ |
| m+r | 0.714 | 3.375 (+18.4%) | +0.0396 / +0.0529 | e0,e1,m,r,p | ✗ | ✗ | ✓ | ✗ |
| t+m | 0.714 | 3.075 (+7.9%) | +0.0165 / +0.0234 | e0,e1,m,r,p | ✗ | ✗ | ✓ | ✓ |
| m,r,v,p（Node-Type） | 0.829 | 3.550 (+24.6%) | +0.0778 / +0.1009 | e0,e1,m,r,p | ✗ | ✗ | ✗ | ✗ |
| all-GLM | 1.000 | 3.800 (+33.3%) | −0.0133 / −0.0235 | e0,e1,m,r,p | ✗ | ✗ | ✗ | ✗ |

关键路径解释：

- `m`（merge）在关键路径上；单独 GLM 只把 Makespan 从 2.85 推到 3.075（+7.9%），仍满足 strict 10%。
- 第二个高质量节点是 `v`（verification）；它使关键路径变为 e0,e1,m,v,p，Makespan 到 3.275（+14.9%），恰好跨过 strict 10%，但在 20% matched 内。
- `t+m` 虽然也在 strict 时延内，但 `t` 的 GLM 能力更差，Q 反而只 +0.0165/+0.0234，说明“能放进两个节点”不等于“有质量”。
- 3 个及以上 GLM 的成本（+28.6%）已超出 20% 预算，且 Makespan 也超出；Node-Type 的 4 节点质量最高但不可部署。

**结构性事实 2：strict 10% Makespan 下最多只有 m 是高质量可行点；m+v 是唯一能把 stable .20 推过 MVS 的两节点组合，但它只能活在被放宽到 20% 的 matched 时延里。**

## 7. 鲁棒性与负结果

### 7.1 H0 pure null

- 100 次切分全部：dQ=0、净收益=0、GQ=0、GF=0、JOINT=0；MGC/CPA/JP/CO 选择 all-DS（成本 0.600，Makespan 2.850），GRm=GRs=1。

### 7.2 mixed H1 .15

- P(Static=GLM)=0.40（训练 24 任务时的选择噪声；人口层是 0/1 单次抽样，不能代表分布）。
- 20% matched：MGC ΔQ **+0.0093**、GQ=0、GF=.01、JOINTm=0；CO 也只有 +0.0320、JOINT .02；Node-Type +0.0108、GQ=0。

### 7.3 上游/解析/联合压力

- upstream 20% matched：MGC +0.0479、GQ=.07、JOINTm=.03、GRs=.08；CO +0.0552、JOINT .04。

## 8. 对 R5 四个问题的直接回答

1. **方向一致时，调度是否真正产生质量收益？**
   是。stable .15：Node-Type +0.0814、MGC 20%m +0.0583、CO +0.0677；stable .20：Node-Type +0.1041、MGC +0.0751、CO +0.0829。人口层 MGC m+v 为 +0.0599/+0.0781。收益真实存在，不是零。

2. **预算约束下，能否避免成本和时延过度增加？**
   成本可以：MGC/JP 在 10/15% 的 GR 为 .92–1.00，20% matched 的 GRm=.99（stable/stress）。时延在 strict 10% 下只有 CPA/JP-strict/CO-strict 能守住（GRs≈1），但它们选择 m，质量停在 +0.032–+0.051。**没有一个策略同时做到“20% 质量组合”与“10% 时延”。**

3. **节点级质量提升能否传递到终端答案？**
   能。stable 情景边际传递率 89–103%；压力情景 98–117%。local−term 间隙存在但稳定，不会吞掉增益。

4. **终端事实净收益能否得到统计支持？**
   在 stable 方向、20% matched 下能：MGC GF=.79（stable .20）、.51（stable .15），净收益 +0.448/+0.298 每任务；但在 10/15% 只有 .05–.08，mixed 为 .01。**统计支持有，但只属于“质量够、预算也够”的窄情形；它不能把 GQ 从失败变成成功。**

## 9. 最终判定

### 9.1 按预算

- **10%：不存在。** 在 Static=DS 的 stable/stress 情景，成本可行集最多 1 个 GLM 节点；CO 切分均值 +0.023–+0.050（人口层 +0.000–+0.048），全部低于 MVS 0.0769；MGC/JP/CPA 的 JOINT=0（除个别 1% 噪声）。这不是算法失败，是可行集上界失败。
- **15%：不存在。** 在 Static=DS 的 stable/stress 情景，与 10% 同一个 1-GLM 质量上界；多出的 5% 成本只放行更低 Q 的单节点分配。人口层 CO15 的 ΔQ 与 CO10 相同。mixed/H0 的预算不绑定，但 CO 仍低于 MVS。
- **20%：**
  - **strict 10% Makespan：不存在。** CO-strict 切分均值 +0.0505（stable .20；人口层 +0.0479），低于 MVS；stable/stress 的可部署臂 JOINTs=0（parse 仅 1/100 个切分，噪声）。
  - **matched 20% Makespan：只在 stable H1 δ=.20 出现临界特例。** MGC 的 100 次切分 JOINTm=.42、JP=.40；人口点估计 +0.0781 刚过 MVS；但切分均值 +0.0751 已低于 MVS、GQ 仅 .46、GRs=0，且 mixed/stress 为 0–.03。**不能称为稳定可部署策略；只能称为“单情景、临界线、放宽时延后的特例”。**
- **总体：不存在跨情景稳定的可部署异构 DAG 调度策略。** 潜在收益（Node-Type +0.081/+0.104）真实，但预算/时延可行集无法稳定兑现。

### 9.2 根因排序

1. **离散成本 + MVS 尺度**：1 GLM = +9.5%，2 GLM = +19.0%；Static=DS 时 10/15% 只能 1 个，20% 只能 2 个。1 个最好节点 m 只给 +0.036/+0.048；2 个 m+v 给 +0.060/+0.078。MVS 1/13 正好卡在 2 节点的临界线上。
2. **关键路径时延**：m 在关键路径上 +7.9%；v 使 Makespan +14.9%，越过 strict 10%。要质量就必须接受时延，要 strict 时延就只能停在 m。
3. **方向异质性**：mixed 下收益塌到 +0.009；真实模型是否存在 stable 式类型互补，是零调用无法回答的。
4. **分配算法不是主因**：CO−MGC 仅 +0.007–+0.023；MGC 已捕获约束 Oracle 的 76–91%（stable .20 的 20% 情景约 91%）；Joint-Pareto 穷举没有实质超过 MGC（mixed +0.0006，其余为负）。

### 9.3 建议

- **不申请真实 API GO，192 继续 HOLD。** 本轮零调用结果没有给出“跨情景稳定通过”的证据；按既定纪律，不能用 Monte Carlo 结果申请真实实验。
- 若未来继续零调用，最有信息量的下一步不是再扩大枚举，而是回答“**能否在不增加第二个 GLM 节点的前提下，用验证/重试/结构重组（RQ2）把 m 的 +0.036/+0.048 推到 MVS**”。这会改变冻结的 R5 机制，必须先设计、先审计，不能直接做。
- 另一个必要问题是真实模型能力：δ=.20 的 stable 方向互补是合成假设；真实 GLM/DS 是否存在同样的类型分工，只有真实模型验证能回答。但该验证需要新的、明确的用户授权，当前不启动。
