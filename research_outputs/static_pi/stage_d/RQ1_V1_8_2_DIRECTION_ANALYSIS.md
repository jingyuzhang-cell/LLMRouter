# RQ1 V1.8.2 方向不一致机制分析

## 1. 现象（V1.8.1 20k）

方向不一致时：Node-Type ΔQ +0.0120，功效 0.075；理想 H1 为 +0.0851、0.979。类型级匹配几乎失效。

## 2. 机制假设

1. 同一种节点类型在不同任务中可能有不同模型优势：抽取节点在简单公告上 DeepSeek 更经济，在多文档/冲突任务上 GLM 更准确；合并/核验节点在复杂时间关系上 GLM 更强，在结构简单时差异小。
2. 任务复杂度、文档数量、证据分散、实体冲突、输入长度是潜在调节变量；V1.8.1 只用“HIGH/MEDIUM”粗分，未测这些特征。
3. 类型级分配取训练任务的类型均值，无法捕捉任务间方向；当方向翻转时，均值接近 0，选择噪声主导。
4. 简单 Task-Conditioned 规则（HIGH+merge/verify/report→GLM，extract/timeline→DS）在方向翻转时也失效；因为它仍是类型级规则，只是加了复杂度阈值。
5. 真正的任务条件化需要可识别的任务特征（文档数、证据分散、冲突数、输入长度）与模型优势的交互；当前材料尚未提供足够变化。

## 3. 必须的比较

| 策略 | 方向一致 | 方向翻转 | 说明 |
|---|---|---|---|
| Best Unified | 基线 | 基线 | 训练选统一 |
| Node-Type | +0.085 | +0.012 | 类型均值 |
| Task-Conditioned | 待测 | 待测 | 简单规则 |
| Cross-fitted Oracle | +0.085 | 下降 | 类型级上限 |

- 所有策略严格训练/验证/测试隔离；不得用测试反推策略。
- 不为了制造正向结果筛选任务或增加有利条件。

## 4. 结论

- 方向不一致是类型级匹配的**结构性失效**，不是样本量问题；增加任务数不能修复。
- 需要任务级特征与方向的可预测性；若特征无法预测方向，则节点级匹配的收益上界就是类型级，不能宣称更高。
- RQ2 的 Router 应以“方向可识别性”为核心问题，而不是继续堆类型规则。
