## 修订一 · N=5 定性与平局规则

- **S3 的 N=5 = 先导性确认样本（pilot confirmation），非充分功效样本量**：若真实胜率 80%，N=5 达 5/5 显著的概率仅 0.8⁵≈33%——N=5 是最低显著性判定门槛；**最终确认性实验（Stage D 终局）按 D2 实测配对差异与方差重算样本量**。
- **平局规则（预登记）**：配对符号检验剔除平局后按有效对数 n 判定（5 对含 1 平 → n=4，需 4/4 才 p=0.0625 → 降为方向性）；平局逐对列出（含双方 TP 值），禁止按原 N 报告。

## 修订二 · S3 三条件核验与控制器盲化

| 核验项 | 实现 |
|---|---|
| 故障持续性 | 每次未修复的 J1 重执行断言使用缺陷部署 spec（fault_still_present 逐次记录） |
| 信息可达性 | E 层每次执行断言 dates 字段在位（上游信息未被人为删除，只断在 J1 部署层） |
| 终端影响（完整下游链路） | **预执行证据基线（零调用引用冻结实测）**：无 relay 时 SINK 无法经其他路径恢复日期——Stage A Static 臂（原 J1）F1/F2 formal **0/3**（×2 独立臂证据）；修复后 6/6 传递（R/X 臂）。执行中逐次记录 J1 输出 dates_relay 在位性与终端 F1/F2 状态的对应 |

**盲化锁死**：`fault_still_present` 仅入执行审计记录；**控制器输入 = 节点输出 + 检测器信号 + 预算状态，结构中无故障标签字段**（沿 V1）。

## 修订三 · H2 定性与报告粒度

- H2 = **工程性非劣效门槛（边际 −6pp）+ 效率方向性重复验证**，不作统计确认性宣称（N=3/场景不足）。
- **比较对象**：质量保持 vs **Simple**；资源效率 vs **Simple 与 Fixed-Composite**（不以 Fixed 质量为唯一参照）。
- **报告粒度（禁止均值掩盖）**：逐场景 × 逐执行给出——Proposed−Simple 质量差、Proposed−Fixed 质量差、实际调用量、增量成本、Makespan、按时情况；任何单场景退化单独标出。

## 修订四 · S2 语义边界（措辞锁定）

S2 = **复合异常场景**（一次性口径偏离 + 一次性超时，同节点同时序）；本实验集合的宣称上限 = "**在多类型故障场景集合中验证动态策略的诊断与选择能力**"；**不宣称任意多故障并发条件下的联合诊断能力**（未设计并发多持续故障场景）。

## 修订五 · S4 纳入（次要机制迁移验证）

- **注入**：在线确定性合同编码节点被持续绕过（bypass 标志持续）；SINK 原始编码持续流出。
- **检测**：D3 枚举纯值；**正确动作 = 重新启用格式编码节点**。
- **格式层作为正式 DAG 执行节点（硬要求）**：以独立节点记录进入执行日志——版本号、输入哈希（SINK 原始输出）、输出哈希（编码后输出）、实际执行成本（0 调用，确定性耗时记录）；**禁止只在评分前做后处理**。
- 预期假设（非结果）：R-only 结构动作不解决格式旁路；π 换模不保证解决；Simple 重跑原始流程不解决；Proposed 识别格式族调用编码；Fixed 全干预含编码。**S4 不与 S3 的 H1 合并、不新增主要显著性检验**——次要验证，按 H1 同规则单独报告（N=5 先导）。
- **科学价值**：S3 检验结构干预、S4 检验格式干预——共同回答"控制器是否真的按错误类型改变动作，而非始终同一种恢复"。

## 修订六 · 新增两项实现门禁 + 分块随机化

| 门禁 | 要求 |
|---|---|
| 第五项 版本与缓存隔离 | 修复后的 J1/J2 spec 必须产生新版本号；重执行携带新 prompt_sha；**旧缓存/旧输出不得冒充修复结果**（版本表逐执行核验） |
| 第六项 上下游哈希完整性 | E→J1→J2→SINK 消费关系逐执行核验（下游记录的 upstream_text_sha 与上游实际输出哈希一致）；**上游修复成功但下游仍消费旧版本 = 该执行 invalid** |
| 顺序（升级） | **分块随机化**：按（场景×重复）成区组，区组内六臂顺序随机（种子入档）；区组间顺序亦随机；单执行内部保留真实并发；**不同臂不同时外部并发**（避免臂间 API 资源互相污染） |
