## 一、核心命题与判定

**核心比较是 C 对 B。** C 优于 A 可能只是因为增加了恢复动作；只有 C 在质量不劣的前提下比 B 用更少的资源，才说明动态决策相对固定策略有价值。

| 假设 | 对比 | 判定规则（执行前固定） |
|---|---|---|
| H1 质量 | C − A | Q_all 配对差：精确单侧符号检验（剔除平局），α=0.05，且平均 ΔQ ≥ 0.10 |
| H2a 质量不劣 | C − B | 每个配对重复 ΔQ(C−B) ≥ −0.05 |
| H2b 资源不多 | C − B | 平均调用数与记账费用 C ≤ B |
| **H2c 时延不劣** | C − B | 平均恢复阶段增量时延 C ≤ B（非劣界 0） |
| H3 安全 | C 对 A、B | 错误断言率 ≤ 对照 + 5pp；无法判定不算通过 |
| H4 恢复有效性 | 三臂 | 被标记槽的终端恢复率（描述性） |

**正向结果的定义**：H1 ∧ H2a ∧ H2b ∧ H2c ∧ H3。

**时延口径的说明**：
- 这个任务没有预先存在的截止时间或服务要求。此前 120s 与 150s 的截止期来自另一个任务族，不采用。
- 因此 H2c 采用相对非劣效：C 不慢于 B，非劣界取 0，且在执行前写定。
- 结论只能表述为“C 的恢复时延不劣于 B”，**不宣称满足任何绝对截止期**。

## 三、设计：同检查点三臂分叉

每个重复先运行共享上游：E_D1、E_D2、J1、J2 各一次，形成检查点 CP_r。在 CP_r 上确定性地计算证据表、基础合计、V5 的 M1 与 M2，以及覆盖状态（第四节）。

A 的 SINK 是三臂共同的“恢复前终端”：
- 无任何标记时，B 与 C 直接复用该输出，不重复计费，三臂计为平局；
- 任一臂有恢复动作时，三臂各自形成最终终端。

## 四、检测状态（V5 + 执行器覆盖检查；修订 1）

对 20 个合同槽，逐槽取一个状态：

| 状态 | 来源 | 含义 |
|---|---|---|
| CONFIRMED | V5（确认类标签） | 正常 |
| EXPLICIT_SUPPRESSION | V5（压制类标签，且有候选证据） | 明确压制 |
| UNKNOWN_LABEL | V5（未知标签，且有候选证据） | 未知标签 |
| OMISSION_WITH_EVIDENCE | V5 OMISSION | J2 未输出该 fact_id，证据表有候选行 |
| **MISSING_NO_EVIDENCE** | **执行器覆盖检查（新增）** | J2 未输出该 fact_id，证据表也无候选行。**不再静默通过**：记录在案，交由终端处理 |
| SUPPRESSED_NO_EVIDENCE | V5（压制类标签，无候选证据） | J2 判为不可核验，且确实无据，是合理拒答 |

覆盖检查只读取合同槽位的 fact_id 列表与 J2 输出中出现的 fact_id，**不读取 Gold 值**。

## 五、三臂策略（修订 2）

**A Static**：CP_r → SINK。故障重试一次后仍失败，则该重复 A 不完整。

**B Fixed-Recovery**：
- 触发条件：EXPLICIT_SUPPRESSION、UNKNOWN_LABEL、OMISSION_WITH_EVIDENCE 中任一出现。
- 动作：固定执行 J2 定向重核（GLM，附加块列出全部触发槽）+ SINK。
- 不处理 M3。
- 每臂每重复最多 3 次调用（重核、SINK、一次重试）。

**C Joint-Dynamic**，按状态分级：

| 状态集合 | C 的第一步 | 调用 |
|---|---|---:|
| 只有明确压制 | SINK 最小范围绕过（删除这些条目） | 1 |
| 含未知标签（单独或与其他状态混合） | J2 定向重核 + SINK，不删除任何条目 | 2 |
| 只有带证据的遗漏 | 先检查恢复前终端：遗漏槽已用证据表逐字引文作答则不动，否则做 J2 定向重核 + SINK | 0 或 2 |
| 无 M1 类标记 | 不动 | 0 |

**每一步之后做终端完整性检查**（零调用，不读 Gold）。目标槽未恢复，或非目标槽出现以下退化之一，就升级一级（绕过 → J2 定向重核 + SINK）；J2 重核后再触发则停止并记录：
- 恢复前引文在证据表中逐字可查，恢复后不可查；
- 新出现 M3 违例；
- 派生槽答案与基础合计不一致。

**C 的 M3 处理**（在 M1 处理之后，对 C 的当前终端，修订 2）：
1. 对 V5 M3 判为 SELF_EVIDENCE_INCONSISTENT 的答案，确定性地改写为 UNKNOWN（移出 answers，写入 unknown_slots），0 次调用。UNDETERMINED 保持原样，不强制判错。
2. 若 C 该重复的预算还剩至少 1 次调用，执行一次 H 反馈 SINK 重跑，反馈中列出 M3 违例槽及原因。
3. 对重跑结果再做 M3 检测，仍违例的答案按第 1 步改写，然后停止，不再继续恢复。

C 每臂每重复最多 5 次调用：绕过、重核、SINK、H 重跑、一次重试。

**每臂每重复只有一次重试机会**，可用于任一节点，计入该臂预算。

## 六、异常分级

**基础设施级，立即停止整批，不重试**：
- 传输错误（HTTP、socket、超时）；
- 输入完整性失败（输入 token 少于 0.25×字符数）；
- 服务方报告的模型族与路由不符；
- 台账完整性失败；
- 任何预算预检触顶；
- **共享上游阶段（检查点形成之前）的任何节点级故障**。

**节点级，可在臂内恢复**：臂自身调用出现空文本、截断、JSON 失败、缺键或异常 stop。用掉该臂唯一一次重试；重试后仍失败，该次恢复动作作废，臂回退到它最后一个成功的终端输出。

## 七、不完整执行的统一口径（修订 3）

1. 三臂的失败都保留原始记录（先写后发台账）。
2. 某臂某重复只要产生过至少一个成功的终端输出，就取最后一个成功输出作为最终结果，按正常评分规则计算。
3. **完全没有终端输出时，三臂一律记 Q_all = 0**，安全指标记为“无法判定”，不得算通过。
4. 同时报告两套结果：包含不完整执行（记零）与剔除不完整执行。两套都标注不完整次数。

## 八、样本量与功效（修订 4）

精确单侧符号检验，α=0.05，剔除平局；假设异常后为正的概率 pp=0.95。

| 情景 | pa | P(有效样本 ≥ 6) | 无条件功效 |
|---|---:|---:|---:|
| **保守（敏感性）** | 0.8 | 0.797 | **0.722** |
| 乐观 | 0.9 | 0.962 | 0.808 |

- **pa 的依据较弱，如实说明**：探针复用的是 SC-E1 的三份旧输入，没有证明千山药机的自然异常概率。0.9 只作乐观情景，0.8 是保守情景。
- **样本量**：8 个重复，不增加。若有效样本少于 6，报告“检验能力不足”，不擅自追加。

## 十、成本与时延口径

- **成本**：每臂按独立部署口径计算，包括共享上游、恢复前 SINK 和本臂的恢复调用。批次实际花费中，共享调用只计一次。
- **时延**：报告两项。
  - **恢复阶段增量时延**：本臂恢复调用的墙钟时间之和，即 H2c 的判定量。
  - **端到端时延**：共享上游 + 恢复前 SINK + 本臂恢复调用。各节点串行执行，按串行之和报告，并注明 E_D1 与 E_D2 理论上可以并行。
