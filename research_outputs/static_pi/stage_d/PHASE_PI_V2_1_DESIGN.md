## 0. 本设计回答什么、不回答什么

### 回答（固定 R₀ 条件下）

| 估计量 | 含义 |
|---|---|
| `Δ_π = Q(Z=1,π=1) − Q(Z=1,π=0)` | **在已做结构调整的条件下，增加剩余节点模型重分配的增量收益** |
| `Δ_Z = Q(Z=1,π=1) − Q(Z=0,π=1)` | **在已做模型重分配的条件下，增加结构调整的增量收益** |
| `I_Zπ = Q11 − Q10 − Q01 + Q00` | Z 与 π 的**交互效应**（互补 or 替代） |

### 不回答（必须写进论文边界）

- **不验证** `a=(Z,R,π)` 三维联合优化。本实验的 R 是**固定策略 R₀**，不是决策变量。
- **不验证**"选择重执行哪些节点"的收益——那需要 R 的层级实现，属第二层研究。
- **不验证**节点级（node-wise）模型异构分配。Phase P 未发现达标交互；
  π 是**剩余节点的整体配置调整**，不是逐节点画像分配。

## 1. R₀：四臂完全相同的固定重执行策略

```text
R₀(异常节点 n) :
  1. versions[n] += 1
  2. state[n] = Ready
  3. 对 n 的每个后代 d（递归）：若 state[d] ∈ {Completed, Ready} 则 state[d] = Ready
  4. 不改变任何节点的 model、sys、prompt
```

**冻结约束**：
- 四臂（Retry-only / Z-only / π-only / Joint）**必须调用完全相同的 R₀ 实现**（同一个函数，不是相同逻辑的两份拷贝）。
- 每个节点最多重执行 2 次（超出即 Failed），四臂一致。
- `exec_llm` 内部的 2 次传输重试（attempt 1/2）属于**传输层**，四臂一致，不计入 Z/π。

**Static 臂不调用 R₀**：异常被记录，节点维持其（可能错误的）输出，下游继续——
这是"无恢复"基线的正确定义。

## 2. π：剩余未执行节点的模型重配置（不只是换失败节点）

### 2.1 形式定义

```text
异常时刻 t_detect(n)：
  U = { m : state[m] ∉ {Completed} } ∪ {n}      # 剩余未完成节点 + 异常节点
  U = U \ {FMT}                                  # FMT 确定性，无模型
π=0: 不改变任何节点 model
π=1: 对 U 中每个 m：spec[m].model = ALT        # ALT = glm53flash 的替代配置 = deepseek
```

- **π=1 会改写尚未完成的全部模型节点的配置**，包括异常节点本身。
- 已完成节点**永不改动**（不重做已完成的工作）。
- **零自由参数**：不设时间阈值、不设节点类型规则。
  理由：Phase P 未发现达标的节点级能力差异，任何"按节点类型分配"的规则都缺乏证据基础；
  按剩余时间设阈值则会引入需另行校准的参数，使 Pilot 无法自洽。

### 2.2 可选的第二水平（不进入本次 Pilot）

> π=1b：仅当 `remaining_time < τ` 时才切到 ALT（截止期压力触发）。

τ 必须由 Pilot 之外的独立标定确定。**本次 Pilot 不实现 π=1b**，避免自由参数。

### 2.3 合法性约束

- 槽位：`deepseek` 并发=1、`glm53flash` 并发=2。π 切换后若槽位不足，**排队而非跳过**，并记录等待时长。
- 预算：π 不额外消耗预算；若预算不足以完成 U，则记录 `budget_blocked`。

## 3. Z：合法作用空间（逐节点 × 逐异常族）

现有检测器产生的异常族：

| 族 | 触发条件 | 出现在 |
|---|---|---|
| `structure` | E1/E2 缺 `positions`；J1 缺 `dates_relay`/`positions_relay` | **S1（E2）、S3（J1）** |
| `model_suspect` | timeout / parse_fail | S2（J2）、S5 |
| `caliber_suspect` | J2 `counts.personal > counts.announcing` | 未在冻结场景中注入 |
| `format` | FMT 答案违反 `PURE` 校验 | S4 |

### 3.1 Z 动作表（冻结）

| 异常 | 节点 | Z 动作 | 合法？ | 依据 |
|---|---|---|---|---|
| structure（缺 positions） | **E2 / E1** | **拆分为两次窄抽取 + 确定性合并**：①仅抽取 positions 字段；②抽取其余字段；合并为原 schema | **需要实现**（见 §3.3） | 真实结构变化（1 节点 → 2 节点 + merge），不伪造 |
| structure（缺 relay） | **J1** | 换用 `REPAIR_LIB['J1']`（`RELAY_ADDENDUM`，强制 `dates_relay`） | **已存在** | 冻结资产 |
| caliber_suspect | **J2** | `J2_SYSTEM + DISAMBIG_ADDENDUM`（计数口径澄清） | **已存在** | 冻结资产 |
| format | **FMT** | **不是 Z**：确定性 L1 规范化，**所有臂统一执行** | 见 §4 | 格式问题不是结构问题 |
| model_suspect | 任意 | **不适用（n/a）**：传输/解析失败没有结构补救，合法补救是重试（R₀）或换模（π） | **显式标注不适用** | 不得伪造修复动作 |

### 3.2 Z 的合法性约束

1. **不改动已完成节点的有效结果**（只重执行异常节点及其闭包，闭包由 R₀ 负责）。
2. **输出合同不变**：Z 前后该节点的输出必须满足同一 schema。
3. **DAG 合法性**：拆分产生的新节点必须在合并后恢复原节点身份与出边；不得出现悬挂依赖。
4. **Z 可以选择"不调整"**：当异常族为 `model_suspect` 或 `format` 时，Z 分支**不产生任何动作**，
   并在日志中记 `z_not_applicable`，不得记作"已修复"。

### 3.3 需要新实现的部分（唯一一处）

E1/E2 的 `positions` 缺失目前**没有任何修复手段**（`REPAIR_LIB` 只有 J1）。
两个选项：

| 选项 | 做法 | 代价 | 评价 |
|---|---|---|---|
| **Z-E2-split** | 异常时把该 E 节点拆成"仅 positions"+"其余字段"两次调用，确定性合并 | 需实现合并器 + 新 user 构造 | **真实结构变化**，推荐 |
| Z-E2-na | 标注 **n/a**，Z 在该场景不产生动作 | 零实现 | 保守，但 S1 的 Z 变异消失 |

**建议：实现 Z-E2-split**。若操作员选择 n/a，则 Z 的处理变异只剩 S3（J1），
见 §6 的功效后果。

## 4. format 处理必须四臂统一（消除 Joint 的额外优势）

当前 `format_repair` 只出现在 `Fixed-Composite` 与 `Proposed-Dynamic` 分支中，
而 R-only / π-only 没有——**这是让 Joint 占便宜的来源之一**。

**V2.1 冻结为 L1 层（非臂差异）**：
- FMT 的确定性格式规范化（`apply_format_rules` + `PURE` 校验 + 单次重入队）
  **在所有六个臂中无条件执行**，包括两个 Static 基线。
- 理由：FMT 是确定性程序节点，不是模型能力；把它做成臂差异等于比较"有无格式化器"，与研究问题无关。
- 若规范化后仍违反 `PURE`，记 `format_violation` 并计入质量，不额外重试。

## 5. 六臂 × 变量矩阵（对齐证明）

| 臂 | 初始配置 | R₀ | Z | π | L1 格式化 | 异常注入 |
|---|---|---|---|---|---|---|
| Static-GLM | GLM 全节点 | ✗ | ✗ | ✗ | ✓ | 相同 |
| Static-DS | DS 全节点 | ✗ | ✗ | ✗ | ✓ | 相同 |
| Retry-only | GLM 全节点 | ✓ | ✗ | ✗ | ✓ | 相同 |
| Z-only | GLM 全节点 | ✓ | ✓ | ✗ | ✓ | 相同 |
| π-only | GLM 全节点 | ✓ | ✗ | ✓ | ✓ | 相同 |
| Joint | GLM 全节点 | ✓ | ✓ | ✓ | ✓ | 相同 |

**对齐要求（冻结前必须逐项断言）**：
1. 四个因子臂的初始 model 都是 `glm53flash`（否则 π 的基线不一致）。
2. 四臂调用**同一个** `R0()` 函数对象。
3. Z 与 π 的动作实现互不依赖（Z 不改 model，π 不改 sys）。
4. L1 在六臂中调用同一函数。
5. 任务、初始 DAG、异常注入点、每执行预算（14 调用 / 180s）、并发槽配置完全相同。

**Joint ≠ Z-only + π-only 的机械拼接**：Joint 在同一异常上**同时**执行 Z 与 π，
其效果是否等于两者之和，正是交互项 `I_Zπ` 要检验的。

## 6. 状态选择：Z 的处理变异只有两个场景（重要）

| 状态 | 注入异常 | 异常族 | Z 是否适用 | π 是否适用 |
|---|---|---|---|---|
| **S1** | E2 丢失 positions | structure | **是**（split） | 是 |
| **S2** | J2 首次超时 | model_suspect | **否** | 是 |
| **S3** | J1 部署缺陷（缺 relay） | structure | **是**（REPAIR_LIB） | 是 |
| **S4** | FMT 绕过 | format | **否**（L1 统一） | 是 |

**若 Pilot 只用 S3+S4（操作员原设想）**：Z 只在 S3 有变异 → `Δ_Z` 与 `I_Zπ`
仅由 **3 个配对单元**支撑，**不足以估计交互效应方差**。

### 建议状态集

| 方案 | 状态 | 六臂执行数 | Z 变异单元 | 评价 |
|---|---|---|---|---|
| A | S3 + S4 | 36 | 3 | 只够估 π 主效应；交互不可估 |

可检验"Z 只在结构异常时才起作用"这一机制预测。

## 7. 估计量与统计方案

### 7.1 配对单元

配对单元 = (状态, 重复)。同一单元内六臂共享任务、异常注入、初始 DAG、预算与槽位。

### 7.2 主估计量（S1+S3 合并，或按状态分层）

```
Δ_π|Z=1 = Joint − Z-only       （H1）
Δ_Z|π=1 = Joint − π-only       （H2）
I_Zπ    = Joint − Z-only − π-only + Retry-only   （H3）
```

**按状态分层报告**：S1 与 S3 的 `Δ` 分别给出（机制分析），主检验用合并（Mantel-Haenszel 或固定效应合并）。

### 7.3 检验形式（必须预注册）

- **双侧精确符号翻转检验**（`exact_perm_dp.py`），α=0.05；
- H1、H2 为两个主检验 → **Holm 校正**（阈值 0.025、0.05）；
- H3（交互）为**探索性**，不进主检验，报告效应量与 CI；
- **单侧检验作为敏感性分析**报告，不作主判据。

N=6 时双侧最小可达 p=2/64=0.031（6/6 同向）；N=9 时 2/512=0.0039。
**Pilot 不做确认性推断**，只估效应量/方差/零差比例。

### 7.4 功效

确认性实验的 N 由 Pilot 的配对差方差决定：
`N ≈ (z_{1-α/2}+z_{1-β})² σ² / Δ²`，再用 `exact_perm_dp` 精确验证。
**不得沿用 V1.3.2 的 0.7719**（旧模型/旧条件）。
