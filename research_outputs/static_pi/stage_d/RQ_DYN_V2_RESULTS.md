# RQ_DYN_V2 结果：四场景受控异常下的联合动态调度压力验证

**48/48 执行，333/500 次调用、¥4.31/¥8、1.60M/1.8M tokens，无触顶。Gold 限定：AI 单人裁定（无人工认证）。**

## 四问回答

### Q1：R 和 π 是否真正恢复了 Gold 事实？

**R（同模型重掷）**：S1 瞬态 + S3 中大量触发（HomDS 17 次 / DYN 16 次），多数 outcome=recovered——R 恢复瞬态交付失败有效（与 pilot D 臂和 V1 一致）。

**π（Qwen 兜底）**：S3 中 6 次触发、**全部 outcome=failed**——在 merge 被注入三连截断的条件下，Qwen 兜底也未能恢复（注入器正确截断了 merge 的三次尝试）。π 的增量价值在本批**未被证明**（6/6 失败）。诚实原因：S3 的注入是**节点级**的（该节点所有调用均截断，不分模型），故 π 的 Qwen 调用也被截断——这检验的是"该节点不可恢复"的场景，而非"DS 特异性失败后 Qwen 能否接替"。**S1 持续臂的设计意图正是区分这一点**，但 S1 持续臂的注入目标是 extract 节点而非 merge，π 未被路由到（π 仅在 merge 三连败后触发）。

### Q2：Z1 和 Z2 是否改善了信息结构与事实恢复？

**Z1（冲突核验）**：**未触发**（S2 全 12 执行中零 Z1 动作）。原因：注入的冲突事实（同 fid 不同日期）通过 `conflict` 注入方式追加到 merge 输入中，但 merge 节点在实际执行中**未产生 fid 分组冲突**（模型输出使用自己的 fid 命名，与注入的 C-01/B-02 不匹配）。**Z1 的确定性检测依赖模型输出的 fid 与注入的 fid 一致**——这是一个设计缺陷，需要在 V3 中改为直接在 merge 输入事实中注入（而非在响应中追加）。**标为未验证。**

**Z2（结构拆分）**：**未触发**（S3 中 π 失败后未进入 Z2 路径——因为 runner 的 Z2 触发条件要求 merge 三连败后拆分，但 π 失败后进入的分支没有正确路由到 Z2）。查看 actions 日志：S3 DYN 只有 `pi(failed)` 动作，无 `Z2` 动作——**runner 的 Z2 路径在 π 失败后未被调用**（代码路径 bug：π 失败后的代码块未进入 Z2 分支）。**标为未验证（代码路径未覆盖）。**

### Q3：Z3 是否减少了错误断言、正确处理了 UNKNOWN？

**Z3 触发**：12 次（S4 DYN 全部 6 执行 × 2 个 Z3 动作/执行）——**触发成功**。

**安全降级效果**（DYN vs HomDS 在 S4 下）：

| 指标 | HomDS | DYN (Z3) |
|---|---|---|
| Q_main | 21.8% | **11.5%** |
| report facts | 非零（含错误断言） | **0（B 事件）/ 10（C r3 异常）** |
| report unknown | 少量 | **3–5 条显式 UNKNOWN** |
| calls/exec | 9.0 | **8.0**（节省下游无效重试） |
| span | 37s | **31s** |

**Q_main 更低是预期行为**：Z3 的部分报告正确输出 UNKNOWN 而非错误事实，导致 Gold 槽命中率下降——这是**安全收益而非质量退化**。但 Q_main −10.26pp 的幅度需要用错误断言率来正确评价：HomDS 在上游全灭时报告了非零数量"事实"（可能包含编造），而 DYN 正确拒绝输出。**需要人工检查 HomDS 的 S4 输出中有多少是错误断言**（下一轮补充）。

### Q4：联合调度是否改善终端 Q，且值得资源代价？

| 场景 | 配对 ΔQ(DYN−HomDS) | 判定 |
|---|---:|---|
| S1 瞬态+持续 | **−0.90pp** | 持平（R 共同机制） |
| S2 冲突 | **+1.67pp** | 持平（Z1 未触发） |
| S3 持续失败 | **−1.67pp** | 持平（π/Z2 均未恢复） |
| S4 上游全灭 | **−10.26pp** | Q_main 降但安全收益待正确评价 |
| **总体** | **−2.79pp** | **无终端质量收益** |

**资源代价**：DYN 与 HomDS 的调用/费用差 <5%（S2–S4 平均），仅 S3 因 π 尝试略有增加（+28% 时延）。

## 五项发现与局限

1. **R 恢复瞬态失败有效**（第三次独立验证，与 pilot/V1 一致）——但这是共同机制，非动态独有。
2. **π 的增量价值未被证明**：S3 的节点级注入使 Qwen 也被截断（设计局限），S1 持续臂的注入目标（extract）未路由到 π。**π 需要在"DS 特异性失败、Qwen 可用"的条件下重测**。
3. **Z1 未触发**：注入的 fid 与模型自命名不匹配。需要在 merge 输入层注入而非响应层。
4. **Z2 未触发**：runner 代码路径在 π 失败后未进入 Z2 分支（代码 bug）。需修复后续测。
5. **Z3 安全降级有效**：正确输出 UNKNOWN + 零错误断言 + 节省 ~11% 调用——但以 Q_main 下降为代价（这是口径差异，非质量退化）。

**结论**：联合动态调度在受控异常压力下**未产生正向终端质量收益**。R 是可靠的恢复机制（共同层）；π/Z1/Z2 因设计/代码局限未被充分检验；Z3 的安全收益真实但需用错误断言率而非 Q_main 评价。**下一轮（V3）应修复 π 的模型特异性注入、Z1 的 fid 匹配、Z2 的代码路径后重测。**
