# 阶段一：终端质量提升（Quality Improvement Phase, QP1）

**状态**：设计与离线准备完成。**零真实调用；本轮不启动任何付费实验。**
**优先关系**：阶段一（质量）→ 阶段二（异构协同与结构优化）→ 阶段三（Z/R/π 动态调度）。H2.1 与 Z/R/π 全部暂缓。

## 1. 为什么先做质量

在"值正确 ∧ 证据定位 ∧ 证据支持"的复合口径下，已有真实输出的终端质量远低于 TP-only 数字：

| 来源 | 单元 | 复合 Q | 值正确 | 定位 | 支持 | UNKNOWN | Gate |
|---|---|---:|---:|---:|---:|---:|---:|
| V2 Pilot | 36 格 / 828 事实 | **7.5%** | 25.5% | 7.7% | 7.5% | 100% | 0% |
| S2 A 条件 | 24 格 / 420 事实 | **3.3%** | 14.9% | 3.8% | 3.3% | 54.5% | 0% |

这不是"模型只会 3%"的终局判断，而是**当前执行链路在证据约束下的真实终端交付水平**。TP-only 的 40–50% 与之不矛盾：值对了，但证据没绑上、引文不逐字、关键事实门未通过。

**结论**：在把复合终端质量提高到 70% 之前，研究动态调度的收益没有说服力。

## 2. QP1 评分器（新版本；冻结 R4/v1.2.3 不变）

`quality_phase_v1/scorer_qp1.py`：

- 支持任务实际 Gold 数量 N（不固定 13 槽，不凑槽）。
- 每个事实分别记录：值正确、证据定位（doc/page 存在且引文逐字在页内）、证据支持（引文支持该事实）。
- 复合 Q = 三项同时满足的事实数 / N。
- 证据支持按"任一引文真正支持"计；派生事实的"全部来源覆盖"作为单独诊断（`derivation_full_coverage`），不进入 Q/Gate（否则单引文格式下 Gate 永远不可达）。
- UNKNOWN 单独评价：正确拒答率；把未知断言成事实要单列。
- Critical Gate 独立报告 PASS/FAIL，**不平均进 Q**。
- Relevance 不进 Q，由独立盲评（I-2）另行处理。
- 值与引文比较复用冻结 v1.2.3 的原语（只读），聚合逻辑为新版本。

独立测试 11/11（`QP1_SCORER_TESTS.json`），含：值错、doc 错、引文非逐字、引文不支持、缺失、UNKNOWN 断言、Critical Gate 不掩盖。

## 3. 错误归因（已有输出，零调用）

`QP1_ERROR_ATTRIBUTION.json`。主要发现：

1. **金额类事实是最大的值错误来源**：S2 的 254 个值错中 **213 个是金额**（罚款、虚增收入/利润、占用、担保、对价）。日期 41、主体 199（V2）、关系 36。
2. **证据绑定是第二约束**：V2 的 136 次定位失败是 **doc 不存在**（节点名 E1/E2 被当成文书 ID）；S2 有 34 次 doc 不存在、13 次引文非逐字。即使值对，也只有约 25–30% 能绑定到正确页码的逐字引文。
3. **UNKNOWN 处理在 S2 明显退化**（54.5%）：既漏拒答，也把未知断言成事实。
4. **Critical Gate 全灭**（V2 0/36、S2 0/24）：关键事实只要有一个不满足三项即 FAIL，平均分不能掩盖。

**归因边界**：这是对既有输出的描述性归因，不是新实验；V2.3 回溯诊断不作确认性证据。输出所用的提示并未强制标准 doc ID 与连续引文，因此 3%–8% 是"当前链路"的下界估计，不是模型能力上限。

## 4. 质量提升实验设计（待授权）

### 4.1 四臂（同一任务、文书、Gold、评分器、模型）

| 臂 | 干预 | 只改变什么 |
|---|---|---|
| Baseline | 现有固定 7 节点执行流程（DS） | — |
| E1 证据约束抽取 | 每个事实必须携带 doc/page/连续逐字引文；无证据不得输出 | 抽取提示与输出合同 |
| E2 逐事实核验 | E1 + v 节点对每个事实的引文做逐条核验；不支持则丢弃或标 UNKNOWN | 核验节点逻辑 |
| E3 终端整合 | E2 + SINK 只使用已核验事实；未核验一律拒答 | 终端汇总逻辑 |

四臂调用数相同（7 节点 × 7 次），差异只在提示与核验/整合逻辑，便于归因。模型统一用 DS，避免把模型差异混入质量干预（模型差异留给阶段二）。

### 4.2 任务与防过拟合

- **开发集（dev）**：E06、MVR1（Gold）+ KANGMEI、GUOEN（Silver）。
- **保留集（held-out）**：E04、MVR2（Gold）+ ZHANGZIDAO、YJT（Silver）。
- 每任务 2 次重复；独立任务为统计单元。
- 任何提示/规则调整只允许在 dev 上做；held-out 在最终验收前不得查看逐题结果（只看宏平均）。
- 最多两轮 dev 迭代；held-out 只跑最终版本。

### 4.3 70% 验收（预注册）

**主终点**：held-out 四任务的**宏平均复合 Q ≥ 0.70**（每任务先算 Q，再对任务取平均；不按事实数加权）。

同时必须报告（缺一不可）：

- 复合终端 Q；
- 键事实值正确率；
- 证据定位成功率；
- 证据支持率；
- UNKNOWN 正确拒答率；
- Critical Gate 通过率；
- 每任务调用数、token、费用、时延。

**判定规则**：
- Q ≥0.70 且 Critical Gate 通过率 ≥0.80 → 阶段一通过，进入阶段二设计。
- Q ≥0.70 但 Gate <0.80 → 不算通过（关键事实错误不能被平均分掩盖）。
- Q <0.70 → 不通过；只允许在 dev 上做一轮归因修正，held-out 不重复看结果。

**70% 是内部质量门槛，不代表动态调度有效。**

### 4.4 可证伪假设

| 假设 | 陈述 | 预期方向 |
|---|---|---|
| H-Q1 | 证据约束抽取（E1）相对 Baseline 提高值正确率与定位率 | 值错误（尤其金额）下降 |
| H-Q2 | 逐事实核验（E2）相对 E1 提高证据支持率 | 不支持引文下降 |
| H-Q3 | 终端整合（E3）相对 E2 提高复合 Q 与 UNKNOWN 正确率 | 断言未知下降 |
| H-Q4 | E3 在 held-out 上达到 Q≥0.70 且 Gate≥0.80 | 阶段一门槛 |
