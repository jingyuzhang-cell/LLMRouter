## 0. 判定

| 判据 | 结果 |

| **P-H1 交互效应（符号反转）** | **FALSE** |
| P-H3 稳定性 | TRUE（仅 T5 达标） |

而 T5 上 GLM 仅领先 0.058。**"未发现异质性"不等于"证明两模型等价"**。

## 3. 三处必须披露的偏离

### P-D1：任务数从 3 降为 1（执行前发现，已记录）

预注册写"3 个独立任务"，但**该基准只有一道任务**（D1–D4 四份文档组成的一个问题），
不存在 3 个独立任务。改为 **1 任务 × 3 重复**，判据中"≥2/3 任务"改为"≥2/3 重复"。
代价：**失去跨任务泛化**，本结论只在单一任务上成立。

### P-D2：首轮 DeepSeek 测量无效（12/15 截断、9 次零字符）

首轮 33 次调用中，DS 有 12 次 `max_tokens` 截断、其中 **9 次返回零字符**——
其推理 token 吃光了输出预算。**这是容量假象，不是能力差异**。
根因：我的执行器漏掉了冻结 `transport.py` 对 DeepSeek 设置的 `thinking: disabled`。

修正后重测 15 次（`thinking: disabled`），**15/15 合规、零截断**。
本报告采用重测数据；GLM 首轮结果有效（0/15 截断）并保留。
**首轮数据不参与判定，但完整保留在账本中**（`PP:*` 前缀）。

### P-D3：T1–T4 的质量指标饱和（测量效度限制）

T1–T4 使用 `contract × grounding`（合同合规 × 证据可溯源率）作为 Gold-free 代理指标，
两个模型都接近或达到 1.0 → **天花板效应，无法区分语义正确性**。
J1/J2 的"判断是否正确"需要人工 Gold，本轮不可得。
因此：**本轮只能排除"合同/溯源层面的能力异质性"，不能排除"语义判断层面的能力异质性"。**

## 4. 已证明 / 未证明

### 已证明
1. 在 thinking=low / disabled 的**同一条件化输入**下，两模型在 5 类节点上
   **未出现符号反转**的能力模式（P-H1 FAIL）。
2. 合同合规：两模型均可稳定输出所需 JSON（各 15/15）。
3. **DeepSeek 在质量可比的条件下快 2–8 倍**，token 略低——这是可用于成本/时延优化的真实差异。
4. GLM 在终端组卷（T5）有稳定但很小的优势（+0.058）。

### 未证明 / 不能声称
1. **不能**声称"两模型能力等价"——T1–T4 指标饱和。
2. **不能**外推到其他任务（单任务）。
3. **不能**外推到其他上游组合（T3–T5 的上游是 GLM 参考链快照）。
4. **不能**据此说异构分配无效，只能说"在本任务、本指标下没有可利用的节点级异质性"。

## 5. 对 Phase Pi / Stage D 的影响

- **Phase Pi 不设异构臂**（预注册的"某模型统一占优 → 用统一模型基线"分支）。
- 统一模型的选择有了实测依据：**若质量为王选 GLM（T5 +0.058），若时延/成本为王选 DS（快 2–8×，
  质量差 ≤0.058）**。这条要在 Phase Pi 里作为**一个明确的对照维度**，而不是默认 GLM。
- Stage D 的 π 维度：由于未发现节点级交互，**π 的腾挪空间主要来自"整体换模"而非"逐节点分配"**——
  这直接收窄了 π-only 与 Joint 的预期差异。**Joint 若要有价值，必须证明其收益来自
  R（重执行集合）与结构，而不是来自 π。**

## 7. 勘误与表述收紧（2026-11-02，零调用复核后）

### 7.1 统计表述

原文写"未发现可利用的节点级能力异质性"，表述过强。复核后的准确表述是：

> **未发现达到预注册门槛、能够可靠用于节点级异构分配的交互效应。**

理由：平均方向**确实存在交叉**——T1（−0.042）、T3（−0.125）偏向 DS，
T4（+0.019）、T5（+0.058）偏向 GLM。交叉存在，但**没有任何一对同时满足
`|Δ|≥0.05` 与"重复同号"**：
- T3 幅度达标（0.125）但三次重复极差 **0.250**，稳定性不达标；
- T1、T4 幅度未达 0.05；
- 仅 T5 同时达标（+0.058，极差 0.044）。

因此**不能**写成"证明不存在能力交互"，只能写"未达到判据"。

### 7.2 时延差异的归因边界

原文"DeepSeek 快 2–8 倍"必须加限定：

> 该差异是**两种执行配置之间的差异**：GLM 为 `thinking: low`（强制思考），
> DeepSeek 为 `thinking: disabled`。**不能全部归因于模型本身。**

这不妨碍研究两种配置在系统中的价值（它们就是实际部署的两种形态），
但**不得**表述为"DeepSeek 模型比 GLM 模型快 2–8 倍"。
