## 0. 你问的四个问题的直接答案（stable .20，20% matched，200 任务）

| 问题 | 测量值 |
|---|---:|
| 事实恢复成功率（边际） | **73.9%** |
| 定位恢复成功率（边际） | **71.6%** |
| 证据支持成功率（边际） | 74.4%；在事实恢复成功的条件下 **77.1%** |
| 三者同时成功（真实联合率） | **40.7%**（朴素乘积 .70³=34.3%） |
| 70% 需要的转换 | **3.21 个/任务**（当前 1.50） |

**为什么联合率只有 40.7%？不是因为某个单阶段特别弱，而是因为缺陷结构：**

| 缺陷类（事实, 定位, 支持） | n | 占比 | 实测联合成功率 |
|---|---:|---:|---:|
| **(1,1,1) 三者全缺** | **579** | **78.3%** | **33.3%（= .70³）** |
| (0,0,1) 只缺支持 | 51 | 6.9% | 64.7% |
| (0,1,0) 只缺定位 | 51 | 6.9% | 66.7% |
| (1,0,0) 只缺事实 | 46 | 6.2% | 76.1% |
| 其他双缺组合 | 12 | 1.6% | 33–60% |

**结构性根因：在该机制里，非 TP 事实（FN）的 loc/sup 从未被置真，所以每个 FN 事实自动落入 (1,1,1) 类，联合成功率被钉死在 p³=.343。** 聚合值 40.7% 高于 34.3% 只是因为 22% 的单缺事实成功率更高。三个阶段的边际成功率几乎相等（.716–.744），没有单一短板；短板是"三缺"结构本身。

## 2. 容量与漏检：一半以上的坏事实根本没被尝试

每任务的坏事实账本（stable .20，20m）：

| 项 | 数量/任务 | 说明 |

**要点：坏事实总量约 7.0/任务，当前机制只触达 3.7 个、转换 1.5 个。** 到 70% 需要 3.21 个转换——即使在现有触达范围内把联合率提到 100%，也只有 3.70 个转换（Q≈73.7%），刚好够；但联合率 .407 时只有 1.50。

## 3. 到 70% 需要什么机制能力（不调参数，只算需求）

| 情形 | 所需每事实产出 | (1,1,1) 类所需单阶段成功率 |
|---|---:|---:|
| 当前容量（3.70 触达/任务） | 3.21/3.70 = **0.87** | p³=.87 → p≈**95%** |
| 修复全部预算跳过（≈5.2 触达） | 3.21/5.2 = 0.62 | p≈**85%** |
| 再加漏检全覆盖（≈7.0 触达） | 3.21/7.0 = 0.46 | p≈**77%**（接近当前 .70³ 的边际） |

**结论：单靠提高重试次数或扩覆盖都不够；70% 需要单阶段恢复成功率从 .70 提到至少 .77–.85，或改变动作结构让一次动作修复多个事实，或提高基础 Q 以降低所需转换数。** 这就是"为什么不能靠调 sens/重试次数达到 70"的定量形式。

## 4. P2 可行性：共享证据恢复的多事实潜力（测量，非新机制）

修复后仍是"TP 但定位/支持未过"的事实（共享证据动作的天然目标池）：

| | stable .20 | H0 |
|---|---:|---:|
| 可证据修复事实/任务 | **1.02** | 0.70 |
| 按节点分布 | e0 56、e1 55、t 32、m 25、v 20、r 13、p 4（共 205/200 任务） | 分散 |

- **即使共享证据恢复把这个池子全部修复（完美），也只 +1.02 转换/任务 ≈ +7.9pp → 65.2%，仍不到 70%。**
- 这个池子集中在 e0/e1（抽取事实常是 TP 但证据链断），不在 r；而 r 的坏事实 92% 是 FN，必须先做事实恢复。
- **共享证据的真正价值更可能在成本侧**：当前 D 每节点尝试 .25 成本单位，预算把 1.14 个已标记真坏节点/任务挡在门外；若同节点多事实共享一次证据动作，可在同预算下提高触达（§3 第二行）。但按上面测算，仅靠成本共省（触达 5.2）也需要单阶段成功率 ≥.85。
- **P2 结论：值得设计（成本侧收益真实），但它单独不能到 70；必须与事实恢复能力提升或更高基础 Q 组合。**

## 5. H0 对比：为什么 H0 增益更大（归因失败的机制解释）

| | stable .20 | H0 |
|---|---:|---:|
| base Q | 45.27% | 37.62% |
| 坏事实池/任务 | ≈7.0 | ≈8.7（触达 3.9 + 漏 4.0） |
| 联合成功率 | 40.7% | 42.7% |
| 转换/任务 | 1.50 | **1.62** |
| 70% 所需转换/任务 | 3.21 | 4.21 |

**H0 的修复增益更大（+13.34 vs +12.00pp）不是机制在利用模型差异，而是 H0 的 base 更差、坏事实更多，同样的修复器有更多可修对象。** 三阶段成功率在两个世界里几乎相同（.73/.72/.74 vs .77/.73/.74）。这从机制上解释了归因门失败，也指明了修复方向：**要让 stable 增益超过 H0，修复动作必须利用"GLM 在 r/m/v/p 上更强"的能力差异（例如用 GLM 重执行坏节点），而不是用与模型无关的均匀恢复概率。**

## 6. 对 P2–P5 的设计输入（不在本轮执行）

1. **P2 共享证据恢复**：目标池 1.02/任务（e0/e1/t 为主）；验证"一次共享动作修复同节点多事实的定位/支持"是否能显著降低每转换成本；预期上限 +7.9pp，**不单独承诺 70**。
2. **P3 终端联合重建**：需要能一次影响多槽的动作；按 §3，所需综合产出 ≥0.62/触达事实。
3. **P4 基础分配×修复预算**：用 R5/JFR 数据可算：all-DS+D（57.27@1.170）、m+V-CR（57.16@1.10–1.20）、m+v 无修复预算（53.29@1.19）。同等预算下"便宜底座+修复"与"贵底座+少修复"目前打平；**真正的问题是用 GLM 重执行坏节点（能力差异修复）能否打破这个平局**。
4. **P5 factorial**：修复动作必须分"模型无关"与"模型相关"两种实现，H0/sham 对照分别检验；归因门改为"stable 增益 − H0 增益 ≥5pp"。
