## 二、Phase Pi 冻结方案就绪核查

### 2.1 能否测真实终端质量 —— **可以**

`stage_d_executor.py:845-847`：
```python
term = D2.SA_EX.build_terminal_output(...)
q = evaluate_terminal_quality(D2.SA_EX.CONTRACT, term, D2.SRC())
```
使用冻结的 `terminal_quality` 独立评分，TP/23 槽位。**满足"真实终端质量"要求。**

### 2.2 是否有两个统一模型基线 —— **没有（硬缺口）**

执行器的节点规格里，**全部 7 个模型节点默认 `model="glm53flash"`**；
DeepSeek 只通过 `swap` 动作出现（π-only / Fixed-Composite / Proposed 臂）。

六臂全部是**策略臂**：Static / R-only / π-only / Simple-Dynamic / Fixed-Composite / Proposed-Dynamic。
**不存在 "全 DeepSeek" 的统一基线臂。**

而 Phase P 刚测出：两配置质量差 ≤0.058，但时延差 2–8 倍。
没有 DS 统一基线，就无法回答"时延优先配置在截止期约束下是否更好"，
也无法把 Joint 的收益与"整体换配置"的收益分开。

**三种补法（需操作员选择，均改动冻结矩阵）**：

| 方案 | 做法 | 代价 |
|---|---|---|
| A | 新增第 7 臂 `Static-DS`（全 DS 静态） | 矩阵 6×32 → 7×32 = 224 执行（+32） |
| B | 整矩阵跑两遍：基线 GLM 版 + 基线 DS 版 | 192 → 384 执行（+192，最贵但最完整） |
| C | 仅 Static/R-only/Joint 三臂加 DS 版 | 192 → 192+96 = 288 |

**建议 A**：最小增量，且足以回答"配置 × 策略"是否交互。

### 2.3 执行器能否直接跑 —— **不能（硬缺口）**

`capital_opinion_pilot/transport.py:24-33` 的 `glm_call` **硬编码 `thinking: {'type':'disabled'}`**。
但 GLM-5.3 已拒绝该参数（1210）。**冻结执行器直接跑会在第一次 GLM 调用即失败。**

必须换成 Phase P 已验证的传输：GLM `thinking: low` + DS `thinking: disabled`
（`phase_p_exec.py` 中的实现可直接复用）。这属于 V2.0 的既定工作，不新增设计。

### 2.4 预算必须重算 —— **不能沿用 V1.3.2 的 2,688 / 9.5M / ¥34.56**

实测（既有真实诊断 + Phase P）：一个 S4 R-only 执行 14 调用消耗 **36,008 token**；
Phase P 平均 **3,291 token/调用**。
- 192 执行 × 约 36K = **约 6.9M token** → 9.5M 上限只剩 2.6M 余量；
- 若按方案 A（224 执行）→ 约 **8.1M**；
- GLM 资源包余 ~49.6M，**token 不是约束**；需重算的是**调用数上限**与现金口径。

### 2.5 矩阵与统计

- S3+S4 = 16 对精确符号翻转（`exact_perm_dp.py` 已支持 N>16，需冻结+独立审计）；
- Pilot 规模：36 执行（6 臂 × S3/S4 各 3 重复）≈ 500–720 调用。

## 四、本轮结论

1. Phase P 的**判定成立**，但表述已收紧：未达门槛 ≠ 不存在交互；时延差属配置差异。
2. Phase P 的**成本账**已复核：¥0.2781，其中 52% 被首轮配置错误浪费。
3. Phase Pi **不能直接开跑**：传输层与基线臂两处硬缺口，加上预算重算。
4. 这三项都是**已定位、有明确解法**的工作，不需要新设计方向——但**都需要操作员批准改动冻结矩阵**。

**建议**：先批 P1（传输）与 P2 方案 A（新增 Static-DS 臂），再按 Pilot 规模授权；
确认性主实验的样本量与预算由 Pilot 结果重算后再定。
