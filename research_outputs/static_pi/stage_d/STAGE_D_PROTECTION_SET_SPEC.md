## 二、操作员裁定（2026-11-02，逐字要点）

1. 统计覆盖 = **全部 8×8×6=384 槽-run，六臂全含，不采用 Proposed-only**。
2. **倒退** = 保护槽位**原本正确**，经对应策略执行后**变为错误**——不是把"模型输出错误"简单计为倒退。
3. **不得**用目标槽位的质量提升抵消保护槽位倒退。
4. 各槽参考基准必须从冻结协议逐项提取（本文件第三节）；基准核清前，`protection_regressions=0` 只能标 MOCK。

**倒退判定的可实现形式（供审计脚本执行）**：
```
regression(slot, arm, scenario, rep) :=
    reference_correct(slot, arm, scenario)          # 第三节基准（六臂历史正确 / 修复臂恢复正确）
    AND NOT correct_in_final(slot, arm, scenario, rep)   # 终局该槽-run 值层不正确（terminal_quality claim 结果，同 Stage C 三级口径）
```
- "correct_in_final" 用与 D2 相同的值层判定（claim status 以 CORRECT 开头；U2 以"未断言具体值"为正确）。
- **无抵消条款**：回归计数只加不减；目标槽位（如 D_3、A 系）的提升不进入该计数。
- 每条倒退必须能落到 `(slot, arm, scenario, rep)` 四元组，供独立复核。

## 五、审计脚本（已交付，零调用；R1 固定）

`protection_set_audit.py`：
- 输入：终局执行记录目录（执行器输出）、基准文件（缺省= 本第三节表导出的 `PROTECTION_BASELINE.json`）；
