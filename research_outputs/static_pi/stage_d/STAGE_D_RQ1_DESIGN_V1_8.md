## 0. 回答"多大的真实收益才值得做"

**最小科学价值收益（MVS）= 中位任务（17 槽位）的 +1 TP ≈ 6.25% 的 task-equal 终端 ΔQ，且至少包含 1 个关键事实 TP。**

**结论**：先有证据表明真实局部互补至少 0.15（终端 ≥MVS），再投入 40 个任务；若只有 0.10，接受探索性结论，不为 80% 功效扩张。

## 3. Oracle 的偏差与正确用法（P3）

**V1.8 发现：在测试集上事后取每节点最大观测值，Oracle 在 H0 下也有 +0.17–0.18 的虚假收益。** 这是 max-of-noisy 选择偏差，不是模型互补。

正确做法：
1. **交叉拟合 Oracle**：在训练/验证集上选每节点模型，在独立测试集上评估；
2. 模拟中报告**真实 Oracle**（用真实参数）作为上限；
3. 报告 Oracle 的 H0 偏差，并从观测 Oracle 中扣除；
4. Oracle 仍不参与训练/选择/部署。

若未校正，不能用“Oracle 有明显收益”证明模型池有互补。

### 3.1 收益分解

- **模型池潜在收益** = 校正 Oracle − Best Unified；
- **策略实现收益** = Node-Type（或 Task-Conditioned）− Best Unified；
- **预测误差损失** = 校正 Oracle − 策略；
- **传播损失** = 局部节点潜在收益 − 终端潜在收益；
- **成本** = 增量 Token/费用/时延。
四者分开报告；不能把 Oracle 与策略的差距简单归因于“模型无互补”。
