## 0. 结论摘要

1. **V2 降级语义修正达到设计目的。** 36/36 次执行全部 `completed`，零失败、零截断。V1 中 Retry-only 与 pi-only 因重执行上限被 hard-fail（TP=0）的阻塞混淆已消除：V2 中两者中位分别为 6.5 与 6.0。
2. **主动作 Z（拆分修复）机械上成功、终端上无收益。** Z-only 在 S1 与 S1b 共 6/6 次恢复 `positions` 字段，全部节点 `COMPLETED`、零降级；但冻结 TP 中位 **5.0**，低于 Retry-only 的 **6.5** 与 Static-GLM 的 **6.0**。配对比较 Z−Retry 中位 **−1.5**（6 对中 1 胜 1 平 4 负）。
3. **π 在 Z 之上没有产生冻结 TP 增益。** Joint−Z-only 中位 **+0.5**（3 胜 2 平 1 负，属噪声）；证据支持型 TP 反而 **−1.5**。π（DeepSeek 重写）使可绑定文书 ID 的证据从 64/138 降到 19/138。
4. **Q 无法用于区分六臂。** 36/36 次执行的 `Q_final` 均为 `None`，由同一组 4 个合同级阻断原因造成，与臂无关。正式终端分数在本合同下不可计算；唯一可比的差分指标是 TP/23。
5. **TP 指标本身被"逐字匹配"主导。** 语义诊断（非评分）显示：材料上与 gold 一致的答案约 95–112/138，而冻结 TP 仅 32–38/138；在全部失败中约 60–78% 属"格式被拒"而非事实矛盾。11/23 个槽位（A3/A4/A5/B3/B3b/C2/D_1–D_4/E3）在六臂上恒为 0，原因是符号值/固定措辞不被精确匹配接受，而非事实错误。真正的事实错误集中在 E2（实例计数：gold 2，模型答 3 或 4）。
6. **唯一的正向信号出现在诊断层，不能作为结论。** 后验语义诊断中 Joint 的材料正确性中位 **19.0/23**，6/6 配对优于 Static-GLM（中位 +2.5）；冻结 TP 完全看不到这一差异（0.0）。该诊断是在看到数据后手写的，仅供假设生成，不得当作已确认收益。

**判定：V2 执行有效、结论为 CONDITIONAL —— 结构修复为真，终端质量收益未获证明；确认性推断应 BLOCKED，直到终端评分合同的有效性问题由操作员裁定。**

## 4. 六个验收问题

**Q1：Z 是否真的抬高终端质量，还是只恢复了一个字段？**
只恢复了字段。Z 恢复 `positions` 6/6、全部节点正常完成，但冻结 TP 中位 5.0 < Retry 6.5、Static-GLM 6.0；配对 Z−Retry 中位 −1.5（1/1/4）。原因有二：(a) 非 Z 臂虽无 `positions` 字段，仍能从原文引用推断职务身份，A1/A2 的材料正确率已为 6/6，Z 没有新增信息；(b) Z 的答案更啰嗦（附加"（公司未被立案）"等），反而更容易被逐字匹配拒绝（A1/A2 冻结 TP 1/6 vs Retry 3/6）。

**Q2：给定 Z，π 是否还有增益？**
没有可确认的增益。Joint−Z-only 冻结 TP 中位 +0.5（3/2/1，噪声）；证据支持型 TP −1.5（1/2/3）；可绑定证据从 64/138 降到 19/138。诊断层的材料正确性 +2.0（5/0/1）是唯一正向信号，但被 π 的证据定位崩塌抵消。

**Q3：Z 是否丢失了其他字段？**
没有。拆分后 `E2_pos`（positions）+ `E2_rest`（其余 5 字段）经 code 合并为 6 字段，规模与原始 E2 相当；J2 在 Z 臂保留的键不少于非 Z 臂。F1/F2 未作答升高同样出现在 Retry-only，不能归因于 Z。

**Q4：拆分的成本是否值得？**
不值得（以当前评分计）。Z 相对 Static-GLM：成本 +11.1%（¥0.02994 vs ¥0.02694），token +12.5%，延迟 +10.9s（117.7 vs 106.8）；换来的冻结 TP 为 −1.0。相对 Retry-only：成本 +9.2%，TP −1.5。

**Q5：是否存在真实的 Q/C/L 净收益？**
没有可确认的净收益。正式 Q 在 36/36 全部被合同级阻断（`Q_final=None`），无法比较；冻结 TP 最好的是 Retry-only（6.5）；诊断层 Joint 材料正确性最优（19.0，6/6 配对胜 Static），但未经冻结评分确认，且成本更高、证据支持为 0。延迟上 Joint 比 Static-GLM 低约 58%，但不及 Static-DS（27.5s）。

**Q6：降级/失败/正常完成的比率在六臂间如何？**
- 非 Z 四臂：6/6 执行含 `COMPLETED_DEGRADED`（S1 为 E2×3、S1b 为 E1×3），失败 0，全节点正常完成 0/6。
- Z-only 与 Joint：降级 0、失败 0、全节点正常完成 6/6。
- 即：Z 是唯一的结构性修复动作，但它修复的是"节点能否正常完成"，不是"终端答案是否更好"。

## 5. 测量有效性发现（必须上抛，先于任何确认性推断）

**M1. 冻结 TP 被符号值逐字匹配主导。** 23 槽中 10 个槽在六臂上恒为 0，其中绝大多数是格式问题而非事实错误；材料正确 95–112/138 vs 冻结 TP 32–38/138。**推论：在现合同下，臂间 TP 差异主要反映措辞风格，不能作为"知识质量"的度量。**

**M2. 证据文书 ID 接口错配。** 评分器要求 `D1–D4`；管道中间产物用节点名 `E1–E4`；π 臂几乎完全不产生可绑定 ID（0–19/138）。这使"证据支持型 TP"在 π 臂上系统性归零。

**M3. Q 的形式化计算对六臂全部不可用。** 36/36 `Q_final=None`，阻断原因同为：`CLAIM_EXTRACTION_INCOMPLETE`、`DELIVERY_INVALID_SEMANTIC_QUALITY_UNAVAILABLE`、`GOLD_CONTRACT_INVALID_VALUE:E3`、`QUESTION_RELEVANCE_NOT_VALIDLY_ASSESSED`。其中 `GOLD_CONTRACT_INVALID_VALUE:E3` 是合同自身缺陷（gold `2(公司+自然人王勇)` 不满足数值合同），与本实验无关但影响全局。

**M4. V1 冒烟文件被覆盖（已如实记录）。** V1 的 `v2/SMOKE_RESULTS.json`（sha256 `dfc870b3c17b…`）在 V2 冒烟时被覆盖，且该路径未纳入 git，原始字节不可恢复。已从 `v2/smoke.log` 逐行重建为 `SMOKE_RESULTS_V1_RECONSTRUCTED.json`（6 条 S1-r1 摘要，明示为重建件）。V1 的账本、主体结果、报告与其余文件均完整保留；`engine_v22.py` 的变更是指令要求的 V2 降级语义。

## 7. 建议（需操作员裁定）

1. **确认性推断暂缓。** 在 M1/M2/M3 未解决前，任何"Z 更好/π 更好"的结论都不可检验；当前数据只能支持"Z 修复结构、不改终端"。
2. **终端评分合同修订（操作员决定，不是本实验可自行做的）。** 对符号槽位补充 `accepted_values` 或启用已校准的语义裁决；修复 `E3` 的 gold 合同值；归一化证据 doc ID（或在评分器接受节点名到文书 ID 的映射）。这是合同修订，不是放宽标准。
3. **若维持现合同**，则确认性实验应以"证据支持型 TP"为准，并把 π 的 doc-ID 崩塌视为 π 的真实代价（而非测量噪声）。
4. **Z 的下一步**应聚焦"拆分后如何让 SINK 少加限定词"，因为当前 Z 的唯一实测负效应来自措辞膨胀导致的格式拒绝，而非信息缺失。
