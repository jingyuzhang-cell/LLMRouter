## 三、矩阵与检验（约束）

- 矩阵：6 臂 × 32 = 192（S0 2 / S1 3 / S2 3 / S3 8 / S4 8 / S5 8），与 V1.3.2 规模相同。
- 主检验：S3+S4 = **16 对**精确符号翻转（2^16 全枚举）。
- **计算约束（已按操作员纠正）**：旧 `exact_perm.py` 用 `2^m` 枚举，`MAX_M=16` 是**实现限制，不是统计上限**。新 `exact_perm_dp.py` 用子集和 DP 精确计算同一符号翻转分布：D2 反演（0.125/0.03125）与 500 例随机枚举逐例一致；m=24 约 1.1ms、m=32 约 2.7ms。因此 **N=24/32 在保留精确检验方法的前提下可行**，无需 Monte Carlo 或近似。
- V2.0 需冻结 `exact_perm_dp.py` 并独立审计；`exact_perm.py` 保持历史冻结。N 由 Profiling/Pilot 后决定，不再固定 16 对。

## 六、预算（待裁定，不能默认沿用 2,688/9.5M）

- 真实诊断：一个 S4 标准端点执行 14 调用消耗 **36,008 tokens**（8,008 in / 28,000 out）；192 执行粗估约 **6.9M tokens**，9.5M 仅剩 2.6M 余量；S5 竞速双请求可能触顶。
- 每个 S4 R-only 在 always-thinking 下 245.6s > 旧 180s 截止期；新模型时延需预检/pilot。
- **D3 候选**：per-exec 20；全局 4,000；token 12M；S0–S4 截止 300s；S5 方向性/探索性。**仅适用于 N=16（192×20=3,840）**。
- N=24（240 执行）→ 最大 4,800 调用；N=32（288 执行）→ 最大 5,760；全局/Token/现金必须按 N 重算。
- 还需补充：实际现金硬上限、失败/迟到计费、Token 预留/结算、诊断调用是否计入；同时加入 Profiling（~60 calls）与 Pilot（36 执行）预算。
- 这些是 V2.0 预算候选，不是 V1.3.2 的授权，也不是当前执行授权。
