## 1. Z 的构念效度：只允许改变 DAG

### 1.1 定义（冻结）

> **Z = 通过改变 DAG 的节点集合、依赖边或任务分解方式，改善异常后的执行计划。**
> 任何**不改变拓扑**的操作（改提示词、改 addendum、改温度）**不属于 Z**。

### 1.2 提示词修复整类移除（不是重新归类）

V2.1 里我把 `RELAY_ADDENDUM`、`DISAMBIG_ADDENDUM` 当作 Z。按您的判断，这是构念混合：
它们不改变节点与边。**V2.2 把它们从所有臂中移除**——不是"归入 prompt repair 子类别"，
而是**系统中不存在 prompt repair 这一干预**。

后果（必须接受）：
- 任何只能靠改提示词缓解的异常，在 V2.2 中**只能靠 R₀ 重跑（同提示词，通常无效）或 π 换模**；
- 这使 Z 的含义唯一：**只有拓扑变化才算 Z**。

### 1.3 唯一合法的 Z 动作：E 节点结构拆分

**触发**：`structure` 异常发生在 E1 或 E2（`positions` 缺失）。

**执行**（真实拓扑改动，必须落 DAG 版本）：

```
t0: DAG v_k:  E_i ──> J1 ──> J2 ──> SINK
Z :  E_i 被替换为两个子节点 + 一个合并节点
t1: DAG v_{k+1}:
      E_i_pos  ─┐
                 ├─> E_i_merge ──> J1 ──> J2 ──> SINK
      E_i_rest ─┘
```

| 子节点 | 输入 | 提示词 | 输出 schema |
|---|---|---|---|
| `E_i_pos` | 同一文档原文 | `E_SYSTEM + E_POSITION_ADDENDUM`（**仅**要求 positions） | `{positions:[...]}` |
| `E_i_rest` | 同一文档原文 | `E_SYSTEM`（不含 positions 要求） | `{subjects,notice_numbers,dates,cause,quotes}` |
| `E_i_merge` | 两子节点输出 | **代码，无模型** | 原 E 节点完整 schema |

**合并规则（确定性）**：两子节点键集**不相交**，故为直接字典并集；无冲突消解，无自由参数。

**合法性断言（实现时必须断言）**：
1. 拆分后 DAG 无环、无悬挂边；
2. `E_i_merge` 的出边集合 == 原 `E_i` 的出边集合；
3. `E_i` 的所有上游边转移到两个子节点；
4. 输出 contract 与拆分前**逐字段相同**；
5. 记录 `dag_version_before/after` 与 `nodes_added`（供审计）。

**调用成本**：Z 事件 +1 次模型调用（1 → 2），最坏情形 7+2+3=12 ≤ 每执行 14 上限（已核算）。

### 1.4 Z 的"不适用"清单（显式，不得伪造）

| 异常族 | 节点 | Z |
|---|---|---|
| `structure`（缺 positions） | E1 / E2 | **适用**（拆分） |
| `structure`（缺 relay） | J1 | **不适用**（见 §2.2） |
| `caliber_suspect` | J2 | **不适用**（原解法是提示词修复，已移除；无拓扑解法） |
| `model_suspect` | 任意 | **不适用**（传输失败无结构补救） |
| `format` | FMT | **不适用**（L1 层，非臂差异） |

**Z 分支在"不适用"时 `acts=[]`，日志记 `z_not_applicable`，绝不记作"已修复"。**

## 2. 状态集重定

### 2.1 为什么 S3 必须剔除

S3 的缺陷是 `J1` 的**部署 spec 缺少 `RELAY_ADDENDUM`**：提示词里没有 relay 指令，
因此**任何模型都不可能输出 `dates_relay`**。合法补救只有两种：
- 改提示词 → 已被 V2.2 排除（不是 Z）；
- 新增一个 relay 子节点（`E1,E2 → R1 → J2`）→ 需要**改写 J2 的输入 contract**（J2 现在接收
  `{J1,E3,E4}`，加入 R1 后语义改变）。

**改写 J2 的输入 contract 会改变下游所有节点的输入，属于实验条件变更，本轮不冻结。**
→ **S3 不进入 V2.2 的 Pilot。**

### 2.2 用 S1b 补足第二个 Z 场景

```text
S1  : corrupt_once 在 E2 删除 positions      （既有）
S1b : corrupt_once 在 E1 删除 positions      （新增，参数化同一注入器）
```

两者是**同一故障类型在不同节点**上的重复，不引入新的构念。这样 Z 有效单元：
`S1 × 3 重复 + S1b × 3 重复 = 6 个配对单元`。

### 2.3 最终状态集

| 状态 | 注入 | 异常族 | Z 适用 | π 适用 | 作用 |
|---|---|---|---|---|---|
| **S1** | E2 丢 positions | structure | **是** | 是 | Z 主场景 |
| **S1b** | E1 丢 positions | structure | **是** | 是 | Z 重复场景 |
| **S4′** | SINK 输出经 L1 后仍违反 PURE | format（残余） | 否 | 是 | π-only 场景（Z 不适用对照） |

**剔除**：S3（无合法 Z）、S2（超时属传输层，与 S4′ 的 π 信息重复，且预算有限时优先保留 Δ_Z 的单元）、
S5（竞速，与本轮 Z/π 问题无关）。

矩阵：**6 臂 × 3 状态 × 3 重复 = 54 次执行**。

## 3. 执行顺序（冻结）

每次异常严格按以下六步，**顺序不可交换**：

```text
1. detect
   锁定：异常节点 n、异常族 fam、当前 DAG 版本 v_k、该时刻的 state 快照

2. R₀（四臂同一函数；Static 两臂跳过）
   versions[n] += 1; state[n] = Ready
   对 n 的全部后代递归：若 state ∈ {Completed, Ready} → state = Ready

3. Z（若 fam 在 §1.4 中适用，且该臂 Z=1）
   执行拓扑改动 → 生成 DAG v_{k+1}；新子节点进入 Ready
   记录 dag_version_before/after、nodes_added、edges_added/removed

4. 重新计算 U（必须在 Z 之后）
   U = { m : state[m] ∉ {Completed, Running} }            # 待派发
       ∪ { 新建的子节点与合并节点 }
   U = U \ {FMT, merge 节点}                                # 确定性节点无模型

5. π（若该臂 π=1）
   对 U 中每个 m：spec[m].model = ALT(deepseek)
   π=0：不改动

6. 重新调度
   按槽位（glm=2 / ds=1）、剩余预算、截止时间派发
```

### 3.1 在途请求（强制规则）

- **`state[m] == Running` 的节点不进入 U**，其请求按原模型正常结算；
- π **不得**修改已派发请求的 model；`spec[m].model` 的改写只对新派发生效；
- **不取消在途请求**（取消语义与费用结算另立课题）；
- 记录 `pi_scope = [实际被改写的节点]`、`pi_skipped_inflight = [...]`。

### 3.2 为什么顺序必须是 R₀ → Z → U → π

反例：E2 异常时 J1 已 Completed。若在 R₀ 之前算 U，J1 不在 U 中；但 R₀ 会把 J1 置 Ready
（依赖失效），它**实际需要重跑**。只有 R₀（与 Z）之后再算 U，才能保证 π 覆盖所有真正要执行的节点。

## 4. S4′：L1 与故障注入的交互（重新定义）

### 4.1 问题

L1 格式化在六臂中**无条件执行**。如果 S4 注入一个 L1 能修的格式错误，那么 L1 修完之后
**没有异常**，动态调度不会被触发——"被统一修复的异常不能当触发条件"。

### 4.2 定义（冻结）

```text
S4′ 注入点：SINK 输出的 PURE 校验违规，且 L1 无法修复（如：日期值语义错误而非格式错误）
检测点：    L1 执行之后
结果：      残余违规 → fam=format_residual → 触发策略
Z：         不适用（无拓扑解法）
π：         适用（换模重跑 SINK）
```

- **记录 `l1_fixed`（L1 是否修复成功）**：若 L1 修好了，该执行不计为异常，也不触发策略；
- 六臂中 L1 行为完全相同，**L1 本身不是变量**；
- 若 S4′ 中 L1 修复率达到 100%（即注入的违规总能被修），则**该状态作废**，
  按 `invalid_reason` 记录，不进入统计分母（并如实报告该状态的作废率）。

## 6. 统计方案（含 N 下限）

### 6.1 Pilot 的定位

**Pilot 不做确认性推断**，只估：配对效应量、重复间方差、零差比例、按状态分层的收益差异、
成本/时延/按期率变化。

### 6.2 N 的硬下限（新）

双侧精确符号翻转、全部同向时的最小 p = `2 / 2^N`：

| N | 6/6 同向 p | Holm 首阈 0.025 |
|---|---|---|
| 6 | 0.03125 | **失败** |
| 7 | 0.015625 | 通过 |
| 8 | 0.007813 | 通过 |
| 9 | 0.003906 | 通过 |

**结论：即使 Pilot 的 54 次执行全部同向，也无法通过 Holm 首阈 0.025。
确认性实验的 N 必须 ≥7（且需按 Pilot 方差重算后可能更大）。**
Pilot 的 6 个 Z 有效单元**只能用于估计**，不得写成确认性证据。

### 6.3 确认性检验形式

双侧精确符号翻转，H1（Δ_π|Z=1）与 H2（Δ_Z|π=1）两个主检验，Holm 校正；
H3（交互 `I_Zπ`）为探索性；单侧作敏感性分析。
