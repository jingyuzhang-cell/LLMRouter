# 四个崩溃案例机制归因报告（零调用 · 2026-11-05）

## 一、机制发现：Fixed-Composite 的 π(swap) 动作破坏 J1 输出

对 S3 r5/r6/r8、S4 r2 四个崩溃案例的执行日志取证，发现一致模式：

### S3 r8（P=14 vs F=3）

| | Proposed-Dynamic | Fixed-Composite |
|---|---|---|
| 异常检测 | J1 structure（1 次） | J1 structure（**2 次**——重复检测） |
| 决策动作 | `structure_repair@J1`（1 个精准动作） | `structure_repair + format_repair + swap` × **2 轮**（6 个动作） |
| 关键差异 | 仅修复结构 | **swap 将 J1 切换到 DS** → 第二次异常 → 再全动作执行 → FMT 失败 |

### S4 r2（P=12 vs F=3）——最典型案例

| | Proposed | Fixed |
|---|---|---|
| 异常 | **无**（anomalies=[]） | J1 structure（1 次） |
| 决策 | 全部节点 `acts=[]`（**零干预**） | `structure_repair + format_repair + swap` |
| 动作数 | **0** | **3**（包括不必要的 swap） |
| TP | 12 | 3 |

**关键发现**：Proposed 在 S4 r2 中**检测到零异常→不干预→TP=12**。Fixed 在同一场景中**误触发了 3 个恢复动作（含 swap）→ TP 骤降至 3**。

### 统一机制

```
Fixed-Composite 对每个检测到的异常执行全部三个动作：
  structure_repair → 正确（修复结构问题）
  format_repair    → 可能正确（修复格式）
  swap(π)          → 将节点模型切换到 DS ← 关键破坏点

swap 导致：
  1. J1 被切换到 DS → DS 在该节点能力不足 → 输出质量下降
  2. 低质量输出再次触发异常检测 → 第二轮全动作恢复
  3. 重复恢复消耗时间/预算 → FMT 或后续节点失败
  4. 终端质量崩溃（TP 从 14 降至 0-6）
```

**Proposed 通过反馈信号识别故障家族（structure），仅选择 `structure_repair`，跳过不必要的 `format_repair` 和 `swap`，避免了这条级联失败路径。**

## 二、四个案例的汇总

| 案例 | P_TP | F_TP | P 动作 | F 动作 | 崩溃根因 |
|---|---|---|---|---|---|
| S3 r5 | 16 | 6 | 精准 Z | Z+F+π ×多轮 | swap 引发二次异常→级联 |
| S3 r6 | 13 | 0 | 精准 Z | Z+F+π ×多轮 | 同上+FMT 失败 |
| S3 r8 | 14 | 3 | 精准 Z（1动作） | Z+F+π ×2轮（6动作） | swap→再异常→再全动作→FMT Failed |
| S4 r2 | 12 | 3 | **零干预** | Z+F+π（3动作） | **误触发不必要的 swap** |

## 三、科学结论

**反馈驱动动态调度的核心价值不是"平均更好"，而是"避免在特定异常类型下的级联质量崩溃"。**

具体机制：全动作固定组合中不必要的 `swap`(π) 动作是崩溃触发器——它将正常工作的 GLM 节点切换到能力不足的 DS，引发二次异常和重复恢复的恶性循环。反馈驱动的 Proposed 通过故障家族分类仅选择匹配动作（structure→Z only），跳过了这一破坏性路径。

这与 QP9/CFL/Stage-3 的发现完全一致：**盲模型切换（π）在该任务体系中主动有害**。Fixed-Composite 因为不区分异常类型而**每次都执行 π**，恰好踩中了这个地雷。

## 四、论文表述建议

核心贡献应表述为：

"反馈驱动的选择性恢复通过故障家族分类避免不必要的模型重分配（π），在特定异常类型下防止了全动作固定组合策略中因模型切换引发的级联质量退化（TP 崩溃 0-6 vs 维持 12-16）。配对精确置换检验 p=0.0547（方向性证据），收益集中于 4/16 配对（去除此 4 对后其余 12 对净差 −1）。"
