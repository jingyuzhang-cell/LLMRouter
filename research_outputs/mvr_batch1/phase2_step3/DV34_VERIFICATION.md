## 1. DV4：操作者质疑成立，且比"舍入规则未定"更严重——**金标准本身算错了**

精确复算：`(24500 − 19804.88) / 19804.88 × 100 = 23.70688436…%`

| 舍入规则 | 两位小数结果 |
|---|---|
| 四舍五入（HALF_UP） | **23.71** |
| 银行家舍入（HALF_EVEN） | **23.71** |
| 截断（DOWN） | 23.70 |

- 冻结合同 DV4 gold = "23.70"，**未声明任何舍入规则**；23.70 只在"截断"下成立，而截断并非任何已冻结的约定。
- **两模型输出的 23.71 是对 percent_change 的正确计算与正常舍入；"错误"在合同侧。** 根因：构建器断言用了 `<0.01` 宽松检查，掩盖了我方心算滑误（误记 23.7038）——合同缺陷，责任在构建侧。
- **处置：DV4 的"稳定值级模型错误"认定撤销**，改记为合同错值实例（冻结合同不改，解释层修正）。

## 2. DV3：口径歧义 + 容差缺失的双重缺陷

- 合同确实冻结了比值口径（derivation `op=ratio` + 谓词"本期/上年同期"），精确值 19.55019；按冻结合同，模型答 18.55（净增长口径）**在字面上为错**——两模型族一致选择了自然语言上同样合理的另一口径（"扩大**了**N倍"）。
- 更深一层：**ratio/percent_change 属非终止小数派生，而 gold 为两位小数且无 tolerance 字段**——评分器的派生检查要求 expected 与 gold 精确相等（19.55019 ≠ 19.55，差 0.0002 > 0），**即使模型输出 19.55 也无法通过推导核验**。该事实在当前规格下结构性不可通过。
- 处置：DV3 保留"按冻结合同为错"的记录，但归类为**口径歧义收敛型 + 合同规格缺陷**；不作为模型算术能力错误。

## 4. 对 Gate-1/Gate-2 结论的正式修正

- **Gate-1 修正**：原"2 个真实稳定值级错误" → **E06 派生层实际为 0 个已证明的模型算术错误**（DV4=合同错值、模型正确；DV3=口径歧义+规格缺陷）。修正后的结构结论：**抽取层零错误 + 派生层"错误"全部源于合同规格缺陷——在正确规格的合同下，两任务尚未证明任何模型能力型错误。**
- **Gate-2 修正**：判定（情况二：无替代能力可利用）维持但机理精化——收敛可来自 (a) 共同解释偏好（DV3：两族模型一致选净增长口径），或 (b) 合同自身错误（DV4：两模型一致算对）。**两类都不可由换模修复**；后者根本不是模型错误。*"收敛型错误不可由换模修复"*的机制表述保留并由此获得第二个实例。
- **研究教训（入下批合同设计规范，不改冻结件）**：①非终止派生（ratio/percent/除法）必须冻结 tolerance 与舍入规则（建议 gold 存高精度 + tolerance 字段 + 舍入约定三件套）；②自然语言谓词含口径歧义时，公式必须进槽位约束（输出契约层消歧——正是选项 B 的核心）；③构建器断言禁止宽松比较（`<0.01` 掩盖了 0.0069 的真实滑误）。
