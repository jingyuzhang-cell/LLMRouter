## 为什么没有进入两臂评测

1. Qwen HTTP成功，JSON可解析，finish_reason=stop。返回顶层为 `node_id/contract/schema`，其中schema下包含claims；冻结输出合同要求顶层直接为claims。原执行器因此判K=false，未提交结果。不能据此认定金额/事实错误；也没有在事后解包改成PASS。
2. Qwen下游四个节点依赖该抽取结果，被阻断。这是依赖合同的正确执行，但使四类节点的时延画像没有观测值。
3. DeepSeek依照协议继续校准，五个模型节点均提交，产出了完整报告。链路接地/合同通过不等于语义正确，12项参考仍PENDING，不能给Q=1。
4. 入口的 `len(usable)!=2` 要求两个模型都具有所有所需合同的资源画像，才进入初始分配。这道完整画像门槛使全部配对在比较前被拒绝。

请求把Schema示例嵌在包含node_id/contract/schema/input的JSON说明内；Qwen保留了外包装。现有证据支持“提示与输出协议交互不匹配”，不能独立区分是模型指令遵循问题还是提示设计歧义，不能把它直接归为内容能力不足。

**本次执行集成仍有实质设计限制：正常校准失败虽不停止整批网络执行，但依赖式校准导致画像缺测，完整画像门槛再次阻止算法比较。** 之前零调用夹具证明可达控制流，并未证明真实输出能满足这一条件。此次不能用“正常退出码0”或“记录了拒绝”宣称核心研究目标完成。
