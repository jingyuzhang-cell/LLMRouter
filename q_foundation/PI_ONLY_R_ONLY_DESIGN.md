# π-only 与 R-only 干预实验设计（零调用，待授权）

> 操作者 2026-11-01 Stage A 复审定序：①保留 Stage A 冻结基线 → ②π-only 针对 J2 计数错误 → ③R-only 针对日期不可达 → ④观察两项干预是否真正改善 Sink → ⑤再入 Joint → ⑥Stage B 补充状态演进证据。本设计只覆盖 ②③，**不含任何已授权调用**。共 15 次调用（π-only 6：DS 3 + GLM 3；R-only 9：GLM 3×3）。

## 共同原则（两臂同守）

1. **逐 run 配对**：两臂均以 baseline run k∈{1,2,3} 的**已保存输出字节**为上游（E/J 层零重跑、零漂移），与各自配对 run 对照。
2. **双口径评分**：冻结评分器 formal 输出 + 确定性分解诊断层（操作者裁决口径），缺一不可。
3. **节点修复 ≠ 终端修复**：节点层与终端层指标分开预登记、分开报告（Stage A 已证二者不一一对应）。
4. **提示词零漂移**：所有沿用节点的 system/user 构造与 baseline 逐字节一致（唯一例外=R 臂 J1 的结构性中继追加，见下）。
5. 不修改 Runner3、不修改冻结评分器、不修改 Stage A 任何原始数据。

## 问题 A · π-only：J2 稳定计数错误（E2=4 vs Gold=2，3/3 全传播）

**假设**：错误源于模型而非信息（J2 的输入含正确信息——四份公告、同一告知书编号），换模型可修复。

### 设计

每个 baseline run k：
```
J2_DS(k) = deepseek-flash( J2_SYSTEM 原文, j2_user(上游=baseline run k 已存 J1/E3/E4 文本，逐字节) )
SINK(k) = glm53flash( SINK_SYSTEM 原文, sink_user(J1=baseline 已存, J2=J2_DS 输出) )
```
- 换模仅 J2 一个节点；SINK 保持 GLM；上游全部冻结复用。
- 调用：**6 次**（DS 3 + GLM 3）；temperature=0 两模型一致。
- 适配器/评分器/MANIFEST 与 Stage A 同链路复用。

### 预登记标准（执行前冻结）

| # | 标准 | 层级 |
|---|---|---|
| C1 | J2_DS 的 announcing_company_count = 2 于 ≥2/3 run | 节点修复 |
| C2 | 终端 E2 = 2 于 ≥2/3 run | **修复传播到 Sink（决定性）** |
| C3 | J2_DS 无节点层倒退：d3_subject_count=2 保持；B3b 绑定语义不倒退（0042026002→公司 / 0042026003→王勇） | 无副作用 |
| C4 | 终端已正确槽位（B1/B2/B4/E1/F3 值、U2 拒判）不因换模倒退（描述性） | 无副作用 |
| C5 | DS 新引入的任何节点错误（含 personal_filing_instances、unresolvable 变化）如实报告——π-only 可能修 A 破 B | 诚实记录 |

**结果解读预登记**：C1+C2 过 → 第一个异构修复实证；C1 过 C2 不过 → 节点可修但传播丢失（机制发现，指向 sink 消费问题）；C1 不过 → 该错误非"换 DS"可解（同等提示词下两模型收敛于此错误），转 prompt/结构手段——三者都是有效科研结果。

### 执行期硬门禁（π-only 专属）

1. **DS 凭据存在性**：`DEEPSEEK_API_KEY` 当前不在环境（历史批次同机制读取、当时在）——执行前须由操作者提供，否则 π-only 臂 BLOCKED（R-only 臂不受影响，可独立授权执行）。
2. **别名白名单按节点扩展**：仅 J2 节点允许 `deepseek`，其余节点仍限 `glm53flash`（逐节点白名单，进 MANIFEST）。
3. **DS 端点前置项**：`api.deepseek.com`（transport OPENAI_MODELS 固定常量）按前置检查 ③④ 口径复核并回显。
4. **成本硬顶**：DS 按实际账单记录（预计 in ~7.5K / out ~6K tokens，量级 <¥0.1）；**硬顶 ¥1.00，超顶即中止**。

## 问题 B · R-only：落款日期拓扑切断（F1/F2/F4 3/3 不可达）

**假设**：错误源于结构而非模型（E 层 3/3 抽到日期，J 层不转发，SINK 禁止 E 旁路）——修复依赖即可恢复终端事实，模型全 GLM 不变。

### 设计（最小拓扑干预：J1 增加日期中继，不加新节点、不改 J2/SINK 提示词）

```
J1'(k) = glm53flash( J1_SYSTEM 原文 + 结构性中继追加, 上游=baseline run k 已存 E1/E2 文本 )
J2'(k) = glm53flash( J2_SYSTEM 原文, j2_user(J1=J1'输出, E3/E4=baseline 已存) )   # 上游版本变化→诚实重算
SINK'(k) = glm53flash( SINK_SYSTEM 原文, sink_user(J1', J2') )                    # SINK 提示词零改动
```

**中继追加指令（J1 system 尾部追加，唯一提示词变化）**：
> 此外，在你的 JSON 输出中增加一个 `dates_relay` 字段：{"D1": {"公告落款日":…, "告知书收到日":…}, "D2": {…}}，取值只从上游抽取结果中的日期逐字转写（含原句引用与页码），不得推断。此字段为中继传递，不影响你的四项归一判定。

J1 是全链路唯一同时消费 E1+E2 且输出直达 SINK 的节点（拓扑事实），中继放 J1 是最小边改动。SINK 无需任何提示词变化——dates_relay 自然出现在其上游材料中。J2 因上游 J1 版本变化必须重算（这正是传播审计验证过的失效-重算机制的真实应用）。

- 调用：**9 次**（GLM 3 节点 × 3 run）；¥0 订阅边际（核算约 ¥0.04）。

### 预登记标准（执行前冻结）

| # | 标准 | 层级 |
|---|---|---|
| C1 | J1'.dates_relay 含 D1=2026-10-09、D2=2026-10-10（或同义原句转写）于 ≥2/3 run | 中继生效 |
| C2 | 终端 F1=2026-10-09 且 F2=2026-10-10（formal CORRECT）于 ≥2/3 run | **终端恢复（决定性）** |
| C3 | F4 语义恢复（落款日不同+收到日相同，诊断口径）于 ≥2/3 run | 终端恢复 |
| C4 | J1' 四项归一判定仍全对（中继不破坏主任务）3/3 | 无副作用-节点 |
| C5 | 终端已正确槽位（B1/B2/B4/E1/F3 值、U2 拒判、B3b 语义）不倒退 | 无副作用-终端 |
| C6 | E2 计数预期不因结构干预改变；若改变如实报告（结构-语义交互的意外信号） | 观察 |

**结果解读预登记**：C1+C2 过 → 第一个结构恢复实证（R-only 有真实收益）；C1 过 C2 不过 → 日期到达但 sink 未使用（消费机制问题，指向 Joint 的第二个干预点）；C1 不过 → 中继指令本身引入问题（如实报告）。
