# 阶段一：质量瓶颈诊断报告（2026-10-31，零调用）

---

## 核心发现："Q=0.81 vs Q=0.30"的差距是**伪差距**

V2.2 单模型 Q=0.8125 与 DAG 实验 Q≈0.30 **不可直接比较**——原因如下：

### 1. 不同任务
| 实验 | 任务 | 事件 |
|---|---|---|
| V2.2 | 1 个任务 | 江苏舜天(600287) |
| Stage-B | T-D1, T-P2 | 基准任务 |
| TGV | TGV-T1, TGV-T2 | 纳川、中铁（新任务） |
| DYNPI | SC-E2, SC-E4 | 康美、乐视 |
| R9B | SC-E1, SC-E3 | 獐子岛、中国船舶 |

**没有任何 DAG 实验使用过江苏舜天任务。**

### 2. 不同评分公式
| 实验 | Q 公式 | 事实集 |
|---|---|---|
| V2.2 | 纯关键词覆盖率 | facts_silver (8 条) |
| Stage-B | Q = f(cov, cite)，引用率纳入 | 任务各自 silver |
| TGV | 归一化子串 vs 裁决参考 | 14 条（6+8） |
| DYNPI | silver 覆盖 | 各任务 silver |

**Stage-B 中 cite=0.0 的 run 直接把 Q 拉到近零——这是评分公式差异，不是质量差异。**

### 3. 不同事实集和难度
V2.2 的 8 条 silver 可能比 TGV 的 14 条裁决参考或 Stage-B 的任务 silver 更容易（更简单的关键词匹配）。

## 但是：Stage-A 有同任务配对比较

Stage-A 在**相同任务**上做了 single_model vs fixed_graph vs auto_graph 的配对实验：

### single_model vs fixed_graph（12 对）
| 指标 | 中位数 |
|---|---|
| ΔQ (single − fixed) | **−0.056** |
| ΔC (single − fixed) | +4,891 tokens |
| Q wins | single 7 / fixed 5 |

**解读**：ΔQ 中位数为负（single 略优于 fixed graph），但差距极小（−0.056）；单模型 win 率 7/12 略高，但不是压倒性的。同时单模型成本高 ~4,900 tokens。

### single_model vs auto_graph（8 对）
| 指标 | 中位数 |
|---|---|
| ΔQ (single − auto) | **−0.056** |
| ΔC | +4,463 tokens |
| Q wins | single 7 / auto 1 |

**解读**：单模型对自动构图优势更明显（7:1），但 ΔQ 中位数同样仅 −0.056。

## 诊断结论

### 已确认的事实
1. **"Q=0.81 vs Q=0.30"是跨任务伪差距，不能作为 DAG 质量瓶颈的证据**
2. **同任务配对数据（Stage-A）显示**：单模型 vs DAG 的 ΔQ 中位数仅 −0.056，差距很小
3. **单模型成本更高**（+4,500~4,900 tokens），在成本维度 DAG 有优势
4. **DAG 的质量损失存在但不大**（~5%），不是此前推测的"严重瓶颈"

### 修正后的理解
- DAG 分解确实有轻微质量损失（~5%），但不是 Q 从 0.81 → 0.30 的悬崖式下降
- 悬崖式差距是**评分口径不统一**造成的伪象
- **报告节点质量瓶颈假说需要降级**——真正的问题可能不在 report 节点本身，而在评分标准不统一导致无法准确测量

### 对 H1 实验设计的影响
- 不需要专门解决"report 节点质量瓶颈"才能做 H1
- H1 的关键前置条件仍是：验证节点异类双亲 + 持久故障 + 模型能力差异
- **但必须使用统一的评分标准**（P0 quality_v4 或冻结的 Silver 口径），否则结果不可解释
