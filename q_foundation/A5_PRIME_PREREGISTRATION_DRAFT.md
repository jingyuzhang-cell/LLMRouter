**状态：DRAFT — 零调用审查产物，不构成执行授权。**
**日期：2026-11-03。**
**依据：2026-11-02 预检 HTTP 400 / code 1210（“该模型始终思考，不支持关闭思考；请使用 low、high 或 max”），Plan A（thinking disabled）不可执行。**

## 一、目标与定位

研究目标不变：在 E1P/E2P 完全相同的前提下，检验 J1 增加 `positions_relay`
能否改善下游 A5 的语义正确性、证据支持与终端交付质量。

但必须预先声明一个**结构性事实**（见第七节实证）：

- 旧合同与 V3 的 A5 值均为精确匹配（NFKC/空白归一后）`均无职务(仅实际控制人)`，无 `accepted_values`；
- 自然语言中继值（如 `均为实际控制人，未在公司担任任何职务`）在冻结评分器中
  **判错**（已实测）；
- 因此 **官方终端 A5 不可能因中继而通过**；终端 fact/evidence 的 A5 增益约为
  **1/断言数（历史 N=20–23 → +4.35–5.00pp）**，Q_raw 更低；实际预期为 0（除非模型偶然输出精确规范值，且无提示要求它这样做）。

所以 A′ 的终点分层必须预先固定：

| 层级 | 终点 | 性质 |
|---|---|---|
| 机制主终点 | A5 语义归一（B vs C） | 辅助指标；预期 B 0/3、C 3/3 |
| 官方主终点 | 旧合同 A5 状态 | 预期两臂 0/6（精确匹配所限） |
| 官方次终点 | 终端 fact / evidence / Q_raw | 预期 Δ≈0；约 1/断言数（N=20–23） |
| 成本时延 | 每节点 in/out tokens、wall、¥核算 | 描述性 |

**A′ 能证明“中继机制是否传递并被 SINK 使用”，不能证明“终端质量提升”。**
若研究目标是后者，应先另立 A5 合同编码修订（例如 `accepted_values`），
且不得把合同修订带来的分数变化表述为模型能力提升。

## 五、正式实验设计

- 样本：3 runs × 2 arms × 3 nodes = **18 次**。
- 上游：`runs_x/run{k}/E1P.json`、`E2P.json`；`runs/run{k}/E3.json`、`E4.json`（全部冻结）。
- 顺序：run1 B→C、run2 C→B、run3 B→C（与 Plan A 预登记一致），臂内 J1→J2→SINK，串行。
- 参数：GLM-5.3-Flash、Anthropic 端点、thinking low、temperature 0、max_tokens 按校准冻结值，
  两臂每节点完全相同。
- 停止规则：HTTP 非 200、429/401、1210、`stop!=end_turn`、JSON 解析失败、任何网络异常
  → 立即停止、保留现场、**不重试、不补跑、不换端点/模型**。
- 输出：`runs_a5_planAPrime/run{k}/{arm}_{node}.json`，记录 system/user、prompt hash、
  request/response body hash、usage（含 reasoning 若返回）、content block 类型与长度、wall、stop。
- 现场隔离：`runs_a5/run1/`（旧 4 文件）与 `runs_a5_planA/`（precheck 400）**只读**，不覆盖、不混入。

## 十一、独立判断：是否值得执行

**我的判断：不值得执行完整的 18 次；至多执行 7 次的分阶段先导。**

理由：

1. **机制结果已被归档强烈预示**。非 positions 臂（Static/Joint/π/R）A5 语义映射 **12/12 失败**；
   X 链（= C 臂等价）**3/3 通过**；官方 A5 在全部 15 个归档 run 中 **0/15 通过**；中止现场 C_J1 已证实 J1 能产出 `positions_relay` 233 字符。
   B 臂（E 有 positions、J1 不中继）在信息流上必然看不到职务句，P2 几乎是拓扑决定的结果，
   不是新的经验发现。
2. **终端质量在冻结合同下不可能改善**。A5 官方值精确匹配 `均无职务(仅实际控制人)`；
   自然语言中继值已实测判错；A5 仅是 23 个事实之一，终端 fact/evidence 增益约 1/断言数（历史 20–23 → 4.35–5.00pp），Q_raw 更低。因此 P4 预期 Δ=0，n=3 也无法分辨。
   若目标是“终端质量提升”，A′ 设计注定给出零结果——这不是模型失败，而是编码口径所致。
3. **唯一新增信息是“thinking=low 下是否仍能中继”与成本时延**。这用 **1 次校准 + run1 的 6 次**
   （共 7 次，累计 21，不动上限）即可回答；run2/run3 的 12 次只增加重复，不增加机制信息。
4. **主线优先级**：A5 是结构补全的支线；反馈驱动异构 DAG 的 Q/C/L 联合优化才是主线。
   在终端效应被合同编码锁零的情况下，继续投入 18 次调用不符合收益/成本。

**因此建议：**

- 若论文需要“B vs C 的干净因果隔离”证据：执行 **C0 + run1（7 次）** 分阶段先导；
  run1 结果与 P1–P6 一致且无异常，再由您决定是否扩到 run2/3（另需 +12 次授权）。
- 若目标是终端质量提升：**不要执行 A′**；先另立 A5 合同编码修订（如 `accepted_values`），
  并明确其为交付口径修复、非模型能力提升。
- 若两者都不紧急：**跳过 A5 在线执行**，以既有离线证据结案，立即回主线。
