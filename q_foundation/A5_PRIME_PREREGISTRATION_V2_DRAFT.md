## 二、B/C 配对设计（修正版）

### 2.1 配对结构

- **3 个 pair**：run1、run2、run3。
- 每个 pair 使用**该 run 自己的**冻结 E1P/E2P（run1 用 run1，run2 用 run2，run3 用 run3）；B/C 两臂共享同一份 E。
- 每个 pair 内 B、C 都执行 J1→J2→SINK（各 3 次）；**pair 内成对比较**。
- 唯一干预：J1 system 是否包含 `J1_POSITIONS_ADDENDUM`（154 字符）。
- J1 user、J2 system/user 模板、SINK system/user 模板、E、模型、thinking、temperature、max_tokens 全部两臂一致。
- 随机化：**平衡随机化**，seed `20261103`，随机选 1 个 run 为 C-first；结果：
  - run1：**C-first**
  - run2：**B-first**
  - run3：**B-first**

- 无并发、无重试、无跨 pair 复用下游输出。

## 三、C0 校准的有效性审查

### 3.1 结论：C0 **不能**完全代表真实 low 模式的 SINK 输入

C0 的 SINK 提示词由**历史 disabled 模式的 J1P+J2X** 构建；A′ 的真实 SINK 提示词由**本次 low 模式的 J1/J2 输出**构建。两者：

- 输入 token 规模相近（历史 4542–4750），但**上游内容/长度会变**；
- low 模式可能改变 J1/J2 的 JSON 长度、字段完整性、引用形态；
- 因此 C0 只能验证**参数兼容性**和**历史规模下的容量代理**，不能保证实际 SINK 输入。

### 3.2 两类验证必须分开

| 验证 | 目的 | 方法 | 能证明什么 |
|---|---|---|---|
| **C0-P 参数兼容** | `thinking={"type":"low"}` 是否被接受；max_tokens=4000 是否可用 | 真实 SINK 提示词（run3 历史上游），low，max_tokens=4000 | 端点和参数可用；不证明实际预算 |
| **C0-B 预算代理** | low 在历史规模 SINK 下的 reasoning 占用 | 同上，记录 usage/stop/JSON | 历史规模下的下界；不代表实际 low 上游 |
| **Sentinel run1** | 实际 low 模式下的预算验证 | 先执行 pair1 的 6 次调用 | 真实 SINK 输入是否在 4000 内完成；唯一有效验证 |

### 3.3 4000 / 8000 的定位

- **4000**：本地 Anthropic 端点 88 条记录中的最高接受值，全部 `end_turn`，无截断 → **已知可用参考上限**。
- **8000**：只在标准端点被接受过；本端点未验证 → **不得假设可用**。
- 若 C0-P 在 4000 下截断，A′ 在 4000 下不可行；**不得自动改 8000**。测试 8000 需单独授权，且即使成功也只是“该提示词下可用”，仍须 sentinel 验证实际 low 上游。
- C0-P 若返回 400/1210/429/401/网络错误 → **停止**，不重试、不换端点/模型。

## 十一、单一推荐路径

**推荐：采用 V4 作为并行仪器（不替代旧/V3），执行 7 次分阶段先导；不直接跑 18 次。**

执行顺序：

1. **C0-P（1 次）**：真实 SINK 提示词（run3 历史上游），`thinking=low`，`max_tokens=4000`。
   - 200 + end_turn + JSON → 通过参数兼容与历史规模代理；
   - 400/1210/429/401/截断 → 停止，不重试、不改 8000。
2. **Sentinel run1（6 次）**：按预登记顺序 C-first 跑 run1 B/C。
   - 任一节点截断/解析失败 → 停止，A′ 在 4000 下不可行；
   - 全部通过 → 得到 1 个完整配对，报告三层次结果。
3. **决策点**：若 run1 的 P1/P2/P4 方向成立、引用条件明确，再由操作者决定是否扩到 run2/3（另需 12 次授权）；若 P4 因新短语未命中白名单，如实报告“正式不可见、语义通过”，**不得追加白名单**。
4. 若目标是终端质量提升而 run1 未显示 V4 Fact 信号：停止 A5 在线线，回主线。

**为什么这是最有科学价值、最可能产生真实正向收益的路径：**

- 它把“信息传递 / 语义正确 / 正式终端”三层分开测量，避免把合同编码修正冒充能力提升；
- 它用 sentinel 真实验证 4000 预算，避免重演此前 13 次截断；
- 它用 1 个配对回答 B/C 因果隔离，避免 12 次重复调用买不到新机制信息；
- 若失败，损失 ≤7 次，且失败本身（4000 不可行/新短语不可见）是有价值的科学结论；
- 若成功，再扩 18 次是可选的稳健性复制，而不是唯一入口。
