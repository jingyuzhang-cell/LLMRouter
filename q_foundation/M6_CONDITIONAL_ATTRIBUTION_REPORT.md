## 成本归因悖论（已解决）

| 实验 | Z 成本 | 原因 |
|---|---|---|
| H1 | **−12% ~ −22%**（降低） | 无 Z 组浪费 4 次无效重试（~7,400 tok） |
| R9B | **+39.6%**（增加） | 无 Z 组（A 臂）快速退出，没有大量浪费 |

**归因公式**：
```
ΔC_Z = C(新增拆分节点) − C(避免的无效重试)
```

**驱动因素**：
- **故障持久性**：持久 → 无 Z 组会持续重试 → Z 节省多
- **无 Z 组退出策略**：快速退出 → Z 无可节省 → Z 是净成本
- **重构成本**：拆分增加 2 个节点 ≈ +2,800 tok（SC-E1 G5 实测）

**调度器学习规则**：
```
IF fault.persistent AND no_Z_group.will_retry_wastefully:
    Z cost = negative (net saving)
ELIF fault.persistent AND no_Z_group.exits_fast:
    Z cost = positive (net cost of split nodes)
```

## 交互效应分析

### 已观测到的交互

| 交互 | 证据 | 结论 |
|---|---|---|
| Z × R | H1 G5 vs G2 | Z 改变了 R 的效果——R 单独无效，但 Z+R 有效 |
| Z × π | H1 G6 vs G5 | **无独立交互证据**——G6 的 π 未实际切换模型 |
| R × π | H1 G4 vs G1/G2/G3 | R+π 联合在持久故障下仍失败——无正向交互 |

### 交互效应公式

```
ΔU(Z+R) ≠ ΔU(Z) + ΔU(R)
```

在 H1 SC-E1 中：
- ΔU(Z alone) = 无法测量（无 Z-only 组）
- ΔU(R alone) = 负向（重试无效）
- ΔU(Z+R) = 正向（恢复执行）
- **交互项 = ΔU(Z+R) − ΔU(Z) − ΔU(R) > 0** — Z 和 R 有正向交互

**含义**：Z 的结构重构创造了 R 的恢复机会——没有 Z 的拆分，R 的重试无处着落。这说明 Z 和 R 不是独立的，结构重构是恢复的前置条件。

## 归因协议（M6_ATTRIBUTION_PROTOCOL 要点）

1. **配对要求**：Level A 归因必须同任务、同初始 DAG、同异常、同参考
2. **成本拆分**：Z 的成本必须拆为"新增结构成本 − 避免浪费收益"
3. **交互分离**：单项效应与交互效应分开计算，不假设可加性
4. **证据分级**：A（配对）/ B（条件近似）/ C（机制/合成）；报告必须标注
5. **不可补造**：数据不足的格子标"不可识别"，不填充推测值
6. **INCOMPLETE 处理**：不自动 Q=0；恢复效果用完成率而非 Q 差异表达
