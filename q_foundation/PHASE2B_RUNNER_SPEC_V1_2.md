# PHASE2B 六要素 Runner 实施规格 V1.1（操作者六项修订全量落实；仍未写任何代码）

> 依据操作者 2026-10-31「有条件通过」裁定修订。已认可部分（六要素架构/write-ahead/双哈希+call_id/身份停批原则/独立审计/失败闭锁/分阶段验收）保持不变；本版仅落实六项必修 + T1–T10 干跑测试矩阵。**授权边界：规格修订允许；代码实施未批准；模型调用 0；PHASE2B HOLD 维持。**

## 要素一：载荷持久化（修订：传输字节与归档记录分离）

- **数据结构**：每次调用四个文件——
  1. `{call_id}.request_body.bin`：**实际交给 HTTP 传输层的请求体字节**——边界显式定义为：①请求序列化完成后的原始字节；②即 HTTP 客户端实际发送的 body；③**TLS 加密之前**；④发送过程中不得再次修改/重新序列化/压缩**而不留记录**（任何传输层自动变换须在 meta 中登记，否则归档与实发不一致即审计失败）；
  2. `{call_id}.request_meta.json`：URL、方法、非敏感请求头、认证配置标识（`auth_ref: zhipu|deepseek-modelpool`）——**API 密钥永不落盘**；
  3. `{call_id}.response_body.bin` + `{call_id}.response_meta.json`（状态码、原始响应字节、headers 非敏感项）。
- **执行时点**：请求体先写入并 **flush + fsync**（write-ahead 强化）成功后才允许发送；响应在收到后、解析前以原始字节落盘。
- **验证断言**：`request_body_sha256 = sha256(.request_body.bin 字节)`——**直接对传输层字节计算，不对重构造 JSON 计算**；响应同理。
- **归档清单（封口①）**：每 run 一份 `MANIFEST.json`——逐文件记录 `{路径, 字节数, 独立 sha256}`（四类载荷文件全覆盖）；对**规范化后的 MANIFEST**（键排序、UTF-8、无空白、**不含任何自身哈希字段**——避免循环计算）计算独立 `manifest_sha256`。审计者据此明确知道归档包包含什么；台账以 manifest_sha256 锚定整包。
- **失败条件**：fsync 失败禁止发送；哈希不匹配；响应文件缺失；MANIFEST 与实际文件不符。
- **验收标准**：审计者可用 `.bin` 重放构造 HTTP 请求（配自身密钥）得到等价调用；逐文件哈希独立重算通过。

## 要素二：四类哈希与关联 ID（修订：计算对象显式分离）

- **数据结构与计算对象**：

| 哈希 | 计算对象 | 用途 |
|---|---|---|
| `prompt_sha256` | **冻结规范化序列化**：完整 messages 数组 `[{role, content}, …]` 的规范 JSON（键排序、UTF-8、无空白、保序、角色与消息边界为数组元素边界）的 sha256 | 验证提示重建 |
| `request_body_sha256` | 实际发送的请求体字节（.bin） | 验证传输载荷 |
| `response_body_sha256` | 实际收到的响应体原始字节 | 验证响应完整性 |
| `artifact_sha256` | 归档文件（meta 等） | 验证归档完整性 |

  台账行携 `{call_id, 四哈希, run_id, node_id, attempt, retry_of}`；`call_id` 每次尝试唯一，重试链显式。
- **执行时点**：`prompt_sha256` 于提示构造完成时；`request_body_sha256` 于发送前对 .bin；`response_body_sha256` 于落盘时。
- **验证断言（提示=实发的完整证明链，五步）**：① 从冻结上游重建提示 → 计算 prompt_sha256；② 从 `.request_body.bin` 反序列化提取 messages/system → 按同一拼接规则计算其 prompt_sha256；③ ①==②（**重建提示就是模型实际收到的提示**）；④ 独立核验 request_body_sha256（传输字节）；⑤ 独立核验 response_body_sha256。
- **发送前等值门（封口②）**：五步链中的 ①②③（重建提示 == 实发 body 提取提示）**必须在请求交接传输层之前完成**——不一致 → **禁止发送并立即闭锁**（不是事后审计才发现）；④⑤ 于发送/落盘时点。
- **失败条件**：任一步不等/不可提取/哈希不匹配；发送前等值门失败。
- **验收标准**：五步链全量通过；四类哈希零混用（audit 逐类独立重算）。

## 要素三：模型真实身份验证（修订：精确匹配 + 证据边界）

- **数据结构**：每调用持久化 `{model_config_sent, model_id_returned, frozen_allowlist:[...], frozen_alias_map(如有), identity_match}`。
- **执行时点**：响应解析后、输出被接受前。
- **验证断言**：**精确相等**（非子串包含）——请求体 model 字段 == 冻结配置；实返 model_id ∈ 冻结允许标识集（精确匹配；别名须事先冻结映射）。
- **失败条件**：实返字段缺失/无法识别/不匹配 → **整批即停**（留全部记录、重新裁定；禁止换模续跑）。
- **验收标准**：100% 精确匹配；**证据边界明示：本要素验证的是"服务商返回的身份与冻结配置一致"，不构成底层模型实际部署身份的密码学证明——报告措辞照此限定。**

## 要素四：实验台账关联（修订：成本核算依据全量入账）

- **数据结构**：台账行在四哈希+call_id 基础上增：
  `{in_tokens, out_tokens, price_table_id + price_table_sha256（冻结牌价版本）, unit_price_in, unit_price_out, fx_rate + fx_source（如需换算）, cost_computation（逐项计算过程）, budget_reserved_this_call（本次调用最大费用预留）, accrued_cny, unknown_fee_flag}`。
- **执行时点**：逐调用；**预算预检 = accrued + 本次最大可能费用 ≤ 现金硬顶**（非仅看已发生）。
- **验证断言**：`cost_computation` 可由 tokens×单价×汇率逐行重算；预留逻辑覆盖最大输出 token 场景。
- **未知费用规则（封口③）**：①费用预留 = 实际输入 token × 输入单价 + **max_tokens × 输出单价**（输出按上限预留）；②缓存计价、推理 token 等计费项按冻结牌价表规则纳入；③**无法确定的费用不得按零处理**——不能给出保守最大费用上界 → 禁止发送；④**T8 规则：已发出但响应丢失的调用，其最大费用预留永久保留**（未收到 usage 不释放预算，防止在途费用被后续调用绕过）。
- **失败条件**：预检不通过 → 禁止发送；对账不吻合；未知费用被按零处理。
- **验收标准**：全量成本逐行重算一致；报告成本措辞统一为"**按冻结牌价核算的成本**"，不得冒充服务商实际结算金额。

## 要素五：独立审计（修订：三级锚点验证 + 审计器独立性）

- **三级锚点验证（取代原"J.quote 出现于 E 输出"单级检查）**：
  - **L1 原文真实性**：E 层每条 quote 必须在冻结 PDF 的对应页面中可定位。**page_sha256 计算对象显式定义（封口④）**：= sha256(**确定性页面文本**)，其中页面文本 = 冻结版本的 PDF 提取工具（工具名+版本号冻结）按**冻结文本规范化规则**输出的该物理页文本。锚点四元组 =（**PDF 原始文件 sha256**，**物理页码**，**页面文本 sha256**，**精确引文匹配**）。**J/SINK 继承时必须同时携带 raw_sha256 与 page_sha256 两者**，废止含义不明的单一 source_hash；
  - **L2 节点继承真实性**：J 层锚点五元组（doc_id/page/quote/来源哈希/判断项）与上游 E 层锚点逐字段一致（防 J 层篡改）；
  - **L3 终端继承真实性**：SINK 引文只能取自 J 层已通过 L2 验证的锚点集合（防 sink 重编或替换）。三层全过方认定证据链完整。
- **审计器独立性（修订）**：audit.py **不复用 runner 的提示构造、哈希、锚点校验函数**——关键校验逻辑独立实现；**audit.py 自身文件 sha256 随批次冻结**，防两模块共享同一错误。
- **独立复现能力（边界澄清）**：随 audit.py 一并冻结——①运行环境与依赖版本清单（Python 版本、stdlib-only 原则下为零第三方依赖；如有依赖则锁版本+哈希）；②**篡改样本集**（故意破坏的载荷/引文/锚点样本库）：正确样本必须 PASS、各类篡改样本必须 FAIL，作为 audit 自身的回归验证；③审计结果可由第三方以冻结环境+冻结样本独立重现。
- **执行时点/断言/失败/验收**：同 V1（每 run 自动 + 报告前置 exit 0；FAIL → AUDIT_FAILED 不释放结果）。

## 要素六：失败闭锁（修订：原子化 + 统一出口 + 超时未知态）

- **原子闭锁**：FAILLOCK 以 `open(O_CREAT|O_EXCL)` 原子创建（同一路径仅一个创建者成功）；**统一调用出口（single egress gateway）**——所有 worker 经同一闸门获取"调用许可"，许可签发与闭锁状态在闸门内同步检查（消除 check-then-act 竞态）；闭锁后**零新许可**。
- **许可失效窗口（边界澄清：覆盖"已签发、尚未交接传输层"的许可）**：闸门的同步保护区覆盖**从许可签发到传输层交接的全程**——FAILLOCK 生效瞬间：①所有尚未交接传输层的许可**立即作废**（闸门拒绝交接，worker 收到 PERMIT_REVOKED）；②已交接传输、尚在途的请求**如实记录为在途请求**（in-flight：call_id+请求字节已存，结果未知，按超时未知态处理）；③二者的区分以闸门交接日志为准。**T9 必须显式验证此窗口**（注入：A 持许可未发送→B 触发闭锁→A 交接被拒、零字节出网）。
- **超时/未知态处理**：请求已发出但无响应 → 记为**结果未知的调用尝试**（保留 call_id、请求体字节已存、retry_of 链）——**既不计为零调用，也不自动重试**；按失败闭锁规则处置（进入闭锁或按预注册重试策略显式决策）。
- **验证断言**：闭锁后新增调用许可数 == 0（以闸门许可日志核验，非仅内部计数）。
- **验收标准**：T9/T10 注入测试证明原子性。
