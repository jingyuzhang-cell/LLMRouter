## CL-1 · P1-1 DAG 依赖澄清：SINK 只消费 J2

**不一致点（操作者指出，成立）**：P1-1 设计文档的 DAG 图为 `E×3 → J1 → J2 → SINK`，但节点规格表将 SINK 的消费上游写为"J1 + J2"，构成 J1→SINK 直接依赖，与已通过的传播审计拓扑（`dag_propagation_audit.py`：`execute("J2", …, ["J1"])`、`execute("SINK", …, ["J2"])`，五项全 PASS）不一致。以冻结审计代码为准：**P1-1 审计拓扑为 E1/E2/E3 → J1 → J2 → SINK（三个 E 节点，无 E4）**。

**修正规定（保留已通过的 DAG 拓扑）**：

1. **SINK 只消费 J2**，无 J1 旁路、无 E 旁路。
2. **J2 = 完整无损传递包**，输出结构：
   ```json
   {
     "state_judgments": "<J1 输出的 18 组合逐字原样>",
     "current_state":      {"<item>": "S3 三维摘要"},
     "cross_stage_conflicts": [{"item": "...", "conflict": "...", "detail": "..."}],
     "derived": {"is_final_finding": false, "prior_notice_cited": true}
   }
   ```
   即 J2 的 `state_judgments` 字段 = J1 输出原文（逐阶段证据随包保留），新增字段仅 `current_state` / `cross_stage_conflicts` / `derived`。
3. **J2 传递完整性核验（适配器职责，冻结）**：J2 返回后，适配器对 `J2.state_judgments` 与 J1 输出做规范化等值比对（sort_keys JSON）。不一致 → 记录为 `j2_transcription_anomaly`（计入 J2 节点失败统计，原始保留，**不静默修复**——修复即改语义，禁止）；SINK 照常消费 J2 包并照常评分，异常随报告如实输出。
4. J2 提示词相应增加一条："`state_judgments` 字段必须逐字复制上游判定结果，不得改写、增删或重新排序。"

**P0 系不受影响**：P0 的 SINK 消费 J1+J2 由 PHASE2B 依赖表独立验证，非本澄清对象。

## CL-2 · P1-1 槽位映射澄清：18 候选组合 vs 17 评分事实

**问题**：6 信息项 × 3 阶段 = 18 组合，合同冻结 17 事实；原设计提示词含"不该有状态记录则跳过该槽位"，与"不能让模型把应判 NOT_DISCLOSED 的槽位直接跳过"冲突。

**结构性与材料性的区分（按冻结合同核实）**：

- 唯一差异组合 = **FD_S1**（正式处罚决定状态 @ S1/公告080）。
- 合同 `item_coverage["正式处罚决定状态"] = ["S2", "S3"]`——**结构性排除**，属合同设计决定，非"材料中未披露"的可判定槽位。
- 排除依据（合同内证据链）：S1 原文对正式处罚决定仅存在**条件性引用**（"若后续经中国证监会行政处罚认定的事实……"），按合同修正③"条件引用→UNKNOWN"，S1 不支撑 FD 的任何确定三维取值；S2 起告知书到达、原文出现明确表述"尚未收到……正式处罚决定"（NOT_YET_RECEIVED 需原文明确），FD 方成为可判定状态项。
- 其余 5 项 × 3 阶段 = 15 组合 + FD_S2 + FD_S3 = **17 评分目标**（分母恒 17，评分器 Fix 1）。

**执行规定**：

1. **J1 输出全部 18 个候选组合，无跳过指令**。原提示词中"若某信息项在某阶段不该有状态记录……跳过该槽位"一句作废，替换为："输出全部 18 个组合（6 信息项 × 3 阶段）；无法从材料判定的按枚举语义如实填写（如 NOT_DISCLOSED / NOT_APPLICABLE / UNKNOWN），不得留空、不得跳过。"
2. **SINK 槽位清单同步为 18 个候选 ID**（VF_S1…FD_S3）。
3. **冻结适配器纯透传**：SINK 输出原样传入评分器，零语义改写、零过滤。评分器按 Gold 17 项迭代（Fix 1：非 Gold 的 fact_id 自然忽略，不计重复、不抵缺失），**FD_S1 自动落为评分外记录**，仅作描述性保留，永不计分、永不映射任何 Gold 值。
4. 若未来合同版本改动了 FD 覆盖（如新增 FD_S1），= 新评分版本号，不静默沿用。

## CL-3 · P0 系证据五元组哈希绑定：可信适配器机制

**问题**：证据锚点五元组 (doc_id, page, quote, page_sha256, raw_sha256) 中，E 层输出只含 quote/page，原文设计未规定哈希由谁生成——且 J1 提示词 schema 中含 `source_raw_sha256` 字段，构成"模型可自行生成哈希"的漏洞。

**执行规定（可信适配器四步，冻结）**：

1. **E 层只抽取 (doc, page, quote)**，输出结构不含任何哈希字段。
2. **适配器按 doc_id 查冻结 `source_pages` 表**（合同内、哈希已验证），取得 `page_sha256` 与 `raw_sha256`。
3. **适配器将双哈希绑定到证据记录**，组装五元组供评分器消费。
4. **J1/J2/SINK 不得生成或修改哈希**：原设计 J1 证据 schema 中的 `source_raw_sha256` 字段**作废移除**，J 层证据结构 = (doc_id, page, quote) 三元组 + 推理理由；提示词中不出现任何哈希字段名。

**保证**：哈希只能来自冻结原始文书（合同 source_pages，raw_sha256 与 PDF 逐页文本绑定），模型输出无法注入或篡改锚点哈希；quote 与 Gold 证据句的逐字比对（match 级）不受影响。

## M-2 · 方法边界记录：四哈希+MANIFEST ≠ OS 级隔离

- BLOCKED_BY_ENVIRONMENT **如实保留**。四哈希+MANIFEST 只提供事后完整性与可追溯性，不能阻止其他进程绕过调用入口、子进程自行出网、网络请求绕过预期通道——**不得描述为 OS 级隔离的等价替代**（可比性检查文档中的"由四哈希补偿"表述以本条为准收窄为"事后可追溯性补偿"）。
- **真实调用前的有界前置确认（不做大规模工程）**：独立确认当前 transport.py 执行通道的必要安全边界——实验入口仅经 transport.py 出网（入口审计）、实验脚本无 subprocess/os.system 出网调用、GLM 臂端点 allowlist = `open.bigmodel.cn`。只读确认，零新模块。

## 下阶段科学主线（操作者定调，记录在案）

三个 Static-π 基线的产出不只是三个答案，而是**三组可继续研究的错误分布**：P0-1 实体归一错误能否被其他模型修复 / P0-2 双编号绑定是否存在稳定模型能力差异 / P1-1 状态演进是否存在跨阶段传播错误。随后：**Static-π → 测量真实错误分布 → π-only（剩余节点换模能否修复）→ R-only（结构恢复与重执行的作用）→ Joint（联合收益）→ 独立 Sink 终端评价（Q/C/L 联合验证）**。

**底线**：节点修复 ≠ 终端质量提升。必须证明 J2/Sink 真正消费了修复结果，且独立评分确认最终事实质量改善。Gateway 串行化继续作为实验环境限制记录：逐调用延迟可报告，不得据此声称真实并行 Makespan 优势。
