## 二、原合同与拆分后合同的逐项语义映射

### 原验证合同分析

原验证节点（e05_chk）的 subtask 为："交叉核查时间推导与治理推理，标注UNRESOLVED"

SYS_R9 合同中 verification 节点的规则：
> "核验分支合同（verification节点）：只核验本分支单侧事实，【禁止】输出任何跨文档一致/不一致结论。"

**关键事实**：在当前合同系统中，verification 节点**本来就被禁止**输出跨文档结论。跨文档一致性判断由 **report 节点**承担。

REPORT_SYS_R9 合同中 report 节点的规则：
> "跨文档比较合同：仅当两侧操作数（含span与doc）都在合并清单中时输出确定结论（一致/不一致）并引用两个操作数值与双侧来源；缺任一侧→conclusion=null且status=insufficient_evidence，【禁止】给出确定一致性结论。"

### 语义映射表

| 原验证合同要求 | 拆分后承担节点 | 保留证据 |
|---|---|---|
| Timeline 单源事实核验 | e05_chk_a（消费 e05_temporal） | SYS_R9 verification 合同："只核验本分支单侧事实" |
| Reasoning 单源事实核验 | e05_chk_b（消费 e05_gov） | 同上 |
| 跨来源主体一致性 | **report 节点（原有+拆分后均在此）** | REPORT_SYS_R9："仅当两侧操作数都在合并清单中时输出确定结论" |
| 跨来源时间一致性 | **report 节点（同上）** | 同上 |
| 跨来源事实矛盾 | **report 节点（同上）** | REPORT_SYS_R9："缺任一侧→禁止确定一致性结论" |
| 最终综合结论 | **report 节点（同上）** | REPORT_SYS_R9："report引用实际使用的事实" |

### 关键结论

**跨来源一致性检查在原设计中就位于 report 节点，不在 verification 节点。**

证据链：
1. SYS_R9 明文规定 verification 节点"禁止输出跨文档结论"
2. REPORT_SYS_R9 明文规定 report 节点负责跨文档比较合同
3. 拆分后 report 的依赖从 [e05_chk] 变为 [e05_chk_a, e05_chk_b]
4. build_prompt_r9 中 report 节点的 prompt 合并**所有**父节点的 fact ledger——拆分后 report 同时接收 chk_a 和 chk_b 的验证结果
5. **结论：拆分不改变跨来源一致性检查的位置和内容——它一直在 report 层，拆分前后等价**
