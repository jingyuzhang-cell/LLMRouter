# Split 子节点输出合同 V2（信息保存合同）

**版本**: V2 | **日期**: 2026-11-01 | **状态**: 冻结待执行 | **SHA-256**: 待计算

## 修正原因

V1 合同仅要求返回 `{"consistent": bool}`，导致上游提取的日期等关键事实在拆分节点处丢失。C1 实验证实：结构恢复（COMPLETE）≠ 信息恢复（Q 正确）——V1 合同下 F/E Q=0/2，仅 F′ 因 flash 随机冗长输出碰巧保留日期获得 Q=2/2。

## V2 合同定义

### 提示词模板（所有 7 臂统一）
```
核验单文档提取的一致性，并回显核验过程中识别到的关键事实。

要求：
1. 逐条核验提取内容中的日期、金额、主体、事由是否与原文一致。
2. 将核验到的每条关键事实完整回显（保留原值、来源、证据）。
3. 不得自行补充、推测或修改事实——仅传递和核验上游提取的内容。
4. 如果未发现关键事实，返回空数组 "key_facts": []，不得省略字段。

输出JSON:
{
  "consistent": true/false,
  "key_facts": [
    {
      "fact": "事实描述",
      "value": "具体值（日期/金额等）",
      "source_node": "来源提取节点ID",
      "source_document": "来源文档标识",
      "evidence": "原文证据引用（截取关键句）"
    }
  ]
}

待核验内容：
{extract_content}
```

### 三项硬约束
1. **信息完整性**：上游提取合同中的下游必需事实，必须经 key_facts 完整传递。
2. **证据可追溯性**：每个事实保留 source_node + source_document + evidence。
3. **真实性**：子节点仅传递和核验，不补充/推测/修改。key_facts 无事实时返回空数组。

## 与 V1 的差异记录

| 项 | V1 | V2 |
|---|---|---|
| 输出字段 | `consistent` 仅 | `consistent` + `key_facts`（必需） |
| 事实回显 | 无要求 | 必须回显（含 value/source/evidence） |
| 空值处理 | — | key_facts=[] 必须存在 |
| 信息丢失风险 | 高（已实证） | 通过合同约束消除 |

## 适用范围
- 所有 7 臂（A/B/C/D/E/F/F′）统一使用 V2
- 仅影响 split 子节点的提示词与输出解析
- 不改变：Z/R/π 决策规则、模型画像、臂定义、评分器、统计方法

## 版本隔离
- V1 下的实验数据全部保留，不覆盖
- V2 下的实验数据独立记录，标注 contract=V2
- 新旧合同下的结果不混在一起分析
