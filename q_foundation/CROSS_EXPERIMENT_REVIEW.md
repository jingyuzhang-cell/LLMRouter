## 二、已证明的事实

### 模型能力差异确实存在
- Stage-B 冻结 PROFILE_Q：reasoning glm53=0.80 vs flash=0.58（差距 0.22）；timeline 0.75 vs 0.60；report 0.85 vs 0.60
- **但** Stage-B 总 Q 最高仅 0.298——六维评分下的绝对质量很低，说明模型能力差距在简单任务上不足以拉开终端质量

### 持久故障下结构重构有机制级证据
- R9B：S2 持久合同故障 @ verification → A（无 Z）0/3 生成报告，B（SPLIT_VERIFY）3/3
- **条件**：故障必须在有异类双亲的验证节点，Z 才有合法空间
- **代价**：B 平均 token +39.6%（18,761 vs 13,437），makespan +30.9%（83.9s vs 64.1s）

### 瞬态故障下 π 重分配有单例质量信号
- DYNPI 唯一自然分化 cell（T1-r2）：Static 死、R-only Q=0.500、π-only Q=0.667
- **但仅 1 个 cell，探索性；T1 整体 ΔQ(π−Static)=0.000**
- 下游推导事实在完成 run 中 100% 恢复（12/12）——执行一旦完成，跨文书推导链传递稳健

### 无故障时动态调度无收益、有成本
- DYNPI：14 个无故障 run 中 π 零误触发（反馈门控正确）；但 π 平均成本 +13.2%
- TGV：MCF-NOT-MANIFESTED=16/16——预期能力断层未出现时，π/Joint 与 R-only Q 几乎相同（0.550 vs 0.517），成本 +5%

### 单模型基线质量远高于 DAG 实验
- V2.2 单模型 Q=0.81 vs Stage-B 最高 0.30 vs R9B B 臂 Q<0.30
- **说明**：DAG 分解后节点质量损失严重，"综合报告"节点的质量是主要瓶颈（report Q prior=0.60-0.85）

## 四、最有收益潜力的条件

基于上述证据，以下条件组合最可能产生动态调度的终端质量收益：

### 条件 1：关键验证节点 × 持久故障 × 模型能力差异
- **证据**：R9B B 臂（SPLIT_VERIFY + π 重分配）3/3 vs A 臂 0/3
- **前提**：verification 节点有异类双亲（timeline + reasoning）
- **收益预期**：从 0（无报告）到有报告——最大的可能收益
- **成本**：约 +40% token / +31% makespan
- **风险**：如果故障不在验证节点，Z 空间不存在

### 条件 2：自然瞬态 parse 失败 × 剩余节点有模型差异
- **证据**：DYNPI T1-r2 唯一分化 cell（π vs R +0.167 Q）
- **前提**：故障为瞬态（重试可修复）但不同模型修复后质量不同
- **收益预期**：中等（+0.1~0.2 Q）
- **成本**：+13% token
- **风险**：n=1，不稳定

### 条件 3：跨文书推导链 × 执行完整性
- **证据**：12/12 完成 run 全量恢复下游推导事实
- **前提**：执行完成（不管用什么策略）
- **收益**：这不是调度收益，是任务设计收益——只要执行完成，推导链就好
- **含义**：调度器的价值在于保证执行完成，而不是提升单个节点质量

## 六、关键瓶颈：为什么历史实验 Q 都很低？

**V2.2 单模型 Q=0.81 vs 所有 DAG 实验 Q<0.35**——差距巨大。可能原因：

1. **报告节点质量瓶颈**：DAG 终端输出= report 节点产物，Q prior 仅 0.60-0.85；而单模型直接输出完整答案
2. **节点间信息丢失**：delta 合同下继承事实→推导→报告的链路中，每一跳都可能丢失上下文
3. **评分器口径**：单模型评分可能使用不同的 Silver/参考集

**这意味着**：即使调度完美，如果 report 节点本身质量不够高，终端 Q 的天花板就被限定了。**下一轮实验必须同时关注调度收益和报告节点质量提升**。

## 七、行动建议

1. **不要立即开始新实验**——先用本复盘结论指导设计
2. **优先验证 H1**（Joint vs 单项在持久验证故障下）——证据基础最强（R9B 机制级 + DYNPI 质量信号）
3. **任务设计须确保**：(a) 验证节点有异类双亲；(b) 参与比较的模型在关键节点类型上有 ≥0.15 Q prior 差距；(c) 有足够的预算余量执行恢复
4. **同时推进 P0/P1 质量门禁**——没有可信 Q 信号，调度收益无法测量
5. **虚拟时钟优先**——在花钱之前用 Stage-B PROFILE_Q + R9B 决策器做仿真预验证
