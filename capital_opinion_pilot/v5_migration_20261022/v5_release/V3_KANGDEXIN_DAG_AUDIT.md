## 一、生成结果

LLM（GLM-5.3）语义计划 → 确定性组装 → 复用 typed_dag_v1 验证器 PASS：

```
t1 index（五份文档语义索引与分段）→ t2 extracts（问询函回复中利润/存款/担保表述抽取）
→ { t3 timeline（问询/立案/告知/处罚时间节点）∥ t4 entity_facts（主体/责任人/违法认定） }
→ t5 factcheck_full（监管认定 vs 公司披露比对）→ t6 report（带引用调查报告）
```

结构合法性：7 条依赖边全部携带类型化数据流；绑定⇄依赖一一对应（验证器强制）；
无装饰性依赖；终端输出与死分支检查通过。

## 二、与舜天初始 DAG 的结构比较（RQ1 首个实测）

| 维度 | 舜天（V2） | 康得新（V3） |
|---|---|---|
| 节点数 | 6 | 6 |
| 契约多重集 | index/extracts/timeline/entity_facts/factcheck_full/report 各 1 | **完全相同** |
| 深度 / 宽度 | 5 / 2 | 5 / 2 |
| 层形状签名 | [1,1,2,1,1] | [1,1,2,1,1] |
| 差异所在 | —— | 仅 goal 文本与 doc 覆盖（内容适配跨年度主题） |

**判定（如实）**：形状签名 **完全同构**。规划器没有采用新注册的跨年度构件
（extracts_f×2 / yearly_recon / factcheck_yr），而是选择了与舜天相同的规范形状。
任务描述明确要求"跨年度"，仍然如此——说明当前规划器在结构选择上趋于保守规范形，
**"不同事件自主产生实质不同 DAG"目前不成立（样本=2 事件，同构）**。
内容层面（goal/文档分配）确有事件适配，但这不等于可优化的结构差异。

## 三、执行可行性审计：一个更实质的发现

康得新证据体量 **127,598 字**（舜天 9.5K 字的 13 倍；单问询回复 5.7 万字），而单 extracts
节点的实际注入预算约 3.3K 字（V2 实测口径）。当前计划**结构合法但执行不可行**：
执行必然大规模截断（F5 式信息损失的放大版）。

这揭示了结构分化的真实驱动力不在"任务语义"而在**证据体量×注入预算约束**：
- 若规划器收到显式的体量-预算可行性反馈（如"单节点注入上限 3.3K 字，语料 127K 字，请分行检索"），
  多分支/分段检索结构就不再是"加节点凑复杂度"，而是被约束逼出的**必要结构**；
- 这正是"节点必要性/真实依赖"审计应该程序化的一维：**evidence-volume feasibility check**
  （已写入 dag_audit_v3_kdx.json 的 flag 字段，建议纳入后续协议）。
