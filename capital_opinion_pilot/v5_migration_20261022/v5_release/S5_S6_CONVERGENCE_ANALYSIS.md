# S5_S6_CONVERGENCE_ANALYSIS — S5 与 S6 收敛原因分析（零付费）

## 1. 逐步复盘

### 触发事件
- 注入类型：**人工注入** model_unavailable（非真实 API 故障）
- 故障节点：t1_extract（事实提取）
- 规划模型：DeepSeek（按真实能力表最优分配：Q_ratio=1.0, lat=2.3s）
- 屏蔽：S6 与 S5 均被告知 DeepSeek 在 t1 不可用

### S5 决策路径（固定局部恢复）
1. 检测到 t1 故障
2. 固定策略：切换到 GLM-5.3（非 DeepSeek 的默认备选）
3. 重跑闭包 {t1,t2,t3,t4}（t1 是根节点→闭包=全部）
4. 执行：4 节点全部 GLM-5.3

### S6 决策路径（联合动态调度）
1. 检测到 t1 故障
2. 枚举 (Z,R,π) 候选：440 个组合
3. 过滤：blocked={('t1','deepseek')}；预算/截止/质量下界约束
4. 优化：Q_output_ratio 加权 → 在可用模型中 GLM-5.3 的 Q_ratio 最高（0.81 vs Flash 0.63 vs Qwen 0.74）
5. 选择：Z=LOCAL, R={t1,t2,t3,t4}, π(t1)=glm53

### 收敛原因
**当 DeepSeek 被屏蔽后，GLM-5.3 是唯一合理选择**：
- GLM-5.3 的 Q_ratio=0.81 > Qwen 0.74 > Flash 0.63
- GLM-5.3 的契约率=100% > Flash 95%
- S5 的固定策略恰好也是"换到 GLM-5.3"
- **这不是算法缺陷——是当前候选集太小导致的合法收敛**

## 2. DeepSeek 不可用的性质

**人工注入**（实验处置），非真实服务商故障。影响：
- 零 token 消耗（不产生实际调用）
- 零成本（无计费）
- 与真实 API 故障的区别：真实故障可能有部分成功调用、超时、速率限制等多种形态

## 6. 结论

**本轮 S5≡S6 是合法收敛（当前候选集下最优解唯一），不构成 S6 无增量收益的证据。**

S6 的差异化价值需要以下条件之一：
1. **更多模型可用**（如故障屏蔽 GLM-5.3 而非 DeepSeek，则 S6 可从 {Flash, Qwen} 中选择而 S5 固定选一个）
2. **更复杂的 DAG**（多提取分支→部分子闭包可独立恢复，S6 可选局部 R 而 S5 全闭包）
3. **更紧的约束**（S6 可在预算/截止下找到 S5 固定策略不可行的方案）
4. **多种故障类型**（contract_fail→S6 可判断是否需要换模型 vs 仅重试；timeout→S6 可选更快的模型）

以上条件在 MULTIBRANCH_DAG_EXPERIMENT_GATE.md 中设计。
