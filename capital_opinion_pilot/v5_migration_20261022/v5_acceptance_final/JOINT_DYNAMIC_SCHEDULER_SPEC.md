# JOINT_DYNAMIC_SCHEDULER_SPEC — 反馈驱动联合动态调度算法规范（RQ2/RQ3 核心，v1.0）

## 1. 联合动作（区别于固定换模型重试的充要定义）
```
a = (Z, R, π)
Z ∈ {NONE, LOCAL, FULL}                # 恢复模式
R ⊆ V  且 R ⊇ closure(失败/受影响节点)  # 重执行节点集（依赖闭包+缓存合法性）
π: R ∪ pending → M                      # 重执行与未执行节点的异构模型分配
```
**D 臂旧行为（固定：Z=LOCAL, R=closure(f), π=换一个模型）只是本动作空间的一个点。**
只有当决策器在 ≥2 个维度上随状态变化（如：预算紧→Z=NONE 或缩 R；截止紧→π 选低时延模型；
质量下界不足→扩 R 或升 π），才构成联合优化。

## 2. 两阶段决策（可审计）
**阶段一：可行性过滤（硬约束，逐条记录拒绝原因）**
1. 依赖合法性：R 必须含故障节点全部下游受影响闭包；已完成且未受影响输出受保护（缓存合法）；
2. 预算：`spent + predict_cost(a) ≤ B`，predict_cost 用校准上界（token 保守估计）；
3. 截止时间：`now + predict_lat(a) ≤ T`，predict_lat 用该模型节点历史时延分布的 P90；
4. 质量下界：`Q_pred(a) ≥ Q_min`，Q_pred 用节点级历史质量表的下四分位（不读 Gold，
   只用历史运行统计——**运行时金盲**：任何决策不得依据 Gold/评分器输出）。

**阶段二：可行集内优化**
目标 `max Q_pred(a) - λ_C·cost(a) - λ_L·lat(a)`（或字典序 Q≥Q_min 下 min cost/lat）；
小图（≤10 节点、≤2-3 模型）**精确枚举**全部 (Z,R,π)（R 由闭包唯一确定于 Z 与故障位置，
π 枚举模型指派）得可审计参考前沿；大图用束搜索。输出：选中动作、被拒动作及原因、
预测 vs 实测对照（Q/C/L 预测误差单独报告）。

## 3. 状态输入
DAG 结构与节点状态、故障类型（contract_fail|unavailable|timeout）、已花预算/时延、
节点级 (模型→Q/C/L) 历史统计表（来自 RQ1 评测，TEST 期冻结不更新）。

## 4. 与固定策略的可分离验证
同一 (事件, 故障节点, 种子, 预算/截止) 配对运行六策略（见 CONTROLLED_FAILURE_PROTOCOL），
联合调度必须同时优于"固定局部恢复"与"固定模型切换"才计 RQ2 增量收益；
按事件聚类 Bootstrap 出 CI。消融：去 Z（固定 LOCAL）/去 π（原模型重试）/去反馈（无视状态）。

## 5. 零付费回放演示（本轮交付）
`replay_joint_decision.py`：用 D 臂三个种子的真实账本（usage/latency/结构）离线重放两阶段
决策，展示 Z/R/π 随（剩余预算, 截止, 故障位置）变化且与固定策略不同——**仅验证决策器可执行
与可审计，不产生新的实测质量收益（REPLAY_ONLY）**。
