# KDX_RETRIEVAL_V2_REPORT — 检索升级对比（零付费）

## 一、方法与公平条件

| 检索器 | 实现 |
|---|---|
| A. IDF 词汇 | 既有（IDF 加权任务词+日期/金额模式加分） |
| B. BM25 | 字符二元组切分，k1=1.5/b=0.75，文档作用域过滤 |
| C. 混合 | 0.5×BM25+0.5×余弦；语义向量=Qwen2.5-1.5B-Instruct 末层均值池化（本地 RTX 4090，fp16，340×1536；零付费） |

三检索器共用：同一查询目标（**仅由冻结 DAG 节点 goal + 调查任务文本 + 文档元数据生成**，
不读取 silver/事实位置）、同一文档作用域、同一注入预算档（3,300/6,600/9,500 字/线）。
silver 仅用于检索完成后的离线评分。出处链完整保留（doc_id/偏移/SHA256/公开日期）。

## 二、过程发现并修复的一个真实 bug

初版相邻窗口去重阈值 60 字恰小于窗口重叠 80 字 → **载有目标引文的块被其高分邻居"去重"掉**
（t2 长期为 0/7 的直接原因）。修正为 200 字（只拦真近重复）后行为恢复正常。该教训已入报告：
去重阈值必须显著大于分窗重叠。

## 三、结果（详见 KDX_RETRIEVAL_COMPARISON.json 与 KDX_RETRIEVAL_ALLOC_SENSITIVITY.json）

**轮转配额（原方案）**：@9,500/线 → 并集 3-5/7；语义混合无增益（C≈B≈A）。
**按文档长度比例分配预算（纯元数据启发，不触 silver）**：

| 预算/线 | A_idf 并集 | B_bm25 并集 |
|---|---|---|
| 9,500 字（19K 总） | 5/7 | 5/7 |
| **19,000 字（38K 总）** | **7/7（两线各自触顶：监管线 A1–A6 + 问询线 A7）** | **7/7** |

冗余率（修复阈值后）=0；来源多样性=5/5 文档；上下文长度即预算封顶（18,450 字/线实测）。

## 四、结论（对应任务三的三层区分）

1. **规划所需证据能否定位**：能——全部 5 份文档的关键段落均可被词汇检索在足够预算下定位；
2. **7 条 silver 引文覆盖**：长度分配@19K/线下 A/B 检索器并集 7/7（事后离线评分）；
3. **限定预算内真实可消费**：3,300/线不可行（2/7）；9,500/线部分可行（5/7）；19,000/线可行（7/7，
   约 12.4K token/线注入）。
- **检索改进的实际收益**：主要来自**预算分配策略**（轮转→长度比例），而非检索器替换
  （BM25≈IDF；本地因果 LM 均值池化向量无增益——粗糙嵌入器的诚实结果）。
- 前沿表仅作事后诊断；未用 silver 指导任何命中。
