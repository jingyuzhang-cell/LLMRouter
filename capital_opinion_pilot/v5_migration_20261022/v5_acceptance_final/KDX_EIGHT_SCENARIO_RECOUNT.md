# KDX_EIGHT_SCENARIO_RECOUNT — 八场景统计核查修正（零付费）

## 修正前的错误

原报告声称"7/8 动作分离"并分类为 4+2+2=8 个场景。核查发现两个统计错误：

**错误 1**：F3 被标记为"S6_UNIQUE_ACTION"，实际是 sequential 单故障 API 的伪影
（JS.choose('t1') 只返回 t1 的 π，t2 显示 '?' 不是因为 S6 做了不同选择）。
F3 的正确分类 = S5=S6 收敛（如果分别处理两个故障节点，S6 也会选 GLM-5.3）。

**错误 2**：将"S6 不同于 S4"与"S6 不同于 S5"混算为"分离"。
联合调度增量的正确度量基准是 **S6 vs S5**（不是 S6 vs S4）。

## 核心发现

**S6 独有的全部分离（4/8）来自同一种机制：识别"无有效模型可完成某节点类型"并选 NONE。**

- 4 个 S6-unique 场景全部涉及 t5（crosssource_check）的模型屏蔽
- 根因：能力表中仅 GLM-5.3 在 crosssource_check 上有 Q>0 产出；屏蔽 GLM-5.3 后，
  S6 的质量约束（q_min）正确判定无可行模型
- S4/S5 不做质量约束检查，盲目分配 Q=0 的模型（Flash/Qwen）执行注定无效的恢复

**这不是"联合动作搜索"的价值——是"质量可行性过滤"的价值。**
S5 如果也加上相同的可行性检查（S5+FeasibilityGate），也能达到同样效果（见消融实验）。
