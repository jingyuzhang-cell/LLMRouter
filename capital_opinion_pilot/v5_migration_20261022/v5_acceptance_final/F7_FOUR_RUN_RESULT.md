## 根因（两个配置缺陷，均已定位到原始响应）

1. **t5 输出上限 1536 不足**：10K 窗口下 verdicts 列表（每条含 fact+failure_reason）实际输出
   2948-3175 字符 ≈ 1900+ token。DS 的 t5 在所有运行中 5 次全部截断于 1536，R4 中 GLM 的 t5
   同样截断。截断 JSON 不可解析 → 契约失败 → 动态策略当作故障触发恢复 → 额外调用 → 超时。
2. **t6 契约解析脆弱**：GLM 在 "report" 字符串内使用原始换行符，严格 `json.loads` 拒绝控制字符
   （R1/R4 的 t6 输出内容完整、长度低于上限，纯解析层拒绝）。

## 五问回答

**1. F7 使静态策略损失了多少质量？** 内容层：1/4→0/4、可达集 1/2→0/2——t1（监管线）被屏蔽
使其证据线整体消失，该线上全部事实丢失。方向明确；幅度受 clean 基线自身被截断缺陷压低
（clean 本应更高）。

**2. S5+Capability 能追回多少？** 全部追回至 clean 的内容层水平（0/2→1/2，RF1 经 t1→glm53
恢复，16.1s 契约通过）。但代价是 8 次调用 / 33.5K token / 98.4s（超时），因为恢复后又被
截断级联拖住。

**3. S6 是否比 S5+Capability 恢复更多、更快或更省？** **否。** 质量相同（1/4、1/2），
更慢（101.7s vs 98.4s），更贵（35.6K vs 33.5K token）。本轮没有任何可测的 S6 独有优势。

**4. S6 是否真正改变了 Z 或 R，而不只是 π？** π：是（一次决策改 4 个节点：t1→glm53、
t3→flash、t4→DS、t6→flash）。R：否（三次故障均取 LOCAL 闭包，与 S5+Cap 固定范围相同）。
Z：三次 LOCAL 后在 t6 故障时变为 **NONE**（n_feasible=0）——这是联合调度器在截止期已破、
预算将尽时**正确拒绝不可行动作**的真实首次观测（Z 维度的可用性价值），但本轮它是由配置
级联诱发的，不构成优化优势证据。

**5. 当前结果是否值得扩展到 ST 与完整五策略？** **不值得，先修复重跑。** 扩展前提：
(a) t5/t4 中游节点输出上限提至 ~2560-3072（预检最坏预留需同步重算）；(b) 契约解析器接受
字符串内控制字符（`json.loads(..., strict=False)`）并保留三层层级；(c) 评分粒度决定
（RF2 类语序变体按锚点严格计，如实报告为局限）。修复后同矩阵重跑（需重新授权，额度与
本轮相当），再决定五策略扩展。
