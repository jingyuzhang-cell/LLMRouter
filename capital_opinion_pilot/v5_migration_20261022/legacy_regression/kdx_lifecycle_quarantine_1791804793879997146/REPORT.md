# 清理失败隔离修复

零模型/HTTP调用。OwnedService清理成功必须确认自有session无存活成员，并查询nvidia-smi GPU PID记录；探针超时、不可用或退出未确认一律失败。只针对本实例自有Popen session，不终止其他实验。

cleanup失败不关闭GPU锁，写持久RESOURCE_QUARANTINED标记。即使管理进程退出导致flock被OS释放，新入口也先检查隔离标记并拒绝启动；不删除锁或自动重试，不自动清除隔离。后续解除必须独立审计资源实际状态。Mock两项新增测试覆盖GPU退出未确认、探针失败、锁保留和下一实例拒绝。70项相关测试通过。

真实GPU退出未在本轮验证。代码检查所有session成员避免leader退出但worker仍存活；GPU探针只提供状态证据，不证明驱动异常一定在截止内恢复。退出检查最多5秒子进程wait加5秒nvidia-smi查询；proc扫描受OS调度影响，不是严格终止证明。自有服务身份与完整输入token一致性仍需受限独立预检。

t2输入V3不变：12296输入+768输出=13064Token。回复实质覆盖UNKNOWN不变。结论：清理失败释放锁缺陷已修复并离线验证；真实服务预检未启动，单节点真实执行仍NO-GO。不修改图/历史超额/评分，不提交推送。
