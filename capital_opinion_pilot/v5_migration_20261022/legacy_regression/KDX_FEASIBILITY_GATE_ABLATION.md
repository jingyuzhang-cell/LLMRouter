# KDX_FEASIBILITY_GATE_ABLATION — S5+可行性门禁消融（零付费）

## 设计
保留 S5 原始基线（无质量检查），新增 S5+Gate（加入与 S6 相同的逐节点质量门禁 q_min=0.1，
但不做联合闭包分析）。比较 S5 / S5+Gate / S6_v3。

## 归因分类

| 来源 | 场景数 | 含义 |
|---|---|---|
| **A: 门禁独立解释** | 2/8 | F2a/F2b——逐节点质量检查就足够；S5 加上同样门禁后与 S6 等效 |
| **C: S6 联合闭包** | 2/8 (+1 伪影) | F4/F5——S6 考虑整个恢复闭包（含非故障节点 t5 的可用性），S5+Gate 只检查故障节点自身 |
| **无优势** | 3/8 | F1a/F1b/F6——三策略完全收敛 |

## 核心发现：S6 的独有价值 = 全闭包可行性分析（非单纯门禁）

**F4/F5 是 S6 真正独有优势的场景**：
- S5+Gate 只检查 t1（故障节点）的可用模型→找到 GLM-5.3 可行→分配并执行
- S6 考虑整个恢复闭包 {t1,merge,t3,t4,t5,t6}→发现 t5（非故障节点）的可用模型也被质量
  门禁拒绝→**正确判定整个恢复不可行**→NONE
- S5+Gate 盲目执行 t1 恢复，但 t5 注定失败→浪费了 t1 的恢复成本

**量化 S6 避免的浪费**（F4 场景）：
- S5+Gate 执行 t1 恢复：~800 tok + 6.2s（DeepSeek→GLM-5.3）
- 然后发现 t5 不可行：已消耗 ~800 tok 白费
- S6 直接 NONE：0 tok + 0s + 决策耗时 727ms
- **S6 节省 ~800 tok + 5.5s + 避免注定失败的执行**

**但**：此优势依赖 Q_output_ratio 的可靠性。如果 Q=0 只是提示词问题（不是模型无能力），
则 S6 的 NONE 判断可能过于保守。
