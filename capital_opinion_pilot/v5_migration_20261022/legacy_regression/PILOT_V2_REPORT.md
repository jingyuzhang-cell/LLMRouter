## 五项核心判定（对照评审要求）

### 1. LLM 自主 DAG 生成是否真正成功 —— **成功**

规划器（GLM-5.3）输出 ≤500 字语义计划：初版计划结构检查未过（1 次反馈），**1 次结构化修复后通过**
（2 次请求信封内）。程序确定性组装为 6 节点图并通过复用的 `typed_dag_v1.validate()`：

```
t0 index（证据索引）→ t1 extracts（关键事实片段）→ { t2 timeline ∥ t3 entity_facts }
→ t4 factcheck_full（交叉核实）→ t5 report（带引用调查报告）
```

任务数、分析分支、依赖结构均由 LLM 计划决定（rationale："以监管处罚书为核心，公告佐证，先抽事实
再建时间线与主体事实，全量核验后成稿"）；程序只做契约映射与类型化绑定。**本轮未使用任何模板回退**
（组装失败即报失败，信封用尽亦报失败）。

### 2. DAG 是否存在非平凡的真实依赖 —— **是，但分支特化度低（如实记录）**

- 7 条依赖边全部携带类型化端口数据流（绑定⇄依赖由验证器强制，伪依赖结构上不可通过）；
- 真实并行层 t2∥t3（最大并行宽 2，深度 5）；
- **冗余标记**：t2（时间线）与 t3（主体事实）的 silver 覆盖集重叠 6/8（F1/F2/F7/F8/F9/F10）——
  两分支在该事件上高度重叠，佐证评审判断：此事件材料链浅，不足以支撑深度分支特化。
  该标记是 flag 非定罪（见 dag_audit_v2.json post_execution_redundancy）。

### 4. 两种模型是否具有可利用的差异 —— **是**（同输入受控对照；extracts 类对照无效已剔除）

| 对照 run | 模型 | 首试契约 | 终态契约 | 尝试 | in/out | 时延 | Q(原文覆盖) |
|---|---|---|---|---|---|---|---|
| extraction r0/r1 | GLM-5.3 | ✅/✅ | ✅/✅ | 1/1 | 652/313, 652/315 | 4.7/5.0s | 0.812/0.812 |
| extraction r0/r1 | Flash | ❌/❌ | ❌/❌ | 2/2 | 1,329/739, 1,329/756 | 14.4/17.8s | 0.688/0.812 |
| verification r0 | GLM-5.3 | ✅ | ✅ | 1 | 1,295/330 | 4.5s | 0.688 |
| verification r0 | Flash | ❌ | ❌ | 2 | 2,615/821 | 16.1s | 0.812 |
| verification r1 | GLM-5.3 | ✅ | ✅ | 1 | 1,295/405 | 9.0s | 0.812 |
| verification r1 | Flash | — | — | — | 调用上限未执行 | | |

- **契约合规**：GLM-5.3 在有效对照中 4/4 首试通过；Flash 0/7（修复后仍 0）。失败形态经原始响应
  定位：Flash 输出被 `contract`/`主体` 等额外顶层键包裹，不满足端口契约——是格式合规问题，其原文
  内容实质丰富（覆盖率可达 0.812）。
- **成本/时延**：Flash 含修复的总 token ≈ 2×、时延 ≈ 2–3×（且修复成功率 0，纯浪费）。
- **稳定性**：extraction 两轮重复中两模型行为一致（GLM-5.3 稳定通过；Flash 稳定失败）。
- **可利用性结论**：在"必须产出合法契约输出"的前提下，此类节点分配给 Flash 当前是纯亏损
  （内容近parity 但合规率为 0 且翻倍成本）；若放宽为"原文内容供下游程序再解析"，Flash 有成本潜力
  ——这构成后续路由/修复策略研究的真实决策空间。
- **诚实披露**：extracts 类对照因执行器 bug（对照时未注入证据包，输入仅 506 token）**无效**，
  已从结论剔除；A2 主链中的 extracts（有注入）正常。

### 5. DAG 相比单强模型是否存在可测量收益 —— **INCONCLUSIVE**

基线（单强模型+同一冻结证据包）在调用上限处被跳过：23/23 次先用尽，而 token 尚余 8,760。
这是本轮执行设计的失误（对照消耗了过多调用），不是结论。修复方式明确：基线应置于对照之前执行
（约 2.1K token、1 次调用）。
