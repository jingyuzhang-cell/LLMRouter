# KDX_NONE_OBJECTIVE_STABILITY — V3 完成奖励稳定性审计（零付费）

## V3 目标函数

```
score(action) = COMPLETION_BONUS + q * 10 - cost * 0.00002 - lat * 0.01  (if Z != NONE)
score(NONE) = 0
```

## 稳定性检查

### 量纲敏感性
COMPLETION_BONUS=100 在当前 token 量级（~800-3000/节点）下安全：
- 恢复动作得分 ≈ 100 + 0~10 - 0.02~0.1 ≈ **100~110**
- NONE 得分 = 0
- 差距 ~100 点，不会被 cost/lat 微调翻转

但如果 token 量级达到 ~500 万（极端大 DAG），cost 项 ≈ 100 → 可能接近 COMPLETION_BONUS。
**建议**：将 COMPLETION_BONUS 改为相对量（如 `max_cost * 10`）而非绝对量 100。

### 分层目标对照（更合理的长期设计）

| 层 | 约束 | 当前 V3 | 建议长期 |
|---|---|---|---|
| 1 硬约束 | 预算/截止/依赖/模型可用 | 二元（过/不过） | 同 |
| 2 完成要求 | 恢复 vs NONE | bonus=100 | 约束式：仅考虑能完成的方案 |
| 3 质量下界 | q_min 过滤 | q_min=0.1（代理） | Gold 校准后精确设定 |
| 4 成本/时延优化 | 加权惩罚 | 微弱权重 | 在满足 1-3 的方案中优化 |

**建议长期设计**：先用约束过滤（1-3），再在满足约束的方案集内优化 C/L（层 4）。
V3 的 bonus 方式是权宜之计，在当前规模下稳定但非最优。

### 错误放弃风险

| 风险 | 当前状态 | 缓解 |
|---|---|---|
| Q 代理误判（Q=0 但模型实际能做） | **存在**——跨源核查 3/4 模型 Q=0 可能是提示词问题 | Gold 校准后重估 |
| 预算估计偏高（能力表均值>实际） | 存在——预测 4783 vs 实际 2123（元道退） | 滚动校准 |
| 截止时间估计偏高 | 存在——P90 vs 实际差距未标定 | 多次实测校准 |

**NONE 错误放弃的量化**：如果 Q=0 的模型实际能完成任务，S6 的 NONE 判断就是错误放弃。
**当前无法排除此可能**——必须等 Gold 校准后才能评估错误放弃率。
