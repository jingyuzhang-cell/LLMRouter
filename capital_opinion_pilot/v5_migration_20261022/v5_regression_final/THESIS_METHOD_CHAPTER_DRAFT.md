# 论文方法章节草稿 — 第三章 系统设计与算法

## 3.1 系统架构

### 3.1.1 总体架构

本系统采用分层架构，自底向上分为四层：

```
┌─────────────────────────────────────────────────┐
│           评价层 (Evaluation Layer)               │
│  T0 执行指标 | T1 官方可验 | T2 Silver 质量       │
├─────────────────────────────────────────────────┤
│           调度层 (Scheduling Layer)               │
│  S6 联合调度器 a=(Z,R,π) | 能力表查询 | 预算守卫  │
├─────────────────────────────────────────────────┤
│           执行层 (Execution Layer)                │
│  DAG 执行器 | 节点契约校验 | 缓存管理 | 故障注入   │
├─────────────────────────────────────────────────┤
│           证据层 (Evidence Layer)                 │
│  分段检索器 | 证据打包 | 出处保留 | 冻结协议       │
└─────────────────────────────────────────────────┘
```

### 3.1.2 证据层

**分段检索器**：将官方文档切分为 450 字证据块（80 字重叠），构建倒排索引。检索时按 IDF 加权评分排序，采用跨文档轮转分配确保每份文档至少获得一个证据块（修复了严格比例分配导致小预算下零检索的问题）。

**证据打包**：保留每块的 doc_id、字符偏移、发布日期和 SHA256 哈希，支持逐条事实的出处追溯。

**冻结协议**：所有证据文档的 URL、哈希、公开日期在实验前冻结，程序化强制截止日期约束（截止日后材料一律不入库）。

### 3.1.3 执行层

**DAG 执行器**：按拓扑层级顺序执行节点。每个节点接收上游输出作为输入，通过模型调用生成结构化 JSON 输出。程序节点（如 facts_merge）零模型调用。

**节点契约校验**：三层校验体系：
1. JSON 语法合法（可解析）
2. Schema 契约合法（顶层键名匹配）
3. 语义可解析（内容可提取）

契约失败区分 `JSON_FAIL`、`CONTRACT_FAIL`、`SEMANTIC_PARSED` 三种状态，不将格式失败混同于能力失败。

**缓存管理**：已完成且未受故障影响的节点输出受保护（cache legality）。恢复时仅重执行受影响闭包，不重复执行缓存合法节点。

**故障注入**：支持三种异常类型：
- `model_unavailable`：传输级模型不可用（零 token）
- `contract_fail`：输出契约不合法（消耗 token 但解析失败）
- `timeout`：服务超时

### 3.1.4 调度层

**S6 联合调度器**（详见 3.2 节）

**能力表**：记录 (node_type, model) → {Q_proxy, C_tokens, L_latency, contract_rate}，来自节点级真实调用测量。能力表在 VAL 阶段滚动更新，TEST 前冻结。

**预算守卫**：三级硬约束：
- 调用次数 ≤ 上限
- 累计实际 Token + 校准输入界 + 1.5×max_tokens ≤ 保证线
- 累计现金 ≤ 硬上限

超限即停，不自动重试。

## 3.2 联合动态调度算法

### 3.2.1 联合动作定义

调度器的动作空间为三元组：

$$a = (Z, R, \pi)$$

其中：
- $Z \in \{NONE, LOCAL, FULL\}$：恢复模式
- $R \subseteq V$：重执行节点集合（依赖闭包 + 缓存合法性约束）
- $\pi: R \cup pending \rightarrow M$：节点到模型的分配

**与固定恢复策略的区别**：固定策略（S4/S5）预先确定 $Z$ 和 $R$ 的规则及 $\pi$ 的选择逻辑，不依赖运行时状态。S6 在每次故障发生时联合枚举 $(Z, R, \pi)$ 的候选组合并选择最优。

### 3.2.2 两阶段决策

**阶段一：可行性过滤**

对每个候选动作 $a = (Z, R, \pi)$，检查四项硬约束：
1. **依赖合法性**：$R$ 必须包含故障节点的全部下游受影响闭包
2. **预算约束**：$spent + predict\_cost(a) \leq B$
3. **截止时间**：$now + predict\_lat(a) \leq T$
4. **质量下界**：$\min_{n \in R} Q(n, \pi(n)) \geq q_{min}$

不可行动作记录拒绝原因，不进入阶段二。

**阶段二：联合优化**

在可行集内最大化加权目标：

$$\max_{a} \left[ w_q \cdot Q_{lower}(a) - w_c \cdot C(a) - w_l \cdot L(a) \right]$$

其中 $Q_{lower} = \min_{n \in R} Q(n, \pi(n))$ 为闭包内最低质量代理，$C(a)$ 为预测 Token 成本，$L(a)$ 为预测端到端时延（能力表 P90 时延之和）。

**NONE 特殊处理**：NONE 不获得完成奖励（score=0），确保任何可行动作优先于放弃。仅当全部候选被约束拒绝时才选择 NONE。

### 3.2.3 候选枚举

对小规模 DAG（≤10 节点、≤4 模型），采用**精确枚举**：
- $Z$ 有 3 种选择（NONE/LOCAL/FULL）
- $R$ 由 $Z$ 和故障位置唯一确定（LOCAL=故障闭包，FULL=全部节点）
- $\pi$ 对 $R$ 中每个 LLM 节点枚举所有模型组合（$|M|^{|R_{LLM}|}$）

总候选数上限：$3 \times 4^8 \approx 196,608$。实际测量枚举耗时 727ms（8 节点×4 模型），可接受。

对大规模 DAG，可采用束搜索（beam search）限制搜索空间。

### 3.2.4 与固定恢复策略的形式化对比

| 策略 | Z | R | π | 决策依据 |
|---|---|---|---|---|
| S4 固定换模型 | LOCAL（固定） | 闭包（固定） | 固定备选模型 | 无（盲切） |
| S5 固定局部恢复 | LOCAL（固定） | 闭包（固定） | 能力表查表 | 单维（质量） |
| S5+ClosureGate | LOCAL（固定） | 闭包（+闭包质量检查） | 能力表查表 | 单维+可行性 |
| S5+Capability | LOCAL（固定） | 闭包（固定） | 能力表轻量选模 | 单维（质量） |
| **S6 联合调度** | **动态选择** | **动态选择** | **联合优化** | **多目标（Q×C×L）** |

**S6 的独有能力**：在质量并列的模型间做出时延导向的选择（多目标权衡），以及全闭包可行性分析（发现下游不可救节点提前放弃）。

## 3.3 质量评价体系

### 3.3.1 分层质量评价

| 层 | 定义 | 可信度 | 用途 |
|---|---|---|---|
| T0 执行指标 | 契约率/截断/Token/时延/现金 | 确定性 | 所有实验 |
| T1 官方可验字段 | 正则锚定在官方原文 | 高 | Silver 评分 |
| T2 Silver 质量 | 模型输出 vs T1 的覆盖率 | 中 | 开发集 |
| T3 人工 Gold | 双人独立标注 | 最高 | 正式结论（待完成） |

### 3.3.2 T1 锚定方法

对每条参考事实，在官方文档全文中定位精确锚点（字符偏移），记录逐字引文和发布日期。程序验证（regex_search_in_official_text）确保每条事实可追溯到官方原文。

### 3.3.3 覆盖率计算

$$T1\_coverage(model\_output) = \frac{|\{r \in T1 : value(r) \text{ or } quote(r) \subseteq output\}|}{|T1|}$$

其中 $value(r)$ 为标准化答案值，$quote(r)$ 为锚定引文前 15 字。匹配使用归一化文本（去除空白和标点差异）。

**敏感性声明**：覆盖率依赖参考集大小。本文报告 4 条和 8 条参考集下的结果，明确标注。

## 3.4 小结

本章设计了面向截止时间约束的反馈驱动异构 DAG 动态调度系统。核心创新包括：
1. 联合动作空间 $a=(Z,R,\pi)$ 及两阶段决策算法
2. 三层节点契约校验（区分格式失败与能力失败）
3. 分层质量评价体系（T0-T3）
4. 证据出处保留与冻结协议
