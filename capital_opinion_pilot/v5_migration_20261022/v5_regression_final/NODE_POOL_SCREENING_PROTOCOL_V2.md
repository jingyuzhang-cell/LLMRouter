# NODE_POOL_SCREENING_PROTOCOL_V2 — 节点级筛选协议（修订版，待阶段 1 通过后授权）

相对 V1 的强制修订（对应裁定第 3 节）：
1. **逐调用记录**：确切模型版本串、stop 原因、截断状态、JSON 契约首试/打捞成功率、
   真实输入输出 token、端到端墙钟时延、费用（双口径）。
2. **2,048 上限长度预检**：以阶段 1 第 3 项实测输出分布为准；某节点类型若 P90 需求 >1,800，
   筛选前先改契约（拆分输出）而不是带病开跑。
3. **Gold 状态联动**：筛选样本来自 DEV/VAL（舜天/康得新/元道退冻结输入）；元道退
   Gold=PENDING 期间，其样本仅计探索性分项；**独立 TEST 事件一律不参与模型池筛选**。
4. **预冻结**：模型保留规则（互补门槛）、嵌套子集 P2={M1,M2}/P3=+M3/P4=+M4、指标定义
   （Q 四类 / C 双口径 / L p50+p95 / 契约率 / 打捞率）在本文件冻结，筛选后不改。
5. **禁止人为优势**：不依任何模型的表现调整样本、提示或评分权重；提示模板与 GLM 完全同文。
6. **故障域记录**：每调用记录 provider/网关/限流事件（RQ2 的跨家族可用性数据基础）。

矩阵不变：4 节点类型 × 5 冻结样本 × 4 模型 = 80 次；同输入 prompt_sha256 断言；
重复与重试不在本预算内（另行授权）。

| 口径 | 定义 | 用途 |
