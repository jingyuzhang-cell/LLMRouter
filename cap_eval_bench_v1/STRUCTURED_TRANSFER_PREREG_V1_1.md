## 2. 三态溯源（按裁决修正）

### 2.1 状态定义：三态只描述**字符串定位**，不描述语义支持

| 状态 | 含义 | 是否自动计入 TP |
|---|---|---|
| `VERIFIED_UNIQUE_SPAN` | 值在 n1 窗口内唯一匹配 | **否，仍须语义核验** |
| `VERIFIED_MULTI_SPAN` | 值在窗口内多处匹配（**保存全部候选位置**） | **否，须核验具体上下文** |
| `UNVERIFIABLE_ABSENT` | 窗口内无匹配 | 否（且永不可为 TP） |

**核心纪律**：字符串定位解决的是"值是否出自 n1 看到的文本"，**不能替代语义证据核验**。
P03 案例即反例：`市场禁入` 在窗口内出现 3 次，全部位于当事人申辩（"请求…不采取证券市场禁入措施"），
字符串定位成功但语义上不构成"监管部门作出了市场禁入处罚"。

### 2.2 三条硬约束（写入 n9 契约与评分器）

1. **保存全部候选位置**：`spans = [[s,e], ...]`，不截断为第一个。
2. **SUPPORTED 的必要条件**：至少有一个候选位置能够支持该 `fact_role`。
   仅"出现过该字符串"不构成支持。
3. **语境不可区分时必须判 `UNKNOWN`**，不得为提高 Recall 强行认定支持。
   明确禁止把否定句、申辩句、假设句、引用他人主张计为正向事实。

评分器侧对应规则（v3 已含，此处明文）：TP 必须同时满足
① 值出现在终端报告 JSON 的**值**中；② 值在本轮 n1 输出中；③ 值在 n1 输入窗口内；
④ 该事实在 n9 被标为 SUPPORTED（若 n9 标 REJECTED/UNKNOWN，即使终端出现也不计 TP）。
④ 为本轮新增，用于把语义核验接入评分。

## 3. Token 预算（单一来源复算）

### 3.1 方法

1. 用**实际构建的 B 臂提示词文本**计字符数（`b_arm_budget.py` 中的 `build_prompts`）。
2. 乘以 **104 次真实调用实测的逐节点 tokens/char**（min/median/max，剔除 1 个已知缓存伪影）。
3. 加上输出 token 估计。
4. **共享 n1 的 token 按操作员要求为两臂各计一次**（实际部署两方案都需执行 n1）。

### 3.2 pad 扫描（同一设计族，只变证据片段长度）

| pad | n9 字符 | B/A 中位 | B/A 最坏 |
|---|---|---|---|
| **10（采用）** | 9,952 | **1.089×** | **1.136×** |
| 15 | 10,477 | 1.100× | 1.149× |
| 20 | 11,002 | 1.112× | 1.162× |
| 35 | 12,577 | 1.147× | 1.200× |

| n1 | 4,884（与 A 臂相同） | 2,944 / 2,944 / 2,944 | 3,245 | 6,189 |

**校验式（任何人可复算）**：
- A 全管道 = 20,503（V7 四个完整块实测均值，n1 6,189 + 非 n1 14,314）
- B 非 n1 = 16,132（中位）；B 全管道 = 6,189 + 16,132 = **22,321**
- **B/A = 22,321 / 20,503 = 1.089×**（最坏 23,300 / 20,503 = 1.136×）
- 门槛 1.15：中位 ✓、最坏 ✓

**如实声明**：1.089× 是点估计。实测比例若整体偏向分布高端则上移至 1.136×，
仍可能在门槛内；但若实际提示词长度超出构建值 10% 以上，则会越界。
**执行后必须报告实测 ratio；若 >1.15，按"质量提升但成本超标"报告，不得宣称达标。**

## 4. 执行结构：每块共享一次 n1（按裁决落实）

```
每个配对块（共 5 块）：
  ① 调用 n1 一次 → 记录原始输出与 SHA256（该块内不可变）
  ② A 臂：同一份 n1 文本 → n1_output[:3000] → 原 V7 契约 n2..n10（9 次）
  ③ B 臂：同一份 n1 文本 → 结构化事实库 → 新契约 n2..n10（9 次）
```

- 每块 1 + 9 + 9 = **19 次**；5 块 = **95 次**；执行上限 **105**（重试预留 10）。
- 每块必须落盘：`n1_output_sha256`、两臂的事实库/中间输出、v3 评分明细。
- **成本归因**：C_A 与 C_B 各自包含完整 n1 成本（共享调用不减免任何一臂）。
  实际花费（n1 只付一次）另列，二者都报告。

## 5. H1–H4 与成本（冻结）

### 5.1 H2 的基线处理（按裁决修正）

- **历史基线**（V6+V7 共 9 个 A 臂块，非本轮）：A03 0/9、A09 0/9、A01 0/9、E01 3/4。
  仅作历史参照，**不作为本轮判据**。
- **本轮判据**：每块对三件事分别计数——
  1. n1 是否提取了该事实（`extracted`）
  2. A 臂终端是否出现（`A_terminal`）
  3. B 臂终端是否出现（`B_terminal`）
- **归因纪律**：若本块 n1 未提取该事实，该块的缺失**不计入传递失败**，也不计入 H2 分母。
  H2 检验只在 `extracted=true` 的块上做：B 臂 recovery 率 = `B_terminal / extracted`。
- 若某事实在 5 块中 n1 提取少于 3 块，则该事实的 H2 结论标注"样本不足"，不据此判定通过/失败。

### 5.2 假设表（冻结）

| 假设 | 指标 | 通过条件 |
|---|---|---|
| **H1 终端质量** | v3 文档支持 TP | B 中位 ≥14；配对 TP 差中位 ≥+3；≥4/5 配对正向 |
| **H2 事实恢复** | A03 / A09 / A01 在 `extracted` 块内的终端恢复率 | 每条 ≥4/5 且 `extracted` 块数 ≥3 |
| **H2b 非回归** | E01 / D03 / D06 在两臂终端 | B ≥4/5（A 臂同步报告，不设历史门槛） |
| **H3 Precision** | 池化 P_v3 | ≥85%，且不低于 A 臂池化 −2pp |
| **H4 溯源诚实** | 无据事实进入 TP 的条数 | B ≤ A |
| **成本** | 实测 C_B/C_A（含 n1 双计） | ≤1.15（点估计 1.089×；越界则如实报告权衡） |

判定：CONFIRMED = H1∧H2∧H3∧H4；CONDITIONAL = H1 达 4/5 且 H3 成立且 H2 回收 ≥2/3；
NEGATIVE = H1 不成立或 H4 破坏或 H2 回收 ≤1/3；INVALID = 执行/预算异常。

## 7. 事实记录 schema（冻结）

```json
{
  "fact_id": "AMT1853",
  "fact_type": "amount",
  "fact_role": "虚增收入",
  "value": "1,000万元",
  "provenance_status": "VERIFIED_MULTI_SPAN",
  "spans": [[1853, 1860], [2767, 2774]],
  "quote": "金额1,000万元、3,000万元"
}
```
- `fact_id` 确定性：`{类型码}{首个 span_start}`；无 span 用 `X{归一化值短哈希}`；不依赖输出顺序。
- `fact_role` 直接取 n1 既有字段（nature/role/type），**不由下游重新判定**。
- `spans` 保存**全部**候选位置（裁决要求）。
- `normalized_value` 不入载荷，由代码计算。
- 位置只在 n9 载荷中下发；n3–n8 以 `fact_id` 引用（不重复下发位置，成本控制）。
