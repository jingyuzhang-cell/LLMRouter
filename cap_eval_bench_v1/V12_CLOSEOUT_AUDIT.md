## 1. D4：集合迭代顺序不确定性

### 1.1 位置与机制

`st_v1_exec.py:205`
```python
sup = parse_n9_supported(text)          # 返回 set
fed = [byid[i] for i in sup if i in byid]   # ← set 迭代，顺序依赖字符串哈希随机化
```
`fed` 的顺序直接决定 n10 提示词中事实列表的顺序。Python 的 `set` 迭代顺序受 `PYTHONHASHSEED`
影响，**跨进程不稳定**；因此同一逻辑输入在不同进程产生的提示词字节不同、`prompt_sha256` 不同。

### 1.2 为什么导致重复调用

Meter 的去重键是 `(purpose, prompt_sha256)`。第 2 次运行（崩溃于 B2 的 JSON 解析）已经完成并记录
B1 的 `B:n10`（call_id 19）；第 3 次运行重放时，`fed` 的 set 顺序与上次不同 → SHA 不同 →
去重未命中 → 重新付费调用（call_id 30）。**重复花费 2,433 tokens。**

### 1.3 重复调用是否改变评分：**是，而且不是无害的**

| 记录 | 提示词字符 | 输入 token | 输出 token | TP | F1 | 缺失事实 |
|---|---|---|---|---|---|---|
| call 19 | 4,297 | 1,545 | 888 | **11** | 0.6667 | D01、D02、D04 |
| call 30（最终采用） | 4,297 | 1,545 | 985 | **14** | 0.7778 | — |

两次**内容完全相同、仅顺序不同**；两次 `stop_reason` 均为 `end_turn`（**不是**输出截断）。
差异集中在三个会计期间截止日（2017-12-31 / 2018-12-31 / 2020-12-31）。

**必须区分的两种解释**（当前数据无法分离）：
1. **顺序效应**：事实在提示词中的位置影响 n10 是否写入报告；
2. **采样噪声**：模型 temperature > 0，即使顺序相同也会波动。

由于两次提示词字节不同，本实验**没有**"同提示词重复"的数据，因此不能把差异归因于顺序
——只能如实记录为"n10 终端产出在内容相同条件下存在 ≥3 条事实的波动"。

### 1.4 敏感性分析（用另一条记录替换 B1）

| 方案 | A TP | B TP | B 中位 | 配对差 | 正向 | H1 |
|---|---|---|---|---|---|---|
| 最终采用（call 30） | 10,11,11,10,11 | 14,14,14,14,14 | 14 | +4,+3,+3,+4,+3（中位 3） | 5/5 | PASS |
| 替换（call 19） | 10,11,11,10,11 | **11**,14,14,14,14 | 14 | +1,+3,+3,+4,+3（中位 3） | 4/5 | **PASS** |

**结论：D4 不改变 H1 判定，但把 B 臂的稳定性从"5/5 = 14"降级为"6 次运行中 5 次 = 14、1 次 = 11"。**

### 1.5 修复方案（仅建议，未改代码）

```python
# 建议差异（最小改动，不触碰历史数据）
- fed = [byid[i] for i in sup if i in byid] or [...]
+ fed = [byid[i] for i in sorted(sup) if i in byid] or [...]
```
同时建议 `parse_n9_supported` 直接 `return sorted(...)`，并新增回归检查：
**同一输入两次构造提示词，SHA 必须相同**。此外，n10 提示词内事实顺序应改为
`(fact_type, span_start)` 的语义顺序，而非字典序，以消除"排序即改变结果"的隐变量。

## 2. D5：n9 输出解析失败（B2）

### 2.1 原始输出形态

B2 的 n9 返回 **48 个单键对象**，键为 `fact_id`、值为状态：
```json
[{"DTE506":"supported"},{"DTE632":"supported"}, ...,{"ENT2781":"supported"}]
```
解析器 `parse_n9_supported` 支持两种形态：`{"supported":[...]}` 与 `[{"fact_id":...,"status":...}]`，
**不支持"单键对象"形态** → 返回空集 → 触发回退分支。

### 2.2 回退实际传递了什么

| 项 | 值 |
|---|---|
| n9 解析结果 | 0 条 |
| 事实库规模 | 48 |
| 溯源分布 | UNIQUE 44 / MULTI 4 / **UNVERIFIABLE_ABSENT 0** |
| 实际喂给 n10 | **48 条**（回退：全部非 UNVERIFIABLE） |
| n9 原始输出中标记 supported | **48 条** |

**回退集合 ≡ n9 判定集合（逐条相同）。** 因此 B2 **完全符合**预注册的结构化传递机制：
值来自 n1、位置在 n1 窗口内、n10 只接收经判定的事实。回退是"形状解析失败"而非"机制失败"。

### 2.3 敏感性分析

| 样本 | A TP | B TP | B 中位 | 配对差 | 正向 | 池化 P（A/B） |
|---|---|---|---|---|---|---|
| 全样本（5 块） | 10,11,11,10,11 | 14,14,14,14,14 | 14 | 中位 +3 | 5/5 | 85.5% / 100% |
| **排除 B2（4 块）** | 10,11,10,11 | 14,14,14,14 | 14 | 中位 **+3.5** | **4/4** | **84.0%** / 100% |

**B2 未被静默删除**，报告两套结果；结论一致。

### 2.4 修复方案（仅建议）

```python
elif isinstance(o, list):
    for x in o:
        if isinstance(x, dict):
            if 'fact_id' in x:  ...(现逻辑)
+           elif len(x) == 1:   # {"FACT_ID": "supported"}
+               fid, st = next(iter(x.items()))
+               if str(st).lower().startswith(('support','确认','verif')): out.add(fid)
```
并建议把 n9 输出的**允许形态写成提示词内的显式 schema + 示例**，同时记录
`n9_parse_ok` 标志（本轮缺此项，只能事后重建）。

## 3. D6：P03 语义误报

### 3.1 窗口内证据跨度（EV[:4000]）

`市场禁入` 在 n1 实际输入窗口内**仅出现 1 次**，@[3783:3787)：

> …符合"从旧兼从轻"原则。欺诈发行的认定应当以骗取发行注册为要件，**行政处罚及市场禁入事先告知书**
> （以下简称告知书）**没有提供**泽达易盛不符合法定发行条件的事实和理由，认定欺诈发行的事实和理由不充分…

（更正：我在结题报告中写的"窗口内三次出现"是 6000 窗口的统计；在实验实际使用的 4000 窗口内只有 1 处。）

该处语境是**当事人在陈述申辩中转述"告知书"**，不是监管机关作出市场禁入处罚的决定。
处罚决定部分位于文档 @7244 之后，在输入窗口之外。

### 3.2 v3 为什么计为 TP

v3 的三个条件全部成立：值出现在终端报告值中 ✓、在本轮 n1 输出中 ✓、在 n1 输入窗口内 ✓。
v3 **不含**语义/语境判定，因此把它计为文档支持。A 臂 B2、B3 各因此多得 1 条 TP（n1 在这两块提取了该词）。

### 3.3 通用"否定语境"规则不可用（重要负面结果）

我尝试过通用否定守卫（±45 字符内含 不采取/不予/请求/申辩/未/没有 等即拒绝），结果：

| 块 | A v3 TP | 通用守卫后 | 被误杀 |
|---|---|---|---|
| B1 | 10 | **6** | A05、A06、A07、A10 |
| B2 | 11 | **6** | A05、A06、A07、A10、P03 |

核心财务造假金额（186,735,305.01 元等）因周围散文含"未按规定披露"而被误杀。
**该规则会把两臂同时废掉，不可采用。**

### 3.4 建议的 v3.1 窄规则（仅对 penalty 类型生效）

> 处罚类事实（`kind == 'penalty'`）的文档支持，要求至少一处出现位置的 ±120 字符内含
> 决定类表述（决定 / 处罚决定 / 本会决定 / 作出下列），且不含申辩类表述
> （申辩 / 请求 / 陈述 / 否认 / 不采取 / 不予处罚 / 不予认定）。

对全部 22 条有效事实逐一核验：**窗口内只有 P03 属于 penalty 类型且命中该规则并被拒绝**，
其余类型完全不受影响（该规则不改变任何 D/A/E 类事实）。

## 5. 证据等级与结论边界

**证据等级：机制级因果证据（单案例、单模型族、5 配对块，v3 评分）**

### 已证明
1. 在 n1 输出字节相同、模型相同、DAG 拓扑相同、max_tokens 相同的条件下，仅改节点间传递表示，
   终端文档支持事实数由 11 → **14**（配对差中位 +3，5/5 正向；v3.1 下 +4）。
2. 回收的事实与截断预测**精确吻合**：A03、A09、A01（A 臂 0/5）在 B 臂 5/5 到达；E01 由 1/5 升至 5/5。
3. A 臂 n2 与 n9 在 **5/5 块**触发 `max_tokens` 截断；B 臂 n1/n9/n10 零截断 → 损失机制是通道容量，非模型能力。
4. B 臂 5 块 Precision **100%**、零无据事实；A 臂 9 条无据数值。
5. 归因成本比 0.763（B 更便宜），因为中间节点只传 ID、值由代码注入。

### 未证明 / 不能声称
1. **不能**声称"结构化传递普遍优于字符截断"——单案例、单一 DAG、单一文档。
2. **不能**声称 14 是可达上限之外的表现；14 恰为 V7 配置的通道天花板。
3. **不能**声称 n10 的 14 条是稳定产出：D4 显示同内容不同顺序可得 11 条（6 次中 1 次）。
4. **不能**把结果外推到其它模型族：本实验模型为 glm-5.3 且**强制思考**（D2），与历史 V7 基线不同协议。
5. **不能**把本轮结论当作异构模型调度的证据：本轮两臂同模型。

### 待验证
- 顺序效应 vs 采样噪声的分离（需同提示词重复，属付费实验）。
- 结构化传递在更大 DAG、更长文档、跨案例上的效果。
- n9 语义核验的质量（B2 的 n9 全部判 supported，未见拒绝——核验是否真正起作用尚不清楚）。
