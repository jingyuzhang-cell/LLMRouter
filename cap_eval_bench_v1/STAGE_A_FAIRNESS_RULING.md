# STAGE_A_FAIRNESS_RULING — 36-run 版本归因与公平性裁定（窗口三；零付费，纯账本推导）

## 一、归因方法与结果（VERSION_ATTRIBUTION.json）
账本 call_id ≤91 = 旧运行器（报告节点契约冲突期）；≥92 = 修复后运行器。逐 run 判定其最终合成
调用的执行版本：

| 类别 | 数量 | 含义 |
|---|---|---|
| UNIFORM（single 臂） | 12 | 单模型提示词在两版本间逐字一致（含公平子句与 768 上限） |
| UNIFORM_NEW（图臂） | 9 | 最终合成在修复后契约下产生（T-M1×4、T-P2×4、T-D1 auto r2） |
| **SALVAGED_CROSS_VERSION（图臂）** | **15** | 最终响应在冲突契约下生成（期一），由修复后解析器跨版本接受 |

## 二、裁定

1. **本批 36-run 定性为诊断性结果**（与裁决一致）：15 个跨版本打捞的图臂 run 与任何臂的配对
   均不构成同条件比较；不可事后将修复前失败改记为修复后成功（本报告未做此类改写——全部
   原始调用与响应按账本保存，归因只是标注）。
2. **保留的版本一致子集**：仅 T-M1 存在同任务、双臂均版本一致的 COMPLETE 配对——
   single 0.774×2 vs graph 0.729×2（另 2 个图 run INCOMPLETE），单模型以 ~0.045 Q 差距与
   ~2.7× 成本优势领先。**n=1 任务、探索性**，方向与全批一致但无确认力。
   T-P2 四个图臂 run 版本一致但全部 INCOMPLETE（证据获取瓶颈）。
3. 端到端任务有效性结论（保留全部 36 run、失败不剔除）不受版本归因影响的部分：
   single 12/12 完成、图臂首节点合同双败 10/12 为未完成主因、长语料全臂低分——这三条
   为**系统诊断事实**，与算法优劣无关。
4. Q|COMPLETE 的 0.630/0.594/0.575（全批口径）降级为**辅助观察**：成功样本非随机缺失，
   且 15 个图 run 属跨版本条件。

## 三、对后续的约束
- 任何确认性 Stage-A 重跑必须在**单一冻结代码版本**下完成全部臂（含 10 次首节点失败的
  工程消除，窗口 2 项）；
- 本批数据可用于：首节点契约摩擦的失败模式分析、检索自给率-质量关系、单模型臂内部
  按条件类的行为（版本一致）；不可用于：跨臂收益结论。
