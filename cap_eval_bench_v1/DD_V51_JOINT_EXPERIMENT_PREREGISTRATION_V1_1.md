## 一、假设与统计判定（修正 #2）

**5 种子定位为可重复性试验（pilot），不做普遍统计推断。**

| 假设 | 内容 | 判定 |
|---|---|---|
| H1 | Joint 的 Q_terminal 优于 Static | 5 种子配对差全部报告；≥4/5 方向为正 **且** 中位配对差 ≥ 最小有意义效应量 |
| H2 | Joint 的 Q_terminal 优于 π-only | 同上 |
| H3 | Joint 的 Q_terminal 优于 R-only | 同上 |
| H0 | 四臂无差异 | 任一假设不满足 → 不确定或负向 |

**最小有意义效应量（预冻结）**: ΔQ_silver ≥ 0.05（Silver 事实覆盖提高 ≥5 个百分点）。

**报告格式**: 每种子配对差值 + 中位差 + 范围 + 方向一致率。不做 p 值检验（5 种子不具统计检验力）；如果方向一致但效应量 < 0.05，判"方向一致但效应量不足"。

**关键对照重新排序**: 最关键的不是 Joint vs Static，而是 **Joint vs π-only** 和 **Joint vs R-only**——联合优化的增量贡献。

## 二、对照公平性（修正 #1）

**四臂使用完全相同的模型池、相同的初始分配、相同的异常注入。区别仅在于异常发生时允许采取的调度动作集。**

| 要素 | 四臂共同设置 |
|---|---|
| 模型池 | glm53 + glm53flash（全部四臂均可用） |
| 初始 π | 全部节点分配 glm53（冻结初始分配） |
| 异常注入 | n3 transport 截断 + n5 evidence_fail（同种子同注入点） |
| 种子 | 1–5（temp=0.7） |

| 臂 | 异常时允许的动作 |
|---|---|
| Static | 同模型重试 1 次；失败则跳过该节点继续 |
| R_only | 计算恢复闭包；闭包内节点用原模型重执行 |
| pi_only | 失败节点换模型重试（glm53↔flash）；后续未执行节点可重新分配 |
| Joint | 枚举 Z 操作 × R 闭包 × π 重分配的合法组合→语义守卫过滤→按冻结规则选择 |

## 三、Joint 动作选择机制（修正 #3，预冻结）

### 3.1 动作空间

**Z（结构操作）**:
- Z_NONE: 不改变 DAG 结构
- Z_FALLBACK: 失败节点用确定性降级替代（直接引用上游原始数据，不调用模型）
- Z_MERGE: 失败节点功能合并到最近的下游节点（下游节点提示词追加失败节点任务）

**R（恢复闭包）**:
- R_EMPTY: 不重执行任何节点
- R_FAILED: 仅重执行失败节点
- R_DOWNSTREAM: 重执行失败节点及其全部下游依赖

**π（模型分配变更）**:
- PI_KEEP: 保持原分配
- PI_SWAP_FAILED: 失败节点换到另一模型
- PI_SWAP_REMAINING: 失败节点 + 全部未执行节点重新分配（强模型给综合节点，弱模型给提取节点）

### 3.2 语义守卫（预冻结）

排除以下候选组合：
- Z_MERGE 如果失败节点是唯一终端节点（synthesis/report）→ 排除
- R_EMPTY 如果失败节点是终端节点的直接上游 → 排除
- PI_SWAP_REMAINING 如果已执行节点 > 70% → 排除（重分配成本过高）

### 3.3 选择规则（确定性，预冻结，不看 Q_silver）

```
score(action) = w1 × coverage_estimate + w2 × (1 / cost_estimate) + w3 × (1 / latency_estimate)

coverage_estimate = 该动作下预期可到达的终端节点比例
cost_estimate = 该动作下剩余需执行的节点数 × 平均 token 成本
latency_estimate = 该动作下预期 makespan

权重: w1=0.5, w2=0.3, w3=0.2（预冻结，不调整）
tie_breaker: score 相同时选动作序 Z_NONE > Z_FALLBACK > Z_MERGE; R_EMPTY > R_FAILED > R_DOWNSTREAM; PI_KEEP > PI_SWAP_FAILED > PI_SWAP_REMAINING
```

**关键约束**: 选择规则**不使用**任何质量评分模型输出作为输入。coverage_estimate 基于图拓扑（节点可达性），不基于内容质量。

## 四、终端指标收紧（修正 #4）

| 指标 | 定义 | 防操纵 |
|---|---|---|
| Q_silver（召回） | 终端报告覆盖 Silver 事实比例 | — |
| Q_precision（精确） | 报告中声明的事实中，有证据支持的比例 | 防止"更长报告=更高覆盖"的假阳性 |
| **Q_F1** | 2×P×R/(P+R)（主指标） | 同时惩罚遗漏和幻觉 |
| Halluc_rate | 终端实体中不在证据文档内的比例 | — |
| Makespan | 从 run 开始到最后节点完成的墙钟时间 | 非∑节点时延 |
| Sum_latency | 各节点时延之和（参考记录） | 供分析 |
| Cost | 总 input+output tokens | — |
| On_time | Makespan ≤ 截止期（120s 模拟） | — |

**主指标**: Q_F1（预冻结）。Q_silver 单独报告但不作为主判定依据。

## 五、异常依赖关系（修正 #4 补充）

D_R1 DAG 结构：
```
n1(extraction) → n2(extraction) → n3(timeline) → n6(timeline_deep) → n9(cross_check) → n10(synthesis)
                  n2 → n4(amounts) → n5(penalties) → n8(amounts_check) ↗ n9
                  n2 → n7(entity_graph) ↗ n6
```

- **n3（timeline）transport 异常**: 在 n2→n3 执行时注入截断；影响路径 n3→n6→n9→n10
- **n5（penalties）evidence_fail 异常**: 在 n4→n5 执行时注入上游数据置空；影响路径 n5→n8→n9→n10

两条路径在 **n9（cross_check）** 汇合，均为独立路径异常（n3 不在 n5 的上游/下游）。一个异常的恢复不影响另一个异常的注入。汇总报告中分别标注两个异常各自的恢复效果。

## 七、汇报承诺

实验完成后固定报告：
1. **科学问题**: (Z,R,π) 联合调度是否产生单独 R 或 π 无法获得的额外终端收益
2. **结果判定**: H1/H2/H3 各自正向/负向/不确定，附每种子配对差值明细
3. **终端质量收益**: Q_F1 / Halluc / Makespan / Cost / On_time，按臂×种子矩阵
4. **投入决策**: 继续（H2+H3 正向且可重复）/ 调整（方向不一致，指明瓶颈）/ 停止（H2 或 H3 负向且可重复）
