## 4. 两个必须披露的缺陷

### D9：预注册的 ID 级完整性判据结构性失效

预注册 §8 要求"每个 fact_id 恰好出现一次"，否则该块 INVALID。
**实测：所有块 `missing_ids` 等于全部 fed 事实数**——因为 n10 的输出是**叙述性报告**，
模型根本不回抄 `fact_id`（分区提示词虽要求，模型未遵守）。

- 该判据衡量的是**格式服从度**，不是数据完整性，用它判 INVALID 会因格式原因废掉全部数据。
- **未据此判 INVALID**；改用**值级覆盖**作为诊断（评分器本身即按值匹配，TP 计算不受影响）。
- 后果：n10 的"是否覆盖全部 fact_id"这一契约**实际未被强制执行**——这是合同合规性缺陷，
  已记录。

### D10：处罚事实从未进入事实库（V1.2 起就存在的隐藏 bug）

n1 输出的处罚条目结构是 `{"type":"罚款","subject":"泽达易盛","context":"…"}`，
**没有 `value` 字段**；而事实库构造器取值逻辑为 `value or name or ''`，取空即 `continue`
→ **所有处罚事实被静默丢弃**。

- 影响：W8 的 P02（警告）、P04（责令改正）虽然 n1 提取到了、也在窗口内，但**永远到不了终端**。
- P01（罚款）之所以成为 TP，是因为它在**金额分区**里作为 `fact_role` 值出现
  （`{"fact_role":"罚款","value":"81,000,440元"}`），属路径巧合。
- 该 bug 在 V1.2、V9 中同样存在（当时 P 类多不在窗口内，故未被发现）。
- **不改变本次判定**：D10 是"少回收 2 条"，使实测值成为**下界**；H-W1 门槛 18 已通过。

## 5. 已证明 / 未证明

### 已证明
1. 在其余一切相同（同模型、同提示词、同 n9/n10 结构、同评分器）条件下，
   仅把 n1 输入窗口 4000→8000，终端文档支持事实 **14 → 19**（配对中位 +5，最差块 +4），
   Precision 保持 100%。
2. 增益**不是**报告组织方式变化带来的：两臂 n10 结构完全相同。
3. 分类型生成消除了审计中观测到的"事实变多→整类丢日期"的失效模式（W8 5/5 块日期完整）。
4. 8000 窗口下 n1 输出 5,000 上限充裕（10/10 次无截断，实际输出未触及上限）。

2. **不能**外推到其他文档/案例；单案例、单文档对、单模型族。
3. **不能**作为动态调度证据；本实验只验证信息覆盖。
4. 未验证 8000 之后继续扩窗的边际收益。
