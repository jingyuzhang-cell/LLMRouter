## 3. 实验设计

| | A 臂（对照） | B 臂（处理） |
|---|---|---|
| n1 | 原提示词 + EV[:4000] + max_tokens=4000 + glm53flash | **完全相同（冻结）** |
| 传递 | `n1_output[:3000]` 字符截断 | 结构化事实库（下述 schema） |
| 其余节点 | V7 原提示词 | 按 §3.2 契约 |
| 模型 | glm53flash 全节点 | 同 |
| 评分 | **v3** | **v3** |
| 块数 | 5 | 5 |

5 组配对块，块内 A/B 顺序随机（沿用既有 seed 机制）。共 **2 × 10 × 5 = 100 次调用**。

### 3.1 事实记录 schema（冻结）

```json
{
  "fact_id": "AMT1853",
  "fact_type": "amount",
  "fact_role": "虚增收入",
  "value": "1,000万元",
  "provenance_status": "VERIFIED_UNIQUE_SPAN",
  "span_start": 1853,
  "quote": "金额1,000万元、3,000万元"
}
```

**字段规则（全部由代码生成，不由模型生成）**

1. `fact_id`：确定性、跨块稳定 = `{类型码}{span_start}`（类型码 DTE/AMT/PEN/ENT）；
   无 span 时用 `{类型码}X{归一化值短哈希}`。不依赖输出顺序。
2. `fact_type`：date / amount / penalty / entity（来自 n1 输出的顶层键）。
3. `fact_role`：直接取 n1 输出的既有字段（amounts.nature / dates.role / entities.role /
   penalties.type），**不由 n2 或任何下游重新判定**，避免角色由模型臆造。
4. `value`：n1 原值，逐字保留。
5. `normalized_value`：**不进传递载荷**，由代码在评分与对齐时计算（省预算且无失真）。
6. `provenance_status`（三态，与 status 分离）：
   - `VERIFIED_UNIQUE_SPAN`：值在 **n1 实际输入窗口**内唯一出现
   - `VERIFIED_MULTI_SPAN`：窗口内多处出现（记录首个 span）；**仍属文档支持**
   - `UNVERIFIABLE_ABSENT`：窗口内无出现 → 不得计为文档支持 TP
7. `span_start` + `quote`：证据片段 = 窗口内 `[span-pad, span_end+pad]`，**pad=10**（预算约束）。
8. `status`（核验状态，仅 n9 可写）：CANDIDATE → SUPPORTED / REJECTED / UNKNOWN。

**关于三态而非二态的说明（对裁决的一处有据偏离）**：
操作员原令为"唯一匹配成功；多处匹配或无匹配标 UNVERIFIABLE"。零调用实测发现，
严格唯一会把 **D03（`2019年6月13日` 出现 3 次）与 E01（公司全名出现 3 次）**判为不可支持，
而这两条在 V6/V7 中一直是文档支持的 TP——这将**人为压低 A 臂基线**，使 H2 失去可比性。
故采用三态：多处出现仍认证为文档支持（并标注），仅"窗口内完全不存在"才判 UNVERIFIABLE。
若操作员坚持二态，需同时接受 A 臂基线下降（D03 恒失、E01 部分失）。

### 3.2 各节点契约（B 臂，冻结）

| 节点 | 输入 | 输出 | 关键约束 |
|---|---|---|---|
| n2 | 金额事实索引 `{fact_id, fact_role, value}` | `{"duplicates":[],"role_conflicts":[]}` | **不得新增事实**；只做冲突检测，不改值 |
| n3 | dates 分区（全量） | `{"timeline":[{"fact_id","order","stage"}]}` | ID 引用，不重写值 |
| n4 | amounts 分区（全量） | `{"amounts":[{"fact_id","role","bucket"}]}` | ID 引用，不重写值 |
| n5 | penalties 分区 | `{"penalties":[...]}` | 同上 |
| n6 | entities 分区 | `{"entities":[{"fact_id","role"}]}` | 同上 |
| n7 | n3 + n6 输出（ID 级） | `{"stages":[]}` | 只做阶段划分 |
| n8 | n4 输出（ID 级） | `{"amounts_checked":[]}` | 只做口径冲突核验 |
| n9 | 全库 + provenance + quote | `{"supported":[],"rejected":[],"unknown":[]}` | **只输出 fact_id，不重复值**；避免 V4/V6/V7 的容量截断复发 |
| n10 | 仅 SUPPORTED 事实的值+角色 | `{"report":{}}` | 只组织已核验事实；UNKNOWN 单列 |

**架构声明（必须写入结论）**：B 臂是"结构化传递契约 + 确定性溯源 + ID 引用消费"的**整体架构**，
不是单一 JSON 格式。因此结论只能表述为"该架构的整体收益"，不得声称证明某个 schema 的效果。
**事实值在 n1 之后不再经过任何模型重写**（除 n10 组织报告），这是本设计的核心保真机制。

### 3.3 证据定位的硬约束（零调用可复核）

- 定位**只在 n1 实际看到的那段窗口文本内**进行（A/B 臂均为 `EV[:4000]`）。
- **禁止**用完整文档（17,205 字符）补充 n1 未看到的证据——否则会人为制造"文档支持"。
- 定位实现与自检脚本随实验一并归档，操作员可离线复核每个 span。

## 4. 预注册假设（冻结）

| 假设 | 指标 | 通过条件 |
|---|---|---|
| **H1 终端质量** | 文档支持 TP（v3） | B 中位 **≥14**；配对 TP 差中位 **≥+3**；**≥4/5** 配对为正向 |
| **H2 事实恢复** | A03、A09、A01 在终端 | 每条在 B 臂 **≥4/5** 块中出现（A 臂基线 0/9） |
| **H2b 非回归** | E01、D03、D06 | 每条在 B 臂 **≥4/5**（A 臂基线 E01 3/4、D03 4/4、D06 4/4） |
| **H3 Precision** | 池化 P_v3 | **≥85%**，且不低于 A 臂池化 **−2pp** |
| **H4 溯源诚实** | UNSUPPORTED_PROVENANCE 计入 TP 的条数 | B **≤** A |
| **成本** | 实测 token 比 | B/A **≤1.15**（点估计 1.106×；若实测越界→如实报告权衡，不宣称达标） |

判定：
- **CONFIRMED**：H1 ∧ H2 ∧ H3 ∧ H4
- **CONDITIONAL**：H1 满足 4/5 块且 H3 成立，H2 至少回收 2/3
- **NEGATIVE**：H1 不成立，或 H4 破坏，或 H2 回收 ≤1/3
- **INVALID**：预算/执行异常（含 n1 输出非合法 JSON、调用超限）

> 注：H1 的 TP≥14 是 **V7 配置下的硬天花板**（窗内可提取事实共 14 条），
> 不是"越高越好"的期望值。达到 14 即意味着"窗内可提取事实 100% 送达终端"。

| 风险 | 处置 |
|---|---|
| 成本实测越界（>1.15×） | 如实报告权衡；不得称"满足门槛"；不得事后调高门槛 |

| 单案例、单模型族 | 结论限定于该案例与 GLM 系；跨案例（非公开案例）需另行验证 |
