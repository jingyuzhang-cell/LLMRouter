## 2. 可行性核算（本案例真实数据，零调用）

### 2.1 现阶段损失的全部来源（来自 V8_2 归因 + REVISED_SCORING_V1）

| 损失位置 | 事实 | 机制 | 结构化传递能否回收 |
|---|---|---|---|
| 输出侧截断 `[:3000]` | A03, A09, E01, A01(flash 布局) | 事实排在 JSON 后部即不可见 | **能** |
| 输入侧窗口 `[:4000/6000]` | D08, A08, A02, P01, P02, P04 | 证据在文档 ≥7244 字符处 | 不能（另一自变量） |
| 提取契约 | D07（证据@1283 窗内）、P03（@3783） | n1 未提取 | 不能（另一自变量） |

### 2.2 关键量化结果：结构化块比现状更小，且携带全部事实

用 V7-B4 与 V8-2 的真实 n1 输出测算精简结构化记录
（`{"id","t","v","st"}`；normalized_value/source_document/evidence_span 由代码确定性生成，
不占用传递预算；context 散文由 evidence_span 回指原文替代）：

| 类型 | Flash n1 原始条数 → 去重 | 精简块字符 | GLM53 原始 → 去重 | 精简块字符 |
|---|---|---|---|---|
| dates | 11 → 11 | 539 | 7 → 7 | 351 |
| amounts | 31 → 29 | 1,556 | 28 → 25 | 1,336 |
| penalties | 1 → 1 | 45 | 1 → 1 | 45 |
| entities | 18 → 18 | 946 | 12 → 12 | 681 |
| **全部四类** | **61 → 59** | **3,086** | **53 → 45** | **2,413** |

对比现状：`n1_output[:3000]` 只能送达 7 个日期值 + 约 20 条金额（且 JSON 在半句处截断）。

> **结论：结构化传递在同等字符预算（3,000 量级）下，把事实送达率从约 50%（20/31 金额）
> 提升到 100%（59/59），无额外预算成本。** 这是本设计的核心可行性依据——
> 它不是"用更多 token 换保真"，而是"用同样的 token 换保真"。

按角色分区后更大余量：n3（dates）539 字符、n4（amounts）1,556、n5（penalties）45、
n6（entities）946、n9（全四类）= 3,086、n10（全四类）= 3,086。

### 2.3 天花板（预注册的收益上限）

若只改传递表示，不改输入窗口与 n1 契约：
- 可回收：A03、A09、E01、A01 → 支持 TP 从 11 → 14（Recall 0.500 → 0.636）
- D07 回收需同时修提取契约（不在本实验自变量内）→ 15/22 = 0.682 为"如果"上限
- 因此**预期区间：Recall 0.50 → 0.64（+0.14 绝对）**，F1_v2 中位 0.627 → 约 0.72
  （Precision 若持平 0.85–1.00）。这是**可证伪的数值预测**，偏离需解释。

## 3. 设计（2 臂 × 5 配对块 = 100 调用）

| 臂 | 传递表示 | 其余 |
|---|---|---|
| **A 对照** | 现状 `n1_output[:3000]`（逐字节复刻 V7） | V7 配置不变，作配对锚点 |
| **B 处理** | 类型化事实记录（下述 schema） | 同上节点/模型/预算 |

单自变量，配对块设计，块间顺序随机（沿用既有 seed 机制）。**不设第三臂**（避免范围蔓延；
n9 证据核验与 n10 组织规则在 B 臂内按操作员指示一并落实，因为它们属于同一"传递契约"整体）。

### 3.1 事实记录 schema（传递用）

```json
{"fact_id":"A01","fact_type":"amount","value":"1,000万元",
 "normalized_value":"1000万元","source_document":"doc1",
 "evidence_span":[1853,1872],"status":"CANDIDATE"}
```
- 传输时只带 `{fact_id, fact_type, value, evidence_span}`（normalized 由代码算）；
- `status ∈ {CANDIDATE, SUPPORTED, REJECTED, UNKNOWN}`，只有 n9 可置 SUPPORTED/REJECTED；
- `evidence_span` 在 n1 输出该事实时由 n1 自行给出（n1 提示词增加"给出原文证据片段"），
  随后由**代码**确定性定位到 EV 中（失败则置 `status=UNVERIFIABLE` 并保留，不丢弃）。

### 3.2 各节点契约修改（最小集）

| 节点 | 现状 | B 臂 |
|---|---|---|
| n2 | "补充遗漏的事实"（假设上游必有遗漏） | **去重与规范化器**："将下列事实去重、统一单位与格式；不得新增事实。输入即全部候选。" |
| n3 | 看 n2[:3000] 整理时间线 | 只收 dates 分区，全量 |
| n4 | 看 n2[:3000] 汇总金额 | 只收 amounts 分区，全量 |
| n5 | 看 n2[:2500] 处罚 | 只收 penalties 分区（注：本案例 n1 仅 1 条） |
| n6 | 看 n2[:3000] 实体 | 只收 entities 分区，全量 |
| n7 | 看 n3[:2000]+n6[:1500] | 同输入源，但均为全量结构化 |
| n8 | 看 n4[:2500] | 全量 amounts 交叉核验（须回填 value 原值） |
| n9 | 输入A=n1[:3000] 旁路 + B 拼接 | **不再用字符旁路**：直接接收 n1 全量结构化 + 中间节点核验结果；须逐条置 status，无据者 REJECTED |
| n10 | 看 n9[:6000] | 只根据 status=SUPPORTED 组织报告；UNKNOWN 单列 |

### 3.3 明确的防作弊/防污染约束

1. **Silver 绝不进入任何提示词**——传递记录只来自 n1 自身抽取（`fact_id` 由类型+序号生成，
   非 Silver ID，避免名称泄漏）。
2. 求值器 v2.2 **预先冻结**（见 REVISED_SCORING_V1.md），本实验前后不得修改；
   实验后若发现问题，另立 v3 并同时重算本实验，不单独改一侧。
3. UNSUPPORTED_PROVENANCE 逐条记录，B 臂的 TP 必须是"文档支持"TP；
   **若 B 臂 TP 增长主要来自无据命中，判为失败**（见 4）。
4. n1 输入窗口保持 4,000/6,000 原样（不带升级）——避免与传递表示混淆。

## 4. 预注册假设与验收（实验前冻结）

**H1（主）**：B 臂文档支持 TP 中位数 ≥ 14（vs A 臂 11），且配对 ≥4/5 为正向。
**H2（保真度）**：A03、A09、E01 在 B 臂 ≥4/5 块中出现在终端（A 臂应为 0/5）。
**H3（Precision 不劣化）**：B 臂 Precision_v2 池化 ≥ 85%，且不低于 A 臂池化 −2pp。
**H4（无据不增）**：B 臂 UNSUPPORTED_PROVENANCE 条数 ≤ A 臂。

判定：
- **CONFIRMED**：H1 ∧ H3 ∧ H4
- **CONDITIONAL**：H1 达 3/5 且 H3 成立
- **NEGATIVE**：H1 不成立，或 H4 破坏（无据命中增加）
- **INVALID**：预算/执行异常

**成本约束**：B 臂总 token ≤ 1.15 × A 臂（若结构化使成本显著上升，
即使质量提升也须报告成本-质量权衡，不得单称"改善"）。

## 6. 风险与已知边界

| 风险 | 处置 |
|---|---|
| 结构化记录格式本身成为新的"契约脆弱点"（模型改写字段名） | 由代码逐条校验 schema；不合规记录按 `UNVERIFIABLE` 保留并计数，不静默丢弃 |
| n2 从"补充者"改为"去重器"后可能仍返回空 | 提示词明确"输入即全部候选，须原样传递每条 fact_id"；若仍空则记录为契约失败 |
| 本案例 n1 仅提取 14/22，天花板受限于提取而非传递 | 已在 §2.3 预注册（Recall 上限 0.636）；跨案例才能检验提取下限 |
| 污染通道（记忆）在 B 臂可能更活跃（n9/n10 看到更多事实） | H4 专项检验；v2.2 溯源规则独立把关 |
| 单案例、单模型族（GLM 系） | 结论限定为"该案例+该模型族"，不作为通用结论 |
