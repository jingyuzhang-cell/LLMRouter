## 1. 科学问题（单一）

## 3. n10 分类型组织（本轮引入、两臂共用）

对每个块，n10 被调用 **4 次**（date / amount / penalty / entity 各一次），每次只收到该类型的事实：

```
system = SYS_DOWN（冻结）
user   = SYS_DOWN + "\n以下为已核验支持的{类型}事实（类型 {t}）。任务：把下列全部 fact_id 逐条写入报告，
         每条保留原始值与语义角色；不得遗漏、不得新增、不得改写数值。输出JSON，字段 report。\n"
       + json([{fact_id, fact_role, value}...] , separators=(',',':'))
       + "\n输出JSON，字段 report。"
```

**空桶也照常调用**（返回空数组），保证两臂调用数完全一致、不引入"调用数差异"这一额外变量。

**合并**（纯代码、无模型、确定性）：
```python
merged = {"report": {"dates": r_date, "amounts": r_amount,
                     "penalties": r_penalty, "entities": r_entity}}
```
预检已验证：合并结构的评分与扁平结构**完全等价**（TP 集与 F1 一致），且合并字节级确定性。

## 10. 执行前偏离记录（2026-11-02，零调用，未影响任何数据）

**D8（发现的真 bug）**：`b_arm_budget.build_store` 对**无证据跨度**的事实使用
`abs(hash(norm(value)))` 生成 fact_id（形如 `DTEX4659`）。Python 字符串哈希**跨进程随机化**，
因此同一 n1 输出在不同进程中会得到不同 fact_id → 不同 n9 提示词 → 不同 SHA。

**发现方式**：本实验启动时的冻结校验（§7）直接拦截（`n9.user_template` 不一致），
**在发出任何调用之前中止**，`w48_LEDGER.jsonl` 未创建，零费用。

**修复**：在 `w48_exec.py` 内新增 `build_store_det()`，无跨度事实改用
`sha1(normalized_value)[:8]` 生成确定性 ID。已跨 `PYTHONHASHSEED=1/999` 验证：
n9 提示词 SHA 均为 `d285ed4a617bbf3a`。

**对冻结哈希的影响**：`w48_PROMPT_FREEZE.json`（V1）的 `n9.user_template` 哈希是经由
随机化代码路径计算的，不可复现，作废；改用 `w48_PROMPT_FREEZE_V2.json`。
其余 11 项哈希在 V1/V2 中完全相同。

**为何这不破坏预注册**：修复发生在**第一次调用之前**，两臂同样使用修复后的构造器，
唯一变量仍是输入窗口。已记录为偏离，未修改任何判据。

**对历史的影响**：V1.2 与 V9 的部分事实 ID 同样受此 bug 影响，但那些运行内部
（单进程、单次）ID 一致，评分不受影响；只是不可跨进程复现。已记入已知限制。
