# P1 治理修正案 001（草案 · 待操作员批准后生效）

**日期**: 2026-10-30 | **修改对象**: P1 人工 Gold 建设的实施方式与验收标准
**动因**: 双人外部评审资源不可得（制备侧无人类通道；操作方招募未落实），不应让 Q Foundation
整体停摆；同时不得以 AI 冒充人类评审（操作员红线，本修正案全程遵守）。

## 一、调整后的 P1 实施方式（方案 A+B 组合）

### 轨道 B（E08 十条事实）——三层结构，目标身份：**Single-Human-Reviewed, Machine-Verified
Reference（单人类审阅、机器核验参考）**

| 层 | 承担者 | 内容 |
|---|---|---|
| 第一层：人类判断 | **人类评审者 1 名**（见 §三确认点） | 逐条核对事实、数值、日期、主体、原文证据（对照原始公告） |
| 第二层：确定性机器核验 | 程序（零调用） | SHA256 复核、span 定位复核、类型化数值/日期计算复核、来源绑定复核 |
| 第三层：AI 对抗复核 | AI（制备方谱系，如实披露） | 寻找遗漏事实、错误解释、错误绑定、潜在矛盾 |

**裁定规则**：三层一致 → 进入"单人类核验参考候选"；机器与人类不一致 → **保留争议，不强行
通过**；证据不足 → UNKNOWN。**U1 恒为 UNKNOWN**（除非未来出现合格新证据并另行授权核验）。

### 轨道 A（C9 123 条候选评分）——目标身份：**Human-AI Reviewed Reference（人类锚定评分参考）**

人类评审者 1 名完成 123 条评分；两个独立 AI 评审配置盲评；高分歧样本集中复核；提示词扰动
稳定性检查；保留逐条依据/置信度/分歧记录。若一名人类也无法落实 → 降级为 **AI-adjudicated
Silver**（不解 P1 门禁）。

## 二、身份与验收标准（正式修订，替代双人盲审标准）

| 产物 | 身份命名 | 禁止的表述 |
|---|---|---|
| 轨道 B 产物 | Single-Human-Reviewed, Machine-Verified Reference | ~~Dual-Human Gold~~、~~独立人类 Gold~~ |
| 轨道 A 产物 | Human-AI Reviewed Reference | ~~双人盲审 Gold~~ |
| 无人类参与时的产物 | AI-adjudicated Silver / Machine-verified Reference | 任何含"human/Gold"的表述 |

- P1 验收按本修正案标准执行；**不得沿用双人盲审标准宣布完成**。
- 单人类方案的证据血统（谁审、机器核验了什么、分歧如何处置）全程落档。
- P2 校准的对照基准 = 上述相应身份的参考；P3 冻结时质量信号的可信度声明与参考身份一致。

## 三、唯一待确认点：第一层人类评审者的人选

按操作员 2026-10-30 提议："此前未参与 E08 参考材料具体制备"者可担任唯一人类裁决者。
**满足该独立性条件且确定可达的人类 = 操作员本人**（全程仅做设计与治理裁决，从未参与材料
制备）。本修正案将第一层人选默认定为**操作员**——请批准时确认；若拟由他人担任，请提供人选
（人选须满足：真实人类、未参与制备、具备公告阅读与主体/数值核对能力）。
**注**：制备方（AI）不可占据第一层——那将违反本修正案自身的红线，产物会自动降级为
Machine-verified Reference。

## 四、轨道 B 执行协议（批准后按此执行，零模型调用）

1. 操作员逐条填写 `PKG_TRACK_B_REVIEWER_1` 工作表（10 事实 + U1）；
2. 制备方出具第二层确定性核验报告（SHA/span/数值/日期/来源，全部已有程序化路径）；
3. 制备方出具第三层 AI 对抗复核报告（披露同谱系身份）；
4. 三层比对：一致项 → 候选；不一致项 → 逐条列出争议与各方依据，交操作员裁定或保留 UNKNOWN；
5. 产出 `E08_REFERENCE_V1.json`（身份=Single-Human-Reviewed, Machine-Verified）+ 全程血统档案；
6. 轨道 A 随后单独推进，不互相等待。

## 五、不变项

冻结材料与协议（C9 校准协议、E08 SILVER 草案）不修改——本修正案是 P1 **实施层**的治理调整；
Conservative Parser / P0 评价器 / 评分规则零改动；P2–P5 门禁关系不变。

## 修订记录 v2（操作员三处收口，2026-10-30 批准条件）

1. **第一层身份披露（§三替换）**：第一层人类核验者 = **项目操作员本人**。其未直接参与参考
   事实制备，但**参与了任务选择与研究设计、评价标准制定、部分事实与候选答案讨论、P1 治理
   规则制定**——本次人工核验属**操作员审阅，不属于独立第三方盲审**。一切相关研究结果须
   完整披露该身份关系。
2. **三层语义（§一裁定规则替换）**：三层为**职责分工而非三个独立证据主体**（人类判事实、
   程序验来源/跨度/数值/计算、AI 找遗漏/错解/矛盾——第三层与制备方存在谱系关联，非独立
   第三方）。**三层一致 = 进入参考候选，不自动获得 Gold 身份**；三层不一致时保留争议及
   各方依据，**不允许通过调整规则使结果强行一致**。
3. **分歧处理（§四第 4 步替换）**：不一致项由操作员**以第一层核验者身份**重新检查原始公告、
   可修正自身初始判断或决定保留争议——**此步不构成第三方仲裁**（操作员不可作为自身核验的
   第二独立裁决人）。无法解决的争议保留为**未解决状态**，不得强行纳入参考答案。

**执行口径确认（操作员 2026-10-30）**：第一层 = 操作员本人（非独立身份披露）；启动范围 =
**先轨道 B**。轨道 A 随后单独推进；P2 依实际参考身份校准（不声称双人一致性证据）；P3 仍经
P2 验收，不提前解锁 P5。本确认不涉及历史数据、冻结代码或模型调用。
