## 1. 公平条款（执行前置条件；对应 Phase-1 两个缺陷）

F1 **统一终端交付合同**：所有臂的最终合成调用必须附带 `canonical_assembler.fair_final_prompt_suffix`
（相同 schema 字段集与 JSON 要求），交付经 `canonical_assembler.assemble` 统一装配（仅校验/规范化
臂自身输出，Silver 盲，缺失字段置空）。装配器输出经隔离门抽查。
F2 **输出预算配平表（冻结）**：最终合成/单模型 768 max_tokens；中间节点维持 phase1 NODE_CAPS
（448–576）且对所有臂同额；截断状态逐 run 记录，Q 一律为"该预算下观测值"并披露截断标志。
F3 **证据与检索配平**：所有臂仅经基准检索 API，按任务同额预算上限；查询词由臂自选（检索策略是被
评能力，其质量经 E_evidence 单独记账，不计入调度功劳）。
F4 **模型集合与解码同额**：{GLM-5.3, GLM-5.3-Flash}，温度/思考设置全臂一致。
F5 **全成本归属**：规划、检索注入、节点执行、修复、最终合成、程序毫秒全部计入该臂；单模型臂无
规划成本（其结构为零）；跨请求复用记 0 新增但显式标记。
F6 **规划合同前置校验（窗口 2 交付项，仅对未来批次生效）**：终局可达性检查进入规划合同校验层，
使该类错误在 ≤2 次信封内获得结构化修复反馈；不得追溯改变 Phase-1 的 T-P1 INVALID。
F7 **动态臂合法性（窗口 1）**：NONE/DECLINE 是恢复决策选项，但仅当终端合同允许或如实记录失败时
合法；决策记录须逐条给出触发信号与理由，缺失即无法主张 RQ2 收益。

## 2. 三层配对矩阵（分阶段执行、分阶段申请）

**Stage A（结构层）**：臂 = single_model / fixed_graph（冻结规范图：index→extracts→{timeline∥
entity_facts}→factcheck_full→report，声明为固定基线而非自主生成）/ auto_graph（真实规划）。
optimized_graph 臂注册待窗口 2 优化器交付后启用。任务 = 条件映射 6 主任务；重复 k=2（配对按
(task, rep) 同序）。规模：6×3×2=36 run；预算估计 ~120–135K token（中位任务 auto ~9.5K、fixed
~8.5K、single ~3.2K；长任务检索上浮）。判定：逐任务方向 + 中位数（工程门槛，非统计证明）。

**Stage B（静态分配层，gated on Stage A）**：在 Stage A 选出的 2 个锚点任务（各条件类 1 个）
的同一张图上：alloc_homogeneous / alloc_router / alloc_rule / alloc_static_opt（后者待窗口 2）。
k=2；规模 2×4×2=16 run；~85–110K。检索/E_evidence 配平口径同 F3。

**Stage C（动态联合层，gated on 窗口 1 交付）**：同一初始图 + 同一异常注入协议（窗口 1 冻结：
故障类型/绑定节点/种子），臂 = dyn_Static / dyn_R_only / dyn_pi_only / dyn_Joint_R_pi /
dyn_Joint_Z_R_pi；k=2；规模 2 任务×5 臂×k2×（含注入异常的重跑）≈ 20–30 run；~110–140K。
**同状态候选比较**：窗口 1 须在同一状态快照上输出全部候选的决策记录供配对评审。

三阶段各自单独申请授权；先 A 后 B/C；A 的结果决定 B/C 锚点与是否继续。

## 3. 统计与归因纪律（承袭 v1.1 附录）
逐 (task,rep) 配对；报 Q 中位、C/L 各维中位、K 比率与方向计数；同任务多 run 相关、不作独立性
显著性宣称；三层归因不可互借成绩；全部离线可复算（trace+retrieval_log+评分器版本冻结）。
