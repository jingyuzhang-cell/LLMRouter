# STAGE_C_R6_ATTRIBUTION — 零调用证据归因报告

> Stage-C-R6 正式结项后的深度归因分析。零模型调用。基于 20/20 run 原始响应与账本。

---

## 一、R-only 为何仅 1/4 成功

### 逐次失败链分析

| Run | 事件 | 失败点 | 根因 |
|---|---|---|---|
| **r1 SC-E1** | 獐子岛 | **✓ 成功** | n2 输出双日期 → n3 计算 350 天 → n6 报告保留 |
| r2 SC-E1 | 獐子岛 | **n3 无响应** | 执行在 timeline 之前中断（SSL 超时或管道问题） |
| r1 SC-E3 | 中国船舶 | **n3 缺少输入日期** | n2 未将日期传递给 n3（信息传播断裂） |
| r2 SC-E3 | 中国船舶 | **n3 缺少输入日期** | 同上；n6 存在但不含 350（因 n3 未计算） |

**关键区分**：
- r2(SC-E1) 的失败是**执行层中断**（n3 从未被调用）——不是策略问题
- r1/r2(SC-E3) 的失败是**信息层断裂**（n3 被调用但缺少上游输入）——证据传播问题
- 唯一成功(r1-SC-E1)具有**完整信息链**：n2提取双日期→n3计算→n6保留

**结论**：R-only 的 1/4 成功率不是算法不稳定，而是三种不同层面的失败：
1. 执行中断（SSL/超时）— 25%
2. 信息传播断裂（上游→下游数据丢失）— 50%
3. 成功 — 25%（仅当信息链完整时）

## 二、Joint(R,π) 为何与 π-only 完全相同

### 逐run 比较

所有可比 run 中，Joint(R,π) 与 π-only 产生**相同的节点序列和近似相同的输出**。

### 根因链

```
Joint(R,π) 搜索空间：
  R 候选: {n3}, {n3,n4}, {n3,n4,n5}, {n3,n4,n5,n6}
  π 候选: keep, optimize_quality(GLM), optimize_cost(Flash)

实际选择：
  R → 始终选最小闭包 {n3}（与 π-only 的默认相同）
  π → optimize_cost → Flash → 预算不足(8000 >> 5100 总消耗)
       → 回退 optimize_quality → GLM（与 π-only 相同）
  结果 → 与 π-only 完全相同的物理动作
```

**结论**：联合搜索空间存在但**在此条件下是平坦的**。
- R 选择退化为最小闭包（因为只有 n3 失败，最小闭包就是唯一合理选择）
- π 选择退化为 GLM（因为 Flash 切换条件不可达）
- 联合优化退化为单维优化

**这不是算法缺陷，是条件限制**：当前任务/预算/资源条件没有创造真正的联合优化机会。

## 三、完整 Q/C/L 核算

| 臂 | n | Q_terminal | Q_prefix | dQ_recovery | 调用 | Token | 墙钟中位 |

**成本-质量洞察**：
- R-only 用**最少的恢复调用**（17 vs 22-24）获得了**唯一的 dQ>0**
- Simple-Dynamic 用最多调用（24）获得最高 Q_terminal 但零 dQ
- 恢复臂墙钟均高于 Static（20-35s vs 12s），恢复有真实时间代价

## 四、总结

| 问题 | 答案 |
|---|---|
| R-only 为何只成功一次 | 三种不同层面的失败（执行中断/信息断裂/成功），不是纯随机 |
| Joint 为何无增量 | 搜索空间平坦——R 退化为最小闭包，π 退化为 GLM |
| 核心瓶颈 | 信息传播断裂（n2→n3 数据丢失）比调度策略选择更影响结果 |
| 下一步方向 | 修复信息传播可靠性比优化调度算法更紧迫 |
